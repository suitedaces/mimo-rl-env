I want a pure slug-generation API in `kubespawner.slugs` for making stable Kubernetes-safe identifiers from arbitrary user and server names. The main function should be `safe_slug(name, is_valid=is_valid_default, max_length=None) -> str`: if `name` already satisfies the supplied validator and length limit, return it unchanged; otherwise return a lowercase sanitized prefix plus `---` plus the first 8 hex characters of a SHA-256 hash of the original input, keeping the whole result within `max_length` or 32 characters by default.

For examples, `safe_slug("jupyter-alex")` should return `"jupyter-alex"`, `safe_slug("jupyter-Alex")` should return `"jupyter-alex---3a1c285c"`, `safe_slug("user@email.com")` should return `"user-email-com---0925f997"`, and `safe_slug("username--servername")` should return `"username-servername---d957f1de"` so names containing `--` cannot collide with joined user/server slugs. With `safe_slug("x" * 17, max_length=16)` it should return `"xxxxx---d04fd59f"`; with an impossible length such as `safe_slug("x" * 16, max_length=11)`, it should raise `ValueError`.

The API should also support validators such as `is_valid_label`: `safe_slug("AbC", is_valid=is_valid_label)` should return `"AbC"`, while `safe_slug("a@b.c", is_valid=is_valid_label)` should return `"a-b-c---d648b243"`. I also need `multi_slug(names, max_length=48) -> str` for combining multiple components with `--` and a single hash suffix computed across the original components using an unambiguous delimiter; for example `multi_slug(["user", "server"])` should return `"user--server---ff173834"`. If the requested `max_length` cannot allocate enough room per component, `multi_slug` should raise `ValueError`.

These functions should be referentially transparent: the same inputs always produce the same outputs, they must not mutate the input list passed to `multi_slug`, and they should not read or write files, use the network, or maintain hidden global state.
