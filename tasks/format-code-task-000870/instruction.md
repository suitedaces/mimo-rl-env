I want OCR-assisted matching for figure and table graphics in the full text parser. When I create FullTextProcessorConfig(use_ocr_model=True), load_models(app_config, app_context, fulltext_processor_config) should load the configured OCR model into FullTextModels.ocr_model, and FullTextProcessor(fulltext_models, config).get_semantic_document_for_layout_document(layout_document, context) should use that OCR model as an additional graphic matcher after bounding-box and related-block-text matching.

I also want a public OpticalCharacterRecognitionGraphicMatcher(ocr_model, max_resolution=1024) matcher with get_graphic_matches(semantic_graphic_list, candidate_semantic_content_list) so I can use this behavior directly. For a SemanticGraphic whose LayoutGraphic has a non-SVG local_file_path, the matcher should open the image, scale it down to max_resolution before OCR if needed, call ocr_model.predict_single(image).get_text(), and compare each OCR text line to the SemanticLabel text of the candidate SemanticFigure or SemanticTable.

For example, OCR text "Figure 1" should match a candidate labeled "Figure 1", and OCR text "Fig 1" should also match "Figure 1". OCR text "Figure 1" should not match a candidate labeled "Figure 2", and OCR text "F 1" should not match "Figure 1". If the OCR output is multiline like "Other\nFigure 1\nMore", the matcher should match using the line containing "Figure 1". Graphics without a local_file_path, and SVG graphics, should not be sent to OCR and should remain unmatched.
