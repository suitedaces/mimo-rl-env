I want `pylingual.decompile(pyc, save_to=None, config_file=None, version=None, top_k=10, trust_lnotab=False, timeout=None) -> DecompilerResult` to support a trusted line-number segmentation mode. When `trust_lnotab` is left as `False`, decompilation should use the normal segmentation model path. When `trust_lnotab=True`, decompilation should skip model-based segmentation and instead split each code object's instructions according to the `.pyc` line-number metadata before translation.

For each bytecode line group in trusted mode, a one-instruction line should receive a single `B` boundary, and a multi-instruction line should receive `B`, zero or more `I` labels, and a final `E` label. Repeated line numbers across nested or later code objects should not be segmented twice; already-seen line numbers should be ignored when deriving later boundaries. Every generated boundary should have confidence score `1`, and the instruction `starts_line` fields should be updated so only `B` boundaries start a new recovered source line while non-`B` instructions have no line start.

The local CLI should expose the same behavior with `pylingual --trust-lnotab PATHS...`, and `pylingual --help` should list `--trust-lnotab` as using the lnotab for segmentation instead of the segmentation model. Passing a bad or empty line grouping while deriving trusted boundaries should fail with `ValueError` instead of silently producing an invalid segmentation.
