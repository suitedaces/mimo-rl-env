I want a `request` package for parsing JWTs directly from `*http.Request` values without hand-extracting the token string first. It should expose `ParseFromRequest(req *http.Request, extractor Extractor, keyFunc jwt.Keyfunc, options ...ParseFromRequestOption) (*jwt.Token, error)`, where the extractor finds the raw token, the default claims type is `jwt.MapClaims`, the default parser is `&jwt.Parser{}`, extractor errors are returned unchanged, and successful extraction is parsed with `ParseWithClaims` and the supplied key callback. It should also expose `ParseFromRequestWithClaims(req *http.Request, extractor Extractor, claims jwt.Claims, keyFunc jwt.Keyfunc) (*jwt.Token, error)` as the custom-claims convenience form, plus `WithClaims(claims jwt.Claims)` and `WithParser(parser *jwt.Parser)` options.

I need an `Extractor` interface with `ExtractToken(*http.Request) (string, error)` and a shared `ErrNoTokenInRequest` error for the no-token case. `HeaderExtractor{"X-Token"}` should return the first non-empty matching header value, so a request with `X-Token: abc.def.ghi` returns `"abc.def.ghi", nil`; with none of the configured headers present it returns `"", ErrNoTokenInRequest`. `ArgumentExtractor{"token"}` should read query or parsed form arguments, so a request for `/?token=abc.def.ghi` returns that value, and a request with no matching argument returns `ErrNoTokenInRequest`.

I also need composition helpers: `MultiExtractor{HeaderExtractor{"X-Token"}, ArgumentExtractor{"token"}}` should try each extractor in order, return the first token it finds, skip `ErrNoTokenInRequest`, return the first other error immediately, and return `ErrNoTokenInRequest` if every extractor misses. `PostExtractionFilter` should wrap another extractor and transform a found token with a `func(string) (string, error)`, returning the filter's token or error; if the wrapped extractor misses or errors, that result should pass through.

For OAuth-style requests, `AuthorizationHeaderExtractor` should read the `Authorization` header and strip a leading `Bearer ` prefix case-insensitively, so `Authorization: Bearer abc.def.ghi` and `Authorization: bearer abc.def.ghi` both extract `abc.def.ghi`, while a non-bearer header value is returned unchanged. `OAuth2Extractor` should first use that authorization-header behavior and then fall back to the `access_token` request argument; for example, if both an Authorization bearer token and `?access_token=other` are present, the header token wins, and if only `?access_token=abc.def.ghi` is present, that argument is used. Calling `ParseFromRequest` with `OAuth2Extractor` and a valid signed JWT from either location should return a parsed token with the expected claims; calling it on a request where the extractor finds nothing should return `ErrNoTokenInRequest` and no token.
