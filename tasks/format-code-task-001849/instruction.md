I want the Fun compiler library to support inline JavaScript `<script>` blocks when compiling a program through `compiler.compileCode(sourceCode: string, opts: object, callback: function)` or `compiler.compileFile(sourceFilePath: string, opts: object, callback: function)`. When compilation succeeds, the callback should receive `null` for the error and a full HTML document string whose generated application script includes the inline JavaScript in an immediately executed function.

For `compileCode('foo = 1\n<script fooVariable=foo>fooVariable.mutate("set", [fun.expressions.Number(2)])</script>\n<div id="out">foo</div>', { minify:false, 'normalize.css':false }, cb)`, the returned HTML should include generated JavaScript that declares a local `fooVariable` bound to the compiled Fun variable, preserves and runs `fooVariable.mutate("set", [fun.expressions.Number(2)])`, and the resulting page should render `2` in `#out`.

For a script nested in a template/XML block, such as `compileCode('<div id="out"><script>fun.emit(hookName, fun.expressions.Text("ready"))</script></div>', { minify:false, 'normalize.css':false }, cb)`, the generated JavaScript should expose a local `hookName` value for the current DOM hook so the script can emit into that element; opening the returned HTML should show `ready` inside `#out`.

For a script inside a function body, such as `compileCode('make = function() { <script>yieldValue(fun.expressions.Text("ok"))</script> }\n<div id="out">make()</div>', { minify:false, 'normalize.css':false }, cb)`, the inline JavaScript should run in the function body and be able to call the surrounding function's `yieldValue`, so the resulting page renders `ok` in `#out`.
