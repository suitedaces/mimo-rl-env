I want Hydra apps run from the command line to honor `hydra.job.env_set` for a single job. When I run an app decorated with `@hydra.main`, such as `python my_app.py +hydra.job.env_set.foo=bar`, the user task should execute with `os.environ["foo"] == "bar"`; if the task prints that value, stdout should contain `bar` and the job should complete normally. The same behavior should work when `hydra.job.env_set` is defined in the config file instead of on the command line.

Values in `hydra.job.env_set` should be resolved against the composed config before the task starts. For example, with config values `foo: bar` and `hydra.job.env_set.foo: ${foo}`, running `python my_app.py` should make the task see `os.environ["foo"] == "bar"`. The temporary environment should already be active for `on_job_start` callbacks and for the task function itself. After the task finishes, whether it returns successfully or raises an exception, Hydra should put the process environment back to the values it had before the job-specific variables were applied, including removing variables that did not exist before the run.
