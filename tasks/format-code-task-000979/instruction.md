Hertz currently treats the names advertised in an HTTP Trailer header as loosely formatted strings. That makes malformed declarations surprisingly easy to accept, can panic when a comma-separated list contains an empty element, and lets a failed update leave a mixture of old and newly parsed state. It also allows Trailer.Set/Add to serialize names that are not valid HTTP field-names. This is risky for applications that proxy or stream chunked messages because trailer declarations are later used to decide which fields may be populated from the wire.\n\nHarden the public protocol.Trailer API and its HTTP/1 chunked-trailer integration. SetTrailers must parse a comma-separated declaration list by trimming optional whitespace (spaces and tabs), canonicalizing valid names using the existing normalization mode, and ignoring empty list elements; an all-empty declaration is a successful no-op. Every non-empty name must be a valid HTTP field-name and must not be one of the fields forbidden in trailers. Invalid input must return an error without changing the trailer's prior declarations or values. Set and Add must apply the same field-name validation and reject invalid names without mutating state, while continuing to reject RFC-forbidden trailer fields.\n\nWhen chunked trailers are read, only names previously declared through SetTrailers may receive values; undeclared fields remain absent. A malformed or forbidden field on the wire must return an error and clear the trailer state rather than exposing partial values. Existing behaviors remain compatible: valid declarations retain their order and normalized spelling, and CopyTo preserves declaration values and the DisableNormalizing setting.
