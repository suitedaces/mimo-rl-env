I want the Go package `github.com/PsionicAlch/byteforge/datastructs/set` to provide a generic unordered unique-member collection through `type Set[T comparable]` and its synchronized sibling `type SyncSet[T comparable]`. For the plain set, callers should be able to construct values with `New[T comparable](size ...int) *Set[T]`, `FromSlice[T comparable](data []T) *Set[T]`, and `FromSyncSet[T comparable](set *SyncSet[T]) *Set[T]`, then use `Contains(item T) bool`, `Push(items ...T)`, `Pop() (T, bool)`, `Peek() (T, bool)`, `Size() int`, `IsEmpty() bool`, `Iter() iter.Seq[T]`, `Remove(item T) bool`, `Clear()`, `Clone() *Set[T]`, `ToSlice() []T`, `Union(other *Set[T]) *Set[T]`, `Intersection(other *Set[T]) *Set[T]`, `Difference(other *Set[T]) *Set[T]`, `SymmetricDifference(other *Set[T]) *Set[T]`, `IsSubsetOf(other *Set[T]) bool`, and `Equals(other *Set[T]) bool`.

A concrete session should work like this: `s := set.FromSlice([]int{1, 2, 2, 3})` has size 3, contains 1, 2, and 3, and does not contain 4; after `s.Push(4, 4)`, size is 4; `s.Remove(2)` returns true and makes `s.Contains(2)` false; a second `s.Remove(2)` returns false. `Peek` on a non-empty set returns one current member with `ok == true` without changing `Size`, while `Pop` returns one current member with `ok == true` and removes it; on an empty set, both return the zero value and `ok == false`. `Clear` makes a set empty, `ToSlice` and `Iter` expose every member exactly once in unspecified order, and `Clone`, `FromSlice`, `FromSet`, and `FromSyncSet` should create independent collections so later mutations to one collection do not mutate the other.

Set algebra must not mutate either operand: for `a := set.FromSlice([]int{1,2,3,4})` and `b := set.FromSlice([]int{3,4,5,6})`, `a.Union(b)` contains `{1,2,3,4,5,6}`, `a.Intersection(b)` contains `{3,4}`, `a.Difference(b)` contains `{1,2}`, `b.Difference(a)` contains `{5,6}`, and `a.SymmetricDifference(b)` contains `{1,2,5,6}`. `IsSubsetOf` should return true for an empty set checked against any set and for `{1,2}` checked against `{1,2,3}`, and false for `{1,2,3}` checked against `{1,2}`. `Equals` should ignore order but require exactly the same unique members.

For concurrent use, callers should be able to construct `SyncSet[T]` values with `NewSync[T comparable](size ...int) *SyncSet[T]`, `SyncFromSlice[T comparable](data []T) *SyncSet[T]`, and `FromSet[T comparable](set *Set[T]) *SyncSet[T]`. The synchronized set should expose `Contains(item T) bool`, `Push(items ...T)`, `Pop() (T, bool)`, `Peek() (T, bool)`, `Size() int`, `IsEmpty() bool`, `Iter() func(func(T) bool)`, `Remove(item T) bool`, `Clear()`, `Clone() *SyncSet[T]`, `ToSlice() []T`, `Union(other *SyncSet[T]) *SyncSet[T]`, `Intersection(other *SyncSet[T]) *SyncSet[T]`, `Difference(other *SyncSet[T]) *SyncSet[T]`, `SymmetricDifference(other *SyncSet[T]) *SyncSet[T]`, `IsSubsetOf(other *SyncSet[T]) bool`, and `Equals(other *SyncSet[T]) bool`, with the same visible membership behavior as the plain set. Concurrent calls to these methods should be race-safe; `Iter` should iterate over a snapshot taken when `Iter` is called, so later writes are not reflected in that iterator. Pairwise `SyncSet` algebra and comparison methods should be safe to call concurrently from multiple goroutines, including opposite-direction calls such as `a.Union(b)` and `b.Union(a)`, without deadlocking and while returning the same membership results as the plain `Set` methods.
