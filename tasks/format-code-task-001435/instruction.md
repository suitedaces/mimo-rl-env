I want fasteners to provide method decorators for thread locks through `fasteners.locked`, `fasteners.read_locked`, and `fasteners.write_locked`, importable from the package top level and from `fasteners.lock`.

`fasteners.locked(*args, lock="_lock", logger=None)` should work both as `@fasteners.locked` and as `@fasteners.locked(lock="custom_attr")`. When a decorated instance method is called, it should look up the named lock attribute on `self`, acquire it before invoking the method with the original `self`, positional arguments, and keyword arguments, return the method's normal return value, and release the lock afterward even if the method raises. For example, a class with `self._lock = threading.Lock()` and a method decorated with `@fasteners.locked` should observe `self._lock.locked() is True` inside the method and `False` after the call returns.

If the configured attribute is a list or tuple of locks, `fasteners.locked` should acquire each lock in order by calling `acquire()` before running the method and release every acquired lock in reverse order afterward. For a list of ten `threading.Lock()` objects, the decorated method should observe all ten as locked while it runs and none locked after it returns. If acquiring the second lock returns `False`, the call should raise `threading.ThreadError` with a message identifying lock 2 and should still release the first lock; if releasing an acquired lock fails during this cleanup, the optional `logger` should receive an exception log entry.

`fasteners.read_locked(*args, lock="_lock")` and `fasteners.write_locked(*args, lock="_lock")` should also work as bare decorators or with a custom lock attribute name. They should look up a `fasteners.ReaderWriterLock` on `self` and run the method inside that lock's `read_lock()` or `write_lock()` context manager respectively. For a class with `self._lock = fasteners.ReaderWriterLock()`, a `@fasteners.read_locked` method should see `self._lock.owner == fasteners.ReaderWriterLock.READER` while it runs, a `@fasteners.write_locked` method should see `self._lock.owner == fasteners.ReaderWriterLock.WRITER`, and after either method returns the owner should be `None`.
