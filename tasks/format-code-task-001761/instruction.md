I want PuTTY's proxy-aware connection API to support outbound SOCKS 4 proxies when `CONF_proxy_type` is set to `PROXY_SOCKS4`. A caller should be able to resolve a target with `name_lookup(const char *host, int port, char **canonicalname, Conf *conf, int addressfamily, LogContext *logctx, const char *lookup_reason_for_logging)` and then create the proxied socket with `new_connection(SockAddr *addr, const char *hostname, int port, bool privport, bool oobinline, bool nodelay, bool keepalive, Plug *plug, Conf *conf, Interactor *interactor)`.

For an IPv4 target, `new_connection` should connect to the configured proxy host and port and send a SOCKS 4 CONNECT request: version 4, command 1, the destination port in network byte order, the four-byte IPv4 address, the configured `CONF_proxy_username` as a NUL-terminated string, and no hostname field. For example, connecting to `192.0.2.10:22` as proxy username `alice` should begin negotiation with bytes equivalent to `04 01 00 16 c0 00 02 0a 61 6c 69 63 65 00`.

When proxy DNS is in automatic mode, SOCKS 4 should resolve hostnames locally instead of delegating DNS to the proxy. When proxy DNS is forced on and the target address is still a hostname, the same API should use SOCKS4A by sending address `0.0.0.1`, then the NUL-terminated username, then the NUL-terminated destination hostname.

The returned socket should report a successful connection after the proxy sends an 8-byte SOCKS 4 reply with reply version 0 and status 90. It should fail with `SOCKS version 4 does not support IPv6` for IPv6 target addresses. It should also surface clear proxy errors for bad replies: a nonzero reply version should say the SOCKS proxy response contained the unexpected version, status 91 should say the SOCKS server reported failure to connect, status 92 should say the server wanted IDENTD on the client, status 93 should say the username and IDENTD do not agree, and any other status should report the unrecognised SOCKS error code.
