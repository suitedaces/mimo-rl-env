I want VirtualiZarr to provide a `ZarrParser(group: str | None = None, skip_variables: Iterable[str] | None = None)` parser that can be passed to `open_virtual_dataset` or called directly as `ZarrParser(...)(url: str, registry: ObjectStoreRegistry) -> ManifestStore` to virtualize an already-existing Zarr store without copying its chunk objects. Given a local Zarr V3 store written from an xarray dataset like `{"data": (("x", "y"), np.arange(36).reshape(6, 6).astype("float32"))}` with `chunks=(2, 2)`, calling the parser should return a `ManifestStore` that can be opened with xarray's Zarr engine as a Zarr V3 store and produce a dataset identical to the source, while its chunk references point at the original `data/c/...` chunk object URLs with offset `0` and the listed object lengths. Given an equivalent Zarr V2 store, the same call should also return a Zarr V3-compatible `ManifestStore`, with initialized chunk objects discovered from V2 chunk keys and exposed through VirtualiZarr's dot-separated manifest keys.

The parser should resolve `url` through the supplied `ObjectStoreRegistry`, including the case where the registry root is a parent prefix and the Zarr store is nested below it, so `ZarrParser()(url="file:///bucket_root/foo/bar.zarr", registry=registry_for_file_bucket_root)` still records references under the original nested store URL. If `group="group_a/nested"` is provided, the returned manifest should use that group as its root; otherwise it should recurse from the store root and include arrays in nested groups as nested `ManifestGroup` entries. If `skip_variables=["air"]` is provided, arrays with those names should be omitted wherever they appear in the walked Zarr hierarchy.

Sparse stores should stay sparse: for a 30 by 30 array with 10 by 10 chunks where only chunks `0.0`, `1.1`, and `2.2` exist, the manifest should contain exactly those chunk keys and preserve the full `(3, 3)` chunk-grid shape so reads of missing chunks fall back to the Zarr fill value. Scalar arrays should be handled without listing a directory: an initialized scalar should produce a single scalar chunk reference, while an uninitialized scalar should produce an empty manifest with scalar chunk-grid shape `()`. Zarr V3 sharded arrays should use the shard grid as the manifest grid so reading the manifest-backed store returns the same data as the source. Calling the parser from inside an already-running asyncio event loop, such as in a notebook, should still complete synchronously and return the same `ManifestStore` result. Invalid URLs or registry misses should surface the normalization or registry exception, and arrays whose metadata uses an unsupported non-regular chunk grid should raise `NotImplementedError` instead of silently producing incorrect references. Repeated calls against an unchanged store should return equivalent manifests, should not mutate the input store or registry, and should only read/list/head existing objects rather than copying chunk bytes or writing new objects.
