I want kubeconfig loading to support Kubernetes user entries that use the GCP auth provider. When I construct `KubeConfigLoader(config_dict, active_context=None, get_google_credentials=None, config_base_path="", config_persister=None, temp_file_path=None)` and the selected user has `auth-provider.name` set to `gcp`, `await loader.load_and_set(client_configuration)` should authenticate with that provider and write `client_configuration.api_key["BearerToken"]` as `Bearer <token>`.

I also want `await loader.load_gcp_token() -> str` as a public method. If the selected GCP auth-provider config already has an unexpired `access-token`, for example `access-token: cached-token` with `expiry: 2999-01-01T00:00:00Z`, it should return `Bearer cached-token`, set `loader.token` to the same value, and must not call `get_google_credentials`. If the token is missing or expired, it should obtain fresh credentials, update the kubeconfig auth-provider config with the new `access-token` and `expiry`, call `config_persister` with the updated config when one was supplied, then return and store `Bearer <new token>`.

The `get_google_credentials` constructor argument should accept either a regular callable or an async callable returning an object with `token` and `expiry` attributes. Without that injected callable, the loader should use the GCP auth-provider config command: require `cmd-path` and `cmd-args` string values, split `cmd-args` like shell arguments, run the command asynchronously, parse its JSON stdout, and read `credential.access_token` plus `credential.token_expiry`. A config missing `cmd-path` or `cmd-args` should raise `ValueError`; non-string values for those keys should also raise `ValueError`.

Finally, `await refresh_token(loader, client_configuration, interval=60)` should support a loader whose provider is `gcp`: on each interval it should refresh through `loader.load_gcp_token()` and copy the current bearer token into `client_configuration.api_key["BearerToken"]`.
