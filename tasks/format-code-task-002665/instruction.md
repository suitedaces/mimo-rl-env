I want DisTube queues to support autoplay through related songs. After I obtain a Queue, `queue.toggleAutoplay(): boolean` should flip `queue.autoplay` from `false` to `true` and back again, returning the new boolean state each time; the deprecated `distube.toggleAutoplay(guild): boolean` should do the same for that guild's queue. Plugins should expose `getRelatedSongs(song): Awaitable<Song[]>` so the queue can ask the plugin that supports a song for recommendations.

I need `queue.addRelatedSong(song?: Song): Promise<Song>` to ask the supporting plugin for related songs, append the first acceptable recommendation to the queue, and resolve with the appended Song. If I pass a Song argument, that Song is used even when `queue.songs` is empty; if I omit it, the current `queue.songs[0]` is used, and an empty queue rejects with a `DisTubeError` for `NO_PLAYING_SONG`. Recommendations whose ids are already in `queue.previousSongs` should be skipped, and if the current song is a streamed/search result with an underlying source song, the queue should also try related songs from that source song when the first lookup has no usable results. The appended related song should inherit the current song's metadata and queue client member before being added. If no recommendation can be found, `queue.addRelatedSong()` should reject with a `DisTubeError` for `NO_RELATED`; the deprecated `distube.addRelatedSong(guild): Promise<Song>` should delegate to the guild queue.

When autoplay is enabled and the current song finishes naturally leaving no queued songs, DisTube should request a related song using the song that just finished, add it to the queue, and start playback of that new song instead of ending the queue. If that automatic related-song lookup fails, DisTube should emit the public `noRelated` event with the queue and the `DisTubeError`, remove the queue, and not emit the normal `finish` event for that autoplay failure. When autoplay is enabled and I call `queue.skip()` or `queue.jump()` past the last queued song, the queue should add a related song instead of throwing `NO_UP_NEXT`, then advance playback to that related song.
