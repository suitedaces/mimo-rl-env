I want `krakenex.API` to support authenticated private Kraken REST calls as part of the same session object. The constructor should accept optional string arguments `key=''` and `secret=''` and keep them available for later private calls; alternatively, `load_key(path)` should read a two-line text file, using the first stripped line as the API key and the second stripped line as the secret.

After `api = krakenex.API(key='my-key', secret='c2VjcmV0')`, `api.query_private(method, data=None, timeout=None)` should build the private endpoint path `/0/private/<method>`, require both credentials, add a fresh millisecond timestamp nonce to the request parameters, sign the request using Kraken's HMAC-SHA512 scheme, send a POST with `API-Key` and `API-Sign` headers, and return the decoded JSON response. Passing `None` for `data` should behave like an empty dict; passing `{'asset': 'XXBT'}` should send that parameter plus the generated nonce. The signature should use the base64-decoded secret as the HMAC key, with a message made from the private URL path bytes followed by the SHA256 digest of `str(nonce) + urlencode(params)`, and the final header value should be the base64-encoded HMAC digest. If either the key or secret is missing, `query_private` should raise `Exception` with exactly this message: "Either key or secret is not set! (Use `load_key()`." before any request is sent. The `timeout` value passed to `query_private` should be forwarded to the private request.
