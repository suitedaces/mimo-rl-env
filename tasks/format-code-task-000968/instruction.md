Large BIG-IP collections are returned as a chain of REST pages, but the SDK's collection APIs currently expose only the first response. Make pagination transparent for both public `get_collection()` variants (`Collection` and `OrganizingCollection`) and for `RESTInterfaceCollection.delete_all()`, without changing ordinary single-page behavior.

For each collection read, start with the same collection URI used today and append every response's `items` until a response has no `nextLink`. Preserve page order, item order, and duplicates. A missing or empty `items` field is an empty page, not the end of traversal when `nextLink` is present. Organizing collections continue to return the accumulated raw entries. Normal collections must apply their existing conversion rules to every page: entries with a registered `kind` become the corresponding resource object, kindless entries remain raw dictionaries, and an unknown `kind` raises `UnregisteredKind`. Hydrated resources must continue to target the configured appliance rather than a `localhost` authority from a server-provided link.

A `nextLink` may be absolute or root-relative. Resolve its path and query against the original collection endpoint, but always use that endpoint's scheme and authority; never send a continuation request to an authority embedded in the response. Continuation fetch exceptions must propagate unchanged. Detect a continuation URL that has already been visited after normalization before requesting it again. Expose this as `f5.bigip.exceptions.PaginationLoop`, subclassing `BigIPException`, and include the repeated normalized URL in the exception text. The same loop rule applies to both forms of `get_collection()` and to `delete_all()`.

`delete_all()` must finish discovering and snapshotting all pages before it deletes anything, so deleting from earlier pages cannot shift later page cursors. After successful discovery, apply `startswith` across the full snapshot and call `delete` for matching names in server order, with the caller's `folder` and `timeout`. Keep the current short-circuit contract: if a delete returns false, stop immediately and return false; otherwise return true. The initial discovery request keeps the existing `$select` and partition `$filter` parameters. A continuation link is a complete cursor, so do not reapply those parameters or the initial positional addressing arguments to later requests, but do pass the caller's timeout to every discovery request and delete. If discovery fails or loops, propagate the error and perform no deletions.
