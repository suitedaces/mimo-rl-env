The framework-based artifactory_managed_user resource validates password and password_policy during Terraform configuration validation. Interpolated values are commonly unknown during planning, so validation must not turn an unknown password or unknown password-policy object/field into an empty or zero value and reject a configuration before the value is known. At the same time, known values must retain the existing Access-compatible policy checks.

Apply these semantics consistently for the nested password_policy settings uppercase, lowercase, special_char, digit, and length. When a policy object is present but a setting is omitted, that setting uses the documented Access default (uppercase 1, lowercase 1, special_char 0, digit 1, length 8); an explicitly configured zero is meaningful and must not be replaced by the default. A known password that satisfies the effective policy is accepted, while one that violates a default or explicit policy is rejected with a validation diagnostic. Policy counts must be non-negative: invalid negative counts must yield a normal validation diagnostic and never panic while constructing a check. Unknown policy values defer the affected check until planning can resolve them. Keep the resource usable with ordinary known passwords and preserve the existing diagnostic-based validation surface.
