I want the `teresa app delete <name>` command to let me remove an application from the current Teresa cluster. The command should be registered under `teresa app`, appear in `teresa app --help` as `delete <name>` with the description "Delete app", and support a `--no-input` flag that skips confirmation.

When I run `teresa app delete foo` without `--no-input`, the CLI should first resolve the current cluster, connect to the server for that cluster, then ask `Are you sure you want to delete foo on <cluster>? (yes/NO) `. If I answer anything other than `yes`, it should print `Delete process aborted!`, make no delete request, and exit successfully. If I answer `yes`, it should ask `Please re type the app name: `; if the response is not exactly `foo`, it should print `Delete process aborted!`, make no delete request, and exit successfully.

When I run `teresa app delete foo --no-input`, the command should skip both prompts and send the delete request immediately. On a successful delete request, stdout should include `The app foo will be deleted in a few minutes` and the command should exit 0.

The server-side delete request should use the authenticated user and app name, require the user to have permission on the app's team, return the existing app-not-found or permission-denied errors when appropriate, and delete the Kubernetes namespace for that app. If the CLI cannot read the current cluster config, connect to the server, or the server returns an error such as app not found or permission denied, it should print the error message on stderr and exit non-zero.
