The XML suppression filter accepts compound Match trees, but the existing disabled-state handling is only reliable for direct children of the top-level filter. As a result, a generated or hand-maintained filter that disables one nested clause can silently change meaning when it is parsed, and serializing that filter loses the operator's disabled state.

Make disablement compositional across the public filter XML format. For every matcher element that accepts the `disabled="true"` attribute, including `And`, `Or`, `Not`, `Match`, and leaf matchers, a disabled matcher must be treated as absent from its containing compound: it must not contribute a true or false result and its descendants must not be evaluated. The containing `And`, `Or`, or `Not` must then apply its existing logic to the remaining enabled children, including the existing empty-compound behavior. This must work at arbitrary nesting depth and for disabled leaves as well as disabled compound branches.

Keep the established behavior for enabled matchers and for top-level `Match` entries, including their public `Filter.match` results. When a filter is written with `writeAsXML`, nested disabled state must be represented in the emitted XML so parsing that XML again preserves the same matching behavior. The change must not require callers to rewrite existing filter files or depend on a particular internal matcher representation.
