Production report endpoints receive attacker-controlled payloads, but `collector.Handler` currently reads the whole request without a bound and can invoke callbacks for early entries before discovering that a later entry is invalid. Harden this existing handler so rejection is cheap, deterministic, and atomic, while retaining its current public API and wire-format compatibility.

Keep the exported signature exactly `func Handler(func(Report), func(CSPReport)) safehttp.Handler`. Validation order is observable: reject non-POST requests with 405 before inspecting their Content-Type or body; then parse Content-Type using MIME media-type rules. The two supported media types are `application/reports+json` and `application/csp-report`, matched case-insensitively and still accepted with syntactically valid parameters. A missing, malformed, or other media type returns 415. Method and media-type rejection must not read the body, and media-type rejection takes precedence even when Content-Length declares an oversized body.

Limit every accepted-media-type request body to 1,048,576 bytes, counting all bytes including trailing whitespace. A body exactly at the limit remains eligible for normal decoding. If a positive Content-Length is already over the limit, return 413 without reading the body. For unknown-length bodies, read at most 1,048,577 bytes, using the extra byte only to detect overflow; an oversized body returns 413. No callback may run for an oversized request.

For `application/reports+json`, require a top-level JSON array containing at most 100 reports. Exactly 100 is valid; 101 or more returns 413. Each array element must be a non-null JSON object, and every report's `body` must itself be a non-null JSON object, including reports whose type is `csp-violation`. Malformed JSON or any wrong-shaped element/body returns 400. Validate and convert the complete batch before invoking the generic callback: if any entry is invalid, invoke it zero times; otherwise invoke it once per report in input order.

For `application/csp-report`, the top level must be a non-null JSON object. Continue accepting both the direct CSP object and the legacy `{"csp-report": {...}}` envelope, but when that envelope member is present its value must be a non-null object; wrong shapes return 400 without invoking the CSP callback.

Apart from these stricter gates, preserve existing decoding behavior: valid generic and CSP batches return 204 with an empty body, unknown generic report types retain their object-valued bodies, CSP field mappings remain unchanged, and the existing `lineno`/`colno` precedence over `line-number`/`column-number` remains intact. Every rejected request must leave both callbacks untouched.
