I want an `AwsXRayLambdaPropagator` API for Lambda trace extraction, usable as `AwsXRayLambdaPropagator().extract(carrier, context=None, getter=default_getter) -> Context`, and available from `opentelemetry.propagators.aws` as well as the `xray-lambda` `opentelemetry_propagator` entry point. It should first extract an `X-Amzn-Trace-Id` header from the supplied carrier using the same AWS X-Ray trace header behavior as `AwsXRayPropagator`.

If the supplied context already has a valid current span, `extract` should not read `_X_AMZN_TRACE_ID`; for example, with an empty carrier and a context containing `SpanContext(1, 2, False)`, the returned context should still expose trace id `0x1`, span id `0x2`, an unsampled trace flag, and the default trace state. If the supplied carrier does not provide a usable X-Ray parent and the current context is invalid, `extract` should fall back to the `_X_AMZN_TRACE_ID` environment variable. For `_X_AMZN_TRACE_ID="Root=1-00000001-d188f8fa79d48a391a778fa6;Parent=53995c3f42cd8ad8;Sampled=1;Foo=Bar"` and an empty carrier, the returned context should contain a remote parent with trace id `0x1d188f8fa79d48a391a778fa6`, span id `0x53995c3f42cd8ad8`, sampled set to true, and the default trace state.

When neither the carrier nor `_X_AMZN_TRACE_ID` provides a trace header, extraction should leave the input context unchanged; with no explicit context this means the returned context has an invalid span context. Calling the method with the same carrier, context, getter, and environment should produce the same extracted context and should not mutate the carrier.
