I want backend response formatting to support a `target` setting on `config.Backend`, including the JSON config key `target`, so a backend response can be narrowed to a nested object before the rest of the response shaping runs. The public library path should work as `formatter := proxy.NewEntityFormatter(&config.Backend{Target: "profile"})`, then `out := formatter.Format(proxy.Response{Data: map[string]interface{}{"id": 1, "profile": map[string]interface{}{"name": "Ada", "active": true}}, IsComplete: true})`; `out.Data` should be `map[string]interface{}{"name": "Ada", "active": true}` and `out.IsComplete` should remain true.

Dotted targets should walk nested objects. For `Target: "payload.user"` and response data `{"payload": {"user": {"name": "Ada"}, "debug": true}, "status": "ok"}`, `Format` should return data `{"name": "Ada"}`. If any target path segment is missing, or if the selected value is not an object, `Format` should return an empty data map while preserving the other response metadata such as `IsComplete`.

The target extraction should happen before allow-list filtering, deny-list filtering, field mapping, grouping, and backend flatmap operations. For example, with `Target: "payload"`, `AllowList: []string{"name"}`, `Mapping: map[string]string{"name": "display_name"}`, and `Group: "user"`, formatting `{"payload": {"name": "Ada", "secret": "x"}, "ignored": true}` should return `{"user": {"display_name": "Ada"}}`. When a backend has flatmap operations configured, those operations should run against the object selected by `target`, and any configured backend `group` should wrap the result after those flatmap operations.

Calling `Format` with the same backend configuration and equivalent response data should produce equivalent output each time, and the feature should not perform filesystem, network, or global-state side effects.
