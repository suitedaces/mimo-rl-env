The public AutomationCondition.replace() API is intended to make it easy to update a condition expression without knowing how that expression is composed. Today replacement works for boolean expressions and dependency wrappers, but several other public constructors silently stop the traversal at their wrapper, so replacing a nested condition either leaves the old behavior in place or drops the wrapper's configuration. This makes reusable condition-building utilities unreliable: a caller cannot safely replace a labeled trigger inside a temporal condition or change the predicate used by a check aggregation.

Extend replacement so it recursively visits every child of the public wrapper conditions used by declarative automation, including since(), newly_true(), any_checks_match(), and all_checks_match(). Replacing a condition object must replace matching nested objects; replacing a label string must replace the condition carrying that label. The returned expression must retain the outer wrapper and all of its observable configuration (such as the outer label, blocking_only setting, and the other Since child), while the original expression remains unchanged. The replacement itself should be installed as the child, including its own label state, and the resulting expression must expose the updated tree through the normal AutomationCondition snapshot/public inspection APIs. Existing replacement behavior for expressions that already recurse must continue to work.
