Harden the public `endpoints.ValidateEndpoints` guard used before StackRox integrations connect to user-supplied services. The current guard only recognizes a few exact lowercase host strings and only walks struct and pointer fields, so equivalent spellings, other local addresses, and endpoint values nested in configuration containers can bypass the protection.

An endpoint value is either a bare authority (`host[:port]`, including bracketed IPv6) or an absolute `http`/`https` URL. Schemes and DNS names are case-insensitive. Parse the authority rather than searching the whole string: userinfo, ports, and paths do not change which host is being validated. Reject malformed URLs, URLs with no host, and absolute URLs using an unsupported scheme by returning an error. Empty tagged strings remain optional and valid.

After canonicalization (case-folding and removing one or more trailing DNS dots), reject `localhost` and `metadata.google.internal`, every IPv4 address in `127.0.0.0/8` or `169.254.0.0/16`, IPv6 loopback `::1`, and IPv6 link-local addresses in `fe80::/10`. Bracketed IPv6 with a port must be handled the same way as an unbracketed host. Names that merely contain a blocked name, such as `localhost.example`, and public addresses such as `10.0.0.1` or `2001:db8::1` must remain allowed.

The validator must inspect every tagged endpoint reachable through finite nested structs, pointers, interfaces, slices, arrays, and maps, including when one of those containers is the top-level value. Nil pointers/interfaces, nil or empty containers, and untagged fields must not cause an error. Existing integration callers should continue to receive a normal validation error for blocked values and no error for safe values; validation must not panic on ordinary optional configuration shapes.
