The one-declaration-per-file sniff is currently too narrow and produces misleading results in modern PHP files: it only observes class tokens, treats anonymous classes as declarations, and its counter must remain isolated between files. Update the standard so the rule reflects the Symfony intent without penalizing legitimate anonymous-class usage.

A file may contain at most one named class-like declaration. Named `class`, `interface`, and `trait` declarations all participate in the same file-wide count, including declarations in different namespaces; the first is accepted and every subsequent named declaration must produce a duplicate-declaration error. Modifiers such as `abstract` and `final` do not change this classification.

An anonymous class introduced by `new class` is never counted and must not itself produce an error, regardless of how many anonymous classes occur or where they appear relative to a named declaration. In particular, an anonymous class before the only named declaration must not consume the one allowed slot, and an anonymous class between two named declarations must not add an extra duplicate report. When the sniffer instance is reused for another filename, counting starts over so the first named declaration in that file is accepted.
