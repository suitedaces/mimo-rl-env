I want a stateful scroll viewport widget for tui-go that I can create with `tui.NewScrollArea(w tui.Widget) *tui.ScrollArea`. The returned `ScrollArea` should implement `tui.Widget`, report `MinSizeHint() image.Point` as `(0,0)`, and report `SizeHint() image.Point` as `(15,8)`.

After I wrap a child widget, `Resize(size image.Point)` should resize the child to its own natural `SizeHint()` and set the scroll area viewport to `size`. `Draw(p *tui.Painter)` should render only the visible rectangle of the child: for example, wrapping a vertical box containing labels `foo`, `bar`, and `test`, resizing the scroll area to `image.Pt(10, 2)`, and drawing it should show only `foo` on the first row and `bar` on the second row. If I call `Scroll(0, 1)` before drawing the same viewport, the visible rows should become `bar` and `test`.

The scroll position should be cumulative and two-dimensional. For a one-line label `Lorem ipsum dolor sit amet, consectetur adipiscing elit.`, a `10x1` viewport should initially draw `Lorem ipsu`; after `Scroll(46, 0)` it should draw `cing elit.`. For a vertical list of `row 0` through `row 9`, a `10x3` viewport after `Scroll(1, 2)` should draw the horizontal slice `ow 2`, `ow 3`, and `ow 4`.

I also need vertical convenience methods. `ScrollToBottom()` should make the bottom-most child rows visible based on the child height and current viewport height, while preserving the current horizontal scroll. `ScrollToTop()` should reset only the vertical scroll to the top, also preserving horizontal scroll. `SetAutoscrollToBottom(true)` should make later `Resize(...)` calls automatically scroll to the bottom, and `SetAutoscrollToBottom(false)` should leave the current scroll position controlled by explicit scroll calls.
