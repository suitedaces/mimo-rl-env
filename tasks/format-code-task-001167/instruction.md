Streamlink's HLS playlist parser currently ignores RFC 8216 EXT-X-DEFINE tags. Playlists that use {$name} placeholders therefore produce unusable segment, key, initialization-map, rendition, and variant URLs, and lose values that are needed while parsing master-playlist attributes.

Add public variable support to the existing playlist-loading surface. An EXT-X-DEFINE with NAME and VALUE binds that name, and an EXT-X-DEFINE with QUERYPARAM binds the named variable from the playlist base URI's query string when it is present. The parsed M3U8 object must expose the successfully bound variables in a variables mapping. A VALUE may reference variables defined earlier in the same playlist; resolve those references when storing the value. Definitions are processed in input order, and redefining a name changes expansion only for later lines. Do not retroactively rewrite objects that were already parsed.

Before normal URI or attribute parsing, expand {$name} placeholders using the definitions currently in scope. Expansion applies to URI lines for segments and variants, URI attributes such as EXT-X-KEY, EXT-X-MAP, and EXT-X-MEDIA, and other quoted attribute values (for example CODECS, GROUP-ID, and NAME). Relative results are resolved against the existing playlist base URI exactly like other playlist references. A placeholder with no bound value, including a missing QUERYPARAM, remains verbatim in the parsed value and must not abort the playlist. Playlists that contain no EXT-X-DEFINE tags must retain their current parsing behavior.
