Add bounded, cancellable collection to `@broofa/asyncconcat` without breaking its existing callers. The utility is often used on response bodies and subprocess output, where an unbounded source can consume arbitrary memory and a caller may stop caring before the stream ends. Extend the exported function so callers can use either `asyncConcat(stream, encoding?, options?)` or the convenient `asyncConcat(stream, options)` form. The options object supports `encoding`, `maxBytes`, and an AbortSignal as `signal`. If both the positional encoding and `options.encoding` are present, the positional value wins. Existing calls with no options must retain their current result shapes: no encoding returns a Buffer, while an encoding returns a string.

The collector must accept Buffer, Uint8Array, and string data chunks and preserve their byte order. Treat strings as UTF-8 bytes before concatenation; the selected encoding only controls conversion of the final bytes to a string. Any other chunk type makes the returned promise reject with a TypeError rather than leaking a synchronous stream-listener exception.

When `maxBytes` is supplied, it must be a finite, non-negative integer; otherwise the returned promise rejects with a RangeError. The limit applies to the accumulated byte length, not JavaScript character count. Exactly `maxBytes` bytes are allowed, including `maxBytes: 0` for an empty stream. As soon as received data would make the total larger than the limit, reject with a RangeError and never resolve with a truncated or partial value. Omitting `maxBytes` preserves the current unbounded behavior.

Cancellation must work at both lifecycle boundaries. If the signal is already aborted when called, reject with that exact `signal.reason`. If it aborts while data is being consumed, reject with that exact reason even if the stream subsequently ends. Ordinary source-stream errors must continue to reject with the original error object.
