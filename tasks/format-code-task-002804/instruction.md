The dataclass binding layer currently breaks on Python 3.14: class annotations may be exposed lazily, so metadata discovery cannot identify which class declared a field and ordinary JSON/XML binding raises XmlContextError before doing any work. Restore reliable runtime annotation discovery while keeping the existing public serialization and parsing contracts intact.

Building metadata for a dataclass must work for both fields declared directly on the requested class and fields inherited from dataclass bases, including normal field metadata such as element names and namespaces. JSON serialization and parsing must continue to include inherited and direct fields and reconstruct their declared Python types. XML serialization must preserve the model namespace rules: a namespaced root remains qualified, explicitly unqualified child fields remain unqualified, and a parsed XML document round-trips to the same model.

XmlContext.build exposes a globalns override for resolving forward references. A class whose annotation refers to a name supplied only by that mapping must bind successfully, and the resolved target must be used by the JSON decoder. Metadata cannot be treated as universal for a class when its resolution inputs differ: reusing one XmlContext first with one globalns mapping and then with another must use the second mapping, and building the same child model under different parent namespaces must give each binding its corresponding qualified element names.
