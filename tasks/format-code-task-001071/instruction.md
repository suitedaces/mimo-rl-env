Modernize the Wiktionary dump ingestion stage so it can consume both legacy and current MediaWiki export shapes without losing the compatibility we already have. The public `wikidict.parse.process()` path currently assumes one namespace URI and fixed child positions; real dumps may use either the `http://www.mediawiki.org/xml/export-0.10/` or `http://www.mediawiki.org/xml/export-0.11/` namespace and may omit or reorder optional metadata.

For each page, obtain the title, numeric namespace, revision, and wikitext by their XML meaning rather than by a fixed child index. Continue accepting legacy revisions where `<text>` is a direct child of `<revision>`. Also accept multi-content revisions where content is under `<slots>`: when more than one slot is present, only the slot whose `role` is `main` supplies the page wikitext; auxiliary slot content must not be treated as the article. Missing contributor, comment, parent id, model, format, or similar metadata must not prevent an otherwise valid page from being read.

Use the page's numeric `<ns>` value as the namespace authority. Namespace `0` pages are eligible even when their titles contain a colon, while every nonzero namespace is excluded even if its title has no colon. Preserve the existing locale-section filtering after the wikitext has been found.

Redirect pages must remain excluded even if they also carry revision text. A page with no revision, no text element in either supported layout, or an empty text element is incomplete: skip it without raising and continue processing later pages in the same dump. Existing 0.10 dumps, including restricted pages and the current parse-stage workflow, must continue to work.
