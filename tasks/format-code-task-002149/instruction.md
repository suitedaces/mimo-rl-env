I want an existing `pipeline_dp.DPEngine` instance to support adding calibrated DP noise directly to pre-aggregated keyed values with `DPEngine.add_dp_noise(col, params, out_explain_computation_report=None)`, where `col` is a collection of `(partition_key, value)` pairs and `params` is a `pipeline_dp.AddDPNoiseParams(noise_kind, l0_sensitivity=None, linf_sensitivity=None, l1_sensitivity=None, l2_sensitivity=None, budget_weight=1, output_noise_stddev=False)` object. This API is for workflows where I have already enforced contribution bounds outside PipelineDP, so the method should not do record-level contribution bounding or partition selection; it should preserve exactly the input partition keys and add noise only to the values.

For a Laplace example, with a `NaiveBudgetAccountant(total_epsilon=2, total_delta=0)`, `LocalBackend`, input `[(0, 0), (1, 1)]`, and `AddDPNoiseParams(noise_kind=NoiseKind.LAPLACE, l0_sensitivity=5, linf_sensitivity=15)`, `add_dp_noise` should return two `(key, noised_value)` rows with keys `0` and `1`, and the Laplace noise should be calibrated with scale `5 * 15 / 2 = 37.5`. For a direct-sensitivity example, `AddDPNoiseParams(noise_kind=NoiseKind.LAPLACE, l1_sensitivity=5)` should calibrate Laplace noise from the provided L1 sensitivity instead of requiring L0/Linf. For Gaussian noise, `AddDPNoiseParams(noise_kind=NoiseKind.GAUSSIAN, l2_sensitivity=3)` should request Gaussian budget, use the accountant's epsilon/delta, and add Gaussian noise calibrated from the L2 sensitivity.

When `output_noise_stddev=True`, each output value should be an object with `noised_value` and `noise_stddev` fields instead of a bare number. For example, with Laplace noise, total epsilon `2`, `l0_sensitivity=5`, and `linf_sensitivity=15`, the reported `noise_stddev` should be about `53.03` because the Laplace scale is `37.5`. If an `ExplainComputationReport` is passed, the call should attach its report generator and include a stage describing the noise kind and parameter, such as `Adding NoiseKind.LAPLACE noise with parameter 37.5` for that example.

`AddDPNoiseParams` should reject non-positive sensitivity values and non-positive `budget_weight` with `ValueError`, including cases like `l0_sensitivity=0`, `linf_sensitivity=-1`, `l1_sensitivity=0`, `l2_sensitivity=-5`, or `budget_weight=0`. Laplace calls should require either `l1_sensitivity` or both `l0_sensitivity` and `linf_sensitivity`; Gaussian calls should require either `l2_sensitivity` or both `l0_sensitivity` and `linf_sensitivity`. The method should allocate privacy budget according to `budget_weight`, annotate the returned collection with the params and computed budget, and leave the input collection's keys unchanged.
