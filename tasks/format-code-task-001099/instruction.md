Azure Blob Storage paginates container and blob listings, but pkgcloud's Azure client currently exposes only the first response page. This makes a successful `getContainers` or `getFiles` call silently incomplete for storage accounts with more than one page. Make both public listing methods consume Azure continuation markers and return a complete logical listing.

For `getContainers(callback)`, issue the normal `comp=list` request and, whenever Azure returns a non-empty `NextMarker`, request the next page with that marker. For `getFiles(container, download, callback)`, do the same while retaining the container-listing parameters `restype=container` and `comp=list`. Marker values are opaque: URL-encode them when placing them in the query string. Stop when `NextMarker` is absent or empty, and concatenate results in page order and in the order entries appeared within each page.

The final callback values must remain pkgcloud model objects, not raw XML data: container listings return Azure `Container` instances, and file listings return Azure `File` instances whose `container` property identifies the requested container. An empty `<Containers>` or `<Blobs>` element is a successful empty listing and must produce `[]`. Preserve both supported `getFiles` call forms, `(container, download, callback)` and `(container, callback)`; omitting `download` must not change listing behavior.

Do not expose partial results. If any page request fails, including a continuation request after earlier pages succeeded, invoke the user's callback exactly once with the normal pkgcloud provider error and no result array. The same rule applies independently to container and file listings.
