The v1alpha2 admission webhook relies on ValidateHTTPRoute and ValidateGateway to reject malformed resources, but several cross-field invariants documented by the API are currently left to controllers or are reported with misleading paths. Strengthen these public validators so admission callers receive deterministic field errors for invalid combinations while valid extended configurations remain usable.

For HTTPRoute validation, reject a rule that contains both RequestRedirect and URLRewrite filters, and apply the same mutual exclusion independently to filters attached to one HTTPBackendRef. Keep the existing rule that core filter types cannot be duplicated, while ExtensionRef filters remain repeatable. A Kubernetes Service backend (default group or explicit Kind Service) must have a port; a non-Service custom backend may omit it. Validation errors for matches and backend references must use the actual nested shape under spec.rules[i] (including matches[j].path and backendRefs[j].filters), and rule indexing must remain correct when more than one rule is present.

For Gateway validation, encrypted HTTPS and TLS listeners must provide TLS configuration, while HTTP, TCP, and UDP listeners must reject TLS configuration. TCP and UDP listeners must not specify a hostname. Listener names are unique within one Gateway, so a duplicate name is rejected at the later listener. Valid HTTP plus HTTPS listeners, a lone redirect or rewrite filter, repeatable extension filters, and custom backends without ports must continue to pass. Preserve the existing public function signatures and field.ErrorList behavior; callers should be able to inspect the returned error fields without parsing strings.
