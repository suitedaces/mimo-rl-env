I want a stateful Go scheduler API in package core with the constructor `core.NewScheduler(l core.Logger) *core.Scheduler` and public methods `AddJob(j core.Job) error`, `RemoveJob(j core.Job) error`, `CronJobs() []cron.Entry`, `Start() error`, `Stop() error`, `IsRunning() bool`, and scheduler-wide middleware installation through `Use(ms ...core.Middleware)`. A job implements `core.Job`; when I add a job with a non-empty cron schedule such as `@every 1s`, `@hourly`, `* * * * *`, or `* * * * * *`, `AddJob` should register it with cron, assign the cron entry ID back to the job via `SetCronJobID`, and apply scheduler-level middlewares to the job before it runs.

A concrete session should work like this: create a scheduler with a logger, add a test job whose schedule is `@every 1s`, call `Start()`, observe `IsRunning() == true`, wait long enough for cron to fire, and the job's `Run(*core.Context)` should be called through the middleware/context execution path. Each fired run should create a fresh `core.Execution`, call `Context.Start()` before the job body, call `Context.Next()` so middleware and the job body execute in order, and then stop the context so duration, failed/skipped state, stdout, stderr, and error details are captured for lifecycle logging and reporting middleware. `Stop()` should wait for any in-flight scheduled job to finish before stopping cron and should leave `IsRunning() == false`.

For error behavior, `AddJob` should return `core.ErrEmptySchedule` when `job.GetSchedule()` is empty, and it should return the cron parser error for invalid schedules such as a seven-field cron string. `RemoveJob(job)` should deregister the cron entry identified by `job.GetCronJobID()` so it will not fire again. `CronJobs()` should expose the currently registered cron entries so callers can inspect the scheduler state.
