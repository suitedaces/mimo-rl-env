I want the `Database` command surface to support due-date based card rollover through `runCommand(cmd: str)`. A caller should be able to create a `Database(filename='data.db')`, issue `set-due-date <card_id> <epoch_seconds|-1>` to store an absolute Unix timestamp or clear the due date with `-1`, issue `set-due-in <card_id> <number><unit>` to set a due date relative to the current time, and issue `move-due-cards <source_list_id>[,<source_list_id>...] to <destination_list_id>` to sweep overdue cards into another list.

`set-due-in` should accept `d`, `w`, `m`, and `y` units, using 1 day = 86400 seconds, 1 week = 604800 seconds, 1 month = 2592000 seconds, and 1 year = 31536000 seconds. For example, with the clock fixed at `1700000000`, running `set-due-in 7 2d` should store `1700172800` on card 7, and `set-due-in 7 3w` should store `1701814400`.

For a concrete session, if list 1 contains card 1 with due date `1`, card 2 with due date `32503680000`, and card 3 with due date `-1`, then `move-due-cards 1 to 2` should move only card 1 to list 2. Future-dated cards and cards with no positive due timestamp should remain in their original source list. If multiple source lists are provided, such as `move-due-cards 1,3 to 2`, all matching overdue cards from those source lists should be moved in one call, and the destination list's card indexes should be normalized afterward to sequential values starting at 0.

Commands that do not match these exact forms, including unsupported relative units, should fail instead of silently changing card due dates or moving cards.
