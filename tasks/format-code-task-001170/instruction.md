The environment loader needs to support dependable composition of property files for real projects that keep shared values in `env/default` and override them in one or more named environments. Today interpolation is checked against the process environment while files are being loaded, which makes file-to-file references order-dependent, rejects valid references, and can leave the process partly changed when a configuration is bad. Improve the public `env.LoadEnv` contract while preserving existing Gauge callers and shell overrides.

A property value may contain placeholders of the form `${NAME}`, where `NAME` is one or more letters, digits, or underscores. Resolve placeholders against the effective environment: properties from the explicitly requested environments are merged in the order supplied (the first value for a key wins), and `default` is included as the fallback environment when it was not explicitly requested. Resolution must be independent of declaration order and must follow transitive references across the merged set. A process environment variable is authoritative over file values, including when it is explicitly set to the empty string; its literal contents are opaque and must not themselves be expanded. A successfully loaded file value may resolve to an empty string and must still be exported. Dollar text that is not a valid `${NAME}` placeholder remains literal.

An undefined placeholder is an error that identifies the missing property. Cyclic references, including direct and indirect cycles, are errors that identify the failure as cyclic and name the participating properties. Loading is transactional: on any interpolation error, none of the candidate values from that call may be published, values from the previously successful load remain available, and the active environment reported by `env.CurrentEnv()` remains unchanged. Only after a successful load should the candidate values be exported and `CurrentEnv()` updated; for a comma-separated selection it reports the trimmed, comma-joined names in their original order. Existing default fallback and first-environment precedence must continue to work.
