Flair's column-format readers currently discard useful CoNLL-style sentence comments, so callers cannot retain identifiers, provenance, or other annotations alongside the tokens they train on. Add a small public metadata API to `Sentence` and thread it through `ColumnDataset` without changing the existing token, label, or relation behavior.

`Sentence` must accept an optional `metadata` mapping when constructed. A sentence created without it starts with an empty mapping, and the supplied mapping is copied so later sentence updates do not mutate the caller's object. Expose the mapping as `sentence.metadata`, plus `add_metadata(key, value)` for setting one entry and `get_metadata(key, default=None)` for lookups. Keys and values in this API are strings; an absent key returns the supplied default (or `None`). Setting an existing key replaces its previous value.

When `ColumnDataset` is given a `comment_symbol`, comments beginning with that symbol and containing a first `=` are sentence metadata: trim whitespace around the key and value, and let the last occurrence of a key win. Comments without `=` are informational and must not create metadata or tokens. Metadata belongs to the sentence in which the comments occur. This must work identically for `in_memory=True` and `in_memory=False`. Existing relation directives such as `# relations = ...` must continue to create the same public `Relation` annotations while ordinary comments are being collected.

Finally, include the current metadata mapping in the dictionary returned by `Sentence.to_dict()`, both with no tag type and when a tag type is requested, using a JSON-serializable mapping. Keep all existing text, token, label, and relation fields and behavior intact.
