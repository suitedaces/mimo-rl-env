The environment-variable configuration overlay needs to be predictable when operators combine it with a config file. Update the configuration loading behavior so environment variables are treated as explicit overrides: boolean settings accept case-insensitive true tokens (true, 1, on, enabled) and false tokens (false, 0, off, disabled), and an unrecognized non-empty token is rejected with an error instead of silently changing the setting. A supplied false value must override a true value from the file, while an unset variable must leave the file value unchanged.

Apply this consistently to anonymous authentication, OIDC enablement and client-id checking, admin-list authorization, and autoschema enablement. The OIDC skip-client-id-check variable and the two admin-list membership variables must override their configured values when supplied. Comma-separated admin and read-only user lists should be trimmed and omit empty entries, and an unset list variable must preserve its configured list.

Keep the existing built-in autoschema defaults for fields that are absent from an otherwise empty configuration, but do not replace non-empty file values when their environment variables are absent; a partially configured autoschema block should receive defaults only for its missing fields. Query-default limits must remain integer values, accept zero, and reject negative values with an error. Existing non-environment configuration behavior and valid overrides must continue to work.
