I want the backup utility to provide a `restore` command for rebuilding a Core Lightning SQLite database from a backup backend. The command should be invoked as `./backup-cli restore <backend-url> <restore-destination>`, where `<backend-url>` can be any supported backup backend URL and `<restore-destination>` is either a database file path or a lightning directory. On a successful run, it should read the backup changes in order, create the destination SQLite database, apply any snapshot entries, replay each recorded transaction entry, commit the result, print no normal output, and exit with code 0. If `<restore-destination>` is a directory, the command should write `lightningd.sqlite3` inside that directory. If the resolved destination database path already exists, the command should fail instead of overwriting it, exit non-zero, and report an error containing `Destination for backup restore exists: <path>`. For example, after a backup has been initialized and populated at `file:///tmp/node/backup.dbak`, running `./backup-cli restore file:///tmp/node/backup.dbak /tmp/node/lightningd.sqlite.restore` should create `/tmp/node/lightningd.sqlite.restore` as a usable SQLite database. Running `./backup-cli restore file:///tmp/node/backup.dbak /tmp/node` should create `/tmp/node/lightningd.sqlite3` when that file is absent, but should fail with the existing-destination error when it is already present.
