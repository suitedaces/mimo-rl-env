I want `pyrogram.Client` to expose an async generator method `stream_media(message, limit: int = 0, offset: int = 0)` so code using an already running client can read Telegram media incrementally without saving a completed file first. The `message` argument should accept either a `pyrogram.types.Message` containing one of audio, document, photo, sticker, animation, video, voice, video_note, or new_chat_photo media, a media object with a `file_id`, or a file ID string.

When I call `async for chunk in app.stream_media(message):`, it should yield `bytes` chunks from the beginning of the media, with each chunk no larger than 1 MiB. Passing `limit=3` should yield at most the first three chunks, and passing `offset=3` should skip the first three chunks before yielding. Passing a negative offset with a real Message object should count backward from the end, so `offset=-3` streams only the last three 1 MiB chunks of the media. If the input Message has no downloadable media, the method should raise `ValueError("This message doesn't contain any downloadable media")`; if the caller passes a file ID string and uses a negative offset, it should raise `ValueError("Negative offsets are not supported for file ids, pass a Message object instead")` because the size is not available.
