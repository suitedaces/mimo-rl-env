The datepicker currently exposes a single selected date, but consumers that build range pickers or custom date UIs have no shared value object for describing a range and no way to ask the month-view generator which visible cells belong to that range. Add a public `NgbDateRange` value object and make the datepicker's public month-view service range-aware without changing existing single-date consumers.\n\nExport `NgbDateRange` from the datepicker module and the package entry point. Its constructor accepts two date structs, with the second endpoint optional for an in-progress selection. It must clone inputs, normalize a complete range so `from` is never after `to`, and expose `isComplete()`, `contains(date)`, `overlaps(other)`, `intersection(other)`, and `equals(other)`. Containment and overlap are inclusive at both endpoints; incomplete ranges are not complete, do not contain dates, do not overlap another range, and have no intersection. `intersection()` returns a new range and must not mutate either operand. Equality compares endpoint values, including the distinction between complete and incomplete ranges. A null date argument is outside every range.\n\nExtend `NgbDatepickerService.generateMonthViewModel` with an optional range argument. When a complete range is supplied, each generated day (including visible days from adjacent months) gets an `inRange` boolean that is true exactly for dates inside the inclusive range and false otherwise. The annotation is independent of min/max or `markDisabled`, so disabled dates can still be in range. An incomplete range produces no in-range annotations. Calls that omit the range must retain the current date-selection behavior and the existing day object shape (no added `inRange` property), preserving compatibility for custom calendars and templates.
