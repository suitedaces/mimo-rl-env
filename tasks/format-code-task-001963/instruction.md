The BSON JSON helper documents that `bson.json_util.loads` rejects Extended JSON type wrappers with wrong value types or extra keys, but several canonical forms still leak `KeyError`/`IndexError`, accept values outside their BSON domain, or silently accept malformed encodings. Harden the public parser so malformed canonical wrappers fail deterministically with `TypeError` or `ValueError`.

For `$numberInt` and `$numberLong`, require a single string payload containing a signed value in the corresponding 32-bit or 64-bit range. `$numberDouble` must likewise have exactly one string payload that parses as a valid double. A `$timestamp` wrapper must contain exactly `t` and `i`, both integers in the BSON timestamp range. Canonical `$binary` must contain only `base64` and `subType`; the payload types, base64 data, and two-character hexadecimal subtype must be validated. Canonical `$regularExpression` must contain exactly `pattern` and `options`, both strings. Malformed `$date` payloads, including non-integral numeric values and invalid date text, must surface as `TypeError` or `ValueError` rather than incidental lookup/index exceptions.

Keep valid canonical values decoding exactly as before, and do not reinterpret MongoDB query documents that use a non-string legacy `$regex` value. The change is limited to parser behavior: callers should still be able to use all currently valid JSON utility output and existing legacy/query syntax.
