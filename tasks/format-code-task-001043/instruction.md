Preserve every configured image mirror throughout the agent installer workflow

Disconnected agent installations can configure several mirrors for the same source repository, including by repeating a source in `imageContentSources`. The generated `registries.conf` knows about those mirrors, but the agent-side mirror projection currently retains only one of them. The projection is later converted into the ImageContentSourcePolicy supplied to `oc`, so fallback mirrors silently disappear during release lookup and extraction. Hand-authored `mirror/registries.conf` files also trigger this path and may contain repeated source blocks or valid registry entries with no mirrors.

Make the agent mirror configuration lossless and consistent across generation, loading, and release extraction. For generated configuration, consolidate repeated source groups into one logical registry in first-source-appearance order. Include every distinct mirror for that source in first-appearance order, without repeating duplicate mirror locations. The generated TOML/config and the existing exported `MirrorConfig` pair projection must agree: `MirrorConfig` remains a flattened list of source/mirror pairs, grouped by source order and then mirror priority.

Apply the same projection rules when loading a hand-authored `registries.conf`. Repeated registry blocks for a source contribute mirrors to that source's logical group; duplicates are removed while preserving the first source and mirror occurrences. A syntactically valid registry entry with no mirrors is still valid configuration: loading must succeed without a panic, the entry remains present in the parsed registry config, and it contributes no `MirrorConfig` pair.

When the public release extraction workflow receives this projection, the ICSP passed to `oc` must contain exactly one `repositoryDigestMirrors` entry per logical source and all of that source's mirrors in priority order. The same complete policy must be used for both the release-image lookup and the subsequent image file extraction. Preserve existing behavior for installations with no custom mirrors and for the common one-source/one-mirror case.
