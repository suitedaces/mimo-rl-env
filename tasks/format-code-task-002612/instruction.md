I want `ScribeDoc` PDF exports to support a `convertDupSourceTextToPaths` option on `doc.exportData('pdf', options)` and `doc.download('pdf', fileName, options)`. In a normal session, I should be able to open an existing PDF, recognize or otherwise load OCR text, then call `await doc.exportData('pdf', { displayMode: 'invis', addOverlay: true, convertDupSourceTextToPaths: true })` and get an `ArrayBuffer` PDF where the original PDF pages are preserved visually, the OCR overlay is added, and the source PDF's existing vector text on the exported pages is converted to path outlines so it is no longer duplicated as selectable/extractable text. The same option should work with visible proof overlays, for example `displayMode: 'proof'`, as long as the input is a PDF and overlay export is enabled.

The option should apply to the actual exported page set: if I pass `minPage`/`maxPage` or `pageArr`, only those selected pages need source text converted to paths. When `convertDupSourceTextToPaths: true` is used, it should request whole-page conversion for every exported page instead of relying on automatic page-category flattening, so clean text-native pages are handled too. If the option is set when it cannot apply, such as exporting from image input, using `addOverlay: false`, or using `displayMode: 'ebook'`, the export should continue without the conversion and emit a console warning explaining that `convertDupSourceTextToPaths` only applies when overlaying OCR text onto a PDF input.
