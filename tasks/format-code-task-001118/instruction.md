Treat the maps supplied to DynamicDirective as replaceable declarative snapshots. Consumers commonly create an inline object literal during every Angular change-detection pass, so replacing a map reference with an equivalent set of entries must be safe and must not look like an input change. The public directive must also reconcile the component with the new snapshot rather than leaving state from an older one behind.

For `ndcDynamicInputs`, deliver values exactly as supplied, including `0`, `false`, and the empty string. When a replacement map changes an existing entry, update the dynamic component; when an entry disappears, clear that component property by assigning `undefined`. If the component exposes `ngOnChanges`, notify it once for a replacement that actually changes entries, with `SimpleChange` previous/current values for changed and removed entries and `isFirstChange()` false. An equivalent replacement must not invoke the hook again and must not throw.

For `ndcDynamicOutputs`, replacing the map must atomically move delivery to the new handlers: events emitted after replacement reach only the new handler, and setting the map to `null` removes all handlers so later events are ignored. Preserve the existing output-name alias mapping used with `NgComponentOutlet`.
