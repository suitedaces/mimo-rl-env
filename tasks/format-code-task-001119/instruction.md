dbt's dependency and package code uses the public helpers in `dbt.semver` to combine version constraints and choose a release from the versions advertised by a registry. Today those helpers parse SemVer prerelease and build components but effectively compare only major, minor, and patch, so a prerelease can be treated as equal to a stable release and resolver output can depend on the registry's input order. Bring the observable behavior in line with Semantic Versioning 2.0.0 while preserving the existing matcher syntax and APIs.

`VersionSpecifier.compare` must order numeric major, minor, and patch components first. When those are equal, a version without a prerelease has higher precedence than one with a prerelease; prerelease identifiers are compared left to right, numeric identifiers numerically, non-numeric identifiers lexically, numeric identifiers before non-numeric identifiers, and a shorter otherwise-equal identifier list first. Build metadata must never affect precedence.

Use that same precedence consistently when reducing exact, lower-bound, and upper-bound constraints and when answering `versions_compatible`: exact prereleases must not match the corresponding stable release, bounds must exclude candidates on the wrong side of a prerelease boundary, and differing build metadata on an otherwise equal version remains compatible. `find_possible_versions` must discard candidates outside the requested range and return the remaining original version strings in descending SemVer precedence. `resolve_to_specific_version` must choose the highest compatible candidate under that ordering and return its original spelling, including build metadata. Existing behavior for ordinary stable versions, unbounded ends, and the public function signatures must remain intact.
