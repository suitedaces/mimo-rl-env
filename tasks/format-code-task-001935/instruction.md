I want `csvq` to load LTSV data as a query table source from the command line. When I run `csvq --repository /tmp/data "select name, age from ltsv(people)"`, it should find `people.ltsv`, parse rows like `name:Alice\tage:30`, use the LTSV labels as column names, and print a normal query result containing Alice's name and age with exit code 0.

I also want `LTSV(table_identifier, encoding, without_null)` to work in SQL table objects. The optional encoding argument should be honored before parsing the file, and when `without_null` is true, missing labels in a row should produce empty strings instead of null values while rows with fewer labels are padded out to the full header.

The import-format flag should accept LTSV for ordinary table references too: `csvq --import-format LTSV --repository /tmp/data "select name from people"` should search for and load `people.ltsv`. If I pass too many arguments to `ltsv(...)`, the command should fail before query execution with a non-zero exit code and an error explaining the table object argument length problem. If a requested LTSV file cannot be found, the command should fail non-zero with the normal missing-table/file error instead of silently treating it as CSV.
