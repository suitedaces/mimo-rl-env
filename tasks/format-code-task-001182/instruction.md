Applications importing an audience currently have to call `subscribe()` once per address, which is slow and makes it difficult to correlate a large import with Mailchimp's batch receipts. Add a public `Newsletter::subscribeMany(array $members, $listName = '', array $options = [])` operation that submits member upserts through Mailchimp's `batches` API.

Each member may be either an email-address string or an associative descriptor containing `email_address`; the descriptor's other keys are per-member Mailchimp fields. Trim surrounding whitespace from an address but otherwise preserve its casing in the outgoing `email_address`. Every member must provide a string address that is non-empty after trimming. Validate the complete input before submitting anything, and reject an invalid entry with `InvalidArgumentException` and the exact message `Member at index N must provide a non-empty email_address.`, where N is its zero-based input index.

Resolve the configured default list when `$listName` is empty and a named list otherwise, just like the existing operations. An unknown name must still raise `InvalidNewsletterList` before any batch request. Empty member input returns `[]` and sends no Mailchimp request.

Build each member payload from defaults `status_if_new => subscribed` and `email_type => html`, then apply the global options, then that member's descriptor fields. The member's normalized address is always authoritative, so a global `email_address` cannot replace it. Later layers must preserve explicit empty strings, empty arrays, zeroes, and false values rather than treating them as absent.

Deduplicate the complete import by trimmed, case-insensitive address before batching. The last occurrence supplies the payload, and the surviving members are ordered by the positions of their last occurrences. Submit one PUT operation per survivor to `lists/{list-id}/members/{subscriber-hash}`; its body is the JSON-encoded member payload. Operation IDs are `member-0`, `member-1`, and so on using the survivor's global zero-based position, including across batch boundaries.

A Mailchimp batch may contain at most 500 operations. Submit chunks sequentially and, on success, return an array containing each batch API response in submission order (including when only one batch is needed). After every submission, honor the package's existing `getLastError()` success convention. If Mailchimp reports an error, stop without submitting later chunks and return `false`; already accepted chunks are not resubmitted.
