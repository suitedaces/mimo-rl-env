Improve the YaklangInspectInformation RPC used by the IDE so its metadata is stable and useful for source-aware tooling. The request contains complete Yaklang source plus an optional Range; analyze the complete document so expressions referenced by a selected call still resolve, but return only CLI and risk metadata calls whose own source span starts inside a non-empty inclusive range. A nil range or an all-zero range must retain the existing full-document behavior.

Within each returned metadata section, preserve lexical source order rather than grouping entries by the order in which helper functions happen to be registered. CLI entries must expose the exact public type label for the declaration (including bool, int, float, urls, hosts, file_or_content, and string-slice), and their option fields must contain decoded literal values, including explicit false, zero, and empty-string values. If the same declaration supplies an option more than once, the last occurrence wins for Help, Required, and Default.

Risk metadata must likewise remain in source order, expose CVE values without source-language quoting, normalize severity aliases to the canonical levels already used by the project, and use an explicit typeVerbose label when supplied; otherwise derive the canonical verbose label from the declared risk type. These improvements must apply to the generic yak collectors even when YakScriptType is another supported plugin type such as mitm, and existing callers that omit a range must continue to receive both CLI and risk sections.
