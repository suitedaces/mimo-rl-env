I want Django-Webpush to expose one-shot notification helpers for sending a JSON payload to all saved browser subscriptions for a Django user or for a named webpush group.

The package-level API should include `send_user_notification(user, payload, ttl=0) -> None` and `send_group_notification(group_name, payload, ttl=0, exclude_user_id=None) -> None`. Both helpers should accept any JSON-serializable payload object, encode it with `json.dumps`, and forward that encoded payload with the given TTL to every matching subscription. For example, `send_user_notification(user, {"head": "Welcome!", "body": "Hello World"}, ttl=1000)` should send the JSON string for that payload to each subscription associated with `user`, and return `None` after dispatching. A payload such as `{"head": "Welcome!", "body": "Hello World", "icon": "https://example.com/icon.png", "url": "https://example.com"}` should preserve all keys and values in the JSON sent downstream.

For groups, `send_group_notification("my_group", payload, ttl=1000)` should look up the webpush group named `my_group` and dispatch once for every subscription saved for that group. If `exclude_user_id` is provided, subscriptions in that group whose user has that id should be skipped while the rest still receive the notification. If the payload is not JSON serializable, the helper should raise `TypeError` before sending anything; if the named group does not exist, it should raise the group model's `DoesNotExist` exception.

I also need the lower-level utilities `send_notification_to_user(user, payload, ttl=0) -> None` and `send_notification_to_group(group_name, payload, ttl=0, exclude_user_id=None) -> None` for callers that already have a serialized payload string. These utilities should perform the same user/group subscription selection, TTL forwarding, and optional group-user exclusion without serializing the payload a second time.
