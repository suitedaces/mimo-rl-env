The byte-bounded LRU in lib/lru is useful as a shared component, but its current implementation cannot be inspected or managed beyond Add/Get/RemoveOldest/Len, and replacing an existing value leaves its byte accounting stale. Extend the public Cache contract while preserving the existing LRU model.

Keep the existing constructor and Value interface, and keep Add, Get, RemoveOldest, and Len source-compatible. Updating an existing key must replace its value in place, make that key most-recently-used, adjust the tracked byte total by the difference between old and new entries, and apply the byte limit immediately; replacement itself is not an eviction callback. A maxBytes value of zero means unlimited capacity.

Expose these methods with exactly these signatures: Peek(key string) (Value, bool), Contains(key string) bool, Remove(key string) bool, Purge(), Resize(maxBytes int64) int, Keys() []string, and Bytes() int64. Peek reports a value without changing recency; Contains reports presence without changing recency. Keys returns an independent snapshot ordered most-recently-used first, and Bytes reports key lengths plus Value.Len for all retained entries. Remove deletes one key, returns true only when it existed, and invokes the configured callback once for that deletion; missing-key removal is a no-op. Purge removes every entry, leaves an empty cache with zero bytes, invokes callbacks once per entry from least-recently-used to most-recently-used, and is harmless when already empty. Resize changes the limit, returns the number of entries evicted, and evicts least-recently-used entries until the new nonzero limit is satisfied; zero again means unlimited.

All exported cache operations, including the new inspection and management methods and the existing methods, must be safe when called concurrently. The callback must observe each actual eviction exactly once. Do not require a particular internal lock or data structure, and do not change the Value accounting convention.
