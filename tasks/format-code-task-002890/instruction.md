I want the gosql wrapper to provide struct-backed CRUD methods on both database handles and transactions: `func (db *DB) Insert(obj interface{}) (sql.Result, error)`, `func (db *DB) Update(obj interface{}) (sql.Result, error)`, `func (db *DB) Delete(obj interface{}) (sql.Result, error)`, plus the same `Insert`, `Update`, and `Delete` signatures on `*Tx`. After I create a handle with `db := gosql.New(sqlDB)`, these methods should inspect the pointed-to model struct, use the model table name and column metadata, build the SQL statement with `?` placeholders, bind arguments in placeholder order, execute it with the underlying `database/sql` executor, and return the resulting `sql.Result` or validation error.

For example, with `type User struct { ID int `idx:"primary"`; Name string }`, calling `db.Insert(&User{Name: "Gopher"})` should execute `insert into user (name) values (?)` with the single argument `"Gopher"`, omitting the zero-valued primary key so the database can generate it. Calling `db.Insert(&User{ID: 5, Name: "Gopher"})` should execute `insert into user (id, name) values (?, ?)` with arguments `5, "Gopher"`.

For updates, `type User struct { ID int `idx:"primary"`; Name string; Email string }` and `db.Update(&User{ID: 5, Name: "Gofer", Email: "gofer@example.com"})` should execute `update user set name = ?, email = ? where id = ?` with non-primary field values first and primary-key values last. For composite primary keys, such as `type T struct { ID int `idx:"primary"`; Name string; Email string `idx:"primary"` }`, `Update` should generate `update t set name = ? where id = ? and email = ?` with arguments in the same order as those placeholders.

For deletes, `db.Delete(&User{ID: 5})` should execute `delete from user where id = ?` with argument `5`, and composite primary keys should be joined in the `where` clause with `and`. The `*Tx` methods should perform the same SQL generation and argument binding but execute through the active transaction.

If the caller passes something that is not a pointer to a model struct, the method should return an error like `obj must be a pointer to your model struct`. If the model has no field tagged `idx:"primary"`, the method should return an error like `model User must have at least one field tagged `idx:"primary"`` and should not execute any SQL.
