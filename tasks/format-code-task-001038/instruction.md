Local commands preprocess a SAM/CloudFormation template into the effective template they run, but conditions are currently left behind as ordinary metadata and `Fn::If` eagerly resolves both alternatives. That makes locally visible resources differ from a deployed stack, lets an invalid expression in a dead branch break local use, and turns `AWS::NoValue` into an ordinary null instead of structural absence.

Make `IntrinsicResolver.resolve_template()` condition-aware for both `Resources` and `Outputs`. An entry with no `Condition` is processed normally. For an entry with a named condition, evaluate that condition before resolving the entry body: omit the entire entry when false, and retain it without its `Condition` member when true. Apply the same rule independently to outputs, including evaluating the condition before the output value. Named conditions may be literal booleans or supported condition expressions, including expressions that refer to another named condition through `Condition`.

`Fn::If` must validate its three-argument shape and named boolean condition as before, but then recursively resolve only the selected value. The unselected value is opaque: an unsupported reference or malformed intrinsic there must neither fail resolution nor leak into the result. This must work in both the true and false directions.

Treat a resolved `Ref: AWS::NoValue` as a structural removal marker throughout resolved resource and output values. Remove the containing mapping member or list element at any nesting depth, preserving the relative order of remaining list elements. Do not implement this by dropping ordinary nulls: an explicit YAML/Python null, including one selected by `Fn::If`, must remain present as null.

In strict mode (`ignore_errors=False`), a missing named condition, a condition whose result is not boolean, or a cycle among named condition references must raise `InvalidIntrinsicException`; cycles must not escape as `RecursionError`. Resolution must not mutate the caller's template and repeated resolution of the same input must be stable. The same effective-template behavior must flow through `SamBaseProvider.get_template()`, using parameter defaults when no override is supplied and existing override precedence when a value is supplied. Preserve the established results and validation behavior of the resolver's other supported intrinsic functions.
