I want the package to export a `calculateRetryDelay(retryObject: RetryObject) -> number` helper that computes Got's default retry delay decision from the supplied retry state. If `retryObject.error.name` is `RetryError`, it should return `1` so explicit retry signals are replayed immediately. If `attemptCount` is greater than `retryOptions.limit`, or the request method is not in `retryOptions.methods`, or neither the error code nor the response status code is configured as retryable, it should return `0` to decline another attempt.

For deterministic examples with `retryOptions.noise: 0`, a GET request with attempt 1, retryable error code `ECONNRESET`, limit 2, and unlimited backoff should return `1000`; the same request at attempt 2 should return `2000`; and with `backoffLimit: 1500`, attempt 3 should return `1500` when the limit still allows it. For HTTP responses, a retryable status with a `retryAfter` value should return that `retryAfter` value when it is not greater than the supplied `computedValue`, and return `0` when it is greater; status `413` should return `0` when there is no usable `retryAfter` value. When `retryOptions.noise` is positive, the returned backoff should be the exponential-or-capped base delay plus a random non-negative jitter smaller than `retryOptions.noise`.

The function should read only the supplied retry object, should not mutate `retryOptions`, `error`, or `response`, and should not perform network or filesystem work.
