I want BitBake's `bb.fetch2.Fetch` API to support Google Cloud Storage source URLs using the `gs://bucket/path/to/object` scheme. A typical session should work as `f = bb.fetch2.Fetch(['gs://example-bucket/releases/pkg-1.0.tar.gz'], d); f.download(); f.checkstatus()`, with the `gs://` URL handled as a normal fetchable source.

For `gs://example-bucket/releases/pkg-1.0.tar.gz`, the default local source filename should be `pkg-1.0.tar.gz`; for `gs://example-bucket/releases/pkg;downloadfilename=source.tar.gz`, the local source filename should be `source.tar.gz`. `download()` should use the Google Cloud Storage client to fetch the bucket object named by the URL path, stripping a leading slash from the object name before calling the storage API, and write the result to the fetcher's target file. It should run BitBake's normal network-access checks before downloading or checking object existence.

If the storage API reports that the object is not found, the caller should get `bb.fetch2.FetchError`. If the API reports success but the target file is missing, or if the target file is zero bytes, `download()` should fail with `bb.fetch2.FetchError`; the zero-byte file should be removed. `checkstatus()` should succeed only when the blob exists and should raise `bb.fetch2.FetchError` when it does not.
