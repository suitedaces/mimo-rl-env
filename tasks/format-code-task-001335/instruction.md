I want the `arxiv_latex_cleaner` CLI to support YAML-configured regex replacements for custom LaTeX macros when I run a command like `python -m arxiv_latex_cleaner INPUT_DIR --config cleaner_config.yaml`. The config file should accept a top-level `patterns_and_insertions` list, where each item has `pattern`, `insertion`, and `description` keys, plus an optional `strip_whitespace` key.

For every retained `.tex` or `.tikz` file in the cleaned output, the tool should apply each `pattern` as a regular expression repeatedly until there are no more matches. Named capture groups from the regex should be available to the `insertion` template using Python-style `{name}` placeholders. For example, a config entry with pattern `(?:\\figcomp{\s*)(?P<path>.*?)\s*}\s*{\s*(?P<box>.*?)\s*}\s*{\s*(?P<width>.*?)\s*}` and insertion `\parbox[c]{{ {box} \linewidth}}{{\includegraphics[width={width}\linewidth]{{figures/{path}}}}}` should turn `\figcomp{panel-a}{.45}{.8}` in the cleaned TeX into `\parbox[c]{.45\linewidth}{\includegraphics[width=.8\linewidth]{figures/panel-a}}`.

By default, whitespace should be stripped from the formatted insertion before it is written. If `strip_whitespace: false` is set for an entry, the formatted insertion should preserve its spaces and line breaks. These replacements need to happen before the cleaner decides which referenced non-TeX files and image files to copy, so an `\includegraphics{figures/panel-a}` introduced by a replacement causes the matching figure file to be included in the `_arXiv` output.

If a replacement entry is malformed, such as missing `pattern`, `insertion`, or `description`, or if the regex cannot compile, the CLI should fail with a non-zero exit instead of silently ignoring the entry. On a valid config, the command should finish successfully and write the transformed TeX files into the sibling `INPUT_DIR_arXiv` directory.
