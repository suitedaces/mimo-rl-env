I want the library to provide a Persian `Lemmatizer` API that I can use as `lemmatizer = Lemmatizer(words_file=default_words, verbs_file=default_verbs, joined_verb_parts=True)` and then call `lemmatizer.lemmatize(word: str, pos: str = '') -> str` for individual tokens.

With the default data, `lemmatizer.lemmatize('کتاب‌ها')` should return `'کتاب'`, `lemmatizer.lemmatize('آتشفشان')` should return `'آتشفشان'`, and unknown tokens that cannot be normalized should be returned unchanged. It should recognize conjugated Persian verbs from the verbs data and return the dictionary form as `past_root#present_root`: for example `lemmatizer.lemmatize('می‌روم')` should return `'رفت#رو'`, `lemmatizer.lemmatize('گفته_شده_است')` should return `'گفت#گو'`, and `lemmatizer.lemmatize('نچشیده_است')` should return `'چشید#چش'`.

The optional POS hint should affect the decision logic: known words should remain unchanged, pronouns should remain unchanged, adjective-like words ending in `ی` with an adjective POS hint should remain unchanged, and verb lookup should apply when the hint is empty or `VERB`. The constructor should accept custom words and verbs file paths, build its lookup at initialization time, and when `joined_verb_parts=True` it should include underscore-joined multi-part verb forms in the verb lookup. Calling `lemmatize` repeatedly with the same input and the same initialized lemmatizer should return the same string and should not mutate the input token.
