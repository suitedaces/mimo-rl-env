Multi-document YAML streams are often assembled from Kubernetes-style resources, and their document order is not stable. Today `dyff between` compares documents only by position, so a harmless reorder produces misleading cross-resource diffs, while streams with different document counts cannot be compared at all.

Add an opt-in identity mode to `dyff between` through a repeatable `--match-documents-by <path>` flag. Each argument is an absolute Go-patch-style path within a document. When at least one selector is supplied, form each document's identity from the ordered tuple of scalar values found at all supplied paths; every selector is part of the identity. Documents with equal composite identities must be compared with each other regardless of their positions in the two streams, and reordering otherwise identical documents must not itself produce a difference. Matched documents continue through the normal comparison engine, including `--ignore-order-changes`.

Identity mode must also support unequal document sets. A document found only in the target stream is reported as an addition with its full content, and a document found only in the source stream is reported as a removal with its full content.

Validate both streams completely before writing a report. If any document lacks a requested selector, exit nonzero without stdout and identify both the selector and the document in the diagnostic. If a selected value is a map or list rather than a scalar, likewise exit nonzero without stdout and identify the selector as requiring a scalar value. A composite identity must be unique within each stream; duplicates in either the source or target are errors raised before report output, and the diagnostic must say that the identity is duplicate and include its value.

This mode is explicitly opt-in. With no `--match-documents-by` flag, retain the existing positional comparison behavior, including the current error for streams with different document counts.
