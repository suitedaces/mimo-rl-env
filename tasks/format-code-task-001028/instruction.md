The inner-message codec is used on broker and client paths, but its current ByteBuffer routines trust corrupted length fields, consume partial input before reporting errors, and can expose implementation-level exceptions. Harden the public MessageDecoder wire-format API so malformed producer data is rejected predictably and callers can safely retry or inspect the buffer.

Keep the existing compact frame format and successful behavior: encodeMessage/encodeMessages must preserve flags, bodies, properties, ordering, and support an empty batch; decodeMessage must decode exactly one frame and leave any following frame unread; decodeMessages and countInnerMsgNum must process every complete frame in order.

For every decode/count operation, validate the declared total size and body/property lengths against the bytes actually available, reject negative lengths, truncated headers or payloads, impossible/inconsistent frame sizes, and malformed later frames with IllegalArgumentException. A failed single-frame, batch, or counting operation must leave the supplied ByteBuffer at its entry position, including when earlier frames in a batch were valid. Encoding must reject null messages, missing bodies, and property payloads that cannot be represented by the short length field with IllegalArgumentException rather than leaking unchecked buffer or array errors. These checks are about observable wire safety; do not change valid-message compatibility or require a particular helper layout.
