Redirect responses from an upstream currently expose internal hostnames and schemes to clients. Extend the proxy's redirect handling with opt-in `autoRewrite` and `protocolRewrite` options so applications can publish stable external URLs without changing ordinary response forwarding.

For 301, 302, 307, and 308 responses with an absolute `Location`, `autoRewrite: true` must replace the location host (including the port when the public request host has a non-default port) with the incoming request's public host. When the public host uses the default port for its scheme, omit that default port in the rewritten authority. `protocolRewrite: 'http'` or `'https'` must independently replace only the scheme while preserving host, port, path, and query. If both options are enabled, apply both transformations; an explicit `hostRewrite` value takes precedence over autoRewrite for the host while protocolRewrite still applies.

Relative Location values must remain byte-for-byte unchanged, and Location headers on non-redirect responses must remain unchanged regardless of rewrite options. Existing status codes, response bodies, headers, and proxy APIs must continue to work as before. The options are opt-in and must not alter redirects when unset.
