I want MongoEngine querysets to support string-matching keyword operators on string-like fields when filtering documents. Users should be able to call `Document.objects(field__contains=value)`, chain `QuerySet.filter(field__startswith=value)`, or compose `Q(field__icontains=value)` expressions, then execute the queryset with methods like `first()` or `count()` and get the documents whose field text matches the requested string condition.

For a document with `name = StringField()`, after saving `Person(name="Guido van Rossum")`, `Person.objects(name__contains="van").first()` should return that document while `Person.objects(name__contains="Van").first()` should return `None`; `name__icontains="Van"` should match it. `name__startswith="Guido"` and `name__endswith="Rossum"` should match case-sensitively, while `name__istartswith="guido"` and `name__iendswith="rossum"` should match case-insensitively. `name__exact="Guido van Rossum"` should match the full value, `name__iexact="gUIDO VAN rOSSUM"` should also match, and partial exact values should not match.

The same filter API should support `wholeword` and `iwholeword`, so `name__wholeword="Guido"` matches but `name__wholeword="Rossu"` does not, and `name__iwholeword="rOSSUM"` matches. It should also support `regex` and `iregex` where the supplied pattern is used as the regular expression, with the `i` form applying case-insensitive matching. Literal string operators such as `contains` must escape user text before building the regular expression, so a search like `name__icontains="[.'Geek"` matches a stored value containing those characters instead of raising a regex parse error. Dict fields containing string values should accept these same string operators, for example `Document.objects(info__title__exact="test")` should match a dictionary entry whose `title` value is exactly `"test"`.
