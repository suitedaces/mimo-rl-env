I want a `Retry` state feature that I can import from `transitions.extensions.states` and combine with a machine class using `@add_state_features(Retry)`. When I construct a `Machine` subclass with a state like `{'name': 'work', 'retries': 2, 'on_failure': 'to_failed'}`, the first transition into `work` from another state should be treated as the initial attempt, then two self-reentries into `work` should still enter the state normally. On the next self-reentry beyond that limit, the machine should not run the normal state entry path for `work`; it should call the configured `on_failure` callback instead, for example allowing `to_failed` to move the model into a `failed` state. Leaving `work` and later entering it again from a different source should reset the retry count for that model. Retry counts should be tracked per model, so two models attached to the same machine do not consume each other's retry allowance. If a state sets `retries` to a positive value without also setting `on_failure`, constructing or adding that state should raise `AttributeError` explaining that retry states require `on_failure` when `retries` is set.
