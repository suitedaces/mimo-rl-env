Extend the locale layer of the country-code library so applications can use normal language tags and ordered language preferences without duplicating complete 250-country files. Today locale registration and every lookup require an exact, lower-cased key, so values such as `en-US` or `pt_BR` do not use the already registered `en` or `pt` data, and a locale cannot override only the countries it needs.

Locale identifiers must be canonicalized by trimming surrounding whitespace, replacing `_` with `-`, and comparing/storing case-insensitively. Registering an identifier that canonicalizes to an existing identifier replaces that locale's data. A lookup for a regional tag first uses an exact registered locale, then successively removes the rightmost subtag (`qx-Latn-CA` -> `qx-Latn` -> `qx`) and merges those layers; a nearer layer overrides a parent only for country codes it supplies, while missing country entries continue to fall back. This applies to `getName`, `getNames`, all name-to-code functions, and the list returned by `langs` must expose canonical registered identifiers.

The `lang` argument may also be an ordered array of preferences. Ignore non-string and blank entries and continue to later preferences when an earlier preference has no name for a particular country. For each country, the first available name in preference order (using that preference's regional fallback) wins; `getNames` returns the union of those effective names. Reverse lookups compare names case-insensitively, and the simple variants additionally ignore diacritics. When the same name is present in multiple selected locales, the country from the earlier preference or nearer fallback layer wins. `getAlpha3Code` and `getSimpleAlpha3Code` must expose the same resolution as their alpha-2 counterparts. Unknown or unusable locales and unknown names retain the existing `undefined` results, while `getNames` returns an empty object. Existing scalar base-locale calls and the built-in locales loaded by the Node entry point must remain compatible, including regional tags selecting their base locale.
