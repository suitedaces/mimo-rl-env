The `scripts/no_import_zds_settings.sh` guard currently searches source text with a grep pipeline. That makes the check noisy in a checkout containing bytecode, misses valid Python import layouts, and cannot be reused on focused paths. Turn it into a syntax-aware architecture check while keeping the public entry point `bash scripts/no_import_zds_settings.sh [PATH ...]`. The rule remains that application code must obtain settings through `django.conf.settings`, not import the project settings package directly.

With no operands, the command must recursively scan the repository's `zds/` tree. With operands, each operand is a file or directory path relative to the caller's working directory; directories are scanned recursively. Only `.py` files participate. Multiple and overlapping operands are allowed, and each physical file must be checked only once.

Report one violation for each Python import statement that directly reaches `zds.settings`: `import zds.settings` or any submodule, `from zds import settings`, and `from zds.settings` (or one of its submodules) imports. Aliases, comma-separated imports, multiline statements, and imports nested in functions or control flow have the same semantics. Relative imports inside a scanned `zds` package must be resolved as Python resolves them, so forms such as `from . import settings` at package root and `from ..settings import test` in a subpackage are violations when they resolve to `zds.settings`. A single statement still produces only one diagnostic when it names the forbidden package more than once.

Files physically inside a `zds/settings/` package are exempt because that package must assemble its own configuration. Comments, strings, non-Python files, `django.conf.settings`, similarly named modules such as `zds.settings_helpers`, and relative imports that resolve somewhere else (for example `zds.feature.settings`) are not violations.

Diagnostics go to stderr, sorted by repository-relative path and then source line, with `/` separators and this exact format: `path:line: direct import of zds.settings is forbidden; import settings from django.conf instead`. The line is the start of the import statement. Stdout is always empty. Exit `0` for a clean scan and produce no stderr; exit `1` when violations are found. A missing operand is an input error: exit `2` and identify the path with text containing `does not exist`. A Python syntax error is also exit `2`, must not be treated as a clean scan, and its stderr diagnostic must identify the file and line with text containing `cannot parse`.
