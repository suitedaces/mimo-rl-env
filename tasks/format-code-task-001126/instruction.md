The tracer already supports several trace propagation styles, but baggage is still effectively tied to the legacy `ot-baggage-*` headers. Services that speak W3C Trace Context therefore lose baggage at a boundary, and mixed-style deployments can silently disagree about which copy is authoritative. Add interoperable W3C Baggage handling to the existing `NewPropagator` surface without regressing current Datadog propagation.

When `tracecontext` is enabled for extraction, read every `baggage` field presented by a text-map carrier in carrier order as one comma-delimited W3C Baggage value. Parse members with optional OWS around the key/value separator; ignore member properties after `;` (they are not represented by the current SpanContext). Keys must be non-empty ASCII token names. Percent-decode `%HH` byte sequences in values, treating `+` as a literal plus. A malformed member, including an invalid key or malformed percent escape, must be skipped while valid neighboring members remain usable. If a key occurs more than once, the first valid member wins.

When `tracecontext` is enabled for injection, serialize the context baggage into one `baggage` field. Include only token-valid keys, sort keys by their bytewise names for deterministic output, and percent-encode every UTF-8 byte except ASCII letters, digits, `-`, `.`, `_`, and `~`, using uppercase hexadecimal. Emit members as `key=value` joined by commas with no extra whitespace. An empty baggage set must not create an empty `baggage` field. Enforce a maximum of 64 emitted members and 8192 bytes for the serialized field; when a sorted candidate would exceed the byte budget, omit that candidate and continue considering later candidates.

The extraction side must apply the same 8192-byte limit to the logical concatenation of the W3C fields and consider at most the first 64 comma-delimited members. If that limit is exceeded, discard W3C baggage but retain any legacy baggage that is otherwise supported. W3C baggage parsing errors and limits must not make an otherwise valid trace context fail extraction.

Propagation styles remain independent and existing behavior remains compatible: Datadog-only mode ignores the standard `baggage` field and continues to read and write `ot-baggage-*`. With both `datadog` and `tracecontext` configured, preserve the configured trace/span extraction precedence, merge W3C baggage into whichever context wins, let a W3C value override a same-key legacy value, retain unrelated legacy entries, and inject both representations. Do not change traceparent/tracestate or the existing behavior of styles that are not enabled.
