I want a pure library function `Write(out io.Writer, ds Dataset, opts ...WriteOption) error` that serializes an in-memory DICOM `Dataset` to a complete DICOM byte stream. Calling it with a `bytes.Buffer` and a dataset containing `MediaStorageSOPClassUID`, `MediaStorageSOPInstanceUID`, `TransferSyntaxUID`, `PatientName`, `Rows`, integer, float, byte, sequence, and pixel data elements should write a full file that can be parsed back with `Parse`/`ParseUntilEOF` into equivalent dataset elements, ignoring automatically computed value lengths and the file meta information group length. The output must include the 128-byte preamble, the `DICM` magic word, file metadata written in explicit little endian, a computed `FileMetaInformationGroupLength`, and then the non-metadata dataset elements encoded using the dataset transfer syntax.

The function should choose byte order and implicit-vs-explicit VR from the dataset's `TransferSyntaxUID`. If the dataset has no transfer syntax, `Write` should return an error wrapping `ErrorElementNotFound`; with `DefaultMissingTransferSyntax()` it should instead use and write implicit VR little endian (`1.2.840.10008.1.2`). With `OverrideMissingTransferSyntax(transferSyntaxUID)`, it should use and write the supplied transfer syntax UID when it is recognized, including implicit little endian, explicit little endian, and explicit big endian. Passing an unknown or non-transfer-syntax UID to `OverrideMissingTransferSyntax` should make `Write` return an error before writing the dataset.

`Write` should reject invalid VRs or value types unless the caller passes `SkipVRVerification()` or `SkipValueTypeVerification()`. It should serialize nested sequences, unknown/private elements, native pixel data for 8-, 16-, and 32-bit samples, encapsulated pixel data with undefined length and frame items, intentionally unprocessed pixel bytes, and intentionally skipped pixel data consistently enough that the library parser can read the result. If the metadata transfer syntax is deflated explicit VR little endian, `Write` should return an unsupported-transfer-syntax error instead of producing bytes. Calling `Write` twice with the same dataset and options should produce equivalent parseable DICOM bytes, and the function should not mutate the input dataset.
