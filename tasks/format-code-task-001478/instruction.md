I want spatialpandas geometry containers to support coordinate-window selection through a `.cx` indexer. A `GeometryArray`, `GeoSeries`, or `GeoDataFrame` should accept expressions like `obj.cx[xmin:xmax, ymin:ymax]` and return only the geometries whose spatial extent intersects that rectangle, preserving the original container shape: arrays return geometry arrays, GeoSeries returns a GeoSeries with the original index values, and GeoDataFrame returns the matching rows using the active geometry column.

For example, with a GeoSeries containing points `(0, 0)`, `(5, 5)`, and `(10, 10)`, `series.cx[1:6, 1:6]` should return only the `(5, 5)` row, while `series.cx[:5, :]` should include the rows whose x coordinates are between the data minimum and 5. Missing slice endpoints should expand to the container's total bounds, scalar coordinates should behave like zero-width slices, and inverted bounds such as `series.cx[6:1, 6:1]` should be normalized to the same window as `series.cx[1:6, 1:6]`. Slice steps are invalid: `series.cx[0:10:2, 0:10]` or `series.cx[0:10, 0:10:2]` should raise `ValueError` explaining that steps are not supported for coordinate intervals.

I also need the same `.cx[xmin:xmax, ymin:ymax]` API on Dask-backed GeoSeries and GeoDataFrames. It should use partition bounds to keep partitions that intersect the requested window, filter overlapping partitions down to matching geometries, pass through fully covered partitions unchanged, and return an empty Dask collection with the same metadata when no partitions intersect. Dask GeoSeries and GeoDataFrames should also expose `.cx_partitions[xmin:xmax, ymin:ymax]`, which returns only the partitions whose spatial bounds intersect the window without row-level filtering. These selections should not filter the original object in place; repeating the same selection on the same input should produce an equivalent result.
