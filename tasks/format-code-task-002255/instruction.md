Pelias builds every search response through the same result-bounding-box and GeoJSON pipeline, but that pipeline currently assumes one serialized Elasticsearch shape and computes longitude extents on a flat number line. This makes mixed backend responses lose valid boxes and makes results around the antimeridian advertise an almost-global collection extent. Normalize result bounding boxes and make the emitted GeoJSON extents geographically correct without changing ordinary responses.

A result `bounding_box` may arrive as the legacy object `{ min_lon, min_lat, max_lon, max_lat }` or as a GeoJSON-order array `[west, south, east, north]`; either representation may already be decoded or may be a JSON string. All four values must be actual finite numbers. Longitudes must be in the inclusive range -180 through 180, latitudes in -90 through 90, and south must not exceed north. West greater than east is valid and denotes a box crossing the antimeridian. Numeric strings, missing/null values, out-of-range coordinates, reversed latitude bounds, malformed JSON, and other shapes are invalid.

For each valid box, emit the feature-level GeoJSON `bbox` as `[west, south, east, north]`, preserving a crossing box with west greater than east. Do not expose the internal `bounding_box` property in feature properties. An invalid box must be omitted without dropping an otherwise valid result; that result's valid `center_point` must instead contribute to the collection extent just as it does when no box was supplied.

The FeatureCollection `bbox` must use the minimum and maximum latitude covered by its contributing boxes and points. Longitude is circular: choose the smallest longitude arc that contains every point and the complete area of every valid box, not merely each box's endpoints. Represent a minimum arc that crosses the antimeridian with west greater than east. If two minimum arcs have equal span, choose the conventional west-to-east representation (`west <= east`); if the inputs collectively cover every longitude, emit `[-180, south, 180, north]`. Keep the existing conventional extent for non-crossing inputs, including mixed boxes and points. An empty FeatureCollection must continue to omit `bbox`.
