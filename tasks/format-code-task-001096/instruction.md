Keep generated declarations out of source trees by adding an optional output-folder mode to `tsm`. Expose a string option as `--outputFolder` with short alias `-o`, and show both forms in CLI help.

When this option is set, every declaration must be written as `<output folder>/<source path relative to the input root>.d.ts`; retain the source filename and its `.scss` suffix. For a directory input, the input root is that directory. For a glob input, it is the longest leading directory before the first glob metacharacter, so both `tsm styles -o types` and `tsm "styles/**/*.scss" -o types` map `styles/components/button.scss` to `types/components/button.scss.d.ts`. Resolve a relative output folder from the process working directory and accept an absolute output folder unchanged. Create any missing nested output directories. While output-folder mode is active, do not also write declarations beside the SCSS sources, and continue honoring `--ignore`.

Use this same mapping in every operating mode. Watch add and change events must generate or replace the mapped declaration, and unlink must remove that mapped declaration. `--listDifferent` must compare against the mapped declaration without writing it: exact content exits successfully, while stale or missing output reports the existing `[INVALID TYPES]` diagnostic and exits with status 1. A missing mapped declaration is a normal invalid result, not an uncaught `ENOENT`, and validation must not create the output directory. `--ignore` applies to `--listDifferent` as it does to generation.

The option is strictly opt-in. With no output folder, generation, removal, and `--listDifferent` must retain the existing adjacent `<source>.d.ts` behavior.
