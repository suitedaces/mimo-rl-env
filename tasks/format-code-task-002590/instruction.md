I want the browser library to provide a stateful sprite-sheet helper used as `var map = new iio.SpriteMap(src, onLoad)` followed by calls to `map.sprite(...)`. Constructing `iio.SpriteMap` should create an image for the supplied sheet URL, expose that image on the instance, set its `src` to the URL, and call the optional `onLoad` handler when the sheet image finishes loading.

`map.sprite(...)` should accept one or more plain configuration objects and merge them into a single animation description. For `map.sprite({ width: 16, height: 32 }, { name: 'walk', origin: [0, 64], numFrames: 3 })`, it should return an object with `name: 'walk'`, `numFrames: 3`, and three frames: `{ x: 0, y: 64, w: 16, h: 32 }`, `{ x: 16, y: 64, w: 16, h: 32 }`, and `{ x: 32, y: 64, w: 16, h: 32 }`, with each frame also pointing at the sheet image from that `SpriteMap` instance. If `numFrames` is omitted, it should default to one frame; for example `map.sprite({ width: 8, height: 8, name: 'idle', origin: [24, 10] })` should produce one frame at `x: 24`, `y: 10`, `w: 8`, and `h: 8`.

If the caller supplies an explicit `frames` array, `sprite(...)` should use that array instead of generating sequential frames. Each supplied frame that lacks a sheet image, width, or height should be completed with the instance's sheet image and the configured `width` and `height`, while preserving any frame coordinates or dimensions the caller already provided.
