I want `Microsimulation(..., dataset: str | USSingleYearDataset | None = None, ...)` to accept US entity-level microdata directly during construction. When `dataset` is a string path or `hf://` dataset URL that resolves to a Pandas HDFStore with top-level entity tables such as `person`, `household`, and `tax_unit`, constructing the simulation should load that file as a `USSingleYearDataset`, extend it to a multi-year dataset, and initialize the simulation from that converted dataset so normal variable calculations can run for the covered years.

When I call `Microsimulation()` without passing `dataset`, the class default dataset should go through the same entity-level loading path, so an entity-level default HDF5 file is accepted the same way as an explicit path. When `dataset` is already a `USSingleYearDataset`, construction should extend it to a multi-year dataset before initializing the simulation. When the string path points to a variable-centric HDF5 file instead of an entity-level HDFStore, construction should leave that dataset for the normal variable-centric loading path. If the supplied string path cannot be resolved to a local file or supported dataset URL, construction should raise `FileNotFoundError` rather than building a simulation with an unresolved dataset.
