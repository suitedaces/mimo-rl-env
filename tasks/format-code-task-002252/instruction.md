I want `s5cmd` commands that accept local filesystem sources to expand `*` and `?` wildcard patterns before operating on files. For example, if `work/` contains `a.txt`, `b.txt`, and `c.log`, running `s5cmd ls 'work/*.txt'` should succeed with exit code 0 and list `work/a.txt` and `work/b.txt` as normal local objects, without including `work/c.log`. If I run a source-consuming command such as `s5cmd cp 'work/*.txt' s3://bucket/prefix/`, the command should operate on each matched file rather than treating the literal string `work/*.txt` as a filename.

When a wildcard match is a directory, `s5cmd` should walk that directory and emit the regular files inside it using paths relative to the wildcard source, so `s5cmd cp 'work/data*' s3://bucket/prefix/` includes files nested under matched directories. The existing symlink-following behavior should still apply during those directory walks. If the local wildcard pattern is invalid or matches nothing, the command should report an error for that source and finish with a non-zero exit code; for a no-match pattern such as `s5cmd ls 'work/*.missing'`, stderr should include a message that no match was found for that pattern.
