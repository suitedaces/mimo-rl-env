I want the tracker `Client` lifecycle to support recurring announces after I construct it with `new Client({ infoHash, peerId, announce, port, getAnnounceOpts })`. When I call `client.start(opts)`, it should send the initial started announce and also schedule future announces to every configured tracker using the tracker protocol's default cadence: 30 minutes for HTTP and UDP trackers, and 30 seconds for WebSocket trackers.

I need a public `client.setInterval(intervalMs)` method that changes the recurring announce cadence for all trackers on that client. Calling `client.setInterval(500)` before or after `client.start()` should make later scheduled announces fire at roughly that interval and emit the normal `update` events from tracker responses; calling it again should replace the old timer rather than leaving duplicate recurring announces running. Calling `client.setInterval(0)` should disable the recurring announce timer.

When an announce response from a tracker supplies an announce interval, the client should adopt that interval for future recurring announces from that tracker: HTTP and WebSocket responses may provide `interval` or `min interval`, and UDP announce responses provide the interval field in seconds. Each scheduled announce should use the client's current default announce options, including fresh values returned by the public `getAnnounceOpts` callback when one is configured. When I call `client.destroy(cb)`, all recurring announce timers for the client should be cleared so no later timer-driven announce can produce `update`, `peer`, or `warning` events after cleanup.
