I want the public `embed(el: HTMLElement | string, spec: VisualizationSpec | string, opts?: EmbedOptions) -> Promise<Result>` API to resolve specs and embed options before rendering. When `spec` is a URL string, `embed` should create the selected Vega loader from `opts.loader`, call `loader.load(spec)`, parse the returned JSON, render that parsed Vega or Vega-Lite spec, and return a `Result` whose `spec` is the parsed spec object rather than the URL string.

I also want a parsed spec to be able to carry default embed options in `usermeta.embedOptions`. For example, if I call `embed(el, {...vlSpec, usermeta: {embedOptions: {loader: {target: '_blank'}, logLevel: vega.None}}})`, those options should be applied during the same embed call, `result.embedOptions` should include them, and the constructed Vega view should use the resolved loader options. If `usermeta.embedOptions.defaultStyle` is a string, `embed` should not inject that string as CSS; it should treat `defaultStyle` as `false` in the resolved embed options.

String-valued `opts.config` and `opts.patch` should be treated as external JSON resources loaded through the resolved loader before rendering. For example, if `opts.config` is `'/chart-config.json'` and the loader returns `{"background":"white"}`, the compiled/rendered view should use that config object and `result.embedOptions.config` should be that parsed object. If `opts.patch` is `'/chart-patch.json'` and the loader returns `[{"op":"add","path":"/description","value":"Hello World!"}]`, the returned `result.vgSpec.description` should be `"Hello World!"` after rendering. If any loaded spec, config, or patch text is not valid JSON, the returned promise should reject with the JSON parsing error instead of rendering with the unresolved string.
