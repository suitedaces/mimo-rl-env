Volcano's node-scoring pipeline combines several plugin stages into the score buckets used by allocation and preemption. At present, a node whose per-node scorer fails can silently come back through a later batch score, invalid floating-point values can become selectable buckets, all-negative rankings can produce no winner, and equal scores are resolved randomly. This makes plugin failures unsafe and scheduling outcomes unnecessarily difficult to reproduce.

Harden the existing public `PrioritizeNodes`, `SortNodes`, and `SelectBestNode` behavior without changing their signatures. For every eligible candidate, `PrioritizeNodes` must form one final score by adding its direct per-node score, its reduced plugin score, and its batch score. A missing contribution is zero. Scores returned for names that were not supplied as candidates are ignored, and no candidate appears more than once in the result.

A per-node map/scoring error disqualifies only that node; other candidates continue through scoring. Reducer inputs and the candidate slice passed to batch scoring must contain only nodes that survived that per-node stage, and later reducer or batch maps must not reintroduce a disqualified node. By contrast, an error from the reducer or from the batch scorer invalidates the aggregate operation, so `PrioritizeNodes` returns an empty score map even if that failing callback also returned partial scores.

Treat `NaN`, positive infinity, and negative infinity as invalid plugin output. A non-finite direct per-node score, plugin-map score, reduced score, or batch score disqualifies the affected node without disqualifying otherwise valid nodes; a node rejected at an earlier stage cannot be restored by a later finite contribution. Returned score-bucket keys must therefore always be finite.

`SortNodes` must return valid nodes by descending numeric score, including when every score is negative. Nodes tied at the same score are ordered by ascending node name. Ignore nil nodes and buckets whose key is non-finite, and do not reorder or otherwise mutate the caller's bucket slices. `SelectBestNode` must use the same ordering and return its first node, or nil when no valid node exists; selection must not use randomness.

Finally, allocation must tolerate scoring that leaves no eligible node. It must not attempt allocation or binding in that case, and the task remains Pending so a later scheduling cycle can retry it. Existing successful finite-score scheduling and the current public function signatures must remain compatible.
