I want the `fzf` CLI's built-in directory walker to support a `--walker-skip=DIRS` option for pruning directories from the candidate list when fzf is launched without piped input and without `FZF_DEFAULT_COMMAND`. `DIRS` is a comma-separated list; empty entries are ignored. By default, the walker should skip `.git` and `node_modules`, so running `fzf --filter ''` in a terminal-backed directory tree should not emit candidates from those directories unless the user supplies a different skip list.

When I run `fzf --walker-skip .git,node_modules,target --filter ''` in a tree containing `src/main.go`, `.git/config`, `node_modules/pkg/index.js`, and `target/app.log`, stdout should include `src/main.go` and should not include any path under `.git`, `node_modules`, or `target`; the command should exit 0 if the filter run otherwise succeeds. Skip entries should work both as simple directory names and as path-like patterns: `--walker-skip foo/bar` should prune `foo/bar` and nested matches like `baz/foo/bar`, while not treating `bazfoo/bar` as a match.

If the user passes `--walker-skip` without an argument, fzf should fail option parsing with a non-zero exit code and report that directory names to ignore are required. `fzf --help` should list `--walker-skip=DIRS` under directory traversal options with its default of `.git,node_modules`, and Bash completion should offer `--walker-skip` alongside the other walker options.
