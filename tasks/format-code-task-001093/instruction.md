CookieJar persistence currently pickles only its cookie mapping, so a restored jar can silently change security scope, forget expiration deadlines, retain stale in-memory state, or accept arbitrary data as a valid save file. Make CookieJar.save() and CookieJar.load() a versioned persistence protocol while keeping existing cookie filtering behavior intact.

A save must contain a version-1 envelope and enough state to round-trip cookies exactly, including host-only flags and scheduled expiration deadlines. Loading that envelope must replace the target jar's complete cookie collection and all derived state (host-only markers, expiration bookkeeping, and filtered-cookie caches), so cookies absent from the file disappear and no value cached before load is observable afterward. Expiration must continue relative to the original absolute deadline after loading.

For backward compatibility, load() must still accept the legacy pickled cookie mapping produced by older aiohttp versions. Unsupported versioned data must raise ValueError and leave the target jar unchanged. File paths may be strings or pathlib paths as before; do not alter update_cookies() or filter_cookies() semantics outside persistence.
