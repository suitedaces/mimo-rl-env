The transport mocker currently stores one response per APDU, so recording a stateful Ledger app silently overwrites earlier responses when the same command is sent more than once. Replace that behavior with ordered transcripts while keeping old snapshot files usable.

A newly constructed `RecordStore` is in transcript mode. Every `recordExchange(apdu, out)` appends that pair, including duplicate APDUs, and captures the buffer bytes rather than retaining mutable inputs. `reverseExchange(apdu)` compares against the next recorded APDU byte-for-byte; a match consumes exactly that record and returns a fresh response buffer. Add `remaining()`, which reports the unconsumed record count, and `reset()`, which rewinds the transcript. A mismatch must throw an `Error` whose message identifies both the expected and received APDU hex, without consuming anything. Once no records remain, replay must throw an `Error` whose message contains `exhausted` and the received APDU hex, and remain exhausted until reset.

Transcript serialization is the exact shape `{ records: [{ apdu: "lowercase hex", out: "lowercase hex" }, ...] }` in recording order. `toObject()` always includes the complete history, not cursor state, and returns detached data. `RecordStore.fromObject()` accepts that shape, copies its data, and starts replay at the beginning. Objects with neither a `records` array nor a legacy `cache` object must still throw an error containing `invalid json`.

Backward compatibility matters for existing `{ cache: { [apduHex]: outHex } }` snapshots because they did not encode order. Stores loaded from that shape must retain the old keyed behavior: known APDUs can be replayed in any order and repeatedly, `remaining()` returns `null`, `reset()` is a no-op, and `toObject()` preserves the exact `{ cache: ... }` shape.

`createTransportReplayer(store)` must give every transport returned by `open()` its own replay session over the store's complete history. Opening or exchanging through one transport must not move the supplied store's cursor or another transport's cursor. Transcript mismatches reject the exchange promise with the same diagnostic and leave that transport's session unchanged; response buffers must remain isolated from caller mutation.

`createTransportRecorder` must remain transparent to callers while producing the transcript: exchange promises resolve with the wrapped transport's response bytes, but completed successful exchanges are ultimately recorded in invocation order even if their promises settle out of order. Snapshot each APDU when `exchange` is invoked so later caller mutation cannot alter the record. Preserve the decorated transport's public `isSupported`, `list`, and `listen` behavior, and keep instance `close()` forwarding to the wrapped transport.
