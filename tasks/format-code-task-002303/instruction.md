I want WebMSX to support the `ASCII8` cartridge format as a stateful mapper. A user should be able to create a ROM with `new wmsx.ROM(...)`, pass it to `wmsx.SlotCreator.createFromROM(...)`, and receive an ASCII 8K mapper cartridge whose public constructor and methods are `new wmsx.CartridgeASCII8K(rom)`, `powerOn()`, `reset()`, `write(address, value)`, `read(address)`, `saveState()`, `loadState(state)`, and `wmsx.CartridgeASCII8K.recreateFromSaveState(state, reusableSlot)`.

`ASCII8` should also appear in `wmsx.SlotFormatsUserOptions`, and automatic selection should accept ROM content that is at least 8 KiB, is an exact multiple of 8 KiB, and starts with the cartridge header bytes `0x41, 0x42`; content that is not an 8 KiB multiple or lacks that header should not be selected as `ASCII8` automatically. The mapper divides the ROM into 8 KiB banks and exposes four 8 KiB pages from CPU addresses `0x4000` through `0xbfff`; reads outside that range return `0xff`.

For a 32 KiB ROM whose four bank-start bytes are `0x41`, `0x11`, `0x22`, and `0x33`, after `reset()` or `powerOn()`, `read(0x4000)`, `read(0x6000)`, `read(0x8000)`, and `read(0xa000)` should all read from bank 0. Calling `write(0x6000, 2)` should map bank 2 into the `0x4000-0x5fff` page, so `read(0x4000)` returns `0x22`. Calling `write(0x6800, 3)` should map bank 3 into the `0x6000-0x7fff` page, so `read(0x6000)` returns `0x33`. Calling `write(0x7000, 5)` should select `5 % numberOfBanks`, so in a four-bank ROM `read(0x8000)` returns the start byte from bank 1. Writes below `0x6000` should leave the mapping unchanged.

`saveState()` should serialize the `ASCII8` format name, ROM state, ROM bytes, current selected bank offsets, and bank count. `loadState(state)` and `wmsx.CartridgeASCII8K.recreateFromSaveState(state, reusableSlot)` should recreate a cartridge that returns the same bytes from the same mapped addresses as the saved cartridge. Separate `wmsx.CartridgeASCII8K` instances should keep independent bank-selection state.
