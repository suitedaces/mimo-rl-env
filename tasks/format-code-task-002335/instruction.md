I want both the TaskPrompter and InvPT evaluation packages to expose a stateful `SaliencyMeter(ignore_index=255, threshold_step=None, beta_squared=1)` for saliency evaluation. A caller should create a meter, call `update(preds, target)` any number of times with PyTorch tensors shaped like saliency maps, and then call `get_score(verbose=False)` to receive a dictionary containing `maxF`.

Predictions are image-scale saliency values: `update` should convert them to floating point values divided by 255, evaluate them as probabilities, ignore target pixels equal to `ignore_index`, and accumulate precision/recall counts over thresholds from `threshold_step` up to but not including 1. If `target` has a singleton channel dimension, such as shape `(B, 1, H, W)`, it should be squeezed before comparing it with `(B, H, W)` predictions. Incompatible shapes should fail with `AssertionError` during `update`.

For a concrete session with `threshold_step=0.6` and `beta_squared=1`, updating with `preds=torch.tensor([[[0., 255.], [0., 255.]]])` and `target=torch.tensor([[[0, 1], [0, 1]]])` should produce a perfect max F-score: TaskPrompter reports `{'maxF': 100.0}` and InvPT reports `{'maxF': 1.0}`. With the same tensors and `threshold_step=0.5`, zeros become positive at the threshold after probability conversion, so the score should be two true positives out of four predicted positives: TaskPrompter reports approximately `{'maxF': 66.6667}` and InvPT reports approximately `{'maxF': 0.6667}`. Multiple `update` calls should accumulate into the same meter, and separate `SaliencyMeter` instances should keep independent accumulated counts.
