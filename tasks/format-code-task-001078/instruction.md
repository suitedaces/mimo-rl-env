The dataset loading API is currently backend-dependent: `doctr.datasets.DataLoader` is available for TensorFlow but disappears when a user selects the PyTorch runtime, even though both dataset implementations expose the same indexing and collation concepts. Make the public loader available on both supported backends with one consistent protocol. A loader accepts a sized dataset, optional shuffling, a positive batch size, optional dropping of an incomplete final batch, an optional worker count, and an optional collation function. Its length must be the number of batches implied by the dataset length and `drop_last`; iteration must reset the epoch cursor, optionally reshuffle the complete index set at the start of every epoch, fetch samples in batch order (using the configured worker facility), and return each batch through the selected collator. With shuffling disabled, ordering must remain dataset order across epochs; with shuffling enabled, every dataset index must occur exactly once in a non-dropped epoch. `drop_last=True` must omit only the incomplete tail, while `False` must yield that tail. A caller-supplied collator must be honored for full and partial batches. Reject zero or negative batch sizes with a clear `ValueError` before any division or iteration occurs. Preserve the existing TensorFlow behavior and make the same API importable and usable when only PyTorch is enabled, including tensor batches and the same batch-count policy.
