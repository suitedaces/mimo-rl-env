AgentTrace is the bridge between framework-specific spans and the conversation history that callers feed into later runs. Its current spans_to_messages() projection is lossy: it removes every message whose role/content appeared earlier, so a user repeating the same words disappears; cumulative LLM snapshots can also be replayed in the wrong shape; and tool spans are rendered as assistant prose while assuming optional tool metadata is always present. Consumers need a deterministic transcript they can safely use for multi-turn prompts and inspection.

Extend the public spans_to_messages API while keeping the no-argument call valid. Process spans in their recorded order and ignore invoke_agent spans and spans with unknown operation names. For each LLM span, treat gen_ai.input.messages as a snapshot: append only the unmatched suffix after the longest prefix already emitted, so a cumulative snapshot is not duplicated, but a genuinely repeated turn and every repeated assistant output remain separate messages. Append a non-empty LLM output as one assistant message for each LLM span, even when its text equals an earlier output.

Represent a tool execution's non-empty gen_ai.output as an AgentMessage with role "tool" and that output as content. Tool name/argument attributes are optional and must never be required merely to recover the result; a tool span without them still yields the tool message. Add include_system and include_tools keyword controls, both defaulting to true. include_system=false removes only system messages from LLM snapshots, while include_tools=false omits tool-execution messages without changing the ordering or contents of user/assistant/system messages. The returned list must contain AgentMessage objects and preserve all remaining message order exactly.
