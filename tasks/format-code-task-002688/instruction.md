I want the `farm` package to support quorum-based writes on a constructed `*farm.Farm`. The constructor should be callable as `farm.New(clusters []cluster.Cluster, writeQuorum int, readStrategy farm.ReadStrategy, repairStrategy farm.RepairStrategy, instr instrumentation.Instrumentation) *farm.Farm`, where `writeQuorum` is the number of cluster-level successes required for a write call to succeed.

A `*farm.Farm` should expose `Insert(tuples []common.KeyScoreMember) error` and `Delete(tuples []common.KeyScoreMember) error`. Calling `Insert` with a non-empty batch should send the same batch to every configured cluster via that cluster's `Insert` method; calling `Delete` with a non-empty batch should send the same batch to every configured cluster via that cluster's `Delete` method. Each method should return `nil` as soon as at least `writeQuorum` clusters have accepted the batch, and an empty batch should return `nil` without requiring any cluster writes.

If fewer than `writeQuorum` clusters accept the batch, the method should return a non-nil error formatted like `no quorum (<cluster errors>)`, with the individual cluster error messages joined by `; `. A session with three clusters and `writeQuorum == 2` should return success when two clusters accept an insert even if the third fails; with the same farm, an insert or delete should return a quorum error when only one cluster accepts it. Insert calls should record insert call/count/duration metrics and insert quorum failures through the provided instrumentation, and delete calls should do the corresponding delete metrics.
