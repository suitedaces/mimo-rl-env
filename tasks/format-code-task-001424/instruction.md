I want the `hackmyresume build` CLI to support an all-formats target. When I run `hackmyresume build resume.json TO out/resume.all`, `.all` should be accepted as a special target extension instead of being reported as an unsupported output format, and the build should generate one output file for every format available from the selected theme. The output filenames should keep the requested directory and basename and replace the trailing `.all` with each concrete format name, so `out/resume.all` can fan out to files like `out/resume.html`, `out/resume.doc`, `out/resume.pdf`, `out/resume.txt`, `out/resume.md`, `out/resume.json`, `out/resume.yml`, and other theme-supported formats.

If I run `hackmyresume build resume.json` without a `TO` target, it should use the same all-formats behavior with the default target path `out/resume.all`. The happy path should complete as a normal successful build and should not emit the invalid-format error for `.all`. The built-in `hackmyresume help build` output should list `.all` as the option to generate all supported formats, and the general help page should include `hackmyresume build rez.json to out/rez.all` as the all-formats example.
