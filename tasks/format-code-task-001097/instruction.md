TransactionBuilder can already resume imported legacy multisig transactions whose partial signatures are not stored in public-key order. Extend that recovery behavior to segwit multisig inputs so independently assembled partial witnesses can be imported and completed safely.

When `TransactionBuilder.fromTransaction(...)` imports a partially signed P2WSH multisig input, a later `sign(...)` call must associate each existing signature with the matching public key from the witnessScript before adding the new signature. This must work for both native P2WSH and P2SH-wrapped P2WSH. The serialized transaction does not contain the spent output amount, so recovery must work when the required witness value and witnessScript are supplied only by the continuation `sign(...)` call.

Do not assume all imported signatures use `SIGHASH_ALL`: use the hash-type byte carried by each signature when determining its public-key position, including when a partial witness mixes `SIGHASH_NONE` and `SIGHASH_SINGLE`. After the remaining signer completes the input, `build()` must emit a valid multisig witness: the CHECKMULTISIG dummy element first, the signatures in witnessScript public-key order with their original hash types preserved, and the witnessScript last. Existing legacy P2SH multisig import and ordering behavior must continue to pass unchanged.
