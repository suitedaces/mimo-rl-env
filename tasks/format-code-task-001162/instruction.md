The `no-invalid-html-attribute` rule validates `rel` in JSX, but its `React.createElement` support does not apply the same static analysis: a literal containing several space-separated relation tokens is treated as one unknown value, and shortcut-icon pairing is skipped entirely. This makes codebases that use the factory API receive different diagnostics from equivalent JSX.

Bring the factory-call path into parity for statically knowable `rel` props. For a literal string, interpret relation tokens separated by HTML whitespace (including tabs) individually. Report an unknown token as never valid, and report a known token used on an element that does not support it as not valid for that element. Preserve the existing handling of non-literal expressions, computed or shorthand properties, non-HTML/custom element names, and unrelated attributes.

Apply the same `shortcut` pairing rule used by JSX: on a `link`, `shortcut` must be followed directly by `icon` within the same literal value; a lone shortcut or a different following token must produce the corresponding pairing diagnostic. Literal array values remain statically checkable: validate each string member independently while leaving dynamic members unchecked. Do not regress the existing JSX diagnostics or autofix behavior.
