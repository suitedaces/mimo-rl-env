I want Python Fire to support custom command argument parsing through public decorators in `fire.decorators`. `SetParseFns(*positional, **named)` should return a decorator that I can apply to a function or method, where each positional parser is a one-argument callable used for the corresponding positional parameter index, and each named parser is used for the matching Python parameter name when Fire calls the target through `fire.Fire(component, command=[...])`.

For example, if a method is decorated with `@fire.decorators.SetParseFns(count=int)`, then `fire.Fire(Component, command=['double', '2'])` should call the method with `count` as the integer `2`, so a method returning `2 * count` returns `4`. If a method is decorated with `@fire.decorators.SetParseFns(float, arg2=str)`, then `fire.Fire(Component, command=['example', '10', '10'])` should pass the first token as `10.0` and the second as the string `'10'`, returning `(10.0, '10')` for a method that returns both values.

I also want `SetParseFn(fn, *arguments)` as a convenience decorator. With no argument names, it should set a default parser used for any command token that does not have a more specific positional or named parser; for instance `@fire.decorators.SetParseFn(str)` on a method accepting `arg1, arg2=None, *varargs, **kwargs` should make `fire.Fire(Component, command=['example', '1', '--arg2=2', '3', '4', '--kwarg=5'])` return `('1', '2', ('3', '4'), {'kwarg': '5'})`. With argument names, `SetParseFn(str, 'mode')` should parse only that named argument with `str` while other arguments continue to use Fire's normal parsing.

Parser selection should be deterministic: a positional parser for the parameter index wins first, then a named parser for the parameter name, then the default parser from `SetParseFn`, and otherwise Fire's normal parser is used. Calling the decorated function directly from Python should still behave like the original function call; the custom parsing should only affect values supplied through Fire command execution. If a selected parser raises an exception, such as `int('bad')` raising `ValueError`, Fire should not silently fall back to another parser for that value.
