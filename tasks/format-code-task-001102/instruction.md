Traceflow's admission webhook currently accepts internally contradictory requests which can allocate a dataplane tag and only fail later on an Agent. Tighten admission validation so invalid endpoint and packet combinations are rejected consistently before a Traceflow starts, while retaining the useful regular and live-traffic forms documented by Antrea.

Apply the same content validation on CREATE and UPDATE. Source `pod` and `ip` are mutually exclusive. Destination `pod`, `service`, and `ip` are mutually exclusive. Every named Pod or Service must include its Namespace; conversely, a destination Namespace must not accompany an IP destination. A regular (non-live) Traceflow requires an existing, non-`hostNetwork` source Pod and exactly one destination (Pod, Service, or IP); a source IP is not a substitute for that Pod. A live-traffic Traceflow may omit either side and may use a source IP, but at least one endpoint must still be a Pod. In particular, destination-only Pod capture, source-IP-to-Pod capture, and source-Pod-to-Service capture are valid. `droppedOnly` is valid only when `liveTraffic` is true.

Validate endpoint IP literals and their family against the packet header family. Supplying `ipv6Header` selects IPv6, including when `ipHeader` is also present as documented; without `ipv6Header`, endpoint IPs must be IPv4. At most one of the TCP, UDP, and ICMP transport header objects may be set. If a non-zero IPv4 `protocol` or an IPv6 `nextHeader` is explicitly supplied alongside a transport header, it must agree with that transport (TCP 6, UDP 17, ICMP 1 for IPv4 or 58 for IPv6). Keep protocol inference when the protocol is omitted or zero, and continue accepting a custom IP protocol when no transport header is supplied.

Treat the Traceflow spec as immutable on UPDATE: an unchanged valid spec is allowed, while any spec change is denied, and an UPDATE without an old object is malformed and must be denied. All denials must return an AdmissionResponse with `Allowed: false`, preserve the request UID, and include a non-empty message which identifies the conflicting or invalid fields (using their API field names such as `liveTraffic`, `droppedOnly`, `ipHeader`, or `nextHeader`). Successful responses must also preserve the request UID.
