The v2 SDK exposes one-page list_resources calls, but consumers that need to process a whole Knowledge Box currently have to duplicate pagination loops. Add a public iter_resources helper to both the synchronous NucliaDB and asynchronous NucliaDBAsync clients.

The helper must lazily fetch pages and yield the Resource objects in server page order. It accepts the Knowledge Box id, an optional non-negative starting page (default 0), an optional positive page_size, and optional query_params. Each request must preserve every caller-supplied query parameter; the explicit page and page_size arguments control the outgoing page and size values when provided, and those control values take precedence over colliding entries in query_params. Do not mutate the caller's dictionary (or nested values) while advancing pages.

After each response, continue with the next integer page until the response's pagination.last is true. An empty page is not an end marker by itself, so a non-final empty page must be followed by later pages. Stop immediately after the final page and preserve the order of resources within and across pages. The asynchronous helper must provide the same semantics while awaiting the existing asynchronous request surface.

Reject a negative starting page or a non-positive page size with ValueError before making a request. If a page request fails, propagate the SDK's normal response exception without yielding fabricated data or silently retrying. Keep the existing one-page list_resources methods and their return values and request behavior compatible for callers that do not use the new helper.
