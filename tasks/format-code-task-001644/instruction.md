I want the shared mail connection object to expose `JMAP.mail.report(messages, asSpam, allowUndo)` for reporting already-loaded email records as spam or not spam. Calling it should inspect each message's `accountId`, `id`, and `storeKey`, group the message ids by account, queue one `Email/report` JMAP method call per account, and return the same `JMAP.mail` object so callers can continue chaining actions.

For example, if I call `JMAP.mail.report([m1, m2], true, false)` where both messages are in account `accA` with ids `e1` and `e2`, the connection should queue `Email/report` with `{ accountId: 'accA', ids: ['e1', 'e2'], type: 'spam' }` and should not queue undo data. If I call `JMAP.mail.report([m1, m3], false, true)` where `m1` is `{ accountId: 'accA', id: 'e1', storeKey: 'sk1' }` and `m3` is `{ accountId: 'accB', id: 'e3', storeKey: 'sk3' }`, it should queue separate `Email/report` calls for `accA` and `accB` with `type: 'notspam'`. With `allowUndo` set, it should also push undo data that can call `report` again for the same message store keys with the opposite spam flag and undo enabled.
