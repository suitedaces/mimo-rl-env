I want the Go API `func Parse(ctx context.Context, libs []string, config ParseConfig) (*ELM, error)` to accept external CQL parameter values through `ParseConfig.Parameters map[result.DefKey]string`. Each map value should be parsed as a standalone CQL term literal or selector before evaluation, and the resulting `*ELM` should carry those parsed values so `(*ELM).Eval` uses them for the matching library parameter.

For a library `library TESTLIB version '1.0.0' parameter Threshold Integer default 5 define TESTRESULT: Threshold`, calling `Parse` with `ParseConfig{Parameters: map[result.DefKey]string{{Name: "Threshold", Library: result.LibKey{Name: "TESTLIB", Version: "1.0.0"}}: "9"}}` and then evaluating should produce `TESTRESULT = 9`; calling `Parse` with no parameters should still evaluate to the library default `5`. For a library with `parameter Tags List<String> define TESTRESULT: Tags`, passing the value `{'alpha', 'beta'}` should evaluate to a two-item string list, and an interval value such as `Interval[@2017, @2019]` should be accepted for interval parameters.

Parameter strings must be single parameter values, not full CQL declarations or arbitrary expressions. Inputs like `define X: 4`, `4 15`, an empty string, or an unresolved invocation such as `invo` should make `Parse` return an error; callers should be able to inspect invalid parameter failures as `*parser.ParameterErrors` tied to the relevant `result.DefKey`, with messages such as `must be a single literal` or the underlying syntax problem. Repeated calls with the same libraries and parameter map should produce equivalent parsed/evaluated results, and `Parse` must not mutate the supplied parameter map or perform filesystem/network side effects for parameter parsing.
