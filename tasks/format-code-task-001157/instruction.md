The server already accepts Grafana connection settings from process environment variables in stdio mode and from per-request headers in SSE mode, but the three clients assembled for Grafana, Incident, and OnCall-related operations can silently use different settings. This makes an SSE request reach the wrong host, lose its credentials, or construct malformed plugin URLs depending on which tool is called. Unify the configuration boundary used by the composed SSE context function so each request gets one effective Grafana URL and API key, and every downstream client built for that request uses the same values.

`GRAFANA_URL` and `GRAFANA_API_KEY` are the defaults. A non-empty `X-Grafana-URL` or `X-Grafana-API-Key` header overrides only its corresponding environment value; an omitted or empty header falls back independently to the environment value. Trim trailing slashes from the effective base URL before storing it or appending API paths, preserve URL schemes and non-root subpaths, and use `http://localhost:3000` when the URL is absent. The generated Grafana client must address `<base>/api/...` with the effective scheme, host, and path and send `Authorization: Bearer <key>` only when a non-empty key is configured. The Incident client must use `<base>/api/plugins/grafana-irm-app/resources/api/v1/` and the same conditional bearer credential. Stdio and SSE with no overriding headers must be behaviorally equivalent, and one request's headers must not leak into another request's context. Existing public context accessors and tool consumers must continue to work.
