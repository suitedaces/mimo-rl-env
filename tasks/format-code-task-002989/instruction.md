I want `web.subdomain_application(mapping, fvars={})` to provide host-based dispatch for web.py applications. The `mapping` argument should be a flat sequence of host regex patterns paired with either mounted `web.application` instances or handler references, and each request should choose the first pattern that fully matches the request `Host` value after stripping any port. For example, with mappings for `r"a\.example\.com"`, `r"b\.example\.com"`, and `r".*\.example\.com"` pointing to apps that return `"a"`, `"b"`, and `"*"`, calling `app.request("/", host="a.example.com").data` should return `b"a"`, `host="b.example.com"` should return `b"b"`, and `host="c.example.com"` should return `b"*"`.

If a host pattern captures groups and dispatches to a handler method, those captured groups should be passed to the handler just like URL captures are. String handler targets should also support regex substitution from the host match before dispatch. When no host pattern matches, a request should produce the normal web.py 404 response, with status `"404 Not Found"` and body `b"not found"`. Separate `subdomain_application` instances should keep their mappings independent, so changing mappings on one instance should not affect another.
