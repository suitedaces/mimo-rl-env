I want one-shot static capability matching for capa rules exposed through `capa.capabilities.common.find_capabilities(ruleset: RuleSet, extractor: StaticFeatureExtractor, disable_progress: bool = False, **kwargs) -> Capabilities`, and also as `capa.capabilities.static.find_static_capabilities(ruleset: RuleSet, extractor: StaticFeatureExtractor, disable_progress: bool = False) -> Capabilities`. Given a static extractor, it should walk the file, functions, basic blocks, and instructions, evaluate rules in the right static scopes, and return a `Capabilities` object containing `matches`, static `feature_counts`, and skipped library function metadata.

For a ruleset with an instruction-scope rule named `push 1000` that requires `mnemonic: push` and `number: 1000`, and a static extractor whose instruction at `0x4071A4` has those features, `find_capabilities(...)` should return a result where `"push 1000"` is present in `capabilities.matches` and one match location is `0x4071A4`. For a ruleset with a basic-block rule named `tight loop`, a function rule named `kill thread loop` that depends on `match: tight loop` plus function features, and a file rule named `kill thread program` that depends on `match: kill thread loop` plus file features, the returned matches should contain all three rule names after one call. File-scope rules must be able to match both raw file/global features and lower-scope rule matches promoted from instruction, basic-block, and function results.

The static matcher should skip functions reported by `extractor.is_library_function(address)`, record each skipped function as a library function with its address and `extractor.get_function_name(address)`, and not produce instruction, basic-block, or function matches from those skipped functions. It should populate per-function feature counts for analyzed non-library functions and a file feature count for file-scope matching. Calling `find_static_capabilities(...)` with an extractor that is not a `StaticFeatureExtractor` should fail instead of silently treating it as a static program. Calling the static matcher twice with the same ruleset and same extractor contents should produce equivalent capability matches.
