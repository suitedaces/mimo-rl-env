The JVM descriptor utilities are used both while loading class files and while selecting an overloaded Java method from PHP. At the moment `Formatter::parseSignature` is permissive about malformed input, and `buildArgumentsSignature` emits strings that are not valid JVM descriptors (for example, it adds a semicolon after primitive types and changes internal class-name separators). That makes method matching depend on accidental parser tolerance and makes bad class-file metadata fail later with unrelated errors.

Bring the public descriptor helpers into alignment with the JVM descriptor grammar while keeping their existing return shape. `Formatter::parseSignature` must parse field descriptors and method descriptors containing every primitive type, object types (including `$` in nested class names), and any array depth. A method result must expose its argument list and argument count as today, with the return descriptor at index `0`; `V` is legal only as a method return type, never as a field or argument. Class names must remain in JVM internal `/` form and array depth must be reported separately.

Malformed descriptors must be rejected immediately with `PHPJava\Exceptions\FormatterException`: this includes empty input, unknown tags, unterminated object names, trailing bytes, incomplete method parentheses or return types, and void arguments. `Formatter::buildArgumentsSignature` must emit the canonical concatenation of argument descriptors: primitive tags have no terminator, object descriptors use `Lname;`, names use `/`, and array dimensions precede the component descriptor. Parsing the generated string must recover the same types, names, and dimensions. Preserve the existing PHP ambiguity conversion contract (`long`/`byte`/`short` to `int`, `double` to `float`, while leaving object descriptors and dimensions intact), since method dispatch relies on it.
