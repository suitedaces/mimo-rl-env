I want the pure pie and ring option builders to support a `limitShowNum` setting for collapsing small slices. The public calls are `pie(columns: string[], rows: object[], settings: object, extra: object, isRing?: boolean) -> object` and `ring(columns: string[], rows: object[], settings: object, extra: object) -> object`; when `settings.limitShowNum` is a positive number, the builders should sort rows by the selected metric in descending order before creating the pie data and legend.

For example, with `columns = ['name', 'value']`, rows `[{name: 'A', value: 10}, {name: 'B', value: 50}, {name: 'C', value: 20}, {name: 'D', value: 5}, {name: 'E', value: 15}]`, `settings = {limitShowNum: 3}`, and visible tooltip/legend, `pie(...)` should return a first series whose data is `[{name: 'B', value: 50}, {name: 'C', value: 20}, {name: 'E', value: 15}, {name: '其他', value: 15}]`, and the legend data should be `['B', 'C', 'E', '其他']`. The tooltip formatter for the `其他` slice should show `其他:` and then list the hidden categories with their formatted values and share of the original total, so this example includes `A: 10 (10.00%)` and `D: 5 (5.00%)`.

The same collapsed-slice behavior should apply to `ring(...)`. For example, with rows `[{name: 'X', value: 5}, {name: 'Y', value: 7}, {name: 'Z', value: 11}, {name: 'W', value: 13}]`, `settings = {limitShowNum: 2}`, and legend visible, `ring(...)` should produce series data `[{name: 'W', value: 13}, {name: 'Z', value: 11}, {name: '其他', value: 12}]` and legend data `['W', 'Z', '其他']`. If `limitShowNum` is omitted, zero, or greater than or equal to the number of rows, no `其他` slice is added; for positive values the rows are still ordered by metric before the chart data is produced.
