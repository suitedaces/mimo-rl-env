I want eaopt to provide Standard Particle Swarm Optimization for minimizing real-valued functions without making me implement the Genome interface myself. The public API should include `NewSPSO(nParticles, nSteps uint, min, max, w float64, parallel bool, rng *rand.Rand) (*SPSO, error)`, `NewDefaultSPSO() (*SPSO, error)`, and `(*SPSO).Minimize(f func([]float64) float64, nDims uint) ([]float64, float64, error)`.

`NewSPSO` should configure a single-population SPSO-2011 style optimizer with `nParticles` particles, `nSteps` evolution steps, initial positions sampled uniformly between `min` and `max`, inertia weight `w`, optional parallel evaluation, and a caller-supplied RNG; passing `nil` for the RNG should still create a usable optimizer. `NewDefaultSPSO` should use 40 particles, 30 steps, bounds `[-5, 5]`, inertia weight `0.5`, sequential evaluation, and a random internal RNG. Invalid construction should fail before minimization: for example `NewSPSO(40, 30, 5, -5, 0.5, false, nil)` should return a non-nil error because `min` is not lower than `max`, and zero particles or zero steps should also return a non-nil error.

A session should work like this: create an optimizer, optionally set fields on its embedded GA such as `spso.GA.RNG = rand.New(rand.NewSource(42))`, then call `spso.Minimize(objective, 2)`. For the two-dimensional Styblinski-Tang objective `0.5 * sum(x_i^4 - 16*x_i^2 + 5*x_i)`, using `NewDefaultSPSO()` with `spso.GA.RNG` set to `rand.New(rand.NewSource(42))` should return approximately `-78.23783` at `[]float64{-2.8586916496046983, -2.9619895273744623}` with a nil error. For a two-dimensional bowl objective `sum(x_i*x_i)`, running through `NewDefaultSPSO()`, setting `spso.GA.ParallelEval = true`, and calling `Minimize` should also complete with a nil error.
