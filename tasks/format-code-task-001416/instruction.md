I want a public action adapter API for the ASX Gym environment so agent code can build readable trade objects and copy them into the nested Gym action dictionary without filling every numeric array by hand. The API should provide `AsxTransaction(company_id, stock_operation, volume, price)` and `AsxAction(end_batch)`, with `AsxAction.add_transaction(transaction)`, `AsxAction.copy_to_env_action(action)`, `AsxAction.to_json_obj()`, and `AsxAction.from_env_action(action)`.

`AsxTransaction.to_json_obj()` should return a JSON-ready dictionary with `company_id` converted to `int`, `volume` and `price` converted to floats rounded to 2 decimals, and `stock_operation` rendered as a readable string. For example, `AsxTransaction("7", BUY_STOCK, 12.345, 6.789).to_json_obj()` should return `{"company_id": 7, "stock_operation": "buy", "volume": 12.35, "price": 6.79}`. The operation labels should be `buy` for `BUY_STOCK`, `sell` for `SELL_STOCK`, `hold` for `HOLD_STOCK`, `top_up` for `TOP_UP_FUND`, `withdraw` for `WITHDRAW_FUND`, and `unknown` for any other operation code.

An `AsxAction` instance should keep its own ordered transaction list. In a session like `a = AsxAction(1); a.add_transaction(AsxTransaction(7, BUY_STOCK, 3, 10.5)); a.add_transaction(AsxTransaction(8, SELL_STOCK, 4, 9.25))`, calling `a.copy_to_env_action(action)` should mutate and return the same `action` dictionary, set `action['company_count']` to `2`, set `action['end_batch']` to `1`, and write the two transactions into index `0` and index `1` of `company_id`, `volume`, `price`, and `stock_operation` arrays in insertion order. Calling `a.to_json_obj()` should return `{"end_batch": 1, "transactions": [...]}` with the same transaction order and each transaction encoded through `AsxTransaction.to_json_obj()`.

`AsxAction.from_env_action(action)` should perform the inverse conversion from a Gym action dictionary: it should read `company_count`, `end_batch`, and the indexed `company_id`, `volume`, `price`, and `stock_operation` arrays, then return an `AsxAction` whose transactions preserve that order. Separate `AsxAction` objects must not share their transaction lists, and these adapters should not read or write files, use the network, or depend on hidden global state.
