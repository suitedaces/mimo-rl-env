I want EliasDB's graph Manager to expose a stateful node-key iterator for scanning the keys of stored nodes by partition and kind. The public API should be `func (gm *Manager) NodeKeyIterator(part string, kind string) (*NodeKeyIterator, error)`, with `NodeKeyIterator.HasNext() bool`, `NodeKeyIterator.Next() string`, `NodeKeyIterator.Error() error`, and a public `LastError error` field.

Given a manager with nodes `key=123, kind=mykind`, `key=789, kind=mykind`, and `key=456, kind=mykind2` stored in partition `main`, calling `gm.NodeKeyIterator("main", "mykind")` should return a non-nil iterator and nil error. Repeatedly calling `HasNext()` and `Next()` should yield only the node keys for that kind, in the stored iterator order, so this session returns `123` and `789` and does not return `456`. Each call to `Next()` advances the iterator state; after all items are consumed, `HasNext()` should be false, `Next()` should return the empty string, and `Error()`/`LastError` should remain nil.

If there is no node storage for the requested partition and kind, `NodeKeyIterator` should return `(nil, nil)`. If creating the underlying iterator fails, it should return a nil iterator and a non-nil `*util.GraphError` with `Type == util.ErrReading`. If reading the next key fails after an iterator has been created, `Next()` should return the empty string and expose the same kind of read error through both `LastError` and `Error()`.
