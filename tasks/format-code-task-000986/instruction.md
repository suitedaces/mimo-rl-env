The pandas implementation of `separate()` exposes the same policy arguments as tidyr, but its public behavior is incomplete: variable-length strings either raise unexpectedly or silently lose the caller's layout, and grouped data can no longer be used reliably after splitting. Complete this API while keeping existing string and symbolic column selectors compatible.

For a source column and the requested `into` names, split each row with the supplied regular-expression separator. Replace the source column in its original position when `remove=True`; when `remove=False`, retain it and insert the generated columns immediately after it. Preserve the input row order and index in both cases. Generated names must be unique, and a missing source column is an error.

Make the `extra` policy meaningful when a row has more pieces than names: `drop` discards surplus pieces, `warn` does the same while emitting a `UserWarning`, and `merge` puts all surplus pieces into the final generated column joined with the literal separator text. Make the `fill` policy meaningful on rows with too few pieces: `right` pads missing values on the right, `left` pads on the left, and the default `warn` behaves like right-fill while emitting a `UserWarning`. Invalid `extra` or `fill` values must be rejected rather than ignored. These decisions are per row, so mixed-length input must be handled without changing unrelated rows.

`convert=True` attempts numeric conversion only for the generated columns and must never rewrite the retained source column. A grouped DataFrame must return a grouped DataFrame with the same named grouping columns, while retaining the original row order, index, and all untouched columns. Existing normal splitting, removal, symbolic selectors, and conversion behavior must remain compatible.
