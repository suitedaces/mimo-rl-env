I want the operator binary to support printing the CRDs it has bundled without connecting to a Kubernetes cluster. When I run `operator --print-calico-crds all`, it should print every bundled Calico CRD to stdout and exit 0; when I run `operator --print-enterprise-crds all`, it should print every bundled Enterprise CRD to stdout and exit 0. Each printed CRD should be preceded by a comment line in the form `# <crd name>`, followed by the CRD serialized as YAML, with `---` printed between CRDs after the first one. The flag value can also be a CRD-name prefix: for example, `operator --print-calico-crds ippools` should print bundled Calico CRDs whose names start with `ippools`, such as `ippools.crd.projectcalico.org`, and `operator --print-enterprise-crds installations` should print Enterprise CRDs whose names start with `installations`, such as `installations.operator.tigera.io`. If `CALICO_API_GROUP=projectcalico.org/v3` is set, the printed Calico or Enterprise CRDs should come from the v3 API group bundle; otherwise they should come from the v1 CRD bundle. If no CRD name matches the supplied prefix, the command should print `no CRD matching <prefix>` to stdout and exit 1. The `--help` output should list both `--print-calico-crds` and `--print-enterprise-crds`, describe that accepted values are `all` or a CRD prefix, and exit 0.
