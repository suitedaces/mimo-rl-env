I want `vogels.define(modelName, config)` to support automatic timestamp fields for the model it returns. When I define a model with `timestamps: true`, then call the returned model's `create(item, [options], callback)`, the item written to DynamoDB and the item passed to the callback should include a `createdAt` field if the caller did not already provide one; the value should be an ISO date string. Calling the returned model's `update(item, [options], callback)` should likewise add an `updatedAt` ISO date string when the caller did not already provide one.

The timestamp fields should be accepted by model validation even when they are not listed in the user's Joi schema. `createdAt` and `updatedAt` in the model config should each accept either a custom attribute name string or `false`: for example `createdAt: 'created'` makes `create` populate `created`, and `updatedAt: 'updated'` makes `update` populate `updated`; `createdAt: false` disables the create timestamp and `updatedAt: false` disables the update timestamp. If the caller already supplies the configured timestamp attribute on create or update, Vogels should leave that value alone rather than replacing it.
