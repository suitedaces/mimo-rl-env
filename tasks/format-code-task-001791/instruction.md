I want the `virter vm commit` CLI subcommand so I can turn an existing VM's current root disk into a reusable local Virter image. The command should be invoked as `virter vm commit vm-name [image-name]`; when `image-name` is omitted, the new image should be named after `vm-name`, and when it is provided, that name should be used instead. On a successful commit it should exit 0, produce no normal stdout, remove the VM domain while preserving its root boot volume, convert that boot volume into an immutable content-addressed image layer, and make a local image tag that can be listed or used as the base for later VM runs.

The command should support `--shutdown`/`-s`, defaulting to true. If the VM is running and shutdown is enabled, Virter should ask libvirt to shut the domain down and poll until it is no longer active; if the configured shutdown timeout expires, the command should exit non-zero and report an error containing `timed out waiting for domain to stop` on stderr. If the VM is running and I pass `--shutdown=false`, the command should exit non-zero and report `must allow shutdown to commit a running VM`.

The command should support `--reset-machine-id`, defaulting to true. When enabled, the VM must be running so Virter can clear `/etc/machine-id` inside the guest over SSH before shutdown; if the VM is not running, the command should exit non-zero and report an error containing `cannot reset machine ID of VM` on stderr. If the preserved root volume cannot be found after the VM domain is removed, the command should exit non-zero and report `could not commit: missing root layer`. `virter vm commit --help` should exit 0 and show the `commit vm-name [image-name]` usage plus the `--shutdown` and `--reset-machine-id` flags.
