I want the AMQP transport package to provide a client-side request/response publisher API for invoking remote Go kit endpoints over AMQP. The public constructor should be `NewPublisher(ch Channel, q *amqp.Queue, enc EncodeRequestFunc, dec DecodeResponseFunc, options ...PublisherOption) *Publisher`, where `EncodeRequestFunc` writes the domain request into an `amqp.Publishing` and `DecodeResponseFunc` converts the matching AMQP reply delivery back into a domain response. After construction, `Publisher.Endpoint() endpoint.Endpoint` should return an endpoint function that encodes the request, publishes it, waits for a reply with the same correlation ID, decodes that reply, and returns the decoded response.

For example, with a mock channel whose reply queue contains a delivery with correlation ID `correlation` and JSON body `{"s":437,"n":"husky"}`, a publisher configured with `PublisherBefore(SetCorrelationID("correlation"))` and JSON encoders/decoders should publish the encoded request and return a response object with squadron `437` and name `husky`. If the request encoder returns `errors.New("err!")`, the endpoint call should return that error without producing a decoded response; if the response decoder returns `errors.New("err!")`, the endpoint call should return that decode error. `PublisherTimeout(d)` should bound the whole request/reply wait: if no matching reply arrives before the timeout, the endpoint should return the context deadline error.

I also need publisher options for `PublisherBefore`, `PublisherAfter`, `PublisherDeliverer`, and `PublisherTimeout`. The default deliverer should publish with the exchange and routing key from the request context, consume from the configured reply queue, ignore deliveries whose correlation ID does not match, Ack the matching reply when consume auto-ack is false, and pass AMQP consume arguments from `SetConsumeArgs`; `SetConsumeAutoAck` should control the consume auto-ack flag. A `SendAndForgetDeliverer` option should publish the request and return immediately without waiting for a reply, so callers can use no-op or nil-tolerant response hooks/decoders for fire-and-forget calls.
