The organization-domain helper is used to derive a stable IAM username domain from an organization display name and the instance base domain. The current implementation produces malformed names for ordinary user input: tabs and repeated whitespace disappear inconsistently, punctuation can leave leading/trailing separators, Unicode names can be cut in the middle of a UTF-8 character, and an overlong base domain can panic while trying to shorten the label. Make NewIAMDomainName a total, deterministic normalization boundary for this public API.

Normalize the organization label by treating each run of Unicode whitespace as one separator, retaining Unicode letters/marks, ASCII digits, and existing hyphens, and removing other characters. The normalized label must be lower-case, have no leading or trailing hyphen, and use a single hyphen for each separator run. Preserve non-ASCII letters as valid UTF-8. Enforce the DNS label limit of 63 octets without splitting a UTF-8 rune; apply the separator trimming after truncation as well.

Return the canonical result as the lower-case label, a dot, and the supplied IAM base domain, and never return a name longer than 253 octets. If the base domain leaves no valid room for a label, or normalization leaves the label empty (including names made only of punctuation or hyphens), return an InvalidArgument error instead of panicking or returning a malformed domain. Existing valid names must continue to work, including custom base domains and Unicode organization names.
