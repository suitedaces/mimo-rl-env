I want `funcy.decorator(deco)` to turn a flat wrapper function into a normal Python decorator. If I write `@decorator` on `def inc(call): return call() + 1`, then `@inc` on `def ten(): return 10` should produce a function where `ten()` returns `11`; if I write `@decorator` on `def add(call, n): return call() + n`, then `@add(2)` on the same `ten` should make `ten()` return `12`.

The wrapper must receive a call object that stores the decorated function and the original positional and keyword arguments, invokes the decorated function when called with no extra arguments, and can append extra positional or keyword arguments when called with them. That call object should expose decorated-function arguments by attribute name, including positional arguments, keyword-only arguments, defaults, `*args`, and `**kwargs`; for example a wrapper returning `call.x` should return `10` for a decorated `lambda x: None` called as `(10)`, return the default `11` for `lambda x=11: None` called with no arguments, and return `(1, 2)` for `lambda *x: None` called as `(1, 2)`. If the wrapper asks for an argument name the decorated function does not have, or for a required argument that was not supplied, accessing that attribute should raise `AttributeError`.

Decorators whose wrapper has only the call parameter should be usable directly as `@my_decorator`. Decorators whose wrapper has additional positional parameters should be usable as decorator factories such as `@add(2)`. Decorators whose wrapper has only keyword-only options after the call parameter should support both `@rate_limit` with omitted parentheses and `@rate_limit(option=value)`.

The resulting decorated functions should preserve the wrapped function metadata: `__name__`, `__module__`, `__doc__`, `__wrapped__`, and `__original__` should point to the expected outer and innermost functions. The decorator factory returned by `decorator()` should also preserve the wrapper name and expose the wrapper function plus bound decorator arguments for introspection. Calling the same decorated function with the same arguments should produce the same result unless the user-supplied wrapper or wrapped function has its own side effects; the helper itself should not perform filesystem, network, or other hidden external side effects.
