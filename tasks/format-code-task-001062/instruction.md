Search pagination is used by the Angular search screens, but the current paginator trusts API values too literally and exposes inconsistent controls when a response is missing, malformed, or asks for a page outside the result set. Improve the public `Paginator(goOn, args)` behavior so callers always receive a coherent, safe state while retaining the existing page-window convention and callback API. With no metadata, initialize page 1 with zero results, a single `[1]` page entry, and both navigation flags false. With metadata, accept numeric strings as well as numbers, truncate fractional values toward zero, treat non-finite or negative counts as zero, treat non-positive page totals as an empty result set, and clamp the current page to the valid range. For a positive page total, expose at most seven consecutive one-based page numbers, always including the clamped current page; preserve the established windowing examples (page 2 of 11 starts at 1, page 8 of 15 shows 8 through 14, and a final-page window ends at the final page). `hasPrevious` and `hasNext` must describe whether an adjacent page exists (`pageNumber > 1` and `pageNumber < total_pages`) rather than the width of the displayed window. `goPrevious` and `goNext` must call the supplied search callback with exactly the adjacent page only when that page is valid, and must be no-ops at either boundary or for an inert empty state. Keep the service compatible with existing Angular consumers and do not alter the callback's argument shape.
