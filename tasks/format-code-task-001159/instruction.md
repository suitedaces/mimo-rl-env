The OGC FilterBuilder is used to turn user- and catalog-supplied filter values into XML sent to WFS services. At the moment it interpolates caller-controlled strings directly into element text and attribute values. A layer name, feature id, function name, or distance unit containing XML punctuation can therefore produce malformed filters or change the generated document instead of being treated as data. Please harden this public builder without changing the filter vocabulary or the output of ordinary inputs.\n\nAll dynamic values placed in XML text nodes must be escaped so that ampersands and angle brackets remain data and the resulting fragment is well-formed. This applies to literals and to property/value-reference names, including the property shortcut methods. Dynamic XML attributes must likewise be escaped for feature ids, function names, and distance units. The decoded values seen by an XML consumer must be exactly the original strings.\n\nThe behavior must work for the default namespace and caller-selected filter namespaces, and for both WFS 1.1-style PropertyName and WFS 2.0 ValueReference output. Escaping must compose through nested logical predicates, unary null predicates, spatial distance predicates, and the outer filter wrapper. Existing ordinary comparison, spatial, logical, function, and version-specific output must remain compatible; this is a serialization safety correction, not a new filter syntax.
