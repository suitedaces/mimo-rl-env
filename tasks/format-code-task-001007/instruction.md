Sqorn's public query builder already supports composing SELECT, DELETE, INSERT, and UPDATE builders, and its tagged-template interpolation rules make nested builders and parameters reusable. The missing piece is the documented `.with` / `.recursive` surface: callers cannot currently express common table expressions without dropping down to raw SQL, and attempts to use those methods fail as unimplemented.

Add CTE support to the Postgres builder while preserving the existing immutable, chainable API and the `{ text, args }` query result shape. `.with` is a tagged-template builder method. Each call defines one CTE exactly as written by the template (for example, `name(columns) as (...)`), and multiple calls are emitted in call order under one `with` keyword before the main SELECT, DELETE, INSERT, or UPDATE statement. A normal template interpolation remains a parameterized value using the dialect's existing placeholders; a `$...` interpolation remains a raw SQL fragment. If an interpolated value is another Sqorn builder, embed that builder's SQL in the CTE body and append its arguments to the same parent argument list.

The `.recursive` getter opts the WITH clause into `with recursive`. It may appear before or after the CTE definitions and must affect the final clause rather than the position where the getter was called. Repeating it must not duplicate the keyword. When no CTE has been defined, `.recursive` is inert and must not emit a stray WITH fragment.

CTEs must compose with existing fluent operations and `.extend`: extending a CTE fragment with a source fragment produces one coherent query, while inspecting either source afterward still yields its original query. Nested builder-valued CTEs retain their own nested WITH clauses and parameter numbering follows rendered SQL order, with CTE parameters before parameters in the consuming statement. Existing non-CTE queries and all current interpolation, aliasing, filtering, returning, and mutation behavior must remain compatible. The feature must be available on the Postgres SELECT, DELETE, INSERT, and UPDATE query pipelines, not only SELECT.
