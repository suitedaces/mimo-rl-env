The library already defines an ETS (Enhanced Transmission Selection) qdisc encoder/decoder, but callers cannot use it through the generic queueing-discipline API: creating an object with Kind ets is rejected as not implemented, and objects returned by Qdisc().Get() cannot expose or decode their ETS options. Wire ETS into the same exported Qdisc workflow as the other supported qdiscs. Attribute must expose an Ets *Ets option, and Add, Replace, Change, and Link must accept a configured ETS object and encode its scalar settings plus the nested quanta and priority-map lists. Preserve explicitly supplied zero values and list order. Get must report Kind ets and reconstruct all supplied ETS fields from netlink options regardless of attribute ordering. Delete must remain usable with only the kind and message, as with other qdisc deletions. Creating ETS without options must return ErrNoArg, while invalid device IDs and unknown kinds retain their existing errors; existing parameterless qdiscs such as qfq must continue to work. Keep the public API and wire behavior implementation-agnostic beyond these observable contracts.
