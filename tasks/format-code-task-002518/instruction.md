I want `gocryptfs` to support a `-zerokey` CLI option for automated tests and other explicitly insecure test setups. When I run `gocryptfs -zerokey CIPHERDIR MOUNTPOINT`, it should use a 32-byte all-zero master key directly instead of prompting for a password or decrypting the master key from `gocryptfs.conf`, and the command should continue into the normal mount flow with exit code 0 when the supplied filesystem options match the encrypted directory. The same option should also work with `gocryptfs -init -zerokey CIPHERDIR`, creating the new filesystem with an all-zero master key stored in the config file, and with `gocryptfs -passwd -zerokey CIPHERDIR`, using the all-zero key as the existing master key before asking for the replacement password.

For observability, using `-zerokey` should print informational output that says an all-zero dummy master key is being used and warns that this mode provides no security and is only for testing. `gocryptfs -hh` should list `-zerokey` with a short description such as "Use all-zero dummy master key". The option should also be accepted through the mount-compatible `-o` syntax, so `gocryptfs CIPHERDIR MOUNTPOINT -o q,zerokey` is equivalent to passing `-q -zerokey`.
