TatSu documents an `@@ignorecase` grammar directive, but parsing a compiled grammar in memory currently diverges from the generated parser and keyword reservations depend on how the keyword was written. Make case handling consistent across both public parser surfaces.

The effective case mode is selected per parse: an explicit `ignorecase` argument to `Grammar.parse()` or a generated parser's `parse()` call overrides the grammar directive; when omitted, the directive value is the default. The same rule must apply on successive calls to a reused parser/model without one call changing the next call's behavior. In that mode, literal/token expressions compare text without regard to case and still return the grammar's declared literal value. With case sensitivity enabled, matching remains exact.

`ignorecase` must not implicitly alter regular-expression pattern expressions; patterns continue to use their own regular-expression flags. A grammar's `@@keyword` declarations reserve identifiers through the `@name` mechanism. In case-insensitive mode, every casing of each declared keyword is rejected, regardless of the declaration's casing. In case-sensitive mode, only the exact declared spelling is reserved; other casings remain valid identifiers. Existing successful parses, AST values, and `FailedParse` error behavior outside these case distinctions must remain compatible. Compiling the grammar and using the generated parser must expose the same observable behavior, including constructor defaults and per-call overrides.
