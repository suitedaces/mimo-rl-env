MatrixOne errors cross several package boundaries where callers add context with fmt.Errorf or combine diagnostics with errors.Join. The current error helpers only recognize a direct *moerr.Error, so a real division-by-zero or similar database error can be misclassified as an unrelated failure after it is wrapped, and ConvertGoError can replace useful context with a new internal error. Bring the moerr package in line with Go's standard error-chain conventions without changing the existing error codes or messages.

IsMoErrCode must keep its current nil and direct-error semantics, then inspect both single-error wrapping and multi-error chains: it returns true when any reachable MatrixOne error has the requested code, and false for nil with a non-Ok code, code mismatches, and chains containing no MatrixOne error. Make *moerr.Error participate in errors.Is matching by error code, so two independently constructed errors with the same code match through an arbitrary wrapper while different codes do not.

ConvertGoError must return an existing MatrixOne error unchanged, including when it is nested inside a fmt.Errorf wrapper or an errors.Join value; preserving that original value also preserves the caller's contextual message and allows IsMoErrCode to classify it. Ordinary non-MatrixOne errors should retain the existing conversion to an internal MatrixOne error, including the original error text. Keep the behavior deterministic and compatible with Go 1.20's standard errors package.
