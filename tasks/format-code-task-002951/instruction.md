I want Go callers to be able to load a Sonobuoy runtime configuration with `config.LoadConfig(pathsToTry ...string) (*config.Config, error)`. The function should read JSON configuration from the filesystem, return a populated `*config.Config`, resolve runtime-derived values before returning, initialize the selected plugins into `LoadedPlugins`, and return an error before any cluster work starts if the configuration file or plugin selection is invalid.

When I call `config.LoadConfig("/tmp/missing.json", "/tmp/good.json")` and `/tmp/missing.json` does not exist but `/tmp/good.json` contains valid Sonobuoy config JSON such as `{"Description":"smoke","UUID":"fixed","Server":{"bindport":8080},"PluginSearchPath":[],"Plugins":[]}`, the function should skip the missing path, load `/tmp/good.json`, and return a config whose `Description == "smoke"`, `UUID == "fixed"`, and `LoadedPlugins` is empty. When I call `config.LoadConfig()` with no paths, it should use `SONOBUOY_CONFIG` if that environment variable is set; otherwise it should try `config.json` and then `/etc/sonobuoy/config.json`.

If the chosen file cannot be read, the returned error should include `open config`; if the file contains malformed JSON, the returned error should identify the config file as an unmarshal failure. After unmarshalling, the function should apply `Config.Resolve()` behavior, so environment overrides like `RESULTS_DIR` are reflected in the returned config and an empty UUID is filled in. If `PluginSearchPath` and `Plugins` select existing plugin definitions, `LoadedPlugins` should contain plugin instances with the selected names; if a selected plugin name is not discovered, the function should return an error like `Configured plugin missing does not exist`. If config validation reports errors, `LoadConfig` should return one error prefixed with `invalid configuration:` rather than returning a partially usable config.
