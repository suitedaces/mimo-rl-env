I want the library function `scriptlint(config: Partial<Config>) -> { issues: JsonMessage[], scripts: PackageScripts }` to assemble the lint rule list from the public configuration keys `strict`, `rules`, and `customRules` before it runs the rules.

With `strict` omitted or `false`, it should run only the minimum built-in rules in this order: `mandatory-test`, `mandatory-start`, `mandatory-dev`, then `no-default-test`. For example, `scriptlint({ packageScripts: {} }).issues.map(i => i.name)` should return `['mandatory-test', 'mandatory-start', 'mandatory-dev']`, and `scriptlint({ packageScripts: { dev: 'echo 1', start: 'echo 1', test: 'echo 1', jest: 'jest' } }).issues.map(i => i.name)` should return `[]` because strict-only rules are not selected.

With `strict: true`, it should run the full built-in standard in the package's documented order. For example, `scriptlint({ strict: true, packageScripts: { dev: 'echo 1', jest: 'jest', start: 'echo 1', test: 'echo 1' } }).issues.map(i => i.name)` should return `['no-aliases', 'uses-allowed-namespace']`.

The `rules` config should be able to disable selected built-in rules by setting their rule name to `false`: `scriptlint({ packageScripts: {}, rules: { 'mandatory-test': false } }).issues.map(i => i.name)` should return `['mandatory-start', 'mandatory-dev']`. Custom rules supplied through `customRules` should only run when their `name` is explicitly set to `true` in `rules`, and enabled custom rules should run before the built-in rules; a config with a custom object rule named `company-scripts` whose `validate` returns `false`, `rules: { 'company-scripts': true }`, and otherwise valid minimum scripts should return `['company-scripts']` as the issue-name list.
