I want `runner.Runner` to provide a stateful flow execution lifecycle with `func (r *Runner) Do(ctx context.Context) bool` and `func (r *Runner) Eval(ctx context.Context) (string, error)`. After I construct a `Runner` with its `State`, `Flow`, `EvalConfig`, optional `Type`, labels, and command line metadata, I should be able to call `Do(ctx)` in a loop; the first call on a fresh `Init` run sets `Created` if needed, moves `Phase` to `Eval`, and returns `true`. The next `Do(ctx)` call should record `LastTry`, evaluate the configured flow, and on success set `Result`, `Phase == Done`, and `Completion`, then return `false`.

`Eval(ctx)` should run the runner's `Flow` through the configured evaluator services, start and flush a run trace using `Cmdline`, log the evaluator summary on success, and return the final rendered result string. If `Type` is nil, the result should be rendered as a `reflow.Fileset` string; otherwise it should be rendered with `values.Sprint` using the supplied `*types.T`. If evaluator execution itself fails, `Eval(ctx)` returns an empty result and that error. If evaluation finishes with a flow error, `Eval(ctx)` returns an empty result and wraps non-Reflow or generic Reflow errors as evaluation errors.

If `Do(ctx)` sees a restartable evaluation error, it should store the recovered error, move to `Retry`, and return `true`; the following retry step increments `AttemptNumber`, waits until at least one minute has elapsed since `LastTry` when necessary, clears `Err`, moves back to `Init`, and allows the run to try again. After three retry attempts, `Do(ctx)` should mark the run `Done`, set `Completion`, and return `false`. For a non-restartable evaluation error, `Do(ctx)` should store the recovered error, mark the run `Done`, set `Completion`, and return `false`. If `Do(ctx)` is called without a scheduler configured, it should log the problem and return `false` without advancing execution.
