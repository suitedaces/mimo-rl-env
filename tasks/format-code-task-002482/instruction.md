I want `discord.app_commands.CommandTree.sync()` to include localized application-command payload fields when a `Translator` has been installed with `await tree.set_translator(translator)`. In a normal bot session, I should be able to construct a `CommandTree(client)`, register slash commands, groups, context menus, parameters, and static `Choice` values that use `locale_str`, then call `await tree.sync()` or `await tree.sync(guild=guild)` and have the bulk-upsert payload sent to Discord include the translated strings.

For each synced command, the sync operation should ask the translator for every `discord.Locale` that has a translatable command name or description and place successful command translations into `name_localizations` and `description_localizations`. The same should work recursively for command groups and subcommands, and for context menu command names. For slash-command parameters, translated display names and descriptions should be included as `name_localizations` and `description_localizations` on the option payload; for static choices on those parameters, translated choice names should be included in each choice payload's `name_localizations`.

If `tree.sync()` is syncing globally, it should send this localized payload through the global bulk-upsert API; if `tree.sync(guild=...)` is syncing a guild, it should send the localized payload through the guild bulk-upsert API with that guild ID. If translation fails, the sync call should raise the translation error before submitting the HTTP bulk-upsert request.
