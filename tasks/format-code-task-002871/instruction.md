I want `CollectionComposer` to expose an accumulated failure sink while I build an Apache Beam pipeline through the composer API. A typical session should work as `result = (CollectionComposer.of(input_pcollection).map('parse', parse_fn).flat_map('expand', expand_fn).filter('keep valid', predicate_fn))`, and the returned composer should have both `result.outputs` for the latest successful output `PCollection` and `result.failures` for a single failure `PCollection` covering the whole chain.

When `CollectionComposer.of(inputs)` is called, the failure side of the composer should start as an empty `PCollection`, so a chain with no mapper, flat-mapper, or predicate exceptions leaves `result.failures` empty while `result.outputs` contains the normal transformed elements. When a `map`, `flat_map`, or `filter` step raises for some elements, those step failures should be collected from that step and merged with any failures already carried by the composer, then the method should return a new `CollectionComposer` with the latest successful outputs and the merged failure collection.

For example, if the input contains `['ok', 'bad-map', 'bad-filter']`, the first `map('map step', mapper)` raises for `bad-map`, and a later `filter('filter step', predicate)` raises for `bad-filter`, then the final `result.outputs` should contain only the elements that made it through the latest successful main output stream, and `result.failures` should contain failures from both `map step` and `filter step`. This accumulation should work across multiple chained calls, including side inputs passed through `*args` or `**kwargs` to `map`, `flat_map`, and `filter`, without requiring users to manually flatten per-step failure collections themselves.
