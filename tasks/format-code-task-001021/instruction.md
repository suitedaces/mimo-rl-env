The Wappalyzer helper is used by Artemis modules as a small batch technology scanner, but its command-line wrapper is currently fragile: input files can contain comments and repeated targets, one bad target can erase useful results for the rest of the batch, and diagnostics can corrupt the JSON consumed by Python callers. Please make the executable a predictable batch boundary while keeping its existing invocation shape (one target-file path) and its result shape (a JSON object mapping each input target to a list of technology names).

Treat the target file as a line-oriented inventory: trim surrounding whitespace, ignore blank lines and lines whose first non-whitespace character is '#', and scan each remaining target at most once even if it is repeated. Preserve the trimmed input string as the result key, including any fragment text. Every retained target must get a non-null JSON array. A target-level request, redirect, or response-body failure must be reported for that target, yield an empty array, and allow the other targets to finish.

Fetching and fingerprinting must be bounded and recoverable. Follow redirects only up to five hops; the sixth hop is a failure, and the original input target remains the key. Retry a transport/request or response-body read failure once immediately, but do not retry a response merely because its HTTP status is non-2xx. A successful response of any status is fingerprinted from its headers and body, while an exhausted retry produces an empty array and a target-identifying diagnostic. Read at most the first 1 MiB of a response body for fingerprinting and discard partial data when a read fails.

The process protocol is part of the public API: successful execution emits exactly one JSON result object on stdout, diagnostics (including per-target failures) go to stderr, and a successful run leaves stderr empty. Invalid invocation (missing the target path, extra arguments, or a path that cannot be opened as a regular file) must fail before making HTTP requests. Keep technology lists compatible with the existing Wappalyzer fingerprint names; their internal ordering is not significant.
