I want MagickWand to support in-memory encoded image blobs as part of the normal stateful wand workflow. On a wand created with `imagick.NewMagickWand()`, the public methods should be `func (mw *MagickWand) ReadImageBlob(blob []byte) error`, `func (mw *MagickWand) PingImageBlob(blob []byte) error`, `func (mw *MagickWand) GetImageBlob() ([]byte, error)`, and `func (mw *MagickWand) GetImagesBlob() ([]byte, error)`.

A typical session should let me read or create an image in one wand, call `GetImageBlob()` to receive the current image encoded as a byte slice, then pass that byte slice to `ReadImageBlob()` on another wand so that the second wand contains the decoded image and can report the same width, height, and format through the existing MagickWand inspection methods. `GetImagesBlob()` should encode the wand's image sequence into one byte slice, using the image format currently selected on the wand; when the selected format cannot store multiple images in one stream, it should still return a valid blob for the first image. If blob encoding fails, or if there is no encodable current image, the blob-returning methods should return `nil` with a non-nil error.

`PingImageBlob()` should accept an encoded byte slice and populate the wand with the available image metadata, such as dimensions and format, without requiring callers to write the bytes to a temporary file. Both `ReadImageBlob([]byte{})` and `PingImageBlob([]byte{})` should reject empty input immediately with a non-nil error whose message is `zero-length blob not permitted`.
