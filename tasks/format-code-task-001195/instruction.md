I want `flux plugin install` to support pinned SHA-256 digest references in addition to plain plugin names and versions. The invocation should be `flux plugin install <name>@sha256:<hex>`, for example `flux plugin install operator@sha256:06e0a38db4fa6bc9f705a577c7e58dc020bfe2618e45488599e5ef7bb62e3a8a`.

When the part after `@` starts with `sha256:`, the command should treat it as a digest rather than as a version string. It should resolve that digest against the plugin's catalog manifest by scanning versions in order and selecting the first platform entry whose checksum exactly matches the digest and whose OS and architecture match the current machine. It should then install the resolved version/platform and exit 0 on success, reporting the installed plugin name and version the same way as other successful plugin installs.

If the manifest has no versions, the command should fail with a non-zero exit and an error like `plugin "operator" has no versions`. If the digest is absent for the current OS/architecture, including when the same digest exists only for another platform, the command should fail with a non-zero exit and an error like `digest "sha256:..." not found for plugin "operator" on linux/amd64`. `flux plugin install --help` should advertise the digest form in the usage string and include an example for installing pinned to a digest.
