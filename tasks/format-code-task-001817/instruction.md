I want the `packem` CLI to use a project-local `.packemrc` YAML file as its build configuration when I run `packem` from a project directory. If `.packemrc` is missing, startup should stop before bundling and print a `NoConfigFoundError` diagnostic that says no `.packemrc` configuration file was detected in this scope.

For a config like `input: src/index.js` and `output: dist/app.js`, `packem` should parse the YAML and continue with an enriched build configuration where the input entry is resolved to an absolute path, the output path is resolved to an absolute path, the output directory is `dist`, and the output file stem is `app`. If `mode` is omitted it should default to `production`, and if `format` is omitted it should default to `iife`.

The `input` key should also accept a list. For example, `input: [src/a.js, ./src/a.js, src/b.js]` should resolve entries to absolute paths and remove duplicate entries after resolution while preserving the remaining entries for the build. If `output` is omitted, `packem` should use a `build` directory under the current working directory, treat that as the output directory, and use an empty output file stem. Before the rest of bundling runs, the resolved output directory should exist on disk.
