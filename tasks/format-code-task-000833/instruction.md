I want to use `SQLAInterface(model_class, session=None)` as a stateful data-access object for SQLAlchemy model mutations. It should provide `add(item: Model, commit: bool = True) -> None`, `edit(item: Model, commit: bool = True) -> None`, `delete(item: Model, commit: bool = True) -> None`, and `delete_all(items: list[Model]) -> None`.

For a normal session, `interface.add(book)` should add the model instance and commit immediately, so a later query in the same database can find the new row. If I call `interface.add(book, commit=False)`, the item should be added to the session without committing, so I can commit the transaction myself later. `interface.edit(book)` should merge the changed model instance and commit immediately, while `interface.edit(book, commit=False)` should merge without committing.

`interface.delete(book)` should remove that model instance from the session and commit immediately, and `interface.delete(book, commit=False)` should delete without committing. When the model has file or image columns with stored filenames, deleting one item should also delete those managed files before removing the row. `interface.delete_all([book1, book2])` should delete every provided item, delete any managed files or images for each one, and commit once after the loop.

If SQLAlchemy raises an error during `add`, the interface should roll back the session and re-raise the original SQLAlchemy exception. If SQLAlchemy raises during `edit`, `delete`, or `delete_all`, the interface should roll back and raise `DatabaseException` with the original SQLAlchemy exception available as the cause.
