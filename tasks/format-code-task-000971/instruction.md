Version discovery is used both by the release tooling and by installed PyEMMA trees, so a damaged Git checkout must not turn importing or building the project into an unrelated traceback. Harden the existing Versioneer Git path while preserving its current version strings and metadata for healthy repositories. The build-time `versioneer` module and the runtime `pyemma/_version.py` implementation are generated counterparts and must agree.

When `git describe --tags --dirty --always --long` identifies a tag, retain the existing PEP 440 rendering inputs: strip the configured `v` prefix, preserve the commit distance, short revision, dirty flag, and full revision id. For an untagged repository, parse the `git rev-list HEAD --count` result when it is a valid decimal count. If that command returns no output or non-numeric output, report a structured version-discovery error instead of raising from integer conversion; the result must render as `unknown` and retain a useful non-empty error explanation.

The public `get_versions()` entry points must also be defensive around unexpected VCS-provider failures. If the keyword and version-file fallbacks are unavailable and the VCS provider raises, return the documented structured `0+unknown` result with an error value rather than leaking the exception. Healthy tagged and untagged paths must remain backward compatible, and the two copies must expose equivalent behavior across all of these cases.
