I want the repository's xtask binary to provide a `generate` subcommand, invoked as `cargo xtask generate [chips...]`. With no chip arguments it should process every supported chip; with one or more chip names such as `esp32c3` or `esp32 esp32s2 esp32s3`, it should process only those packages. Chip names should be validated by the CLI, so an unsupported chip name fails during argument parsing with a non-zero exit code before any generation work starts.

For each requested chip, the command should first apply that chip's SVD patch set, then replace the chip's generated `src/` tree. If the old `src/` directory cannot be removed, the command should warn and continue generation. It should read `<chip>/svd/<chip>.svd`, choose svd2rust's RISC-V output when the chip's configured build target contains `riscv` and Xtensa LX output otherwise, and generate with the repository policy: debug impls behind `impl-register-debug`, defmt support behind `defmt`, interrupt link section `.rwtext.interrupt`, legacy identifier formatting with constant-case enum type/read names and PascalCase enum values, maximum cluster sizing, and no top-level peripherals struct except for `esp32s2-ulp`, `esp32s3-ulp`, and `esp32c6-lp`.

The command should write the rendered Rust crate into the chip package, include the repository HTML logo attribute in the crate docs, translate generated `doc_auto_cfg` attributes to `doc_cfg`, write `device.x`, and write the svd2rust `build.rs` for the same configuration. It should then split the generated Rust into the package `src/` directory with `form`, remove the temporary `lib.rs`, and run `cargo fmt` in that chip package, retrying transient formatter failures a few times. A successful generation run exits 0 after all requested chips finish; if SVD patching, SVD reading, rendering, writing generated files, splitting the source tree, or formatting fails for any requested chip, `generate` exits non-zero instead of reporting success. The generated files are the observable output, so normal successful runs do not need to print a data stream to stdout.
