I want the library to provide a stateful `ListBindAdapter` class for RecyclerView lists whose view types are registered as contiguous binder sections. A user should be able to create `new ListBindAdapter()`, call `addBinder(DataBinder binder)`, `addAllBinder(List<DataBinder> dataSet)`, or `addAllBinder(DataBinder... dataSet)`, and then have the adapter behave as if those binders' rows were concatenated in registration order. `getBinderList()` should expose the current ordered binder list.

For example, after registering three binders with item counts 1, 2, and 3, `getItemCount()` should return 6. For global positions 0, 1, 2, 3, 4, and 5, `getItemViewType(position)` should return 0, 1, 1, 2, 2, and 2 respectively, and `getDataBinder(1)` should return the second registered binder. With the same binders, `getBinderPosition(0)`, `getBinderPosition(1)`, `getBinderPosition(2)`, and `getBinderPosition(4)` should return 0, 0, 1, and 1 respectively, so binding receives the local position inside the selected binder section. `getPosition(secondBinder, 0)` should return 1, `getPosition(secondBinder, 1)` should return 2, and `getPosition(thirdBinder, 2)` should return 5. Calling `getItemViewType()` with a position beyond all registered rows should raise `IllegalArgumentException`, and calling `getPosition()` with a binder that is not registered in this adapter should raise `IllegalStateException`.

The binder range notification methods should translate binder-local starts into global RecyclerView positions while preserving the requested range size: `notifyBinderItemRangeChanged(secondBinder, 1, 2)` should notify a change starting at global position 2 with count 2, `notifyBinderItemRangeInserted(thirdBinder, 0, 3)` should notify an insert starting at global position 3 with count 3, and `notifyBinderItemRangeRemoved(firstBinder, 0, 1)` should notify a removal starting at global position 0 with count 1. I also want an `EnumListBindAdapter<E extends Enum<E>>` convenience base class for the same ordered-section strategy, where `getDataBinder(E e)` returns the binder at `e.ordinal()`, so an enum value like `SECOND` maps to the binder registered at index 1.
