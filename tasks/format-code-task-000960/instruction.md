Time-dependent geometry is currently difficult to use safely: the provider assumes callers pass time keys in insertion order, has no way to choose a discontinuous schedule, and malformed schedules can fail with incidental exceptions or silently become a static configuration. Add an explicit interpolation policy to the public geometry configuration and provider APIs while preserving existing callers.

The public `Geometry.from_dict` configuration must accept `geometry_interpolation_mode`, defaulting to `piecewise_linear`, with the values `piecewise_linear` and `step` (case-insensitive strings and the corresponding `InterpolationMode` enum are accepted where the provider API is called directly). For a time-dependent `geometry_configs` mapping, normalize slices by ascending finite time before constructing the provider without mutating the caller's mapping. Piecewise-linear mode interpolates every numeric geometry field between neighboring slices; step mode holds the slice at the greatest configured time less than or equal to the requested time. Requests outside the schedule use the first or last slice respectively.

Reject an empty schedule, non-finite time keys, or an unknown interpolation policy with `ValueError`. A time-dependent schedule must still reject slices with different geometry types or meshes, and an empty `geometry_configs` mapping must not silently fall back to a static default. Existing static geometry configuration and the default linear interpolation behavior must remain compatible.
