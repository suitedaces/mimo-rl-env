I want `mycoder-agent` to support OpenAI-compatible chat completion providers through its LLM provider API. A user should be able to construct `new OpenAIProvider(model: string, options?: { apiKey?: string; baseUrl?: string; organization?: string; contextWindow?: number })` and then call `await provider.generateText(options)` repeatedly on that instance, with each call using the configured model, API key, optional base URL, and the normalized `GenerateOptions` shape.

`createProvider('openai', model?, options?)` should also select this provider, defaulting to model `gpt-4o-2024-05-13`, `OPENAI_API_KEY` as the documented key name, and provider metadata where `name === 'openai'` and `provider === 'openai.chat'`. `createProvider('xai', model?, options?)` should use the same OpenAI-compatible chat implementation with default model `grok-2-latest`, default base URL `https://api.x.ai/v1`, and documented key name `XAI_API_KEY`.

When I call `generateText` with normalized `system`, `user`, and `assistant` messages, it should send OpenAI chat messages with the same roles and content. When the history includes a normalized `tool_use` message, it should send an assistant message with an OpenAI `tool_calls` entry containing the same tool call id, function name, and JSON argument string; when the history includes a normalized `tool_result`, it should send an OpenAI `tool` message with the same content and `tool_call_id`.

When `functions` are supplied, `generateText` should pass them as OpenAI chat `tools` of type `function`, preserving each function name, description, and JSON schema parameters. Generation options should map to OpenAI request fields: `temperature`, `maxTokens` as `max_tokens`, `stopSequences` as `stop`, `topP` as `top_p`, `presencePenalty`, `frequencyPenalty`, and `responseFormat: 'json_object'` as an OpenAI JSON-object response format.

For a response whose first choice contains assistant text `This is a test response`, one function tool call with id `tool-call-1`, name `testFunction`, arguments `{"arg1":"value1"}`, and usage `{ prompt_tokens: 10, completion_tokens: 20 }`, `generateText` should return normalized text `This is a test response`, one normalized tool call with that id/name/content, `tokenUsage.input === 10`, `tokenUsage.output === 20`, and `totalTokens === 30`. It should report known context windows for OpenAI model names such as `gpt-4` as `8192` and `gpt-4o` as `128000`, or use `options.contextWindow` for an unknown model when provided.

If the OpenAI-compatible API call fails, `generateText` should reject with an `Error` whose message starts with `Error calling OpenAI API:` followed by the underlying error message. Separate `OpenAIProvider` instances should keep their own model and client configuration so calls made through one instance do not change another instance's model or base URL.
