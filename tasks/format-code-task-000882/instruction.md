I want an exported `Stats` class for envoy-curses that I can use as a stateful in-memory model for Envoy admin `/stats` output. I should be able to construct it with `new Stats({statsURI, log, bufferSize, pollingInterval})`; `statsURI` is required and missing it should throw `Error('Stats ctor: statsURI is required')`, while `bufferSize` defaults to 20 and `pollingInterval` defaults to 1000 milliseconds.

The public methods should be `start()`, `pollStats()`, `getStatNames(statsPrefix)`, `getStatsTable(match)`, `getCurrentStatValue(statName)`, `getSeries(statName)`, and `getSeriesAsGauge(statName)`. Calling `pollStats()` should fetch `statsURI`, read the response as text, parse colon-delimited lines like `server.uptime: 10` and `cluster.demo.upstream_rq_total: 7`, store each stat's numeric value in a circular sample buffer, record the sample timestamp formatted as `HH:MM:ss`, and emit an `updated` event after the model is refreshed. Calling `start()` should perform one immediate poll and then continue polling on the configured interval.

For a concrete session with `bufferSize: 4`, after a poll whose body contains `server.uptime: 10\nserver.memory_allocated: 100\ncluster.demo.upstream_rq_total: 7`, `getCurrentStatValue('server.uptime')` should return `10`, and `getStatsTable(/^server\./)` should return `[['Stat Name', 'Stat Value'], ['server.uptime', '10'], ['server.memory_allocated', '100']]`. After later polls where `cluster.demo.upstream_rq_total` is `12`, then `20`, then `30`, `getSeries('cluster.demo.upstream_rq_total')` should return an object with timestamp strings in `x` and counter deltas `[5, 8]` in `y` for the stored samples the series traversal includes. For gauge stats, if `server.memory_allocated` is sampled as `100`, then `130`, then `125`, then `140`, `getSeriesAsGauge('server.memory_allocated')` should return the sampled gauge values `[100, 130, 125]` in `y` with matching timestamp strings in `x`.

Filtering names should work from the stored stats: `getStatNames('cluster.demo.')` should return a set containing the final component of matching dotted names, such as `upstream_rq_total`. Unknown stats should not throw from lookup methods: `getCurrentStatValue('missing.stat')` should log an unknown-series error and return `err - missing.stat`, while `getSeries('missing.stat')` and `getSeriesAsGauge('missing.stat')` should log the same kind of error and return `null`. Failed fetches should be caught and logged as `Error polling stats: <error>` without emitting an `updated` event.
