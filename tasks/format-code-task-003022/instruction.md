I want nvitop to expose a one-shot `take_snapshots(devices: Device | Iterable[Device] | None = None, *, gpu_processes: bool | GpuProcess | Iterable[GpuProcess] | None = None) -> SnapshotResult` function from both `nvitop` and `nvitop.api`. It should return a named tuple with `.devices` and `.gpu_processes`, where each item is a serializable snapshot object rather than a live device or process object. When I call `take_snapshots()` on a machine where `Device.all()` returns physical GPUs and one physical GPU has MIG children, the device snapshot list should include each physical GPU plus that GPU's MIG devices in discovery order, while GPU process collection should come from the leaf devices: MIG children when present, otherwise the physical GPU. When I call `take_snapshots([cuda0, cuda1])`, it should snapshot exactly those two requested devices in order and collect GPU process snapshots from those devices. When I call `take_snapshots(gpu_processes=False)`, it should snapshot all physical devices from `Device.all()` and return an empty `.gpu_processes` list. When I pass explicit GPU processes, such as `take_snapshots(gpu_processes=[p0_on_cuda0, p1_on_cuda0, p2_on_cuda1])`, it should snapshot the unique devices used by those processes in first-seen order and return process snapshots for exactly the provided processes. Passing a single `Device` should behave like a one-item device list, and passing a single `GpuProcess` should behave like a one-item process list. If both `devices` and explicit `gpu_processes` are provided, the device snapshots should follow the requested `devices` argument while the process snapshots should still be limited to the explicit process argument. Process snapshots should be taken in failsafe mode so that processes disappearing during collection produce fallback snapshot values instead of aborting the whole call. Invalid non-iterable values that are neither a `Device` for `devices` nor a `GpuProcess`/boolean for `gpu_processes` should raise `TypeError`.
