I want an `AnchorAugHead(anchor_generator, train_cfg=None, test_cfg=None)` dense head module that can be constructed directly and selected through the model head registry as `AnchorAugHead`. `anchor_generator` should be a standard anchor-generator config, and the head should expose `init_weights(pretrained=None)` as a successful no-op plus `forward_train(x, img_metas, gt_bboxes, proposal_cfg=None)` for proposal generation.

When `forward_train` is called, it should build grid anchors over the FPN feature maps in `x`, optionally restrict generation to `proposal_cfg.generate_from_single_level`, compare every anchor against the pasted ground-truth boxes in `gt_bboxes`, and return one proposal tensor per image. Anchors whose IoU with that image's pasted box is greater than `proposal_cfg.iou_thr` should be kept; if an image has no anchor above the threshold, the method should fall back to the top `proposal_cfg.nms_pre` anchors sorted by IoU for that image. The method should assign per-proposal scores, run batched NMS independently per image using `proposal_cfg.nms_thr`, and return tensors whose first four columns are proposal box coordinates and whose fifth column is the NMS score.

For example, with one image, one 1x1 feature map, an anchor generator using stride 16, scale 1, and ratio 1.0, and a pasted box `[-8, -8, 8, 8]`, `forward_train` should return a single proposal for that image with coordinates `[-8, -8, 8, 8]` when `iou_thr` is below 1.0. With a 1x2 feature map and a tiny pasted box near the first anchor, if `iou_thr` is high enough that no anchor qualifies and `nms_pre=1`, the returned proposal should be the single highest-IoU anchor for that image rather than an empty tensor. Multiple images in the same batch should be processed independently so NMS for one image never suppresses proposals from another image.
