Harden the public `helper/fields` configuration-field API so validation is safe, complete, and consistent for callers that build schemas dynamically. `FieldData.Validate` must inspect the schema as well as the raw map: every required field that is absent or has its type's empty value is invalid, values must be convertible to their declared primitive type, raw keys not present in the schema must be rejected, and an unsupported `FieldType` declaration must be rejected even when that field has no raw value. Validation must report these problems as an error and must never panic when the declared type is a map or array. Empty maps and arrays are valid when optional, while non-empty values of all supported types remain valid.

Preserve the getter contract while making validation stricter. `FieldData.Get` returns an explicitly supplied value, including false, zero, an empty string, or an empty collection, rather than replacing it with a schema default; an unset known field returns its default or type zero, and an unknown field still follows the documented panic behavior. `GetOk` must distinguish an explicitly supplied zero/false value from an unset known field and from an unknown field. `GetOkErr` must distinguish an absent known field (nil value, false, nil error), a present value that fails conversion (presence true plus an error), and an unknown field (an error and presence false). Keep the existing exported types, method signatures, and successful conversions compatible with current callers.
