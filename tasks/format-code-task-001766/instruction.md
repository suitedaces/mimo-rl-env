I need the embedded Go API to let callers inspect the remaining expiration time for keys stored in a selected `*ledis.DB`. After a caller obtains a DB with the existing `ledis.Open(cfg *config.Config) (*ledis.Ledis, error)` and `(*Ledis).Select(index int) (*ledis.DB, error)` flow, the DB should expose these lookup methods: `TTL(key []byte) (int64, error)` for string keys, `LTTL(key []byte) (int64, error)` for lists, `HTTL(key []byte) (int64, error)` for hashes, `STTL(key []byte) (int64, error)` for sets, and `ZTTL(key []byte) (int64, error)` for sorted sets.

For each data type, if a key has no expiration metadata or does not exist, the matching TTL method should return `-1, nil`. If I create a key, attach a 60 second expiration using that data type's existing expire method, and immediately call the matching TTL method, it should return a positive `int64` no greater than 60 and no error. If I call the matching persist method and then call the TTL method again, it should return `-1, nil`. If the stored deadline has already passed by the time the TTL method reads it, it should report `-1` rather than a zero or negative remaining duration.

Invalid keys should be rejected consistently across all five lookup methods: an empty key should return `-1` plus a non-nil error whose message is `invalid key size`. These methods should be read-only observations: calling them should not create a key, delete a key, extend or shorten an expiration, or otherwise change the database state.
