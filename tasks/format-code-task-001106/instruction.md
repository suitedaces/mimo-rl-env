The optional wrappers are intended to model a value that may be absent, but their current lifecycle is unsafe and inconsistent: calling Get on a zero-value wrapper can panic, Set does not reliably change the wrapper because it is a value-receiver mutation, and generated wrappers do not offer a way to clear a value after it has been set. Make the public lifecycle consistent for every checked-in primitive wrapper (including Error) and for wrappers emitted by cmd/optional.
    
A zero-value wrapper must be absent. Calling Get while absent must return that type's zero value and a non-nil error whose message is exactly "value not present"; it must never dereference or panic. Set must persistently mark the addressable wrapper present and Get must then return exactly the value supplied, including false, empty strings, and other zero values, with a nil error. Present must track that state.
    
Add a public Unset operation to every wrapper. Unset must clear presence, be safe to call repeatedly, and restore the absent behavior of Get, OrElse, and If: OrElse returns its fallback and If does not invoke its callback while absent. If invokes its callback when a value is present. Existing constructors and the behavior of already-present values must remain compatible.
    
These state transitions (safe absent Get, persistent Set/Get, Present, and Unset) must be emitted by the generator for a user-defined type, so a newly generated exported wrapper can be used through that lifecycle without hand edits. Keep the existing public type and constructor naming conventions intact.
