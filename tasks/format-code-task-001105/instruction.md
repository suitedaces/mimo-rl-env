The unwanted-pattern checker is used both directly on individual files and from repository-wide quality checks. Its current command-line entry point only opens the literal path arguments, even though the Makefile contract passes directory roots and documents extension and exclusion filters. Extend the public CLI so each supplied path may be a file or a directory: directories must be traversed recursively, while files are checked directly. Add `--included-file-extensions` (and its short form `-ife`) as a comma-separated filter; matching is case-insensitive, whitespace around entries is ignored, and entries may be written with or without a leading dot. When the option is omitted, retain the existing behavior of checking every selected file. Add `--excluded-file-paths` (and `-efp`) as a comma-separated list of file or directory paths to skip; whitespace is ignored, exclusions apply to descendants of an excluded directory, and an excluded file is skipped. A file selected more than once through overlapping roots or explicit arguments must be checked once, with results emitted in deterministic lexical path order. Preserve the existing validation-type choices, custom `--format` substitution, exit-status convention (nonzero when any finding is emitted, zero otherwise), and direct single-file use. Missing input paths must fail cleanly with a nonzero status and an explanatory `Source path does not exist: <path>` diagnostic rather than a traceback.
