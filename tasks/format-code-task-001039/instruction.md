Channel manifests use ordered lists of version rules for selecting cloud images and for describing kops/Kubernetes version guidance. As channels evolve, a broad fallback entry can appear before a version-specific override, and overlapping overrides can be appended later. The current lookup helpers stop at the first match, so the result depends on incidental ordering and malformed entries can also make selection unsafe.

Update the public channel lookup behavior so `Channel.FindImage`, `FindKopsVersionSpec`, and `FindKubernetesVersionSpec` evaluate the complete candidate list. A non-empty `KubernetesVersion` or `Range` is an explicit rule: parse it with the repository's semver range support and consider it only when valid and matching the requested version. An empty range is a fallback rule that matches every version. Explicit matching rules always take precedence over fallback rules, even when the fallback appears later. When several matching rules have the same specificity (all explicit or all fallback), the rule declared later wins. Invalid ranges are ignored rather than returned or treated as matches.

`FindImage` must continue filtering by the requested cloud provider before selecting a rule, ignore nil image entries, and return nil when no usable image matches. The two version-spec helpers must return nil when no valid rule matches. Keep the existing public lookup signatures.
