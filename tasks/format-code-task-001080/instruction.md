The model YAML/dict persistence API needs to be reliable for workflows that repeatedly serialize model collections and restore shared fit parameters. At present, serializing a collection can mutate live Parameter objects and produce different link identifiers on each call, while malformed or inconsistent link metadata can be silently accepted during loading. This makes generated configuration hard to diff and can turn a typo into a model whose parameters no longer have the intended coupling.

Make Models.to_dict() and Models.to_yaml() deterministic and side-effect free. Repeated calls on the same collection, and calls on equivalent freshly constructed collections, must produce identical serialized content, including stable link labels for each shared-parameter group. Serialization must describe only actual sharing: parameters that are not shared must omit link metadata, and distinct shared groups must receive distinct labels even when their parameter names are the same. Existing serialization for collections without shared parameters must remain compatible.

Models.from_dict() and Models.from_yaml() must not mutate the caller's dictionary or any nested link metadata while loading. Valid documents must recreate the public parameter-sharing identity: every occurrence with the same link label is the same Parameter object, occurrences with different labels or no label remain independent, and changing a restored shared parameter is visible through all members of its group but not through other groups. A link that names no parameter in the document, or a link group whose occurrences disagree on serialized parameter values or units, must be rejected with ValueError instead of silently creating an inconsistent collection.
