I want the job transport factory to support local development without a Redis server. When I call `const jobs = require("./lib/transports/redis")({})` or pass settings that do not include `redisHost`, it should return a stateful local job transport object instead of trying to connect to Redis.

The local transport should persist its data in a `.jobs` JSON file at the project root, creating that file with `{}` when it does not exist. It should expose `addJob(settings)`, `getJobList(cb)`, and `getJob(cb)` so jobs are stored FIFO: after `addJob({ id: "a", caption: "one" })` and `addJob({ id: "b" })`, `getJobList(cb)` should call back with `null` for the error and an array containing those two objects in order; the first `getJob(cb)` should return `{ id: "a", caption: "one" }`, the second should return `{ id: "b" }`, and a later call when the queue is empty should return `null` for the job.

The same object should also expose `setField(key, field, value)`, `getHash(key, cb)`, and `incrementField(key, field)` for job status fields. For example, after `setField("video-1", "status", "frames")`, `getHash("video-1", cb)` should call back with `{ status: "frames" }`; an unknown key should return `null`. Calling `incrementField("video-1", "framesComplete")` twice should make `getHash("video-1", cb)` include `framesComplete: 2`, starting from zero when the field is missing.

For the local transport lifecycle, `quit()` should be a no-op that does not throw, `cleanJobs(cb)` should delete the `.jobs` file and report completion through its callback, and `workerDelay()` should return a number from 0 up to but not including 1000 so local workers can stagger their polling.
