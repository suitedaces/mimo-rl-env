I want an `EcosystemsService` vulnerability provider that I can use as a stateful client object: `EcosystemsService(cache_dir: Path | None = None, timeout: int | None = None)`, with a public `query(spec: Dependency) -> tuple[Dependency, list[VulnerabilityResult]]` method. Constructing it should create an HTTP session that uses pip-audit's cache directory handling without relying on pip's cache, and the `timeout` value should be passed through to provider requests.

When I call `query()` with `SkippedDependency(name="foo", skip_reason="skip-reason")`, it should return that same dependency with an empty vulnerability list and should not contact the network. When I call it with `ResolvedDependency("Foo_Bar", Version("1.0.0"))`, it should request Ecosyste.ms advisories from `https://advisories.ecosyste.ms/api/v1/advisories` using query parameters `ecosystem=pypi` and `package_name=foo-bar`, then normalize the JSON response into `VulnerabilityResult` objects.

For an empty Ecosyste.ms response, `query()` should return the original resolved dependency and an empty list. For an advisory whose identifiers are `['GHSA-x', 'PYSEC-2024-1', 'CVE-2024-1']`, title is `"first line\nsecond line"`, `withdrawn_at` is null, and whose PyPI package records include `vulnerable_version_range: "< 1.0.1"` with `first_patched_version: "1.0.1"`, querying version `1.0.0` should return one vulnerability with primary id `PYSEC-2024-1`, the other identifiers as aliases, description `"first line second line"`, and fix versions `[Version("1.0.1")]`. If the title is empty or missing, the description should fall back to the advisory description, and if both are empty it should be `"N/A"`.

The provider should ignore advisories marked withdrawn, ignore advisories for non-`pypi` ecosystems or different package names, and ignore advisories whose vulnerable version range does not contain the requested version. Vulnerable version ranges from Ecosyste.ms may use a single `=` for exact matches, and the service should treat those as valid PEP 440 exact-version specifiers. If the HTTP request times out while connecting, `query()` should raise `ConnectionError` with the message `Could not connect to ESMS' vulnerability feed`; if the provider returns another HTTP error status, it should raise `ServiceError`.
