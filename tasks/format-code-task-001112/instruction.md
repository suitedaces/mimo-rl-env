Make `jax/tools/pgo_nsys_converter.py` safe to use in local and automated profile-processing workflows. Today the tool assumes that every conversion starts from an Nsys profile, the advertised `--post_process` mode has no effect, output is opened before the input has been validated, and cleanup uses directory-wide globs. A failed or concurrent conversion can therefore destroy a previous result or unrelated profiling files.

The CLI must accept exactly one input source: the existing `--profile_path PATH` option for an Nsys profile, or a new `--csv_profile PATH` option for an already exported `nvtxkernsum` CSV. Supplying both or neither is an argument error that names both alternatives. CSV mode must not require or invoke `nsys`. Profile mode must locate `nsys`, run its `stats` command for the `nvtxkernsum` report using the supplied profile, and convert the generated report. If `nsys` is unavailable or exits unsuccessfully, the converter must exit nonzero and identify `nsys` in the diagnostic.

A report CSV must contain the `NVTX Range` and `Avg (ns)` columns. A convertible row is one whose NVTX range contains `hlo_op=<name>#`; the name is the text after `hlo_op=` through the next `#`. Rows without that complete marker are ignored, even if their timing cell is not numeric. For each convertible row, require `Avg (ns)` to be a finite, non-negative number, convert nanoseconds to microseconds by dividing by 1000, and normally emit entries in CSV order without removing duplicates. Each output entry remains protobuf text in the form `costs { name: "<name>" cost_us: <value> }`; names containing quotes or backslashes must be encoded as valid protobuf string literals.

When `--post_process` is absent, every convertible row is retained. When it is present, emit one entry per distinct HLO name using that name's minimum observed cost, with names ordered by their first appearance in the CSV. Missing required columns and invalid timing values are conversion errors; diagnostics must name the missing column or, for a bad timing value, identify `Avg (ns)` and the one-based CSV file row (including the header as row 1).

Write `--pgle_output_path` atomically: no validation, CSV parsing, or `nsys` failure may truncate or replace an existing output. After a successful profile conversion, delete only the report CSV and database artifacts generated by that invocation, never unrelated `.csv` or `.sqlite` files in either directory. Add `--keep_intermediates` to retain those generated report and database artifacts instead.
