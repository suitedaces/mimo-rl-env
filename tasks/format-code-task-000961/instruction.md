The agent's log streamer receives the complete process-output snapshot repeatedly while a job runs. Make this public component safe for that lifecycle: malformed worker settings and repeated startup must be rejected instead of creating a streamer that can never drain, and a snapshot that goes backwards must be reported as an error rather than causing a slice panic. For valid settings, Start must initialize the streamer, and a second Start call must be rejected. Process must treat its argument as a cumulative byte snapshot: an empty or unchanged snapshot produces no chunk, while a longer snapshot emits only the newly appended suffix, split into chunks no larger than MaxChunkSizeBytes. Each emitted LogStreamerChunk must contain the exact byte data, a 1-based strictly increasing Order, an Offset equal to the number of bytes emitted before that chunk, and Size equal to len(Data). A shrinking snapshot must not emit additional data. Stop must wait until every queued callback has run, including callbacks that return errors; a callback error increments FailedChunks and must not prevent later chunks from being processed. Keep the existing exported constructor, methods, and chunk types compatible so JobRunner callers continue to use the streamer without special coordination.
