I want `logstream.New(ctx context.Context, wg *sync.WaitGroup, waker waker.Waker, pathname string, oneShot logstream.OneShotMode) (logstream.LogStream, error)` to support datagram socket log sources when `pathname` uses `udp://host:port` or `unixgram:///path`. The returned `LogStream` should listen on the requested datagram socket and expose received log events through `Lines() <-chan *logline.LogLine`.

For example, after creating a stream with `pathname == "udp://[::]:12345"` and `OneShotDisabled`, sending the datagram bytes `"alpha\n"` to `[::]:12345` should produce a `LogLine` whose `Filename` is `"udp://[::]:12345"` and whose `Line` is `"alpha"`. Creating a stream with `pathname == "unixgram:///tmp/mtail.sock"` should behave the same way for a Unix datagram socket, with `Filename` set to `"unixgram:///tmp/mtail.sock"`.

If the datagram address is empty, such as `udp://` or `unixgram://`, `New` should return `ErrEmptySocketAddress` instead of starting a stream. Canceling the context should interrupt a blocked datagram read, close the underlying socket, wait for the stream goroutine to finish through the supplied wait group, flush any partial line already buffered, and then close the `Lines()` channel. In `OneShotEnabled` mode, a zero-length datagram read should end the stream after any previously received lines have been emitted.
