I want the Go client to provide a stateful aliases batching API for Elasticsearch's `_aliases` endpoint. The entry points should be `func (c *Client) Alias() *AliasService` and `func NewAliasService(client *Client) *AliasService`, and callers should be able to build a request with fluent methods before executing it with `Do(ctx context.Context) (*AliasResult, error)`.

The service should support `Pretty(bool)`, `Human(bool)`, `ErrorTrace(bool)`, `FilterPath(...string)`, `Header(string, string)`, and `Headers(http.Header)` so the final `POST /_aliases` request carries the matching query parameters and request headers. It should support action accumulation with `Add(indexName string, aliasName string)`, `AddWithFilter(indexName string, aliasName string, filter Query)`, `Remove(indexName string, aliasName string)`, and `Action(...AliasAction)`, where every call appends to the same pending batch and `Do` sends `{"actions":[...]}` in one request.

I also need public action builders for direct batching: `NewAliasAddAction(alias string) *AliasAddAction`, `NewAliasRemoveAction(alias string) *AliasRemoveAction`, and `NewAliasRemoveIndexAction(index string) *AliasRemoveIndexAction`. An add action should expose `Index(...string)`, `Filter(Query)`, `Routing(string)`, `IndexRouting(string)`, `SearchRouting(...string)`, `IsWriteIndex(bool)`, `Validate() error`, and `Source() (interface{}, error)`. For `NewAliasAddAction("alias1").Index("index1")`, `Source` should marshal as `{"add":{"alias":"alias1","index":"index1"}}`; for two indices it should use `indices`, and `SearchRouting("r1", "r2")` should become `"search_routing":"r1,r2"`. If an add action has a filter such as `NewTermQuery("user", "olivere")`, the action source should include that query under `filter`.

A remove action should expose `Index(...string)`, `Validate() error`, and `Source() (interface{}, error)`. For `NewAliasRemoveAction("alias1").Index("index1")`, `Source` should marshal as `{"remove":{"alias":"alias1","index":"index1"}}`; with multiple indices it should use an `indices` array. A remove-index action should expose `Validate() error` and `Source() (interface{}, error)`, and `NewAliasRemoveIndexAction("index1").Source()` should marshal as `{"remove_index":{"index":"index1"}}`.

Validation should reject missing aliases and missing indices before any HTTP request is sent, returning errors like `missing required fields: [Alias]`, `missing required fields: [Index]`, or `missing required field: index` for remove-index. An add action with `IsWriteIndex` set and more than one target index should return an error explaining that more than one target index was specified with the `is_write_index` flag. When Elasticsearch returns a successful response, `Do` should decode `acknowledged`, `shards_acknowledged`, and optional `index` fields into `AliasResult`.
