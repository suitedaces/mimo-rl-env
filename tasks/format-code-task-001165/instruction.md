The RPC helper receives pending blocks and pending logs through two ingress paths: the mining/txpool subscriptions and the remote eth-backend event stream. The txpool handlers already define the intended public behavior, but the remote PENDING_LOGS and PENDING_BLOCK events are currently ignored, and malformed RLP can leak zero values to subscribers. Bring both paths to one predictable contract.

For a non-empty, valid RLP payload, a PENDING_LOGS event must decode to `types.Logs` and be delivered to every active `SubscribePendingLogs` subscriber. A PENDING_BLOCK payload must decode to `*types.Block`, become the value returned by `LastPendingBlock`, and be delivered to every active `SubscribePendingBlock` subscriber. The same delivery and state behavior must continue for valid txpool `OnPendingLogsReply` and `OnPendingBlockReply` messages.

An empty payload, malformed RLP, or nil reply is not an event: ignore it without publishing anything, replacing an earlier pending block, or panicking. In particular, a malformed block must leave the last valid block observable through `LastPendingBlock`. Keep the existing public subscription APIs and their observable delivery semantics unchanged.
