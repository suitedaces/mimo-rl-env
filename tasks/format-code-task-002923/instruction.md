I want the stateful `Zotero` client to provide pagination helpers for multi-result read API calls. After I create a `Zotero` instance and call a read method such as `top(limit=1)`, I should be able to call `follow()` with no arguments to fetch and return the page referenced by the response's `Link: rel="next"` header; repeated `follow()` calls should advance through later pages using the updated link state. In local API mode, `follow()` should handle next-page links from `http://localhost:23119/api/...` without producing a duplicated `/api` path.

I also need `iterfollow()` to return a generator that yields each successive `follow()` result while a next link exists, and then stops. `makeiter(api_call_result)` should require link state from a paginated API call; if no self link is available, it should raise `RuntimeError` with a clear message. When link state is present, `makeiter(...)` should reset the next link to the stored self link, preserve query parameters such as `limit` and `locale`, and return the `iterfollow()` generator so the first iteration fetches the first page again.

For eager retrieval, `everything(query)` should take the first page returned by a multi-result read call, fetch all remaining linked pages with `follow()`, and return a single combined result. For list responses, it should extend a list; for bibliography/feed-style responses with an `entries` collection, it should return a copied object whose `entries` contains entries from every page. Finally, `all_top(**kwargs)` should be a convenience method equivalent to fetching `top(**kwargs)` and passing that first page into `everything()`, so `zot.all_top(limit=2)` returns all top-level items across every page rather than just the first two.
