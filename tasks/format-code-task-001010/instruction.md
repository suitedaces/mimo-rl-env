The `bgp_facts` Ansible module collects neighbor details from `vtysh -c "show ip bgp neighbors"` and publishes them under `ansible_facts.bgp_neighbors`. The current parser assumes every neighbor address is dotted-decimal, so IPv6 peers can overwrite an IPv4 record or disappear entirely; operators then receive an incomplete and misleading inventory even though vtysh reported all peers. Update the module so a successful collection represents every neighbor reported by vtysh, regardless of address family.\n\nEach `BGP neighbor is ...` record must be keyed by the exact address text shown in the header, keeping compressed and expanded IPv6 spellings distinct. IPv4 behavior must remain intact. For IPv6 records, populate the same documented scalar fields as for IPv4: remote and local AS numbers, description, lower-case session state, minimum advertisement interval, accepted-prefix count, established and dropped connection counts, and remote router ID. Preserve the values associated with the record they came from.\n\nThe per-neighbor `message statistics` mapping must likewise be retained for both families. Every reported category (including names containing spaces such as `Route Refresh`) carries integer `sent` and `rcvd` values, and zeroes are real values rather than omissions. The module should continue returning these facts through its normal Ansible result so existing IPv4 consumers remain compatible.
