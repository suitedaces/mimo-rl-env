The entity-query container is also used with virtual entities produced while exploding block references. Those entities intentionally have no DXF handle, and callers may also combine entities from separate drawings, where the same handle string is valid in each drawing. Make the public EntityQuery.extend() and EntityQuery.remove() operations respect entity identity and drawing boundaries while retaining the existing handle-based uniqueness for persisted entities.

With unique=True (the default), extending a query must preserve the first-seen order, keep distinct handle-less entity objects as separate entries, suppress a repeated reference to the same handle-less object, and suppress distinct persisted objects that share a handle. With unique=False, extension must remain a straightforward append that preserves every item and its order.

Removing with a query string must remove exactly the entities in the container that match that query, leaving nonmatching entities untouched even when they have no handle or happen to share a handle string with a matching entity from another drawing. Existing query parsing and matching semantics, including ordering of survivors, must remain unchanged.
