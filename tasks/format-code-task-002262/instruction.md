I want a stateful `SingleFileStorage` class for treating one local aggregate calendar/contact file as a vdirsyncer storage, with `storage_name == "singlefile"` and a constructor usable as `SingleFileStorage(path, encoding="utf-8", **storage_kwargs)`. The constructor should expand `~` and make the path absolute, require that the target path already points to a regular file, remember the encoding, and still accept the standard storage kwargs such as `collection`, `instance_name`, `read_only`, and `no_delete` through the base storage API.

I need `await SingleFileStorage.create_collection(collection, path=...)` to create the backing file and return storage kwargs containing the resolved `path` and the same `collection`: with `collection="work"` and `path="/tmp/%s.ics"` it should create `/tmp/work.ics`, while `collection=None` should create the exact path supplied. If a non-null collection is requested and the path pattern cannot substitute exactly one `%s`, it should raise `ValueError`. I also need `SingleFileStorage.discover(path=...)` to scan existing files matching a single `%s` placeholder and yield kwargs whose `path` points to each matched file and whose `collection` is the matched placeholder text; passing a `collection` argument should raise `TypeError`, and a path pattern without exactly one `%s` should raise `NotImplementedError`.

Once constructed, the async methods should be `list()`, `get(href)`, `get_multi(hrefs)`, `upload(item)`, `update(href, item, etag)`, `delete(href, etag)`, and `at_once()`. Given an empty file and an `Item` whose raw text contains `UID:alice`, `await s.upload(item)` should return `("alice", item.hash)`, `s.list()` should yield `("alice", item.hash)`, and `await s.get("alice")` should return that item and etag. Uploading another item with `UID:bob` should keep both items in the same aggregate file, split them back into separate hrefs on later reads, and preserve case-sensitive UIDs as distinct hrefs. `get_multi(["alice", "alice", "bob"])` should yield each unique href once in input order.

Updating an existing href with its current etag should replace only that item in the aggregate file and return the new item hash. Deleting an existing href with its current etag should remove that item and rewrite the aggregate file from the remaining items. Uploading a duplicate href should raise `AlreadyExistingError`; getting, updating, or deleting a missing href should raise `NotFoundError`; updating or deleting with a stale etag should raise `WrongEtagError`. When writes happen inside `async with s.at_once():`, uploads, updates, and deletes should be buffered in memory and written back to the file once when the context exits, and if the backing file was changed by another process since it was read, the write should raise `PreconditionFailed` instead of overwriting those outside changes.
