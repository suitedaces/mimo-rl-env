I want the Go client to expose multi-search as a stateful service builder. The public entry points should be `func (c *Client) MultiSearch() *MultiSearchService` and `func NewMultiSearchService(client *Client) *MultiSearchService`, with fluent methods `Pretty(bool)`, `Human(bool)`, `ErrorTrace(bool)`, `FilterPath(...string)`, `Header(string, string)`, `Headers(http.Header)`, `Add(...*SearchRequest)`, `Index(...string)`, `MaxConcurrentSearches(int)`, `PreFilterShardSize(int)`, and `Do(context.Context) (*MultiSearchResult, error)`.

A normal session should let me build two `SearchRequest` values, call `client.MultiSearch().Add(req1, req2).Pretty(true).Do(ctx)`, and have the client send one `GET` request to `/_msearch`. `Do` should encode the batch as newline-delimited JSON with one header line and one body line per added search request, plus the required trailing newline. If I set default indices on the multi-search service with `Index("logs")`, those indices should apply only to added search requests that do not already specify their own indices.

The service should pass request-level options as Elasticsearch query parameters: `pretty`, `human`, `error_trace`, comma-joined `filter_path`, `max_concurrent_searches`, and `pre_filter_shard_size`. Custom HTTP headers set through `Header` or `Headers` should be included on the outgoing request. On success, `Do` should decode Elasticsearch's combined response into `MultiSearchResult`, where `TookInMillis` maps from the top-level `took` field and `Responses` contains one `*SearchResult` for each submitted search. If building a request header or body fails, if the HTTP request fails, or if response decoding fails, `Do` should return the error instead of a partial result.
