I want generic slice helper functions in `github.com/PsionicAlch/byteforge/functions/slices` for one-shot transforms and indexed callbacks: `Map[T any, R any, S ~[]T](s S, f func(T) R) []R`, `ParallelMap[T any, R any, S ~[]T](s S, f func(T) R, workers ...int) []R`, `Filter[T any, S ~[]T](s S, f func(T) bool) S`, `ParallelFilter[T any, S ~[]T](s S, f func(T) bool, workers ...int) S`, `ForEach[T any, E ~[]T](s E, f func(int, T))`, and `ParallelForEach[T any, E ~[]T](s E, f func(int, T), workers ...int)`.

`Map([]int{0, 1, 2, 3, 4, 5}, func(n int) int { return n * 2 })` should return `[]int{0, 2, 4, 6, 8, 10}`, and `Map([]int{0, 1, 2}, strconv.Itoa)` should return `[]string{"0", "1", "2"}`. `Filter([]int{1, 2, 3, 4, 5, 6}, func(n int) bool { return n%2 == 0 })` should return `[]int{2, 4, 6}` while preserving the input slice type and original order. `ForEach([]int{10, 20, 30}, cb)` should call `cb` exactly once per element with `(0, 10)`, `(1, 20)`, and `(2, 30)` in ascending index order.

The parallel variants should provide the same observable results for map and filter while evaluating callbacks through a worker pool. If the optional worker count is omitted or is non-positive, they should use `runtime.GOMAXPROCS(0)` workers; if a positive worker count is provided, they should use that many workers. `ParallelMap([]int{1, 2, 3, 4}, func(n int) int { return n * n }, 2)` should return `[]int{1, 4, 9, 16}` in original order, and `ParallelFilter([]int{1, 2, 3, 4, 5}, func(n int) bool { return n > 2 }, 2)` should return `[]int{3, 4, 5}` in original order. `ParallelForEach([]string{"a", "b", "c"}, cb, 2)` should invoke `cb` once for each index/value pair before returning, with no guarantee about callback order.

Empty input slices should complete immediately: map returns a zero-length result slice, filter returns a zero-length result of the input slice type, and foreach must not invoke the callback. These helpers should not mutate the input slice or perform filesystem, network, or global-state side effects; repeated calls with the same input and deterministic callbacks should produce the same results. If a callback panics, the helper should not recover it or convert it to another error.
