我在使用 `crocks/Result/tryCatch` 包装函数后，发现包装后的函数和直接调用原函数在一些常见调用方式下表现不一致，尤其是原函数需要多个入参、再交给 `curry` 组合、或依赖调用方提供的上下文时。

请修复 `tryCatch` 的对外行为：包装后的安全函数应把调用时提供的参数按原调用意图传给被包装函数；成功执行时仍返回 `Ok`，抛错时仍返回 `Err`。包装后的函数也应保留与原函数一致的可观察 arity/`length`，使依赖函数参数个数的组合工具能够按原函数的参数个数等待输入。

如果调用者通过 `call`、`apply` 或对象方法调用包装后的函数，被包装函数应看到相同的 `this` 上下文。相关文档中 `tryCatch` 的函数签名也要同步说明它可以包装多参数函数，并使用项目现有的 variadic `(*)` 记法表达这一点。
