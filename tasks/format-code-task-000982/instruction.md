The stream transports currently decode every framed payload as RFC 5424, which prevents callers from reusing the framing packages with the RFC 3164 parser or with another parser that implements the public Machine interface. Add a public parser option that supplies the message decoder used by both octet-counting and non-transparent parsers.

When a non-nil machine is supplied, every complete frame must be passed to that exact machine, preserving the transport boundary rules: octet-counting uses the declared number of bytes (including UTF-8 payloads), while non-transparent mode uses only the selected LF or NUL trailer and keeps other bytes in the payload. The supplied machine must receive the repository's existing best-effort setting unchanged; the framing parser must not silently enable or disable best effort on the caller's machine.

Decoder results and errors must retain the existing listener contract. In strict mode, octet-counting emits successful frames and then emits the decoder error without exposing a partial message or consuming later frames. In best-effort mode it emits the decoder's message/error pair and continues with later frames. Non-transparent framing forwards the decoder's message/error pair for each delimited frame and continues in both modes; an unterminated final candidate is still reported according to the existing EOF behavior.

A nil machine keeps the current RFC 5424 default. The option must be harmless when applied to a parser implementation that does not support machine selection, and existing Parser implementations must remain source-compatible. Parser instances may be reused for independent readers without replaying bytes, stale errors, or stale framing state; existing listener, trailer, and message-parser options must continue to work together regardless of option order.
