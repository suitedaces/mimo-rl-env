Commander action handlers are currently fire-and-forget, which makes it difficult for an embedding application or test runner to know when promise-based command work has finished. Add an asynchronous parsing lifecycle while preserving the existing synchronous parser.

Add `Command#parseAsync(argv)` (also available on the package's exported program instance). It must perform the same argument parsing and action selection as `parse(argv)`, always return a Promise, and resolve to the Command object on which it was called only after the selected action's asynchronous lifecycle has completed. Action callbacks keep their existing receiver and arguments. A Promise or arbitrary thenable returned by an action must be assimilated and awaited. This applies to top-level actions, named subcommands selected by their name or alias, and the wildcard `*` action.

Add a chainable `Command#hook(event, listener)` API for the two lifecycle events `preAction` and `postAction`. Reject any other event name synchronously with an Error. Hooks run only when an action is selected. Each listener receives `(thisCommand, actionCommand)`, where `thisCommand` is the command on which that hook was registered and `actionCommand` is the command whose action will run. For a subcommand action, run pre-action hooks from the root down through the action command, then the action, then post-action hooks from the action command back up to the root. Hooks registered for the same event on the same command run in registration order. For a top-level action, the root's hooks run once around that action.

During `parseAsync`, every hook and the action are sequential lifecycle stages: await a returned Promise or thenable before starting the next stage. If a pre-action hook rejects, do not run later pre-action hooks, the action, or any post-action hook. If the action throws synchronously or its result rejects, reject the Promise with that exact thrown/rejected value and do not run post-action hooks. If a post-action hook rejects, preserve that exact rejection and do not run any remaining post-action hooks. Results from one parse invocation must not leak into a later `parseAsync` call on the same Command; a failed first invocation must not poison a successful second one.

Keep `parse(argv)` backward-compatible: it returns the Command synchronously, invokes synchronous hook/action/post-hook callbacks in lifecycle order before returning, and does not wait for returned thenables. Existing synchronous action dispatch and option parsing must continue to work.

Expose `parseAsync` and `hook` in the bundled TypeScript declarations. The hook event parameter must accept `'preAction' | 'postAction'`, hook listeners must receive two Command values and may return either synchronously or via Promise, and `parseAsync` must type as a Promise of Command.
