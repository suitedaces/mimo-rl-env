I need two exported rewriter classes that work with `RewriteHandler`: `ScalarFieldToObjectFieldRewriter` and `NestFieldOutputsRewriter`. Their constructors must accept the normal field-matching options (`fieldName`, optional `rootTypes` and `matchConditions`) plus, respectively, `objectFieldName`, or `newOutputName` and `outputsToNest`; constructing either class without `fieldName` and without `matchConditions` must throw an `Error`.

For a session such as `handler = new RewriteHandler([new ScalarFieldToObjectFieldRewriter({ fieldName: 'title', objectFieldName: 'text' })])`, `handler.rewriteRequest('query { thing { title } }')` should produce a query selecting `thing { title { text } }`, and `handler.rewriteResponse({ thing: { title: { text: 'THING' } } })` should return `{ thing: { title: 'THING' } }`. The scalar rewrite must also turn an object array such as `{ thing: { titles: [{ text: 'A' }, { text: 'B' }] } }` into `{ thing: { titles: ['A', 'B'] } }` when configured for `titles`, while unrelated fields remain unchanged. A scalar field that already has a selection set must be skipped.

For `new NestFieldOutputsRewriter({ fieldName: 'createCat', newOutputName: 'cat', outputsToNest: ['id', 'name'] })`, a request selecting `createCat { id name executionTime }` should be sent as `createCat { executionTime cat { id name } }`; the response `{ createCat: { cat: { id: 1, name: 'jack' }, executionTime: 10 } }` should be returned as `{ createCat: { id: 1, name: 'jack', executionTime: 10 } }`. Only selected fields listed in `outputsToNest` move under the payload field, unrelated selections stay at the parent, and an existing `cat` selection prevents another nesting pass. Both response transformations must handle arrays of parent results, and null or non-object response branches must remain unchanged where they cannot be transformed. The classes must be publicly importable from the package root.
