I want SanitizeEmail to provide stateful activation controls for deciding whether an outgoing Mail message is sanitized. The public API should include `SanitizeEmail.force_sanitize` and `SanitizeEmail.force_sanitize=(value)` where `value` may be `true`, `false`, or `nil`; a non-`nil` value takes precedence over configured activation for later deliveries. `SanitizeEmail::Config.configure` should support `config[:engage] = true`, `false`, or `nil`: `true` engages sanitization, `false` leaves messages unchanged, and `nil` falls through to `config[:activation_proc]`. `config[:activation_proc]` should be a callable that receives the Mail message and whose truthy or falsey return value decides whether that message is sanitized when `force_sanitize` and `engage` are both `nil`; by default the gem should be inert and leave messages unchanged.

For a concrete session, after configuring `sanitized_to: "safe@example.test"` and `engage: true`, delivering a message addressed to `real@example.test` should run the normal sanitizing flow so the delivered message is addressed to `safe@example.test` and records the original recipient header. With the same safe recipient config but `engage: false`, delivering the same message should keep `real@example.test` and should not add original-recipient sanitization headers. If `force_sanitize` is set to `false`, it should keep the original recipient even when `activation_proc` returns true; if `force_sanitize` is set to `true`, it should sanitize even when configured activation would otherwise deny it. Messages with `perform_deliveries` false should never be sanitized.

I also need scoped overrides: `SanitizeEmail.sanitary(config_options = {}) { ... }` should require a block, temporarily merge the provided config options for deliveries inside the block, force sanitization by default, and put the prior config and force state back after the block exits even if the block raises. If `sanitary` receives `engage:` or `activation_proc:` in its options, those options should decide activation instead of the default force-on behavior. `SanitizeEmail.unsanitary { ... }` should require a block, force deliveries inside the block to remain unsanitized, and put the prior force state back afterward. Calling either scoped method without a block should raise `SanitizeEmail::MissingBlockParameter` with a message naming the method that needs a block.

For compatibility, `config[:local_environments]` in Rails should map to an activation proc that engages only when `Rails.env` is included in that list, and configuring deprecated `config[:force_sanitize]` should warn and copy that value into `SanitizeEmail.force_sanitize`.
