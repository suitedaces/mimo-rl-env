The Across SDK currently rebuilds its rate-model index from each incoming event batch, which makes polling fragile: a later page can erase earlier history, replayed logs can duplicate entries, and malformed data can partially alter what callers observe. Extend the public rate-model utility so it can be used safely by an event poller and by historical inspection tools.

Keep the existing latest and historical lookup methods compatible, but make event ingestion cumulative. updateWithEvents must validate the whole batch before committing it: every event needs a valid Ethereum address, normalized and exposed in checksum form, non-negative integer block, transaction, and log positions, and a JSON rate-model payload with exactly the four keys UBar, R0, R1, and R2, each holding a string. Events are ordered by block number, then transaction index, then log index. A repeated event identity (token plus those three positions) is an idempotent replay only when its payload is identical; a conflicting payload is an error. The caller's array and event objects must not be reordered or mutated, and a rejected batch must leave the prior index unchanged.

Add a public getRateModelEvents(l1Token, atBlock?) history query. It returns independent event records in chronological order for the checksummed token address; with atBlock supplied it includes only events at or before that block, including block 0. Unknown tokens and a block before the first event must fail consistently with the existing lookup methods. Returned records must be snapshots, so changing one cannot mutate the dictionary. getRateModelForBlockNumber must select the latest event at or before the requested block, including same-block transaction/log precedence, and an explicit block number of 0 must not be mistaken for an omitted argument. getL1TokensFromRateModel(atBlock?) must apply the same block-zero rule and return a deterministic lexicographically sorted list of checksummed token addresses.
