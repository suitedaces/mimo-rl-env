Source freshness state selection is used to defer work until an upstream source has actually advanced, but the current source_status selector mishandles failed freshness snapshots and silently accepts unsupported status names. Make the public source_status:fresher selector compare the current and previous freshness artifacts deterministically. A source is fresher when it has no matching entry in the previous artifact, or when its current max_loaded_at is strictly later than the previous value. Equal and older timestamps must not match. A source whose current or previous freshness entry is a runtime error has no comparable timestamp and must never be selected, even if the other snapshot has a later timestamp.

Keep the existing state-artifact preconditions: missing previous sources or missing current sources must raise the established InternalException instead of returning an empty selection. Reject an unsupported source-status value such as staler with RuntimeException rather than treating it as a valid selector that happens to match nothing. The selector must continue to compose with graph modifiers: source_status:fresher+ includes the selected source and its downstream nodes using the normal NodeSelector expansion. Preserve the existing public selector and artifact types and do not require a warehouse connection.
