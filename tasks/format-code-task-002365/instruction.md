I want the `xar` command to support a `--dump-header` operation for inspecting the fixed binary header of an archive without unpacking the archive. The invocation is `xar --dump-header -f archive.xar`, and on a readable archive it should exit 0 and print the header summary to stdout with these lines: `magic:                   0x78617221 (OK)`, `size:                    <decimal header size>`, `version:                 <decimal version>`, `Compressed TOC length:   <decimal bytes>`, `Uncompressed TOC length: <decimal bytes>`, and `TOC Checksum algorithm:  <decimal id> (<name>)`.

For checksum algorithm ids, it should label 0 as `none`, 1 as `sha1`, 2 as `md5`, unknown numeric values as `unknown`, and the extended algorithm form as `OTHER + <algorithm name>` when the header contains a valid NUL-terminated algorithm name. If the extended algorithm header is malformed, it should still exit 0 but describe the problem in the checksum line, using `OTHER + invalid header length`, `OTHER + invalid non-nul terminated name`, or `OTHER + invalid empty name` as appropriate. If the magic number is not the XAR magic value, the command should still print the decoded fields and mark the first line as `(BAD)` instead of `(OK)`. If the archive path cannot be opened, it should print the operating-system open error to stderr and exit non-zero; if fewer than the base header bytes can be read, it should print `error reading header` to stderr and exit non-zero. `xar --help` should list `--dump-header` as the option that prints the xar binary header information.
