The VFS-backed simple clientset is used as a Kubernetes-style state-store client, but its instance-group interface currently ignores ListOptions selectors and leaves Patch and DeleteCollection unimplemented. Bring those operations into behavioral parity so callers can safely query and mutate instance groups without bypassing the generated InstanceGroupInterface.

For List, apply standard Kubernetes label-selector syntax to the effective metadata labels returned by the VFS client, including the synthesized `kops.k8s.io/cluster` label. Support field selection on `metadata.name`; equality and inequality must work, and label and field selectors must both match when supplied together. Matching results must retain the existing deterministic name ordering. Empty selectors continue to select every instance group. A malformed label or field selector must return an error rather than an unfiltered or partial result.

Patch must support `types.JSONPatchType` and `types.MergePatchType` with their standard JSON Patch and JSON Merge Patch semantics. Apply a patch to the current stored instance group, preserve fields the patch does not change, persist the result, and return that persisted object. The result must pass the same instance-group validation as a normal update. Increment `metadata.generation` exactly once when the spec changes, but do not increment it for metadata-only patches. The addressed object's name is immutable. Malformed patches, patches that produce an invalid instance group, rename attempts, unsupported patch types, and non-empty subresource arguments must fail without changing stored state. Patching a missing instance group must return a Kubernetes NotFound error.

DeleteCollection must use the same label/field selector behavior as List and delete only the matching instance groups. No matches is a successful no-op, while empty selectors delete the whole collection. If either selector is malformed, return an error before deleting anything.
