I want the Go driver client options builder to support custom DNS SRV service names for mongodb+srv connections. The public API should include `func (c *ClientOptions) SetSRVServiceName(srvName string) *ClientOptions`, usable in a chain such as `options.Client().SetSRVServiceName("customname").ApplyURI("mongodb+srv://cluster.example.com")`.

When a custom service name is set this way, SRV polling for that topology should query `_customname._tcp.cluster.example.com` instead of the default `_mongodb._tcp.cluster.example.com`. The URI option `srvServiceName=<name>` on a `mongodb+srv://` URI should also be supported; for example, `options.Client().ApplyURI("mongodb+srv://cluster.example.com/?srvServiceName=customname")` should use `customname` for initial SRV seedlist discovery and for later SRV polling.

Invalid URI usage should be reported through the normal client options validation path: `srvServiceName` on a non-SRV URI such as `mongodb://localhost/?srvServiceName=customname` should produce an error, and an empty service name or a service name longer than 62 characters should produce an error. If no custom service name is configured, `mongodb+srv://` discovery should continue to use the default `mongodb` service name.
