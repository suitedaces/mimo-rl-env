I want bots created by this package to handle incoming chat messages through `Respond(ctx context.Context, input Input) error`. After I register commands on a bot, calling `Respond` with an ordinary `Input` should find the first registered command whose `Match(input)` returns true, execute only that command, and if it returns `CommandResponse{Content: "pong"}` send an `Output` to `input.ReplyTo()` whose content is `"pong"`. If no registered command matches, `Respond` should return nil and send nothing; if the matched command returns an error, `Respond` should return that error.

I need help inputs to work through the same method: when `Respond` receives a `*HelpInput` and there is no active conversation for that sender, it should send a `*CommandHelps` value to the help input's reply destination. The help list should contain each registered command's identifier and non-empty instruction, preserving command registration order and omitting commands whose instruction is an empty string.

I also need multi-message conversation state to take priority over normal command matching. When a command response includes `UserContext: NewUserContext(next)`, `Respond` should store that next step under the sender key when storage is configured, while still sending any non-nil content from the response. On the next `Respond` call from the same sender, the stored next step should be deleted and invoked with the new input instead of matching registered commands; if that next step returns content, the bot should send it to the new input's reply destination, and if it returns another user context, that next step should be stored for a later message. When the next input is an `*AbortInput`, `Respond` should delete the stored context, return nil, not invoke the stored next step, and send nothing. If retrieving the stored context fails, `Respond` should return that storage error; if storing a new context fails, the response content should still be sent and `Respond` should not fail.

The public `Commands` collection should also provide the dispatch helpers used by this flow: `FindFirstMatched(input Input) Command` should return the first appended command whose `Match` returns true or nil when none match; `ExecuteFirstMatched(ctx context.Context, input Input) (*CommandResponse, error)` should return nil, nil when none match or return the matched command's `Execute` result; and `Helps(input *HelpInput) *CommandHelps` should aggregate the non-empty command instructions with their identifiers.
