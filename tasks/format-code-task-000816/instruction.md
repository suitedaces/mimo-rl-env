I want the public finite-automaton facade on `regexpTree.fa` to accept a regular expression and expose one-shot helpers for building automata and testing strings. The API should include `fa.toNFA(regexp: string | RegExp | AST): NFA`, `fa.toDFA(regexp: string | RegExp | AST): DFA`, and `fa.test(regexp: string | RegExp | AST, string: string): boolean`.

For `fa.toNFA(/a*/)` the returned object should be an `fa.NFA`; its matcher should accept `''`, `'a'`, and `'aa'`, and reject `'ab'`. For `fa.toDFA(/a*/)` the returned object should be an `fa.DFA`; its matcher should accept `''`, `'a'`, and `'aa'`. For `fa.test(/ab|c*/, 'ab')`, `fa.test(/ab|c*/, '')`, `fa.test(/ab|c*/, 'c')`, and `fa.test(/ab|c*/, 'ccc')`, the result should be `true`, while `fa.test(/a|b/, 'c')` should be `false`.

The converter should support simple characters, concatenation, disjunction, groups, and the `*`, `+`, and `?` quantifiers. It should accept the same pattern as a JavaScript `RegExp` object, a regexp string, or an already parsed AST. If the regexp has flags, it should throw `Error` because flags are not supported by this interpreter; if the AST contains an unsupported node type or a non-simple character node, it should also throw `Error` explaining that the construct is unsupported. Calling these helpers repeatedly with equivalent inputs should produce equivalent automata or booleans, and the input string or AST should not be mutated.
