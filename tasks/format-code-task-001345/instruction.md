I want Glazier task configurations to support a `Get` action, with `pull` as a legacy alias, for materializing one or more source files at local destination paths during an imaging run. The action should be usable as `Get(args, build_info)`, where `args` is a list of entries shaped as `[source, destination]` or `[source, destination, sha256]`; `Validate()` should accept only that nested list shape and raise a validation error when the top-level value is not a list, an entry has fewer than two or more than three items, or any entry item is not a string.

When `Run()` is called, it should process each entry in order. Sources beginning with Glazier path tokens should be expanded using the active build information, including `#` for the active config tree, `@` for the binary store, and `%` for the active branch, while escaped tokens like `\#`, `\@`, and `\%` should remain literal. A source that is not already an explicit HTTP(S) URL or local drive path should be treated as a legacy untagged relative name under the active config path.

For each entry, `Run()` should create the destination directory path before transferring the file, then download or copy the resolved source to the exact destination with progress enabled. If destination directory creation fails, the action should raise an action error that identifies the destination. If the transfer fails, it should print downloader debug information and raise an action error identifying the resolved source. When the optional third argument is a non-empty SHA256 digest, `Run()` should verify the saved destination file against it and raise an action error if the digest does not match; when the third argument is absent or an empty string, SHA256 verification should be skipped.
