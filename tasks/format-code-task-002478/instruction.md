## CSS 里引用了不存在的 asset 时，整个编译就炸了

我在把一个老 Rails 项目切到 propshaft。项目的 CSS 里有一些 `url(...)` 指向的文件已经不在仓库里了（有的是第三方主题留下的、有的是以前删过资源忘了清 CSS）。

只要请求到任意一个引用了这种 CSS 的页面，propshaft 就会从 `CssAssetUrls` 这个 compiler 抛 `Propshaft::MissingAssetError`，整个响应 500，页面打不开。但实际上 CSS 里其它 99% 的 `url(...)` 都是好的，仅仅因为有一条死链就让整张样式表 + 整个页面挂掉，感觉太激进了。

浏览器自己遇到 CSS 里有指向 404 资源的 `url(...)` 也只是那一条规则不生效而已，不会拒绝渲染整个页面。我之前用 Sprockets 时这种情况也只是日志里出现一行提示，不会让请求失败。

希望 propshaft 在 CSS 编译时遇到找不到的 asset 时，不要直接 raise 把整个编译流程打断 —— 至少在日志里留个记录方便我去清理，但 CSS 应该还能正常产出、页面应该还能正常渲染。
