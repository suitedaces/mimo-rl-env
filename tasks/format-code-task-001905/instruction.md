I want `@microlink/mql` to expose an async `fetchFromApi(apiUrl: string, opts?: object): Promise<object>` function for executing an already-built Microlink API URL and normalizing the response shape.

When I call `await fetchFromApi('http://localhost:3000/?url=https%3A%2F%2Fexample.com', { responseType: 'json', retry: 0 })` and the server returns HTTP 200 with JSON `{"status":"success","data":{"title":"Example"}}`, it should resolve to the parsed payload with a `response` property containing the final response URL, parsed body, response headers, and numeric status code. When I call it with `{ responseType: 'arrayBuffer', retry: 0 }` and the server returns binary content, it should resolve to the raw response metadata object `{ url, body, headers, statusCode }` where `body` is the `ArrayBuffer`.

The function should pass through request options supported by the HTTP client, including hooks and retry configuration, and should default `timeout` to disabled when the caller does not provide one. For non-2xx API responses with a JSON error body, it should reject with `MicrolinkError` while preserving fields such as `status`, `data`, `code`, `message`, `more`, the final URL, headers, and HTTP status code. For plain-text, empty, unreadable, or transport-level failures, it should reject with `MicrolinkError` using `code: 'EFATALCLIENT'`, `status: 'error'`, a useful message in `data.url`, the failing URL, available headers, and the HTTP status code when one exists.
