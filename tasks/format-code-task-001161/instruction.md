docformatter is deliberately conservative around structured reStructuredText because reflowing a directive or list can change its meaning. That caution is useful, but it currently makes a whole description opaque when only one small region is structured: prose before and after a directive, literal block, doctest, list, or Sphinx field is left unwrapped. Add an opt-in structured-wrapping mode, exposed as the `--wrap-structured` command-line option and the equivalent `wrap-structured` setting in supported configuration files, for users who want mixed docstrings formatted without damaging their structured regions.

With this mode enabled, keep the existing summary normalization and configured wrapping widths. Reflow ordinary prose paragraphs independently on each side of protected structured regions, and resume formatting after every region rather than abandoning the entire description. Preserve directive markers and their option/body indentation and text, preserve literal blocks introduced by an explicit-literal marker such as `Example::`, preserve doctest prompts and output exactly, and preserve list items plus their continuation and nested-item indentation and authored spacing. Structured regions must remain in their original relative order, separated from surrounding paragraphs as required for valid reST. Sphinx field lists adjacent to protected regions must still use the existing field-list wrapping rules.

The default behavior must remain backward compatible: without `--wrap-structured`, a description containing a directive continues to use the current cautious behavior. The new setting must be read from `[tool.docformatter]` configuration with command-line options taking precedence, just like the existing formatter settings. Formatting must be stable when the same structured document is processed again.
