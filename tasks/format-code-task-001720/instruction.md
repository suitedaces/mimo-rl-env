Harden every NFS path that comes from a CSI request or from one of our volume/snapshot IDs. Today these values are fed through path joining before they are fully checked, so `.`/`..`, absolute subdirectories, metadata expansion, or extra ID fields can redirect controller work outside the intended export or working directory. Validation must reject the unsafe value; silently cleaning it into a different path is not acceptable.

Use one consistent path contract across node publish, dynamic provisioning, clones, and snapshots. A `share` may be `/` and may otherwise be a relative or absolute nested export path with optional boundary slashes, but none of its path components may be exactly `.` or `..`. A `subDir` and every name/path component recovered from an ID must be relative and must not contain a `.` or `..` component; ordinary hidden names such as `.data` remain valid. Validate a templated `subDir` after PVC/PV metadata substitution, because a metadata value can introduce separators or traversal. Values that the controller serializes into its `#`-delimited IDs (server, share, resolved subdirectory, volume name, snapshot name, and snapshot storage-class overrides) must not themselves contain `#`.

Make ID decoding strict as well. The current `#` volume form accepts exactly three, four, or five fields and must reject extra fields. Its server and subdirectory fields must be non-empty; the base-share field may be empty to represent `/`, and the optional UUID field may be empty, but any non-empty path-bearing field follows the confinement rules above. Keep accepting the legacy slash form, including nested base directories, when all recovered paths are safe. Snapshot IDs have exactly five fields; server, snapshot UUID, archive path, and source/archive name must be non-empty, the archive-path field must equal the snapshot UUID field, and every path-bearing field must be safe.

Validate the complete request before trying a mount or populating a working/target directory. Unsafe direct fields supplied to `CreateVolume`, `CreateSnapshot`, or `NodePublishVolume` return `InvalidArgument`. An unsafe or noncanonical source volume/snapshot ID supplied to `CreateSnapshot` or as `CreateVolume.VolumeContentSource` is treated as an unavailable source and returns `NotFound`; in particular, destination creation must not begin before its content source has passed validation. Delete remains CSI-idempotent: malformed or unsafe volume/snapshot IDs return an empty successful response, without mounting or changing local data.

Preserve existing valid behavior: root and nested shares, nested relative subdirectories, IPv6 servers, metadata substitution, current safe IDs, safe legacy volume IDs, existing on-delete policies, and the existing create/delete/publish/snapshot happy paths must continue to work.
