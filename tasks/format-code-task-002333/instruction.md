I want the `wgdb` command-line tool to expose index management commands for an optional shared-memory database name. `wgdb [shmname] createindex <column>` should parse `<column>` as a decimal integer, attach or create the target database, take a write lock, create a single-column T-tree index, produce no stdout on the command path, and exit 0 when the command completes. `wgdb [shmname] createhash <column> [<column> ...]` should parse every remaining argument as a decimal column number, create one JSON hash index over those columns under a write lock, produce no stdout on the command path, and exit 0 when the command completes. `wgdb [shmname] dropindex <index id>` should parse the id as a decimal integer, drop that index under a write lock, print `Index dropped.` plus a newline on stdout when it succeeds, and print `Failed to drop index.` plus a newline on stderr when the drop call reports failure. `wgdb [shmname] listindex` should take a read lock and print `No indexes in the database.` plus a newline when there are none; otherwise it should print the header `col\ttype\tmulti\tid\tmask\n` and then one tab-separated line per indexed column entry with the column number, type code (`T`, `TJ`, `#`, or `#J`), indexed field count, index id, and mask marker (`-` when templates are disabled, otherwise `Y` or `N`). If any of these commands cannot attach to the database, they should print `Failed to attach to database.` plus a newline on stderr and exit 1. `wgdb help` should list the four command forms and their short descriptions.
