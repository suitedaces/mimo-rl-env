I want the `telegram-upload` CLI to support an upload large-file split mode through `telegram-upload --large-files split FILE [FILE ...]`. When an input file is larger than the current Telegram account's maximum upload size, this mode should send the file as consecutive document parts instead of failing the upload. Each part should read from the original file at the correct byte offset, be capped to the account max size except for the final remainder, and preserve byte order so concatenating the uploaded parts recreates the original file exactly.

The generated part filenames should be deterministic: use the original basename plus a two-digit numeric suffix, such as `large-video.mkv.00`, `large-video.mkv.01`, and so on. Split parts should be forced to upload as files/documents so the exact part filenames are preserved. For a file whose size is exactly `max_file_size + 1000`, split mode should upload two parts: the first with size `max_file_size` named `basename.00`, and the second with size `1000` named `basename.01`. If the send completes successfully, the command should exit with code 0. The `--large-files` help/choice text should include `split` as an accepted value alongside the default fail policy.
