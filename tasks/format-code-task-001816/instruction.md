I want a Go library function `ReadLDAPMessage(bytes *Bytes) (LDAPMessage, error)` that decodes one BER-encoded LDAPMessage envelope in a single call. It should expect the outer value to be a universal SEQUENCE, read the message ID, dispatch the protocol operation by its LDAP application tag into the matching public `ProtocolOp` concrete type, and attach optional message controls when a context-specific `[0]` controls sequence is present.

For `ReadLDAPMessage(NewBytes(0, []byte{0x30, 0x0c, 0x02, 0x01, 0x01, 0x60, 0x07, 0x02, 0x01, 0x03, 0x04, 0x00, 0x80, 0x00}))`, I expect no error, `MessageID().Int() == 1`, `ProtocolOp()` to have dynamic type `BindRequest`, `ProtocolOpName() == "BindRequest"`, and `Controls() == nil`. For `ReadLDAPMessage(NewBytes(0, []byte{0x30, 0x34, 0x02, 0x01, 0x24, 0x65, 0x07, 0x0a, 0x01, 0x00, 0x04, 0x00, 0x04, 0x00, 0xa0, 0x26, 0x30, 0x24, 0x04, 0x16, 0x31, 0x2e, 0x32, 0x2e, 0x38, 0x34, 0x30, 0x2e, 0x31, 0x31, 0x33, 0x35, 0x35, 0x36, 0x2e, 0x31, 0x2e, 0x34, 0x2e, 0x33, 0x31, 0x39, 0x01, 0x01, 0xff, 0x04, 0x07, 0x30, 0x05, 0x02, 0x01, 0x00, 0x04, 0x00}))`, I expect no error, `MessageID().Int() == 36`, `ProtocolOp()` to have dynamic type `SearchResultDone`, and `Controls()` to contain one control with type `"1.2.840.113556.1.4.319"`, criticality `true`, and value bytes `{0x30, 0x05, 0x02, 0x01, 0x00, 0x04, 0x00}`.

The protocol-op dispatcher should recognize the LDAP application tags for the package's public request and response types, including bind, unbind, search, modify, add, delete, modify DN, compare, abandon, extended, and intermediate operations. If the next tag after the message ID is not one of those protocol-op application tags, `ReadLDAPMessage` should return a non-nil `LdapError`. If a control encodes `criticality` as BOOLEAN FALSE instead of omitting the default value, `ReadLDAPMessage` should also return a non-nil `LdapError`; invalid BER inside the envelope should be reported through the returned error rather than panicking.
