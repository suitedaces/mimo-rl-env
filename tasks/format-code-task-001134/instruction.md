Harden the reverse proxy's HTTP header boundary. A `Connection` field describes only the current transport hop, but the proxy currently forwards request-side connection metadata and only applies a small static denylist to upstream responses. That can leak credentials or internal control fields, and response fields that should have been discarded can still affect redirect, buffering, and cookie behavior.

For both the request sent to urllib3 and the Django response returned to the client, remove these field names case-insensitively: `Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `Proxy-Connection`, `TE`, `Trailer`, the legacy spelling `Trailers`, `Transfer-Encoding`, and `Upgrade`. Also read every value of every `Connection` field on that leg, split comma-separated members, trim surrounding whitespace, ignore empty members, and remove the header whose name exactly matches each member (case-insensitively). A token must not remove a longer header with a similar prefix.

Request filtering applies to the final header set passed to urllib3, including headers added by a subclass through the documented `get_proxy_request_headers()` extension point. Thus an extension cannot accidentally reintroduce a fixed or connection-nominated field. Keep the existing request behavior for unrelated fields: the original `Host` and `Accept-Encoding` remain omitted, while ordinary end-to-end request headers and values remain available upstream.

On the response leg, discard connection-scoped fields before any response processing can consume them, not merely while copying headers to Django. In particular, a connection-scoped `Location` must neither be rewritten nor exposed; a connection-scoped `Content-Type` must behave as absent and use the existing guessed/default content type; a connection-scoped `Content-Length` on a non-HTML response must take the existing unknown-length streaming path and remain absent from the client response; and a connection-scoped `Set-Cookie` must not create Django cookies.

Preserve the neighboring behavior for fields that are not connection-scoped. Multiple ordinary `Set-Cookie` values must still produce their distinct cookies and attributes. Status, body bytes, and ordinary end-to-end response headers must remain unchanged, and an ordinary absolute `Location` for the upstream origin must still be rewritten to the incoming request's scheme and host while preserving its path, query, and fragment.
