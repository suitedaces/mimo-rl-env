I want the `search_index` command to index Hugo Markdown front matter into Sonic when I run `search_index -c conf.yaml`. The config file should support `sonic_host`, `sonic_password`, `sonic_collection`, `sonic_bucket`, and `root_path` in addition to the existing post selection settings; the Sonic ingester should connect to `sonic_host` on port 1491 with `sonic_password`. For each selected Markdown file, inspect front matter lines only until `author: ""`, read `title: "..."`, `description: "..."`, and `draft: ...`, and skip any post missing either title or description. For a published post at `/site/content/post/hello.md` with `root_path: /site/content`, title `Hello`, and description `First post`, the command should flush the existing Sonic object and then bulk-push one record to the configured collection and bucket with searchable text `Hello First post`; the object id must be decryptable by the existing search service into `/post/hello.md|Hello`. On that happy path it should log `开始连接Sonic服务`, `新增索引数据：1`, `开始写入索引数据`, and `成功写入索引：1`, and exit with code 0. For a draft post with valid title and description, it should flush the corresponding Sonic object so the post is removed from search results, should not bulk-push it, should log `删除索引数据：1`, and should exit with code 0. If all selected posts are missing searchable metadata, it should log `没有索引数据需要更新`, avoid connecting to Sonic, and exit with code 0. If a selected Markdown file cannot be opened while preparing its Sonic record, the command should print the open error and exit non-zero. If Sonic reports per-object bulk push errors, the command should log `写入索引有异常` followed by `Object: <object> - Error: <error>` lines for each failed object.
