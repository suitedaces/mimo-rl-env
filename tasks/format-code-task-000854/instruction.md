I want `efro.dataclassio` to provide JSON string convenience helpers for its dataclass serialization API.

Please add `dataclass_to_json(obj: Any, coerce_to_float: bool = True, pretty: bool = False, sort_keys: bool | None = None) -> str`. It should serialize the object through the existing JSON codec dict conversion and then return a JSON string. For a dataclass whose JSON dict is `{"name": "bob", "score": 7}`, `dataclass_to_json(obj)` should return compact JSON like `{"name":"bob","score":7}` with comma/colon separators and no spaces. With `pretty=True`, it should return indented JSON using two spaces, and keys should be sorted by default. With `sort_keys=True` or `False`, the explicit value should control key sorting for both compact and pretty output. If the underlying dict contains non-finite float values, the JSON export should fail with the standard `ValueError` from JSON encoding instead of emitting `NaN` or infinities.

Please also add `dataclass_from_json(cls: type[T], json_str: str, *, coerce_to_float: bool = True, allow_unknown_attrs: bool = True, discard_unknown_attrs: bool = False, lossy: bool = False) -> T`. It should parse the JSON string and then construct the target dataclass using the existing dict input path while forwarding those keyword options unchanged. For example, if `User(name='bob', score=7)` serializes to `{"name":"bob","score":7}`, then `dataclass_from_json(User, '{"name":"bob","score":7}')` should return an equal `User` instance. Invalid JSON such as `'{'` should raise `json.JSONDecodeError`, and valid JSON whose decoded value cannot be loaded into the target dataclass should surface the same validation exception that the dict input API would raise.

Both helpers should be importable directly from `efro.dataclassio`, should be deterministic for the same input and options, and should not perform filesystem, network, or global-state side effects.
