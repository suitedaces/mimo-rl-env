Extend the public `rubico/x/defaultsDeep` helper so callers can choose what counts as an already-present value while filling nested configuration data. The current one-argument form must remain compatible: when no predicate is supplied, null and undefined source values receive defaults, other values are retained, arrays and plain objects are merged recursively, and extra source array elements are preserved.

Support `defaultsDeep(defaultCollection, isPresent)(value)`, where `isPresent` is a synchronous predicate receiving each source value at the corresponding path. For every defaulted property or array slot, retain the source value when the predicate returns truthy and use the default when it returns falsy. Apply that decision independently at every recursive object and array path: an accepted object/array branch is recursively merged with its matching default branch, while a rejected branch is replaced by the default branch rather than merged through the rejected value. Values beyond the length or keys supplied by the defaults remain unchanged.

The operation must continue to return null, undefined, and non-array/non-plain-object inputs unchanged, and it must not mutate the source value or nested structures. Function values in the data are ordinary values; only the optional second argument is the presence predicate. Predicate exceptions should propagate to the caller. Keep the existing return shapes and synchronous behavior.
