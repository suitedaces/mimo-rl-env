Operators running TFM-capable switches need more control over the capacity estimates Faucet derives for its OpenFlow tables. Add an optional datapath-level `port_scale_factor` (a positive integer, default 1) that scales only the automatic estimates for tables whose sizing depends on both VLAN and port counts. VLAN-only tables, and explicitly configured table sizes, must not be multiplied by this factor.

Make `table_sizes` useful as a genuine partial override: entries supplied for individual tables take precedence over their automatic estimate while omitted entries continue to be estimated normally. An explicit size is still subject to `min_wildcard_table_size`, but it must not be rounded or replaced by an automatic estimate; this applies to exact-match tables as well. Automatic estimates must continue to round upward to the configured minimum-size quantum, and non-exact (wildcard) tables must continue to respect `max_wildcard_table_size`. The factor must be validated and configurations with zero or negative values must be rejected with `InvalidConfigError`. Omitting the new option must preserve existing table-sizing behavior and existing configuration parsing APIs.
