Machine consumers use Deepchecks results outside notebooks, so SuiteResult JSON must be safe to persist and reload across runs. At present, suite metadata is silently discarded and disabling display serialization produces a payload that the loader cannot consume. Tighten the public JSON contract for SuiteResult.to_json() and SuiteResult.from_json() without changing the meaning of a check result.

The serialized suite must include its extra_info list exactly as exposed by the SuiteResult, including order and an empty list when there is no extra information. Loading that JSON must restore the suite name, extra_info, result order, and the distinction between CheckResult and CheckFailure. CheckResult condition decisions must retain each condition category, name, and details so that passed(fail_if_warning=...) gives the same answer before and after a round trip; failure objects must remain represented as failures.

When to_json(with_display=False) is used, the resulting JSON must still be valid input to SuiteResult.from_json(), and every reloaded CheckResult must expose an empty display list. When display serialization is enabled, existing public display values that are supported by the JSON serializer, including text and data frames, must continue to round-trip with their types and values intact. For compatibility with payloads produced by older versions, a missing top-level extra_info field means an empty list, and a missing or null CheckResult display field means an empty display list. Do not require callers to rewrite persisted reports to obtain these guarantees.
