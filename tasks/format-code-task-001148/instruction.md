The Settings and FTU flows share mutable network records while configuring Wi-Fi. The shared WifiHelper currently assumes every record has a security list and every device has an active connection, can leave credentials from a previous authentication mode on a reused record, and may show the same access point twice when the platform reports security capabilities in a different order. Harden this public helper so callers get safe, deterministic profile objects and scan results.\n\nTreat a missing or non-array security value as an open network: the classification helpers and connection comparison must not throw when network, connection, or security data is absent. When setPassword reconfigures a network, remove credentials belonging to the previous mode (PSK, WEP, EAP, password, identity, phase2, and server-certificate fields) before applying the new mode. WPA-EAP must record its EAP method, retain password and identity only when non-empty, and omit phase2/certificate when the caller selects \"No\"/\"none\"; switching to WPA-PSK must not retain enterprise fields. isValidInput must accept SIM without credentials, require both non-empty credentials for PEAP/TLS/TTLS, and reject unsupported EAP methods and unknown key-management values while preserving the existing WPA-PSK and WEP rules.\n\ngetAvailableAndKnownNetworks must request known networks only after available networks succeeds. Its result keeps available-network order, appends known-only networks in their order, de-duplicates by SSID plus security values regardless of security-list ordering, and gives an available record precedence over a known duplicate. A known-network failure is a successful result containing available networks; an available-network failure propagates the original error and does not request known networks. Do not mutate either request's result arrays or network records. isConnected must compare SSID and normalized security safely, returning false when either side lacks connection data.
