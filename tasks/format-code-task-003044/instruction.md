I want Structurae to expose schema-based packed bitfield classes for TypeScript users. The public API should include `BitFieldMixin<T extends Record<K, number>, K extends keyof T>(schema: T): BitFieldConstructor<K>`, `BigBitFieldMixin<T extends Record<K, number>, K extends keyof T>(schema: T): BitFieldConstructor<K, bigint>`, the ready-made `BitField` constructor for 31 one-bit numeric flags, and the public `BitFieldConstructor` / `BitFieldStructure` types. A generated bitfield constructor should accept no argument, a packed `number` or `bigint`, another compatible bitfield instance, an array of numbers, or an object keyed by schema field names, and each instance should expose a mutable `.value`.

For `const Field = BitFieldMixin({ width: 16, height: 15 })`, `new Field({ width: 65535, height: 32767 }).value` should be `2147483647`, `new Field([20, 1]).value` should be `65556`, `Field.encode({ width: 20, height: 1 })` and `Field.encode([20, 1])` should both return `65556`, and `Field.decode(65556)` should return `{ width: 20, height: 1 }`. Number-backed schemas must enforce the JavaScript bitwise size limit: calling `BitFieldMixin({ a: 1, b: 31 })` should throw `TypeError` because the total layout exceeds 31 bits.

Generated instances should support `get(field): number`, `set(field, value = 1): this`, `has(...fields): boolean`, `match(matcherOrTuple): boolean`, `[Symbol.iterator](): Generator<number>`, `toJSON(): N`, `toObject(): Record<K, number>`, `toString(): string`, and `valueOf(): N`. For `const Flags = BitFieldMixin({ human: 1, gender: 1, tall: 1 })` and `const flags = new Flags({ human: 1, gender: 0, tall: 1 })`, `flags.get("gender")` should be `0`, `flags.has("human", "tall")` should be `true`, `flags.set("gender").get("gender")` should be `1`, and `flags.set("human", 0).has("human", "tall")` should be `false`. `new Field({ width: 20, height: 1 }).toObject()` should return `{ width: 20, height: 1 }`, JSON serialization should produce the packed numeric value `65556`, string coercion should produce `"65556"`, numeric coercion should produce `65556`, and iteration should yield `[20, 1]` in schema order.

Generated classes should also expose static helpers for validation, matching, and field sizing. `BitFieldMixin({ age: 7, gender: 1 }).isValid({ age: 20, gender: 0 })` should be `true`, while `.isValid({ age: 200, gender: -1 })` should be `false`; omitted fields are allowed. `BitField.getMinSize(100)` should return `7`, and `BitField.getMinSize(Number.MAX_SAFE_INTEGER)` should return `53`. For a value `new Field({ width: 8, height: 9 })`, `.match({ width: 8 })` and `.match(Field.getMatcher({ width: 8 }))` should be `true`, while `.match({ width: 7 })` should be `false`; `Field.match(value, Field.getMatcher(...))` should support the same precomputed matcher tuple path.

For large layouts, `BigBitFieldMixin` should keep the same schema-driven behavior but store the packed value as a `bigint`. With `const LargeField = BigBitFieldMixin({ location: 7, open: 1, width: 31, height: 15 })`, `new LargeField({ location: 20, open: 1, width: 3500, height: 5 }).value` should be `2748779965588n`, constructing from `[20, 1, 3500, 5]` should produce the same value, and constructing from `2748779965588n` should allow `get("width")` to return `3500`. `new LargeField(...).set("width", 3000).get("width")` should return `3000`, `.toObject()` should return `{ location: 20, open: 1, width: 3500, height: 5 }`, string coercion should produce `"2748779965588"`, `valueOf()` and `toJSON()` should return the packed bigint, and iteration should yield `[20, 1, 3500, 5]`. `LargeField.isValid({ location: 21, open: 1 })` should be `true`, `LargeField.isValid({ location: 200 })` and `LargeField.isValid({ open: 4 })` should be `false`, `LargeField.getMinSize(4375759717)` should return `33`, and a matcher from `LargeField.getMatcher({ location: 2, width: 12 })` should have `3074n` as its packed match value and work with instance `.match(...)`.
