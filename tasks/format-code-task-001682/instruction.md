I want `Deposit` instances to support automatic funding completion from a caller-owned JavaScript process. Given a deposit object, `deposit.autoSubmit()` should start watching for the deposit's Bitcoin funding transaction, wait until that transaction reaches the required confirmation count, build the funding proof, and submit it to the Ethereum deposit contract so the deposit can become ACTIVE.

`autoSubmit()` should return an object with `fundingTransaction`, `fundingConfirmations`, and `proofTransaction` promises. `fundingTransaction` resolves to the detected Bitcoin transaction, `fundingConfirmations` resolves to the transaction plus the required confirmation count, and `proofTransaction` resolves when the funding proof transaction has been submitted. If proof submission fails, the error should be emitted through the deposit's existing error handler mechanism.

I also want `deposit.autoMint()` for the same lifecycle when I want the deposit qualified and minted in one flow. It should watch the funding transaction, wait for enough confirmations, build the proof, submit the vending-machine qualify-and-mint transaction, and resolve the minted TBTC amount. `autoMint()` should return an object with `fundingTransaction`, `fundingConfirmations`, and `mintedTBTC` promises, where `mintedTBTC` resolves to the minted amount as a BN-denominated whole TBTC value.

Calling either method more than once on the same `Deposit` should not restart monitoring or submit duplicate Ethereum transactions. The first call creates the shared auto-submission state, and later calls to either `autoSubmit()` or `autoMint()` return that same state, so whichever mode starts first determines the mode for that deposit.
