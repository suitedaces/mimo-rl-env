I want Sequelize model definition to automatically add a default primary key when I define a model without one. Using an existing Sequelize instance, `sequelize.define(modelName, attributes, options?)` and `Model.init(attributes, options)` should inspect the provided attributes during definition; if no attribute has `primaryKey: true` and `options.noPrimaryKey` is not true, the resulting model should include an `id` attribute before the user-defined attributes.

For example, after `const User = sequelize.define('User', { name: DataTypes.STRING }, { timestamps: false })`, `User.primaryKeyAttribute` should be `'id'`, `User.modelDefinition.attributes.get('id')` should be an integer attribute with `allowNull: false`, `primaryKey: true`, `autoIncrement: true`, and `_autoGenerated: true`, and the user-defined `name` attribute should still be present. The same behavior should apply when defining a class with `User.init({ name: DataTypes.STRING }, { sequelize, timestamps: false })`.

If I explicitly opt out with `noPrimaryKey: true`, no default `id` attribute should be added and `primaryKeyAttribute` should remain `null` unless I declared another primary key myself. If I define an `id` attribute but do not set its `primaryKey` option at all, model definition should fail with an error telling me that an attribute called `id` was defined but `primaryKey` is not set, and that I should set `primaryKey: true` or explicitly set `primaryKey: false` if that is intentional. If I declare any attribute with `primaryKey: true`, Sequelize should not add an extra default `id` primary key.
