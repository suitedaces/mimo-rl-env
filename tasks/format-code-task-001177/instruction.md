The generation API currently accepts only one EOS piece and stops as soon as it appears, which is too rigid for tokenizers that expose aliases and for callers that need a short non-empty prefix before termination. Extend the public generation configuration and stop-condition behavior while preserving existing scalar-EOS callers.

Both GreedyGeneratorConfig and SampleGeneratorConfig must accept eos_id as either a single integer or a non-empty sequence of integer piece IDs. Any listed ID terminates its sequence. Reject an empty sequence and reject members that are not integers. Add min_generated_pieces with a default of 0; it must be a non-negative integer no greater than max_generated_pieces. An EOS match before this minimum must be emitted and must not complete the sequence; once the minimum has been reached, EOS must complete the sequence with the existing default policy of excluding the EOS piece from yielded output. Existing scalar eos_id behavior remains valid.

The maximum generated-piece limit remains inclusive: reaching it completes a sequence and yields the final generated piece. If EOS and the maximum are reached together, the sequence must still be retired and the boundary piece must be yielded (the length limit takes precedence over EOS exclusion for that step). In a batch, completion is per sequence: finished rows stop producing work while unfinished rows continue, and yielded sequence IDs continue to refer to their original input positions. Missing EOS or maximum values must continue to be rejected when a concrete stop condition is requested.
