NamespaceMerge overlays several read-only namespace resources behind the S3-compatible object API. Ordinary object and multipart-upload listings intentionally collapse the same key to the newest object, but version listings currently pass through that same key-only reducer, so older versions and delete markers disappear. This makes GET Bucket versions unusable for merged buckets and also produces incorrect pagination markers.

Make list_object_versions version-aware while preserving the existing namespace dispatch. Every successful namespace's version and delete-marker records must remain visible; only exact logical duplicates (same key, version_id, and delete_marker flag) may be collapsed, and when such a duplicate exists retain the record with the greatest create_time. Sort the merged version page by key ascending and, for records sharing a key, by create_time descending. Deduplicate common prefixes and return them in lexical order. Apply the requested limit to the combined stream of objects and common prefixes, not independently to each category. If the merged data exceeds the limit, or any upstream namespace reports truncation, set is_truncated and emit next_marker for the last emitted key; emit next_version_id_marker only when that last emitted entry is an object version. A zero limit must return an empty, non-truncated result with no markers.

Do not regress list_objects or list_uploads: those APIs must continue selecting the newest object per key from the merged namespaces and retain their existing response shape. The public methods must remain usable with a single namespace as well as multiple namespaces.
