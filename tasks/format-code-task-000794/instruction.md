I want the stateful EVM library to support nested contract-call execution when bytecode run through `FakeBlockchain` and `chain.vm.runCode(environment)` reaches the `CALL` (`0xf1`), `CALLCODE` (`0xf2`), or `DELEGATECALL` (`0xf4`) opcodes.

For `CALL`, the opcode should pop gas, target address, value, input memory offset, input size, return memory offset, and return size from the stack; read the requested input bytes from caller memory; execute the target account's code in a nested frame whose account is the target, whose caller is the current account, whose value is the popped value, and whose depth is one greater than the caller. For `CALLCODE`, it should execute the target account's code while keeping the current account as the execution account and using the current account as caller. For `DELEGATECALL`, it should execute the target account's code while keeping the current execution account and current caller, and with zero call value.

Each nested call should run inside a checkpointed blockchain layer. If the nested frame stops without reverting, commit that layer, push `1` to the caller stack, copy up to the requested return size into caller memory at the requested return offset with zero padding, store the full nested return bytes as the caller's last return data, and advance the caller program counter past the call opcode. If the nested frame reverts or otherwise does not finish cleanly, roll back the layer, push `0` to the caller stack, clear the caller's last return data, leave return memory uncopied, and still advance past the call opcode.

A concrete session should work like this: create `const chain = new FakeBlockchain()`, install an account at address `"2"` whose code stores `0x2a` in memory and returns 32 bytes, then run caller bytecode that pushes return size `32`, return offset `0`, zero input size and offset, zero value, address `2`, gas, and executes `CALL`. The resulting `state.stack` should contain a success flag of `1`, `state.memory` should contain the 32 returned bytes at offset `0`, and `state.lastReturned` should equal those 32 bytes. If the target account instead writes storage and then executes `REVERT`, the caller should receive stack flag `0`, the target storage write should not be visible through the blockchain after the call, and `state.lastReturned` should be an empty array.
