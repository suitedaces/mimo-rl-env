I want the `ocrmypdf` command to accept a supported image file anywhere it accepts the `input_pdf_or_image` positional input, convert that single image into the pipeline's input PDF, and then continue OCR normally. For example, `ocrmypdf --image-dpi 200 page.png output.pdf` should treat `page.png` as a one-page document, use 200 DPI for the image-to-PDF layout, produce `output.pdf`, and exit with code 0 when the rest of the OCR run succeeds.

If the image has usable embedded DPI metadata above the low-credibility threshold, `ocrmypdf image.png output.pdf` should use that embedded resolution without requiring `--image-dpi`. If the image has no embedded DPI, or its embedded DPI is not credible, the command should fail before page analysis with exit code 2 and an error telling me to estimate the scan resolution and pass `--image-dpi`.

The image input checks should reject image formats that cannot be safely converted: RGBA or LA images should fail with exit code 2 and an error about removing the alpha channel, and CMYK images without an ICC profile should fail with exit code 2 and an error that the CMYK image has no ICC profile. If the file is not a readable supported image after it is determined not to be a PDF, the command should fail with exit code 2, report useful diagnostics such as missing, directory, regular file, or empty-file status where applicable, and should not create the requested output PDF.
