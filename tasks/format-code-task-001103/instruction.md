Teach the public `dask.compute` function to compute Dask collections nested inside ordinary Python containers. Today only arguments that are themselves Dask collections are discovered, so a structure such as `{'left': [x + 1], 'total': x.sum()}` is returned with lazy objects still inside it.

By default, `compute` should recursively traverse built-in lists, tuples, dictionaries, and sets. It must discover collections in dictionary keys as well as values and in set members, compute every discovered collection, and rebuild the same container structure and built-in container types with concrete results in the corresponding positions. Non-Dask values and empty containers must survive unchanged, and the outer return value must remain a tuple with one result per positional argument.

Nested collections are still part of one `compute` operation: merge their graphs and honor each collection's optimizer and finalizer, so shared dependencies are evaluated once rather than independently for each leaf. Scheduler selection must consider all collections found during traversal. With no explicit `get=`, incompatible default schedulers must raise the same `ValueError` as incompatible top-level collections; an explicit `get=` must override that conflict. Any other scheduler keyword arguments must continue to reach the selected scheduler.

Add a `traverse` keyword argument, defaulting to `True`. When `traverse=False`, only positional arguments that are directly Dask collections are computed; containers are treated as literal values and returned untouched even if they contain collections. Preserve the existing behavior for directly supplied collections and literal positional arguments.
