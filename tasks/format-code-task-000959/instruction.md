Harden multi-instance Pi-hole configuration so splitting is the single validation boundary for client settings. Today `EnvConfig.Split()` can return unusable entries (including empty hosts, unsupported protocols, ambiguous credentials, and malformed IPv6 URLs), leaving failures until client construction or HTTP use. Callers should be able to treat a successful split as a complete, normalized set of endpoints.

For `pihole_protocol`, `pihole_port`, `pihole_password`, and `pihole_api_token`, retain the existing list model: an option may be omitted, supplied once for every hostname, or supplied once per hostname. Any other count must fail and the error must name the option, the supplied count, and the hostname count. Empty values in a per-host string list remain positional; they must not shift later credentials onto an earlier host. Trim string values. A missing or blank protocol means `http`, and protocol matching is case-insensitive after trimming. A missing or zero port means `80`. Missing credentials remain empty.

Normalize each hostname by trimming whitespace, lowercasing DNS names, removing a terminal DNS root dot, and accepting either bare or bracketed ordinary IPv6 literals while storing the literal without brackets. A hostname field must contain only a DNS hostname, IPv4 address, or IPv6 literal: reject empty values, schemes, user info, paths, query strings, fragments, and embedded ports (the port has its own option). Only `http` and `https` protocols are valid. Password and API-token authentication are mutually exclusive for each resulting instance, although different instances may use different methods.

Reject duplicate effective endpoints after normalization. Endpoint identity is the `(protocol, hostname, port)` tuple, so credentials do not make duplicate endpoints distinct, while the same hostname with a different protocol or port is allowed. Splitting is atomic: every validation or cardinality failure returns a nil config slice. Value errors must identify the relevant option and 1-based instance; duplicate errors must identify both 1-based instances. Diagnostics must never include password or API-token contents. Reject a split with no hostnames.

Keep `Config.Validate()` useful for callers that construct one config directly: it must enforce the same per-instance hostname, protocol, and mutually-exclusive-authentication rules, and accept DNS names plus bare or bracketed IPv6 literals. `PIHoleLoginURL()` and `PIHoleStatsURL()` must continue returning their existing `/admin/` paths and query string, omit the authority port when `PIHolePort` is zero, preserve existing DNS/IPv4 URL output, and generate a valid single-bracket authority for both bare and already-bracketed IPv6 input. `Config.String()` must continue redacting both authentication fields.
