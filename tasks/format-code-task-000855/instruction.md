The current `sortObjectsArray` helper is useful for simple flat records, but consumers now need to order data from API responses where the sort key may be nested and ties need a deterministic secondary key. Extend the exported comparator factory without breaking callers that already pass a single property string.

The factory must accept either the existing string form or an ordered array of criteria strings. A criterion is a dotted property path, optionally prefixed with `-` to request descending order; without the prefix it is ascending. Criteria arrays are evaluated lexicographically from left to right: the first non-equal criterion decides the result, and later criteria are consulted when earlier values compare equal. A dotted path follows each named segment through the record; if a segment cannot be read, that value is considered missing.

Treat both `null` and `undefined` (including a missing path) as missing values. For every criterion, missing values must sort after all defined values in both ascending and descending modes. Two missing values compare equal for that criterion, so a later criterion can still order those records; if every criterion is equal, the comparator must report equality so the caller's stable `Array.sort` preserves input order. Defined values should retain the helper's normal JavaScript relational ordering.

Keep the public named export and the legacy single-string behavior, including the current descending prefix. When every record lacks a requested legacy property, comparisons remain equal and the original array order is unchanged. Add focused regression coverage for the new combinations while retaining the existing sort tests. `sortObjectsArray` must remain directly usable as the callback passed to `Array.prototype.sort`.
