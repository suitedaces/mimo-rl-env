Make `lerna exec` suitable for reproducible automation by adding explicit environment overlays for commands run in workspace packages. Today `exec` deliberately starts children with the caller's environment plus Lerna's two documented package/root variables, but there is no way to provide a checked-in set of values or package-specific overrides without mutating the shell that launched Lerna.

Add repeatable `--env-file <path>` and `--package-env-file <path>` options, plus repeatable inline `--env KEY=VALUE` assignments. A common env-file path is resolved relative to the Lerna workspace root and must exist; package-env-file paths are resolved separately relative to each package being executed, and a package may simply have no such file. Parse files using dotenv-style syntax: blank lines and full-line comments are ignored, quoted values are unquoted, and empty assignments remain present as empty strings.

For every package, merge values in this order: common files in command-line order, then existing package-relative files in command-line order, then the inherited process environment, then inline assignments in command-line order. A later value at a given layer replaces an earlier value; the first `=` separates a key from its value so values may contain further equals signs. Inline values may be empty. The inherited environment therefore wins over files, while inline values win over inherited values.

The child environment must always set `LERNA_PACKAGE_NAME` to the actual package name and `LERNA_ROOT_PATH` to the workspace root, even when files or inline assignments try to override them. Apply the same environment semantics to ordinary buffered execution and to `--parallel` execution, with each package receiving its own package-relative overlay.

A missing required common file must fail before any package command starts with the exact message `Environment file not found: <path>`. An inline entry without an `=` must likewise fail before starting commands with the exact message `Invalid environment assignment "<entry>"; expected KEY=VALUE`. In either case no package command may start or produce package-command side effects. Loading overlays must not mutate the parent Node process environment or leak values into a later `lerna exec` invocation. Existing invocations without these new options must continue to execute in the selected packages as before.
