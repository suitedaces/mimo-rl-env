Declarative tailscaled configurations are often repeated across machines, and maintaining copies makes shared defaults difficult to update safely. Add composable configuration files to the public `conffile.Load` behavior.

A top-level `include` member may be either one path string or an array of path strings. A list is applied from left to right. Relative paths are resolved from the directory of the document containing that particular `include`; absolute paths are accepted unchanged. Included documents may recursively include other documents. Values of any other JSON type, and arrays containing non-string entries, must be rejected as invalid include declarations.

Composition is deterministic. For each document, first merge its resolved includes in list order, then merge the document's own members except `include`. When both winning and existing values are JSON objects, merge them recursively. In every other case the later value replaces the earlier one. Replacement must be based on presence, not truthiness: `false`, an empty string, an empty array, and explicit `null` all override inherited values. Thus a later include wins over an earlier include, and the including document wins over all of its includes.

Every participating document must be valid HuJSON and must independently declare the supported `version` value `alpha0`. Missing and unsupported versions in an included document are errors even if a later layer declares a valid version. After composition, decode the effective document with the same strict schema as today, so unknown configuration members are still rejected. Missing files and HuJSON parse failures must identify the offending source path; version failures must identify that source and the bad or missing version.

Reject direct and indirect include cycles. The cycle error must clearly describe recursive/cyclic inclusion and identify every file in the loop. Cycle tracking is limited to the active include chain: the same shared file may be included through separate completed branches without being treated as a cycle.

The returned `Config` continues to describe the root document: `Path` points to that root and `Raw` contains its exact original bytes, including comments, trailing commas, and the include declaration. `Std` is valid standard JSON for the fully merged, include-free effective document; it preserves the winning source members and explicit values, including empty and null values. `Parsed` and `Version` are derived from that same effective document. Standalone files without `include` must continue to accept HuJSON comments and trailing commas and produce their existing parsed values.
