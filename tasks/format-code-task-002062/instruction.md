I want Solid model instances to expose `toJsonLD(options?: { ids?: boolean; timestamps?: boolean; history?: boolean }): Record<string, unknown>` so application code can export the current in-memory model graph as JSON-LD without saving it. For example, if I create a `Person` model with a URL, `name`, `nickName`, an array of friend URLs, and a `createdAt` date, then `person.toJsonLD()` should return a JSON-LD object with the model `@id`, `@type`, RDF `@context`, ordinary RDF fields such as `name`, compacted fields such as `vcard:nickname`, key arrays as `{ "@id": ... }` references, and timestamp metadata rendered as an xsd dateTime value.

When loaded Solid document relations are present, `toJsonLD()` should include those related models in the JSON-LD output using the relation's RDF property or reverse property. For example, a `Movie` with a loaded `actions` relation should serialize the movie plus an `actions` array containing each related action's JSON-LD data, while avoiding recursive re-embedding of the parent movie.

The options should default to `{ ids: true, timestamps: true, history: true }`. If I call `model.toJsonLD({ ids: false, timestamps: false, history: false })`, the returned JSON-LD should omit model `@id` values, omit timestamp metadata relations, and omit history operation relations from the exported graph, including for related models. Calling `toJsonLD` must not mutate the model or its related models; after a minimal export, their URLs, metadata relations, history operations, dirty state, and loaded relations should remain available on the original instances. The method should only compute and return JSON-LD in memory, with no filesystem, network, or engine writes.
