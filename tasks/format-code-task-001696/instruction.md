I want the `KWStyle` command-line tool to support a simple XML export mode for parser errors. The invocation should be `KWStyle -xml <config.kws.xml> -exportxml <report.xml> <input-file>`; after parsing the input file with the selected configuration, KWStyle should create or overwrite `<report.xml>`. The report should contain one `<Error>` block for each collected parser error, in parser/file order, with exactly these child elements on separate lines: `SourceLineNumber1` with the first line, `SourceLineNumber2` with the last line covered by the error, and `ErrorNumber` with KWStyle's numeric error code. Do not wrap the blocks in an extra root element and do not include filenames, descriptions, warnings, or HTML markup in this simple XML file. For the tabs configuration in `Testing/Data/kwsTabsTest-KWStyleConfiguration.kws.xml` run against `Testing/Data/kwsTabsTest-test.cxx`, the file should contain four `<Error>` blocks for lines 3, 4, 5, and 6, each with matching `SourceLineNumber1`/`SourceLineNumber2` and `ErrorNumber` 10. For a file that produces no parser errors, the export file should be created but contain no `<Error>` blocks. If the report path cannot be opened for writing, KWStyle should print `Cannot open file for writing:` and no XML report content should be produced.
