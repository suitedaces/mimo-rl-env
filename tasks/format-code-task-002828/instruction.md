I want `remix-auth-socials` to expose first-class Google OAuth support from the package entry point. The public API should include `GoogleStrategy<User>`, `GoogleStrategyOptions`, `GoogleProfile`, `GoogleExtraParams`, `GoogleScope`, `GoogleStrategyDefaultScopes`, `GoogleStrategyDefaultName`, and `SocialsProvider.GOOGLE === "google"`.

`GoogleStrategy` should be constructed as `new GoogleStrategy<User>(options: GoogleStrategyOptions, verify: OAuth2Strategy<User>["verify"])`. `GoogleStrategyOptions` requires `clientId: string`, `clientSecret: string`, and `redirectURI: string`, and accepts optional `scopes?: string[]`, `accessType?: "online" | "offline"`, `includeGrantedScopes?: boolean`, `prompt?: "none" | "consent" | "select_account"`, `hd?: string`, and `loginHint?: string`.

A default instance should have `strategy.name === "google"`, use `https://accounts.google.com/o/oauth2/v2/auth` as the authorization endpoint, use `https://oauth2.googleapis.com/token` as the token endpoint, and request the default scopes `openid`, `https://www.googleapis.com/auth/userinfo.profile`, and `https://www.googleapis.com/auth/userinfo.email` when no custom scopes are provided. When the OAuth authorization request is created, it should add `access_type` using the configured value or `online`, and `include_granted_scopes` using the configured value or `false`; if `prompt`, `hd`, or `loginHint` are configured, the resulting Google authorization parameters should include `prompt`, `hd`, and `login_hint` respectively.

The class should also provide `GoogleStrategy.userProfile(tokens: OAuth2Tokens): Promise<GoogleProfile>`. It should request `https://www.googleapis.com/oauth2/v3/userinfo` with an `Authorization: Bearer <access token>` header using `tokens.accessToken()`. If Google returns `{ "sub": "g-1", "name": "Alice Example", "given_name": "Alice", "family_name": "Example", "picture": "https://cdn.test/alice.jpg", "locale": "en", "email": "alice@example.com", "email_verified": true, "hd": "example.com" }`, it should resolve to a profile with `id: "g-1"`, `displayName: "Alice Example"`, `name.givenName: "Alice"`, `name.familyName: "Example"`, `emails: [{ value: "alice@example.com" }]`, `photos: [{ value: "https://cdn.test/alice.jpg" }]`, and `_json` equal to the full Google response. If Google returns `{ "sub": "g-2", "name": "Bob Stone", "given_name": "Bob", "family_name": "Stone", "picture": "https://cdn.test/bob.png", "locale": "fr", "email": "bob@example.net", "email_verified": false, "hd": "" }`, the same fields should be normalized to Bob's values. If the userinfo response is not OK, `userProfile` should reject with `Error` whose message starts with `Failed to fetch user profile:` and includes the response status text.
