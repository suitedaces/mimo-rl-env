I want a stateful `Pool` class for running FFmpeg worker jobs in the browser. It should be used as `const pool = new Pool(); const files = await pool.spawnJob({params, onLog, MEMFS, WORKERFS}); pool.destroy();` where `params` is the FFmpeg argument array, `onLog(line)` receives each stdout and stderr line from the worker, `MEMFS` is an optional list of in-memory files, and `WORKERFS` is an optional list of browser Blob/File inputs to mount for the job.

Each `spawnJob(...)` call should create a fresh ffmpeg.js worker, wait for its `ready` message, run FFmpeg with the provided arguments, and return a Promise that resolves to the worker's output `MEMFS` file list when the job finishes successfully. For example, one call can run video pass arguments and resolve with files such as pass logs or `1.webm`, while another call on the same `Pool` can run muxer arguments and resolve with `out.webm`; both jobs should report their stdout/stderr through their own `onLog` callback. Multiple calls on the same `Pool` may be in flight at once, and each worker should be removed from that pool after success or failure.

If the worker reports `{type: "error", data: "boom"}`, the Promise should reject with `Error("boom")`. If the worker exits with a non-zero code such as `7`, the Promise should reject with `Error("Process exited with 7")`. If the first worker message is not `ready`, the job should reject with an error explaining the bad worker message. Calling `destroy()` should terminate every worker currently owned by that `Pool`, and calling `destroy()` again should be harmless.
