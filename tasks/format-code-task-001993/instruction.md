I want cursor-based pagination methods on an opened `*graphdb.DB` so callers can page through stored graph data without offset scans. The public API should include `ListNodes(afterID graphdb.NodeID, limit int) (*graphdb.NodePage, error)`, `ListEdges(afterID graphdb.EdgeID, limit int) (*graphdb.EdgePage, error)`, and `ListNodesByLabel(label string, afterID graphdb.NodeID, limit int) (*graphdb.NodePage, error)`.

`graphdb.NodePage` should expose `Nodes []*graphdb.Node`, `NextCursor graphdb.NodeID`, and `HasMore bool`, with JSON field names `nodes`, `next_cursor`, and `has_more`. `graphdb.EdgePage` should expose `Edges []*graphdb.Edge`, `NextCursor graphdb.EdgeID`, and `HasMore bool`, with JSON field names `edges`, `next_cursor`, and `has_more`.

For `ListNodes`, passing `afterID == 0` should return the first page; passing a prior page's `NextCursor` should continue after that node ID. For example, after adding two nodes Alice and Bob, `ListNodes(0, 1)` should return one node, set `HasMore == true`, and set `NextCursor` to the returned node's ID; calling `ListNodes(page.NextCursor, 1)` should return the next node. If `limit <= 0`, the method should use a default page size of 50. Empty result pages should return an empty, non-nil `Nodes` slice, `HasMore == false`, and `NextCursor == 0`.

For `ListEdges`, the same cursor behavior should apply over edge IDs and the result should contain decoded `*graphdb.Edge` values with their `ID`, `From`, `To`, `Label`, and `Props` fields populated. For example, after creating an edge `alice -[KNOWS]-> bob`, `ListEdges(0, 1)` should return that edge and set `NextCursor` to its edge ID.

For `ListNodesByLabel`, the method should page only nodes that have the requested label. For example, with Alice labeled `Person` and a separate unlabeled node, `ListNodesByLabel("Person", 0, 10)` should return Alice and not the unlabeled node, and a later call using the returned `NextCursor` should skip nodes at or before that cursor. All three methods should return the error `graphdb: database is closed` when called after `db.Close()`.
