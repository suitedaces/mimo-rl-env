The Breakpad stackwalker emits a pipe-delimited stream that is converted by the public pipe_dump_to_json_dump helper before processors consume it. In production the stream can contain sparse thread ids, records arriving out of order, malformed or unknown lines, and a crash declaration whose thread is absent or empty. The converter currently treats the happy-path ordering as an invariant, which can silently attach bad rows to the wrong thread or fail while constructing the summary used by signature generation. Harden this boundary while preserving the existing JSON shape and canonical behavior.

Recognize an optional Status|VALUE record as the top-level status field, and continue ignoring unrelated record types. Only non-negative integer thread ids and rows with a valid integer frame number are frame records; invalid rows must not alter any thread. Create empty thread entries for gaps in otherwise valid ids, and order each thread's frames by ascending frame number with stable encounter order for duplicate numbers. frame_count must equal the number of retained frames.

The optional crashing_thread summary should be emitted only when the declared index refers to an existing thread containing at least one retained frame. An absent, negative, or out-of-range index, and an existing thread with no frames, must leave the summary out without raising. For a valid thread, report its index, the complete retained-frame count in total_frames, and at most the first ten ordered frame objects in frames. Keep module, OS/CPU, crash-info extraction, sparse-thread padding, and all existing valid-stream output compatible.
