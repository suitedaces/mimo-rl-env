I want a `Ppar(*patterns)` event pattern that lets me run several child event patterns in parallel through the normal pattern stream API. After constructing it, converting it with `iter()` or `stm.stream()` should produce a stateful event stream whose `next(inevent=None)` calls merge the child streams by scheduled logical time.

Each child should start scheduled at time 0 in the order it was passed. On every step, the stream should advance the child scheduled earliest, convert that child output to an event, schedule that same child again at the current logical time plus the event's own `delta`, and yield the event with `delta` replaced by the time until the next scheduled child event. For example, if child A emits events with values `a1`, `a2` and `delta == 1`, and child B emits events with values `b1`, `b2` and `delta == 0.5`, then `Ppar(A, B)` should yield `a1` with `delta == 0`, then `b1` with `delta == 0.5`, then `b2` with `delta == 0.5`, then `a2` with `delta == 0` when both are scheduled at beat 1.

If one child stream ends while others remain, the parallel stream should yield a silent event for the gap until the next remaining child event. If all child streams end, the `Ppar` stream should stop cleanly with the standard stream exhaustion behavior; `Ppar()` with no children should stop immediately.
