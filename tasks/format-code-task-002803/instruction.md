I want TediCross startup to let me keep bot tokens out of settings.yaml by using the public token placeholder `env`. When I run `node dist/main.js --config ./settings.yaml`, a YAML file with `telegram.token: env` should authenticate the Telegram bot with `TELEGRAM_BOT_TOKEN`, and `discord.token: env` should authenticate Discord with `DISCORD_BOT_TOKEN`; the literal string `env` must not be passed to either bot client as the token.

If the YAML omits `telegram.token` or `discord.token`, startup should apply the same `env` placeholder default for that platform token when normalizing settings. If a token is a normal literal value such as `12345:abc` or `discord-secret`, startup should use that literal value unchanged and serialize the same literal back through the normalized settings object. This behavior should be deterministic for the same YAML and environment variables, and it should not mutate unrelated Telegram or Discord settings while resolving tokens.
