Plugin startup currently accepts a requested list but does not give callers a reliable resolved result: transitive dependencies can be skipped, ordering varies with set iteration, and a bad graph can start loading plugins before the configuration error is exposed. That makes plugin startup non-reproducible and leaves callers unable to determine what is actually available.

Make plugin dependency resolution a deterministic, fail-fast planning step. When `loadPlugins` is given requested plugin directory names, it must resolve their full transitive dependency closure from the discovered plugin metadata, load every resolved plugin at most once, and return the names that were successfully loaded. Dependencies must always load before the plugins that require them; when several plugins are independently eligible, use lexicographic directory-name order so the returned sequence is stable. A plugin requested more than once must still be loaded once.

Reject an unknown requested plugin, an unknown transitive dependency, or a dependency cycle before calling the plugin loader for any member of that request. Keep the existing best-effort behavior for runtime plugin load errors: a failed plugin must not abort unrelated plugins, but no plugin whose direct or transitive dependency failed may be loaded or included in the returned result. `toposort` remains a public utility and must continue to produce dependency-first layers, including support for dependencies that are not original graph keys and self-dependencies being ignored, without modifying the caller-provided graph or its dependency sets.
