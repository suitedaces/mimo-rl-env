Complete the Joda-style fractional-second and time-zone pattern support in `libbeat/common/dtfmt`. The package currently has a compiled formatter with several public output paths, but it rejects `S`, `z`, and `Z`, which prevents callers from producing precise, zone-aware timestamps without leaving this formatter.

An unquoted run of one through nine `S` characters must emit exactly that many leading decimal digits from the timestamp's nine-digit nanosecond fraction. The value is left-zero-padded to nine digits before selecting the requested width, so output is truncated rather than rounded; for example, 5 milliseconds is `0`, `005`, and `005000000` for widths 1, 3, and 9. A run longer than nine is an invalid pattern and `NewFormatter` must return an error.

Time-zone patterns use the zone attached to the supplied `time.Time`, without converting the timestamp. For whole-minute offsets, one `Z` emits a signed compact offset such as `+0545`, `-0330`, or `+0000`; two emit the colon form `+05:45`, `-03:30`, or `+00:00`; three or more emit `time.Time.Location().String()`. One or more lowercase `z` characters emit the abbreviation returned by `time.Time.Zone()`, independent of token width. These tokens must compose normally with the existing calendar and clock fields.

Quoted occurrences of `S`, `z`, and `Z` remain ordinary literals, including quoted runs that would be invalid if unquoted. The new behavior must be identical through the top-level `Format` function and a compiled formatter's `Format`, `AppendTo`, and `Write` methods. `AppendTo` must preserve its input prefix, and `Write` must return the actual number of bytes written. Existing supported patterns and literal behavior must continue to produce their current results.
