Applications often need the same readable URL slug in separate tenant or locale namespaces, but uniqueness in HasSlug is currently global for the model table. Add an opt-in scoped-uniqueness option without changing existing users' behavior.

Expose a fluent `SlugOptions::scopeUniqueSlugsBy($fieldNames)` method. It accepts either one model attribute name as a string or an array of attribute names and returns the same `SlugOptions` instance so it composes with the existing option builder. A configured empty array, an empty string, or an array containing an empty attribute name is invalid: configuring or saving with it must throw `Spatie\Sluggable\InvalidOption`, and the invalid model must not be persisted.

When no scope option is configured, slug collisions remain global exactly as they are today. When a scope is configured, another row is a collision only when its slug and every configured scope attribute equal the current model's values. Null is a real scope value: null matches null but not a non-null value. Scope attributes constrain only the uniqueness lookup; they must not be incorporated into the generated slug text. Thus equal source text in different scopes may keep the same unsuffixed slug, while equal source text in the same scope receives the package's normal `-1`, `-2`, ... suffixes. For compound scopes, differing in any one configured attribute is enough to make the slug available.

Apply the rule on both creates and updates. If an existing model moves between scopes, uniqueness must be evaluated against its destination/current scope values even when its slug source did not change. As in the existing global lookup, the row being updated must not collide with itself, so an unrelated later update cannot advance its suffix. `allowDuplicateSlugs()` must continue to bypass uniqueness checks even when a scope is configured. Preserve the existing source normalization, numeric suffix format, maximum-length behavior, and default global-uniqueness behavior for models that do not opt in.
