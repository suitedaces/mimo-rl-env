SunPy's dependency diagnostics are used in bug reports and environment checks, but the current report can be misleading: it treats every metadata marker as a simple string, treats an explicitly empty extra selection like the default selection, and renders aggregate extras as if SunPy were an optional dependency. Make the dependency-reporting API follow PEP 508 metadata and make system_info() a useful, stable report.

get_requirements(package) must parse each requirement with packaging's PEP 508 rules. Requirements whose environment markers are false for the running interpreter are inactive. A requirement with an extra marker is associated with every named extra for which that marker is true (including markers combining extra tests with other environment predicates); requirements without an extra marker belong to required. Preserve the parsed Requirement objects and de-duplicate a package within a group.

find_dependencies(package, extras=None) must use only the requested groups: None means the required group, an explicitly empty iterable means no groups, and unknown names are ignored. It must not count the queried package itself as one of its dependencies, even when an aggregate extra refers back to it. Installed dependencies are returned with their versions; missing dependencies are returned with the existing Missing <requirement> representation. When selected groups require the same missing package, combine their constraints into one report while retaining all applicable constraints.

missing_dependencies_by_extra() must expose the required group and each active extra discovered in metadata, honor exclude_extras, and apply the same self-dependency rule; self-only aggregate groups therefore report an empty mapping rather than a missing SunPy entry.

system_info() must retain its existing headings, general information, installation path, and required-dependency section, while its Optional Dependencies section lists the concrete dependencies from all non-required groups. The optional list is unique and alphabetically sorted, reports installed versions or Missing <requirement> text, and never includes SunPy itself or a required-only package. The output must remain usable when optional packages are absent.
