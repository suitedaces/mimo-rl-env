I want the MiniStar CLI to provide an interactive `createPlugin` command for starting a new plugin package. When I run `npx mini-star createPlugin`, it should prompt for `Plugin Name`, reject an empty name with `Require Plugin Name!`, prompt for `Language` with `Typescript` producing `ts` and `Javascript` producing `js`, then ask `Ensure to create plugin: [<name>] ?` before writing anything. If I decline the confirmation, the command should exit successfully without creating plugin files or printing the completion message. If I confirm a JavaScript plugin named `demo`, it should create `<pluginRoot>/plugins/demo/package.json` whose `name` is `@<scope>/demo`, `main` is `src/index.js`, `version` is `0.0.0`, `private` is `true`, and `dependencies` is `{}`, copying configured `author` and `license` into the package when those config values are present; it should also create `<pluginRoot>/plugins/demo/src/index.js` containing `console.log("Hello World!")` and print `Plugin [demo] create completed: <absolute path to src/index.js>` before exiting with code 0. If I confirm a TypeScript plugin, it should use `src/index.ts` in the package metadata, create the same starter source file at that path, and also write `tsconfig.json` extending `../../tsconfig.json` with `compilerOptions.rootDir` set to `./src`. The repo-level `npm run plugin:new` shortcut should invoke this same `createPlugin` flow. If the target plugin directory cannot be created, for example because `<pluginRoot>/plugins/<name>` already exists, the command should fail with a non-zero exit instead of silently overwriting the existing plugin.
