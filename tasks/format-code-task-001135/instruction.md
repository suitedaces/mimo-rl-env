The package metadata command needs to behave predictably for automation and for packages that use rich JSON metadata. Today, npm pkg set rejects an assignment whose value is intentionally empty, even though an empty string is a valid package.json value; the same limitation affects appending an empty string to an existing array. The command must distinguish a missing value separator from an explicit empty value, preserve every character after the first separator (including additional equals signs), and write the resulting nested property or array item.

When --json is enabled, values supplied to set are JSON values rather than strings. Preserve the type and value of valid false, zero, null, and empty-string inputs. Invalid assignment syntax (no equals sign or no key) must report the normal usage error, and processing a multi-assignment invocation must be all-or-nothing: if a later assignment is invalid, no earlier assignment from that invocation may be persisted.

npm pkg get should treat a missing property and a property below a null intermediate as an absent result, returning the normal empty object instead of throwing. Dot-notation expansion over an array of objects must skip null entries and still return values from later objects. Existing workspace targeting remains part of the public contract: with a workspace selector, reads and writes apply only to the selected workspace, leave sibling workspaces unchanged, and workspace reads use the command's normal workspace-keyed JSON output. Existing non-edge npm pkg behavior should remain compatible.
