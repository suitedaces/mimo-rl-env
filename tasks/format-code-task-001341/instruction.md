I want a GCS-backed retriever in `github.com/google/cql/retriever/gcs` for evaluating CQL against FHIR R4 bundles stored in Cloud Storage. The public API should be `func New(gcsFile, endpointURL string) (*Retriever, error)` and `func (r *Retriever) Retrieve(ctx context.Context, fhirResourceType string) ([]*r4pb.ContainedResource, error)`.

A typical session should work like: `ret, err := gcsretriever.New("gs://TestBucket/TestFile", serverURL)` and then `patients, err := ret.Retrieve(ctx, "Patient")`. If `gs://TestBucket/TestFile` contains a FHIR Bundle JSON with a Patient resource whose id is `1`, an Encounter resource whose id is `1`, and an Observation resource whose id is `1`, then `Retrieve(ctx, "Patient")` should return exactly the Patient contained resource, `Retrieve(ctx, "Encounter")` should return exactly the Encounter contained resource, and `Retrieve(ctx, "Condition")` should return an empty slice. Repeated `Retrieve` calls on the same constructed retriever should return data from the already-loaded bundle rather than reading the GCS object again.

`New` should reject malformed GCS paths such as `"not-a-gs-path"` by returning a nil retriever and a non-nil error that identifies the path parsing failure. If the bucket client cannot be created or the object reader cannot be opened, `New` should return a nil retriever and a non-nil error that identifies the failed GCS access. If the object is readable but does not contain valid R4 FHIR Bundle JSON, `New` should return a nil retriever and the parsing error. Separate `Retriever` instances created from different GCS paths should keep their loaded bundle contents independent.
