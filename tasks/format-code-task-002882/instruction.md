The Python client exposes the BYTES and BF16 tensor codecs used by both HTTP and gRPC inference results. Their wire formats are deliberately simple, but malformed server responses currently leak `struct.error`/`TypeError`, and callers that pass a buffer-protocol value such as `bytearray` or `memoryview` do not get the same behavior as callers passing `bytes`. In addition, byte-like objects stored in an object array can be converted to their Python representation instead of being sent as their raw bytes. Harden this public utility surface without changing the wire formats or the existing NumPy-facing return types.

`deserialize_bytes_tensor` must accept any bytes-like object, parse little-endian uint32 length prefixes in sequence, and return a one-dimensional `np.object_` array in wire order. Element contents are opaque bytes: embedded NULs and zero-length elements must be preserved exactly, and an empty payload returns an empty object array. A payload with an incomplete prefix, a length that extends beyond the available bytes, trailing bytes that cannot begin a complete element, or a value that does not expose the buffer protocol must fail fast with `InferenceServerException` rather than exposing a lower-level unpacking/type exception or returning partial data.

`deserialize_bf16_tensor` must likewise accept bytes-like inputs and decode every two-byte little-endian bfloat16 value to the existing one-dimensional `np.float32` result. Any non-buffer input or payload whose total length is not a multiple of two must raise `InferenceServerException` before a partial result can escape.

When `serialize_byte_tensor` receives an object-dtype array, each element that is `bytes`, `bytearray`, `memoryview`, or a NumPy bytes scalar must be framed using its raw byte contents. Serialization must retain C-order traversal, embedded NULs, and empty elements. Keep all existing public function names and return conventions intact.
