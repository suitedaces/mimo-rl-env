I want `urlwatch` to support browser-rendered jobs in the jobs YAML so I can monitor pages that need JavaScript before their final HTML is available. When my jobs file contains an entry with `kind: browser` and `navigate: "http://127.0.0.1:8000/page.html"`, or just a unique `navigate` key, running `urlwatch --urls jobs.yaml --test-filter 1` should launch a Playwright browser, navigate to that URL, and print the rendered page HTML to stdout, including DOM changes made by page scripts.

The job should accept `browser`, `useragent`, `wait_until`, and `wait_for` options. If `browser` is omitted it should use Chromium; if `useragent` is set it should create the page with that user agent; if `wait_until` is set it should pass that load-state value to navigation; if `wait_for` is set it should wait for the matching CSS or XPath locator before returning the page content. The deprecated `wait_until` values `networkidle0` and `networkidle2` should still work by treating them as `networkidle` and logging a warning.

The job location shown by commands such as `urlwatch --urls jobs.yaml --list` should be the configured `navigate` URL unless `user_visible_url` is set, in which case that value should be shown instead. `urlwatch --urls jobs.yaml --change-location 1 http://127.0.0.1:8000/other.html` should update the browser job's navigation target. A successful browser job run should exit 0 through `--test-filter`; if Playwright cannot navigate or the configured selector never appears, the command should fail non-zero rather than returning stale or partial content.
