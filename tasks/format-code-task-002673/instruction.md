I want Turbolift to provide a `turbolift pr-status` command for checking the rollout status of pull requests in a campaign. The command should read campaign data from `repos.txt` by default, accept `--repos <file>` to use a different repository list, and `turbolift pr-status --help` should exit 0 while showing the `pr-status` command, the `--list` flag, and the `--repos` flag.

When I run `turbolift pr-status` in a campaign with cloned working copies under `work/<org>/<repo>`, it should check each repository for the pull request matching the campaign branch, print progress lines like `Checking PR status for org/repo1`, finish with `turbolift pr-status completed`, and exit 0. Without `--list`, stdout should include a summary table with `State` and `Count` columns and rows for `Merged`, `Open`, `Closed`, `Skipped`, and `No PR Found`; for one merged PR, one open PR, one closed PR, no skipped repos, and no missing PRs, those rows should show counts of 1, 1, 1, 0, and 0 respectively. It should not print per-repository detail rows unless `--list` is supplied.

When I run `turbolift pr-status --list`, it should still print the summary and should also print a detail table with columns `Repository`, `State`, `Reviews`, `Checks status`, and `URL`. The check status shown for each row should be `FAILURE` if any status check contains `FAILURE`, otherwise `PENDING` if any status check contains `PENDING`, otherwise `SUCCESS`. For example, an open PR with review decision `REVIEW_REQUIRED` and one failed check should appear as an `OPEN REVIEW_REQUIRED FAILURE` row, while a merged PR with review decision `APPROVED` and only successful checks should appear as `MERGED APPROVED SUCCESS`.

If a repository listed in the campaign has no working copy at `work/<org>/<repo>`, the command should warn that the directory does not exist, count it under `Skipped`, omit it from the detail table, and still exit 0. If checking a repository does not find a campaign pull request, the command should log `No PR found`, count it under `No PR Found`, continue with the remaining repositories, and still exit 0.

The command should total pull request reactions across all reported PRs and print them after the summary as `Reactions:` followed by only nonzero totals in this stable order: 👍, 👎, 😆, 🎉, 😕, ❤️, 🚀, 👀. For example, if the PRs have four thumbs-up reactions, three thumbs-down reactions, and one rocket reaction, stdout should include `Reactions: 👍 4   👎 3   🚀 1`.
