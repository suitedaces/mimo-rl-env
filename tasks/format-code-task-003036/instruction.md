I want `ngMidwayTester(moduleName, options)` to return tester instances with a public `destroy()` method for ending a test harness session cleanly after a spec finishes.

A typical session should work like this: create `var tester = ngMidwayTester('MyMod')`, drive the harness with calls such as `tester.attach()`, `tester.visit('/route', callback)`, or `tester.until(exp, callback)`, then call `tester.destroy()` once the spec is done. After `destroy()`, the harness root element should be removed from the document body, Angular data attached to the page body should be cleared, and the tester's root scope should be destroyed so watchers and scope state from that instance no longer stay alive.

If `tester.until(...)` or `tester.visit(...)` has started asynchronous polling and the condition has not completed yet, calling `tester.destroy()` should cancel that outstanding polling so its callback does not fire later against a torn-down harness. Cleanup should make successive tester instances independent: after destroying one tester that changed `$location` or attached DOM, a new `ngMidwayTester('MyMod')` instance should be able to set and read its own path, root element, and root scope state without inheriting stale DOM or Angular body data from an earlier instance.
