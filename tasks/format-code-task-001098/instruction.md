Sourcify's creator-transaction lookup is currently hard-coded to a handful of provider-specific formats. That makes it difficult to onboard explorers and indexers whose account endpoints use a different URL shape, require credentials, or return the deployment hash inside a nested response. Add a declarative custom creator API strategy to the existing chain extension configuration and make getCreatorTx use it before the legacy provider strategies.

The public configuration must accept an ordered list of custom API descriptors. Each descriptor has a URL template, a dot-separated response path, and optional environment-backed request headers. Expand ${ADDRESS} to the requested contract address and ${CHAIN_ID} to the chain's numeric ID. Header values come from the named environment variables and are omitted when the variable is unset.

For each custom descriptor, issue a GET request and read the value at the configured response path, including numeric array segments. Only a non-empty string that is a 66-character hexadecimal transaction hash beginning with 0x counts as a result. Try descriptors in declaration order; continue after a non-successful HTTP response, a missing path, or an invalid value, and return immediately after the first valid hash. Custom APIs run before the existing provider strategies. If no custom descriptor succeeds, fall back to the existing providers and return their result, or null when every configured strategy fails. Existing configurations that do not declare custom APIs must behave exactly as before.
