The table-filter package currently accepts @file imports, but an imported file cannot compose another file and relative paths are interpreted from the process working directory. This makes large, shared filter configurations difficult to maintain and prevents column filters from using the same composition model. Extend the public table and column filter parsers so an imported file may import further files. A top-level @path remains relative to the caller's working directory; an @child path written inside a file is resolved relative to that including file, so nested configurations work regardless of the caller's cwd. Rules from imported content participate at the exact include position and retain the existing last-matching-rule-wins behavior, including when an inner rule overrides an exclusion from an outer file. Apply these semantics consistently to Parse and ParseColumnFilter, while preserving blank-line/comment handling and existing direct-import behavior. Detect an active include cycle before descending and return a normal parse error that identifies the participating files; do not recurse indefinitely. Missing or unreadable files must continue to return the existing contextual open/read errors.
