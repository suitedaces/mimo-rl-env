Boot option prefix handling currently loses provenance when the same normalized option appears both with and without `inst.`. `KernelArguments` strips the prefix into one dictionary entry and remembers only that a prefix appeared somewhere, so a later legacy `stage2=` value can be treated as if it were `inst.stage2=`. This can bypass `AnacondaArgumentParser(require_prefix=True)`, and it also destroys the original ordering needed by repeated options.

Preserve each parsed kernel-argument occurrence as a public raw view. `KernelArguments.items_raw()` must yield one `(key, value)` pair per occurrence, in command-line order, retaining the exact `inst.` prefix on that occurrence. This raw view must coexist with the existing normalized mapping API: `items()`, `get()`, membership, and `is_enabled()` continue to address keys without `inst.`; ordinary duplicate scalars remain last-value-wins; `CMDLINE_LIST` options such as `addrepo` remain lists; and `CMDLINE_APPEND` options such as `modprobe.blacklist` remain space-joined strings. List and append aggregation must follow original occurrence order even when prefixed and unprefixed spellings are interleaved.

Make `AnacondaArgumentParser.parse_boot_cmdline()` consume occurrence provenance correctly. With `bootarg_prefix="inst."` and `require_prefix=True`, only prefixed occurrences may affect the namespace; recognized unprefixed occurrences must be ignored even when a prefixed spelling of the same option appears elsewhere. With `require_prefix=False`, both spellings are accepted and applied in original order, so normal argparse last-occurrence behavior still applies to scalar options. In both modes, `removed_no_inst_bootargs` records every recognized unprefixed string occurrence in encounter order, including duplicates. For append/list actions, each accepted value is applied individually and in order, while rejected legacy values never leak into the result.

Keep the documented mapping input path working as well as string/`KernelArguments` input: a plain mapping is iterated in mapping order, prefixed and unprefixed keys obey the same acceptance rules, list values are fed item-by-item to append actions, and parsing does not mutate caller-owned lists. Finally, ordinary program command-line scalar options must continue to override values derived from the boot command line.
