I want Nomad's job-file commands to accept Nomad API JSON job specifications with a `-json` flag. The supported invocations should be `nomad job run -json <path>`, `nomad job plan -json <path>`, and `nomad job validate -json <path>`; the existing `nomad run`, `nomad plan`, and `nomad validate` aliases should accept the same flag.

When the flag is present, the command should decode the input as JSON instead of HCL2. It should accept both a bare JSON job object and an object with a top-level `Job` field, such as output from `nomad job inspect -json` or `nomad job run -output`. For example, `nomad job run -json -output ./job.json` where `job.json` contains `{ "Job": { "ID": "example", "Name": "example", "Type": "service", "Datacenters": ["dc1"], "TaskGroups": [] } }` should exit 0 and write the decoded API job JSON to stdout, including the `ID`, `Name`, `Type`, `Datacenters`, and `TaskGroups` from the nested `Job` value. The same file without the outer `Job` wrapper should decode to the same job.

For `nomad job run -json <path>` submissions, the job submission metadata should preserve the exact JSON source and mark the submission format as `json`, so later source inspection can distinguish JSON submissions from HCL2 submissions. `nomad job validate -json <path>` should validate the decoded API job, and `nomad job plan -json <path>` should plan the decoded API job.

Invalid JSON should fail before any HCL2 parsing is attempted: `nomad job validate -json bad.json` should exit 1 and print an error containing `Error getting job struct: Failed to parse JSON job`, while `nomad job plan -json bad.json` should exit 255 with the same parse-error text. Because HCL variables are not meaningful for API JSON input, combining `-json` with `-var` or `-var-file` should fail before parsing; `job run` and `job validate` should exit 1, `job plan` should exit 255, and stderr should include `Invalid job options: cannot use variables with JSON files.` The help output for `nomad job run -help`, `nomad job plan -help`, and `nomad job validate -help` should list `-json` and explain that it parses the job file as JSON and uses a top-level `Job` value when present.
