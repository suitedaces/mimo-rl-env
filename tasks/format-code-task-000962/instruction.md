Regal's existing inline ignore directive is tied to a physical next line and is applied during Rego evaluation, which makes suppressions fragile around spacing and inconsistent with diagnostics produced elsewhere in the linter. Make inline suppression a property of the complete lint report so the same source directive works for bundled Rego rules, custom Rego rules, and Go rules.

Recognize directives only from actual parsed Rego comments after trimming surrounding whitespace from the comment payload. The two lowercase forms are `regal ignore:<rules>` for a point suppression and `regal ignore-file:<rules>` for a file suppression. `<rules>` is a comma-separated list of rule titles; trim whitespace around each title. A comment that merely contains those words, a string literal containing directive text, or a differently cased directive keyword is ordinary source and must not suppress anything.

A standalone `regal ignore:` comment applies to the next code-bearing line, skipping blank and comment-only lines, and to that line only. A directive in a trailing comment applies to diagnostics starting on that same line. Point suppressions affect every selected diagnostic at the target row, but cannot hide a file-level diagnostic that has no source row. In either directive form, the reserved title `all` selects every rule. Named suppressions must leave diagnostics from unlisted rules visible.

A `regal ignore-file:` directive applies to its source file as a whole regardless of where the comment appears, including diagnostics located before the comment and file-level diagnostics such as `opa-fmt`. Suppression state must never leak between files in a multi-file lint. After all engines have contributed their findings and suppressions have been applied, the returned report summary must describe the remaining findings: preserve the number of scanned/skipped files, and recompute violation and failed-file counts. Existing configuration-based rule levels, per-rule file ignores, and explicit linter ignore settings must continue to work alongside source directives.
