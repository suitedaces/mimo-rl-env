I want `Repo(path=None, odbt=GitCmdObjectDB, search_parent_directories=False, expand_vars=True)` to recognize Git linked worktrees when opening a repository. When `path` points at a linked worktree directory whose `.git` entry is a regular file containing `gitdir: <path>`, constructing `Repo(path)` should parse that file, resolve absolute and relative gitdir values, set `repo.git_dir` to the linked worktree administrative directory, and set `repo.working_tree_dir` to the linked worktree directory.

I also need `Repo()` to support linked-worktree autodiscovery when `GIT_DIR` points directly at a linked worktree administrative directory containing `gitdir`, `commondir`, and `HEAD`. If `GIT_WORK_TREE` is unset, the constructor should read the administrative directory's `gitdir` file and derive the worktree directory from the referenced `.git` file path. If `GIT_WORK_TREE` is set, the constructor should use that environment value as `repo.working_tree_dir`.

For callers that only need to inspect a worktree `.git` file, expose `find_worktree_git_dir(dotgit)` so it returns the gitdir value from a regular `.git` file containing a `gitdir: ...` line. It should return `None` when the path is missing, not a regular file, or not in that format, and malformed files should produce `None` instead of raising from line parsing.
