The resource export writers are used by CSV, KML, and shapefile exports, but their shared mapping layer currently makes repeated exports depend on earlier calls and mishandles optional data. Make the export contract deterministic and reusable. A schema must populate configured resource type names, identity fields, primary names, alternate names, and empty values for unmapped columns; when no resource-type configuration is available, the raw entity type identifier remains the fallback. Field mappings must collect child entities, dates, numbers, and domain labels without changing the input resource, must tolerate an omitted optional collection, and must apply concept filters by matching the mapped domain's parent relationship. If a preferred mapping has no values, an alternate entity type may supply the values for both ordinary and domain mappings. Joining list-valued fields must sort values and produce a semicolon-plus-space string while leaving scalar values unchanged and not reordering caller-owned lists. CSV export must be safe to reuse: each invocation emits only its supplied resources, and caller-provided mapping dictionaries are not populated or otherwise mutated as a side effect. Preserve the existing output headers and resource identity semantics while fixing these observable behaviors across the shared writer consumers.
