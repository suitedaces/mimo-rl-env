I want `kube-score` to score the network-facing relationships between Services, Pods, Ingresses, and NetworkPolicies when I run `kube-score score [--output-format json] <manifest.yaml>`. `kube-score list` should include these default checks: `ingress-targets-service` for Ingress, `pod-networkpolicy` for Pod, `networkpolicy-targets-pod` for NetworkPolicy, `service-targets-pod` for Service, and `service-type` for Service.

For Services, a `ClusterIP` Service whose selector matches at least one Pod or workload pod template in the same namespace should get grade 10 for `Service Targets Pod`; the same Service with no matching Pod labels in its namespace should get grade 1 with summary `The services selector does not match any pods`. `ExternalName` Services should pass `Service Targets Pod` without requiring a selector match. A Service of type `NodePort` should get grade 5 for `Service Type` with summary `The service is of type NodePort`; non-NodePort Services should get grade 10 for that check.

For Pods and workload pod templates, `Pod NetworkPolicy` should verify that a matching NetworkPolicy exists in the same namespace. If matching ingress and egress coverage both exist, the grade should be 10; if only ingress exists, the grade should be 5 with summary `The pod does not have a matching egress NetworkPolicy`; if only egress exists, the grade should be 5 with summary `The pod does not have a matching ingress NetworkPolicy`; if neither exists, the grade should be 1 with summary `The pod does not have a matching NetworkPolicy`. A NetworkPolicy with an empty pod selector should count as matching all pods in its namespace, and default Kubernetes policyTypes behavior should be honored: omitted policyTypes implies ingress coverage and implies egress coverage only when egress rules are present.

For NetworkPolicies, `NetworkPolicy targets Pod` should get grade 10 when the policy selector matches at least one Pod or workload pod template in the same namespace, including the empty selector case. It should get grade 1 with summary `The NetworkPolicys selector doesn't match any pods` when it selects nothing in that namespace.

For Ingresses, `Ingress targets Service` should verify every HTTP backend service reference against Services in the same namespace. A backend that resolves by service name and numeric port, or by service name and named port, should get grade 10. A missing backend match should get grade 1 with summary `No service match was found`; the description should say `No service with name <name> and port number <port> was found` for numeric ports or `No service with name <name> and port named <name> was found` for named ports. An Ingress path with no service backend should also fail this check without crashing.

When these checks produce a critical grade and no `--ignore-test` option suppresses them, `kube-score score` should exit with code 1. When the only issue from this feature is the NodePort warning, `kube-score score` should exit 0 by default and exit 1 when `--exit-one-on-warning` is set.
