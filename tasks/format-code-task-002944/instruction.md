I want a `*Handle` route lookup API for Linux network namespaces. After I create a handle with `NewHandle()` or `NewHandleAt(...)`, I need to call `h.RouteGetWithOptions(destination net.IP, options *RouteGetOptions) ([]Route, error)` to ask the kernel which route it would use for a destination, and I need `h.RouteGet(destination net.IP) ([]Route, error)` as the same lookup with no options.

For example, `routes, err := h.RouteGet(net.ParseIP("8.8.8.8"))` should issue an IPv4 route lookup and return the decoded `[]Route` entries from the kernel, including fields such as destination, gateway, table, output link index, source address, priority, metrics, encapsulation, and multipath nexthops when the kernel reports them. For an IPv6 input such as `net.ParseIP("2001:4860:4860::8888")`, the request should use an IPv6 destination length and return IPv6 route data decoded into the same `Route` model.

`RouteGetWithOptions` should also support the lookup options in `RouteGetOptions`: resolve `VrfName`, `Iif`, and `Oif` through the handle's link lookup methods and encode their link indexes; accept `IifIndex` and `OifIndex` directly; include `SrcAddr`, `UID`, and nonzero `Mark` when provided; and set FIB-match lookup behavior when `FIBMatch` is true. If a named VRF/interface cannot be found, the method should return that error without sending a misleading lookup. If the kernel rejects the route request or any returned route message cannot be decoded, the method should return the error; otherwise it should return all decoded routes in order.
