I want a stateful MySQL v4 binlog stream reader for log sequences spread across multiple files. The public constructor should be `NewLogStreamV4EventReader(logDirectory string, logPrefix string, startingLogFileNum uint, isRelayLog bool, logger Logger) EventReader`; it should open files named `logPrefix` plus a zero-padded six-digit file number under `logDirectory`, parse each file with the existing v4 log-file parser, and let callers consume the stream by repeatedly calling `NextEvent() (Event, error)` followed by `Close() error` when done.

For example, if `NewLogStreamV4EventReader(dir, "bin.", 0, false, logger)` reads `bin.000000` containing a format-description event, an XID event, and a rotate event to `bin.000001`, then successive `NextEvent` calls should return those three typed events, close the first file, open `bin.000001`, and continue returning typed events from the new file. A stop event should also advance to the next numbered file, so after a stop in `bin.000001` the next read should try `bin.000002`. Numbering should roll over from `999999` to `000000`.

If the next file cannot be opened, `NextEvent` should return nil event plus a `*FailedToOpenFileError` whose `LogFileNum` is the file number it tried, and callers should be able to retry the same reader after that file appears. If a rotate event names a file with the wrong prefix, a non-numeric six-digit suffix, or a number other than the expected next file number, `NextEvent` should return the rotate event together with a `*InvalidRotationError` and leave the current reader usable for subsequent events in the same file when possible.

When `isRelayLog` is true, the reader should treat the first format-description event in each relay log file and relay-log wrapper rotate events as file-management records and not return them to the caller, while still returning a master's binlog rotate event that does not match the relay prefix. There should also be an injectable constructor `NewLogStreamV4EventReaderWithLogFileReaderCreator(logDirectory string, logPrefix string, startingLogFileNum uint, isRelayLog bool, logger Logger, newLogFileReader LogFileReaderCreator) EventReader`, where `LogFileReaderCreator` has signature `func(dir string, file string, parsers V4EventParserMap) (EventReader, error)`, so tests and custom storage layers can provide file readers without using `os.Open`. Calling `Close()` should close the currently open file reader if any, and after close, `NextEvent()` should return an error instead of opening or reading more files.
