I want an existing `IObjectRepository` instance to support `void AddObjectFromFile(ObjectGeneration generation, std::string_view objectName, const void* data, size_t dataSize)` for importing object bytes that have already been read from another source. When I call it with `ObjectGeneration::JSON`, an object identifier like `custom.scenery_pack`, and a buffer containing a packed `.parkobj` object, it should write the bytes into the user objects directory using that identifier with a `.parkobj` extension, choosing a unique suffixed filename if the target already exists, then scan the new file so `FindObject("custom.scenery_pack")` can return the imported repository item in the same repository instance. When I call it with `ObjectGeneration::DAT` and a buffer whose first bytes are an `RCTObjectEntry`, it should derive the installed `.DAT` filename from that entry, write the supplied bytes into the user objects directory with collision-safe suffixing, and scan the new file so `FindObjectLegacy(entry.GetName())` can find it afterward. The method should not require the caller to rebuild the whole repository after a successful import; the repository's in-memory lookup state should be updated by the call. If writing or scanning the file fails, the method should catch the failure and report `Failed saving object: [<objectName>] to '<path>'.` without throwing to the caller.
