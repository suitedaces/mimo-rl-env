I want the Go control package to expose `control.ConvertToParagraph(incoming interface{}) (*control.Paragraph, error)` as a pure conversion helper. Given a pointer to a struct, it should return a new `*control.Paragraph` whose `Order` follows struct-field order and whose `Values` map contains Debian control field strings: field names are used as keys unless a `control:"Name"` tag overrides them, and `control:"-"` fields are skipped.

For example, `type Basic struct { Foo string; Count int; Enabled bool }` with `&Basic{Foo:"hello", Count:2, Enabled:true}` should return `Order == []string{"Foo", "Count", "Enabled"}` and `Values == map[string]string{"Foo":"hello", "Count":"2", "Enabled":"yes"}`. For `type Tagged struct { Package string `control:"Source"`; Arches []string `control:"Architecture" delim:", "`; Empty string; Required string `required:"true"` }` with `&Tagged{Package:"demo", Arches:[]string{"amd64", "arm64"}}`, it should return keys `Source`, `Architecture`, and `Required`, values `demo`, `amd64, arm64`, and the empty string; the unrequired empty `Empty` field should be omitted. Slices should join elements with a space by default or the `delim` tag when present, booleans should encode as `yes` or `no`, integers and uints should be decimal strings, pointer fields should encode the pointed-to value, and `multiline:"true"` should prefix the encoded value with a newline.

If the struct anonymously embeds a `control.Paragraph`, `ConvertToParagraph` should preserve those existing paragraph fields while overlaying the struct-derived fields, so unknown fields survive a parse/edit/write round trip. Struct-valued fields should be accepted only when they implement `control.Marshallable` via `MarshalControl() (string, error)`, and that method's string or error should be propagated. Passing a non-pointer should return a non-nil error like `Can only Decode a pointer to a Struct`; passing a pointer to a non-struct should return a non-nil error like `Can only Decode a Struct`; a nested struct that does not implement `control.Marshallable` should return a non-nil error naming that type. Calling it twice with the same input should produce equal paragraphs, should not mutate the input struct, and should not read or write the filesystem, network, or package-level state.
