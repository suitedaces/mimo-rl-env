Make the GitHub personal-access-token transport fail over across its token pool when one token is rate limited. Today `MakeGitHubTransport` simply assigns one token to each request, so an exhausted token is handed back to the generic rate-limit layer even when another configured token could serve the request immediately. Keep the existing public constructor signature and ordinary `http.RoundTripper` contract.

Normalize the supplied token list by trimming surrounding whitespace, dropping empty entries, and removing exact duplicates while preserving first occurrence order. If normalization leaves no usable token, `RoundTrip` must return a nil response and an error containing `no usable GitHub access tokens`, without calling the inner transport. Logical requests use round-robin starting tokens: the first request starts with the first normalized token, the next request with the second, and so on. A logical request advances this global starting position exactly once; its failover attempts do not consume additional starting positions.

Every attempt sent to the inner transport must be a request value distinct from the caller's request, preserve the caller's non-authorization headers, and contain exactly one `Authorization` value in the form `Bearer <token>`. Do not mutate the caller's request or headers, including any pre-existing authorization values.

Treat a response as exhaustion of the current token only when its status is 403 or 429 and `X-RateLimit-Remaining` parses as integer zero. A zero header on another status, either status with a nonzero value, or either status without a parseable remaining header is an ordinary response: return it immediately without trying another token. For a token-exhausted response, try the remaining normalized tokens once each in circular order from the request's starting token. Close each response body that is discarded for another attempt. If every token is exhausted, return the final limited response with its body still open for the caller.

Failover is allowed when the request has no body, or when its `GetBody` function makes the body replayable; every attempt must receive the complete original payload. If a non-empty request body has no `GetBody`, do not retry it: return the first limited response, still open. Before beginning a failover attempt, honor cancellation of the request context; close the limited response and return a nil response with the context error. An error from the inner transport must stop the logical request immediately, return a nil response, and remain discoverable with `errors.Is` rather than being converted into a retry.
