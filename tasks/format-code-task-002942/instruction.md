I want `cache-dit-metrics` to support a `clip_score` metric for scoring generated images against text prompts. The metric should appear in `cache-dit-metrics --help` as a valid positional metric choice, and the prompt flags `--prompt-true/-p` and `--ref-prompt-true/-rp` should describe that they can be used for CLIP Score inputs.

For the normal CLI path, `cache-dit-metrics clip_score --prompt-true prompts.txt --img-test images/` should read `prompts.txt` as UTF-8 text with one prompt per line, find supported image files under `images/`, sort them naturally by filename suffix, score each image-prompt pair up to the shorter of the two lists, and log one summary line to stdout in the existing metrics format: `<prompt-file-basename> vs <image-dir-basename>, Num: <count>, CLIP_SCORE: <mean score with five decimals>`. A successful run should exit 0. If there are no image-prompt pairs to score, it should emit no `CLIP_SCORE` metric line and still finish cleanly.

The scorer should load the CLIP model from `CLIP_MODEL_DIR` when that environment variable is set, otherwise use `laion/CLIP-ViT-g-14-laion2B-s12B-b42K`, run on the current accelerator when one is available and CPU otherwise, convert image inputs to RGB, and use the model's image-text logit as the per-pair score. When summaries are requested with `--summary`, `clip_score` should be treated as a higher-is-better metric when sorting formatted results.
