I want `gdrive` sync commands to honor a `.gdriveignore` file placed in the root of the local sync directory. When I run `gdrive sync upload --dry-run ./local-dir <fileId>`, the sync planner should read `./local-dir/.gdriveignore` and exclude matching local files and directories from the upload plan, so ignored paths are not counted as local files and do not appear in stdout action lines such as `Uploading ...`, `Updating ...`, or `Creating directory ...`.

The same ignore behavior should apply when I run `gdrive sync download --dry-run <fileId> ./local-dir`: ignored local paths should be omitted from local tree comparison, so they are not treated as local conflicts or extraneous local files. For example, if `.gdriveignore` contains `build/` and `*.log`, then `build/app.bin` and `debug.log` under the sync root should be skipped, while `src/main.go` should still be compared normally. The ignore syntax should follow gitignore-style matching, but only the `.gdriveignore` file in the sync root should be read; ignore files in subdirectories should not affect sync planning. If the root `.gdriveignore` file is malformed or cannot be parsed, the sync command should exit non-zero and print an error that starts with `Failed to prepare ignorer:`.
