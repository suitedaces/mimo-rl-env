I want loaded `AutoencoderKL` objects to provide a pure latent-to-image decode API: `decode(z: torch.FloatTensor, return_dict: bool = True) -> AutoencoderKLOutput`. The method should take a batch of latent tensors, optionally apply the VAE post-quantization projection, run the decoder network, and return image-space tensors without mutating `z`, touching the filesystem, using the network, or changing hidden module-level state.

When I create `AutoencoderKL(latent_channels=4, out_channels=3, block_out_channels=(32,), layers_per_block=1, norm_num_groups=32, use_post_quant_conv=True)`, zero all decoder and post-quantization parameters, and call `decode(torch.zeros(2, 4, 8, 8))`, I should get an `AutoencoderKLOutput` whose `.sample` is a zero tensor with shape `(2, 3, 8, 8)`. With `return_dict=False` for the same input, I should get a one-item tuple containing that tensor.

When I create `AutoencoderKL(latent_channels=4, out_channels=1, block_out_channels=(32, 64), layers_per_block=1, norm_num_groups=32, use_post_quant_conv=False)`, zero the decoder parameters, and call `decode(torch.ones(1, 4, 4, 5), return_dict=False)`, the returned tuple should contain a zero tensor with shape `(1, 1, 8, 10)`, showing that the decoder upsamples once for the two configured channel blocks. If `z` has the wrong number of channels, such as shape `(1, 5, 4, 4)` for `latent_channels=4`, `decode` should raise a PyTorch `RuntimeError` instead of silently reshaping or accepting it.

The `AutoencoderKL` constructor should expose the decoder-related options `out_channels: int = 3`, `up_block_types: Tuple[str] = ("UpDecoderBlock2D",)`, and `use_post_quant_conv: bool = True`. The local checkpoint loader should pass the VAE config keys `out_channels`, `up_block_types`, and `use_post_quant_conv` into `AutoencoderKL`; `out_channels` determines the decoded tensor channel count, `use_post_quant_conv` toggles the projection before decoding, and `up_block_types` keeps Hugging Face-style decoder configs accepted by the public constructor.
