The unused-resource report currently covers EC2 security groups, volumes, Elastic IPs, and network interfaces, but it misses load balancers even though the collector already records both generations of the Elastic Load Balancing APIs. Extend the `find_unused` public surface so operators can identify abandoned load balancers from an offline account-data snapshot.

Expose a regional helper named `find_unused_load_balancers(region)`. It must inspect classic ELB data from `elb-describe-load-balancers`: a classic load balancer is unused only when its `Instances` list is present and empty, or when the field is absent (the AWS response's zero-registration shape); any listed instance keeps it out of the result. For each returned classic entry, report an object with `id` and `name` equal to `LoadBalancerName` and `type` equal to `classic`, preserving the source order.

Also inspect ALB/NLB data from `elbv2-describe-load-balancers`. Use each load balancer ARN to read its collected target groups and each target-group ARN to read collected target health. A v2 load balancer is unused when collection is complete and every target group has zero `TargetHealthDescriptions` (including a load balancer with no target groups). The presence of any target registration counts as used regardless of whether its health state is healthy, unhealthy, draining, or another value. A missing target-group listing or missing target-health response means the snapshot is incomplete, so do not report that load balancer as unused. V2 result objects use the load balancer ARN as `id`, `LoadBalancerName` as `name`, and the API `Type` as `type`; preserve API order, with classic results before v2 results.

Wire this helper into `find_unused_resources(accounts)` under the `load_balancers` category for each region. Keep the existing omission convention: a category is absent when its result is empty, while the region and account envelopes remain present. Existing categories and their behavior must remain unchanged.
