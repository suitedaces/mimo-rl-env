I want Goja's JavaScript Runtime to support the BigInt-oriented DataView methods on existing DataView instances: DataView.prototype.getBigInt64(byteOffset, littleEndian), DataView.prototype.getBigUint64(byteOffset, littleEndian), DataView.prototype.setBigInt64(byteOffset, value, littleEndian), and DataView.prototype.setBigUint64(byteOffset, value, littleEndian).

Given `const dv = new DataView(new ArrayBuffer(8))`, calling `dv.setBigInt64(0, -2n, false)` should return `undefined` and a later `dv.getBigInt64(0, false)` should return `-2n`. With the same buffer, `dv.setBigUint64(0, 0x0102030405060708n, true)` should store the value in little-endian byte order, and `dv.getBigUint64(0, true)` should return `0x0102030405060708n` while `dv.getBigUint64(0, false)` observes the bytes as the opposite-endian value.

The methods should validate their receiver as a DataView and throw TypeError when called with an incompatible `this`. They should also respect the DataView byte offset, byte length, and detached-buffer checks: reading or writing eight bytes past the view bounds should throw RangeError, and using a detached ArrayBuffer should throw TypeError. The setters should require BigInt-compatible values and write exactly eight bytes into the underlying ArrayBuffer without changing the DataView's length or offset.
