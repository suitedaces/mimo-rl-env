TypeScript users can place an `@import` declaration in a JSDoc block so later comments in the same file can refer to its imported types. Compact, single-line blocks currently behave differently from multiline blocks: valid declarations may be reported as `Bad @import tag`, and their bindings are then reported as undefined. Make TypeScript-mode import handling independent of whether the JSDoc block is single-line or multiline.

For `jsdoc/check-values`, a valid single-line `@import` must be accepted for named imports, aliases, combined default-plus-named imports, namespace imports, and `import type` declarations. Malformed import syntax must continue to produce the existing `Bad @import tag` diagnostic.

For `jsdoc/no-undefined-types`, every local binding introduced by a valid `@import` must be available to later JSDoc type expressions in that file. An unaliased named import introduces its exported name; an aliased import introduces only the alias; a default import introduces its local default name; and a namespace import introduces the namespace root used by qualified types such as `Namespace.Member`. `import type` declarations follow the same local-binding rules. Do not treat the exported side of an alias as a local definition. Preserve the existing accepted behavior and type visibility for multiline `@import` blocks.
