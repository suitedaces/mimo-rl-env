The AJAX conversion utilities currently have inconsistent behavior when they are composed. In particular, a request object supplied while rendering an exception can leak into the JSON encoder as an unsupported option, causing the error handler itself to fail; middleware can also wrap a response that is already an AJAX JSON envelope. This makes ordinary view errors appear as 500s unrelated to the original failure and makes it unsafe to combine the package's public entry points.

Make the public AJAX surface consistent across `render_to_json`, the `@ajax` decorator, and `AJAXMiddleware`. Rendering an `Http404` (whether called directly, raised by a decorated view, or observed by middleware) must produce the normal JSON envelope with status 404, the `NOT FOUND` status text, and the exception message as content. Other exceptions raised during an AJAX request must produce a 500 envelope; when `DEBUG` is false the content must be a generic safe message and must not disclose the exception text or traceback. Context such as the request may be accepted for logging/reporting but must never be passed as an option to the JSON encoder.

The decorator must continue to envelope ordinary `HttpResponse` values using their status code, reason phrase, and body, while preserving its existing mandatory non-AJAX guard and allowing `mandatory=False` calls to pass through unchanged for non-AJAX requests. The middleware must convert AJAX responses and exception results using the same envelope rules, leave non-AJAX responses and exception handling untouched, and recognize an already JSON response as already converted rather than nesting it again. Existing serializer options, including a caller-provided JSON encoder and standard `json.dumps` options, must continue to work.
