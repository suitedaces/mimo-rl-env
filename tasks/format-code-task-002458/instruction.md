I want smart-npm's CLI (`snpm` or `smart-npm`, and `npm` when it is aliased to the same binary) to include two extended web shortcut subcommands, `stats` and `user`, that are handled by smart-npm itself instead of being forwarded to npm.

When I run `snpm stats lodash`, it should attempt to open `http://mora.sinaapp.com/utils/npm-stats.php?months=2&pkg=lodash` in the default browser and exit with code 0. `snpm stats lodash express` should attempt one browser open per non-numeric package name, using the same default two-month window. The `stats` command should accept a month count as `-m6`, `-m 6`, `--month 6`, or `--months 6`; for example, `snpm stats -m 3 lodash` and `snpm stats --months 3 lodash` should open `http://mora.sinaapp.com/utils/npm-stats.php?months=3&pkg=lodash`, and numeric month arguments should not be treated as package names. If `stats` is run without a package name, it should print a blank-line-padded usage message containing `Usage: npm stats [ -m{number} ] {package}` to stderr, perform no browser open, and exit with code 0.

For users, `snpm user zhonglei` should open `https://www.npmjs.com/~zhonglei` and exit with code 0. `snpm user alice bob` should attempt one browser open per username. If the `-t` flag is present, `snpm user -t zhonglei` should open `https://npm.taobao.org/~zhonglei` instead. If `user` is run without a username, it should print a blank-line-padded usage message containing `Usage: npm user [-t] {username}` to stderr, perform no browser open, and exit with code 0.

For both subcommands, if launching the browser fails, smart-npm should print `Can not open browser, please open your browser to visit: <url>` to stdout with the exact URL it tried to open, then exit with code 0. If the browser launcher writes stdout or stderr text on success, smart-npm should print that text before exiting with code 0.
