Typed QuarkChain transactions already carry a version-1 recovery path, but the Python API cannot produce the same typed signatures that wallet clients verify. Complete the public transaction surface so a dApp can build, sign, serialize, and recover one transaction consistently.

`tx_to_typed_data(raw_tx)` must describe the complete unsigned typed payload in the wallet's canonical order: `nonce`, `gasPrice`, `gasLimit`, `to`, `value`, `data`, `networkId`, `fromFullShardKey`, `toFullShardKey`, `gasTokenId`, `transferTokenId`, then `qkcDomain`. Keep the existing record shape and hexadecimal value convention. The shard records must use the names matching the transaction's `from_full_shard_key` and `to_full_shard_key` attributes, with type `uint32`; token records must use the camel-case names above and type `uint64`; `qkcDomain` remains the final string record with value `bottom-quark`. Every field in that sequence participates in `typed_signature_hash`, so changing either token id or the network id changes the digest even when all other transaction fields are unchanged.

Add a public `Transaction.sign_typed(key, network_id=None)` operation analogous to the existing signer. It signs the typed digest, marks the transaction as version 1, returns the same transaction object, and honors an explicitly supplied network id including zero. A typed signature must remain recoverable as `sender` after RLP encoding and decoding. Existing `Transaction.sign()` behavior remains the legacy version-0 signing path and must continue to recover the same sender after serialization; the typed additions must not change that compatibility contract.
