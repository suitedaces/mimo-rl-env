I want Zone objects to expose a `changes(desired: Zone, target) -> list[Change]` method that compares the receiver as the existing DNS zone state against `desired` as the desired DNS zone state for a specific target provider. The method should return concrete `Delete`, `Update`, and `Create` change objects needed to make the existing zone match the desired zone, without mutating either zone.

For example, if an existing `example.com.` zone contains an A record `www` with TTL 300 and value `1.1.1.1`, and the desired zone contains the same A record with TTL 300 and value `2.2.2.2`, then `existing.changes(desired, target)` should return a one-item list containing an `Update` whose `existing` record is the old A record and whose `new` record is the desired A record. If the existing zone contains an A record `old` that is absent from the desired zone and `target.supports(record)` is true for that record, the result should include `Delete(record)`. If the desired zone contains an A record `new` that is absent from the existing zone and `target.supports(record)` is true for that record, the result should include `Create(record)`.

Records marked with `octodns.ignored` should be skipped whether they appear in the existing zone or desired zone. Records with a non-empty `octodns.included` list should only be considered when `target.id` is in that list, and records whose `octodns.excluded` list contains `target.id` should be skipped. Missing records whose type the target does not support should not produce `Delete` or `Create` changes. Calling `changes` repeatedly with the same existing zone, desired zone, and target should produce equal results and should not write to the filesystem, use the network, or update global state.
