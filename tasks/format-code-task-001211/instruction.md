I want established `Conversation` instances to support direct TCP and UDP forwarding channels as part of their stateful channel lifecycle.

The public methods should be `OpenUDPForwardingChannel(maxPacketSize uint64, datagramsQueueSize uint64, localAddr *net.UDPAddr, remoteAddr *net.UDPAddr) (Channel, error)` and `OpenTCPForwardingChannel(maxPacketSize uint64, datagramsQueueSize uint64, localAddr *net.TCPAddr, remoteAddr *net.TCPAddr) (Channel, error)`. Each method should open a new HTTP/3 stream for the conversation, send the SSH3 channel header immediately, register the channel with the conversation, and return `nil, err` without registering a channel if opening the stream fails.

For UDP forwarding, the channel type on the wire should be `direct-udp`; the returned value should be a `*UDPForwardingChannelImpl` whose embedded `Channel` is usable for normal channel operations and whose `RemoteAddr` is the requested remote UDP address. The UDP forwarding channel must also be able to send QUIC datagrams through the parent conversation, so `SendDatagram` on the returned channel prefixes the conversation stream id and channel id before sending through the conversation datagram sender.

For TCP forwarding, the channel type on the wire should be `direct-tcp`; the returned value should be a `*TCPForwardingChannelImpl` whose embedded `Channel` is usable for normal channel operations and whose `RemoteAddr` is the requested remote TCP address.

Both forwarding channel headers should include the remote address after the standard channel header: an address-family varint for IPv4 or IPv6, the raw IP bytes, and the port in two-byte big-endian order. On the receiving side, when a peer opens a `direct-udp` or `direct-tcp` channel, `AcceptChannel` should eventually return the corresponding forwarding wrapper type with `RemoteAddr` populated from those header bytes. If the forwarding header has an invalid address family or is too short to contain the declared address and port, the stream hijacker should return an error and the channel should not be queued for acceptance.
