The formatter's ISO presets currently produce ambiguous local date-times and offer no reusable way to render a numeric offset in the standard colonized form. Add timezone-aware ISO presets and token support while keeping the existing mask API compatible.

The named `isoDateTime` mask must render local calendar fields as `yyyy-mm-ddTHH:MM:ss` followed by the offset in `+/-HH:MM` form. The offset must be calculated from the supplied instant, so daylight-saving changes and both positive and negative local zones are reflected. Add `isoDateTimeMillis`, which has the same local-time and offset behavior but inserts exactly three millisecond digits before the offset (including leading zeroes). Add `isoUtcDateTimeMillis`, which formats UTC fields with three millisecond digits and a trailing `Z`.

Expose a `P` mask token for the colonized numeric offset. It follows the same sign and minute semantics as the existing `o` token; `o` must remain the compact `+/-HHMM` representation. In local mode `P` reflects the date's actual timezone offset; when UTC mode is selected it is `+00:00`. UTC mode may be selected by the existing `UTC:` prefix or the boolean `utc` argument, and GMT mode by `GMT:`; these modes must continue to select UTC calendar fields, with `Z` remaining `UTC` or `GMT` respectively. Quoted mask text remains literal, so a quoted `P` is not expanded. The existing compact `o` token and quoted-mask behavior must remain compatible.
