I want completed technology objects to apply their technology-specific completion behavior through the stateful `Tech` API. Code should be able to construct a technology with `Tech(spec)` and call `tech.finish(is_player=True, loading_savegame=False)`; that call should run the technology's configured effect against the current game/player state in addition to the normal completed-buyable state transition.

For example, if the technology's configured effect grants income, finishing that `Tech` should make the player's income reflect that grant immediately. If the configured effect changes discovery display, suspicion/discovery modifiers, labor efficiency, job profit, or the endgame state, calling `Tech.finish(...)` should make those configured changes observable through the same global player/map state that the rest of the game reads. The method must pass the `loading_savegame` flag through to the effect so one-shot effects such as win story display or one-time suspicion reduction can suppress load-time behavior while still restoring persistent state.

I also need a public `register_on_tech_researched_handler(func)` hook for code that reacts to newly completed research. Registering a handler should return the same function so it can be used as a decorator, and every `Tech.finish(..., loading_savegame=False)` call should invoke registered handlers with the completed `Tech` object. Calling `Tech.finish(..., loading_savegame=True)` should not notify those handlers, because save loading should not behave like newly completed research.
