The CLI currently remembers generated methods by their source text and later searches the file for that text. That loses occurrence identity: two identical methods collapse to one dictionary entry, and text-based positions are also unsafe once a UTF-8 file contains multibyte characters. Make source rewriting location-aware while keeping the existing parsing and response behavior stable.

Expose each `TreesitterMethodNode`'s half-open Tree-sitter byte range as public `start_byte` and `end_byte` attributes. These are UTF-8 byte offsets, must mirror the wrapped syntax node, and slicing the original encoded source with them must produce `method_source_code`.

Add a public `doc_comments_ai.utils.SourceReplacement(start_byte, end_byte, content)` value object with readable attributes of those names, plus `write_code_snippets_to_file(file_path, replacements)`. The writer accepts any iterable of replacements, materializes positions against one original UTF-8 snapshot, and replaces every range exactly with its `content`; content is not stripped or implicitly indented, and all bytes outside the ranges remain unchanged. Input order must not matter, adjacent ranges are valid, and an empty iterable is a no-op.

Validation belongs to the batch writer so a `SourceReplacement` can represent a value before it is checked. Every range must be non-empty, within the original byte length, and start and end on UTF-8 character boundaries. Ranges must not overlap. A violation raises `ValueError`, and the file must remain byte-for-byte unchanged even when another replacement in the same batch is valid.

Update `aicomment` so every generated response is applied to the same parsed method occurrence that produced its prompt. Identical method source text must therefore receive distinct responses in parser order rather than collapsing or targeting the first match twice. Generated snippets are still interpreted relative to the original method's starting column: the original leading indentation is retained for the first line and reapplied after each newline, while surrounding file text is preserved. Do not write any generated snippets until generation for every selected method has succeeded; if a later generation raises, the input file stays unchanged.

Keep the existing `write_code_snippet_to_file` entry point working, including its current behavior of indenting both lines when a two-line replacement targets an indented textual occurrence. Existing Python and Java method names, documentation strings, and `method_source_code` values must remain unchanged. Also preserve markdown response extraction for unlabelled fences, language-labelled fences, and fenced code followed by prose.
