I want gh3 to expose a stateful GitHub gist browsing API. Callers should be able to create `new Gh3.Gists(ghUser)`, call `fetch(pagesInfo, paginationInfo, callback)`, and then inspect the accumulated result with `getGists()`, `eachGist(callback)`, and `filter(comparator)`. `fetch` should request the public gists for `ghUser.login` from `/users/<login>/gists`, pass `pagesInfo` through as request query data, append each returned gist as a `Gh3.Gist` object, and invoke `callback(null, gistsInstance)` on success; on an API error it should invoke `callback(Error(message), response)` using the GitHub error message.

I also want callers to inspect one gist by creating `new Gh3.Gist(gistData)`, where the constructor copies the supplied gist fields onto the instance. Calling `fetchContents(callback)` should request `/gists/<id>`, reset `files` to an empty array, move every entry from the response `files` object into that array, copy the remaining response metadata onto the gist instance, and call back with `(null, gistInstance)`. After that, `getFiles()` should return the files array, `eachFile(callback)` should visit every file object, and `getFileByName(name)` should return the file whose `filename` equals `name`.

For discussion browsing, `Gh3.Gist` should provide `fetchComments(callback)`, `getComments()`, `eachComment(callback)`, and `filterComments(comparator)`. `fetchComments` should request `/gists/<id>/comments`, reset `comments` to an empty array, wrap each returned comment as a `Gh3.GistComment` whose constructor copies the comment fields onto the instance, then call back with `(null, gistInstance)`. On content or comment request errors, the callback should receive `Error(response.responseJSON.message)` and the raw response. Separate `Gh3.Gists` and `Gh3.Gist` instances should keep their own `gists`, `files`, and `comments` arrays so one browsing session does not mutate another.
