The signature comparison command is useful for checking rule changes, but today it can only replay crash IDs by fetching production data. That makes saved regression corpora awkward to use, prevents deterministic offline runs, and lets the signature pipeline mutate the processed-crash object that a caller may still need. Add a reusable comparison operation and an offline, stream-friendly replay mode.

`SignatureGenerator` should expose `compare(raw_crash, processed_crash, crash_id=None)`. It must run the generator's configured pipeline on private copies, leaving both caller-provided mappings unchanged even when a rule mutates nested data. Return exactly `crash_id`, `old_signature`, `new_signature`, `changed`, and `notes`: the old signature is the input processed crash's `signature` or `""` when absent, the new signature and notes come from normal generation, and `changed` is their equality comparison. Resolve the result ID by presence, not truthiness: a non-`None` argument wins (including `""`), otherwise use `raw_crash["uuid"]` when that key exists, then `processed_crash["crash_id"]` when that key exists, and finally `None`. Empty IDs at either mapping level must therefore be preserved.

For `python -m socorro.signature`, add a repeatable `--input PATH` option for offline replay with `--format=json`; `--input -` reads standard input. Consume each source as newline-delimited JSON in option order, ignore blank lines, and never make HTTP requests in this mode. Every nonblank record must be an object containing `raw_crash` and `processed_crash` objects; `crash_id` is optional but, when present, must be a JSON string. Feed valid records through the normal signature pipeline. Emit one JSON object per retained record, in input order, with exactly the five comparison fields above; booleans, null IDs, and notes must remain native JSON values. A clean replay exits successfully. Existing `--different-only` filtering applies after comparison and omits only records whose `changed` value is false.

A bad JSON line, a non-object record, missing or wrongly typed members, or an unreadable input path must produce a human-readable stderr diagnostic identifying the source (and `source:line` for record errors), but must not print a traceback or prevent later records or later sources from being processed. If any such error occurred, finish with status 1 after emitting all valid results. Supplying positional crash IDs together with `--input` is a command-line usage error with status 2. Preserve the existing positional crash-ID remote workflow and its text output, and do not change the existing `SignatureGenerator.generate()` or rule-pipeline behavior.
