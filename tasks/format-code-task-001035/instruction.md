js2php currently treats some source it cannot translate as if conversion succeeded: the library logs an AST node to the console, drops that construct, and returns plausible-looking partial PHP. The command-line wrapper can then print that partial output with a zero status. This is especially risky in build scripts, and the wrapper's current choice between a file and stdin also changes merely because stdin is redirected.

Make translation failures explicit and consistent across the public library and CLI. The function exported by the package must continue to accept a source string, and may now take an optional second object with `sourceName`; omitting it uses `<input>`. Expose `UnsupportedSyntaxError` and `ParseError` as properties of that function. Both are real `Error` subclasses with `name`, `code`, `sourceName`, and one-based `line` and `column` fields. Unsupported syntax uses code `E_UNSUPPORTED_SYNTAX`, also exposes the most specific ESTree `nodeType`, and has the exact message `Unsupported syntax: <nodeType>`. Parser failures use code `E_PARSE` and retain the parser's useful reason in their message.

Encountering an AST node for which no PHP can be emitted must throw `UnsupportedSyntaxError` instead of logging or continuing. Apply the same fail-closed rule to syntax the parser accepts but the emitter does not support safely: array and object destructuring patterns, rest parameters, and spread elements must currently fail with node types `ArrayPattern`, `ObjectPattern`, `RestElement`, and `SpreadElement` respectively. Do not write diagnostics through `console.log`. Supported input must keep producing the same PHP string, whether or not `sourceName` is supplied.

Make the `js2php` executable use one deterministic input contract. With one file operand it must read that file even when stdin is redirected; with no operand or with `-` it reads stdin. Successful stdout is byte-for-byte the library result, without an extra blank line, and stderr is empty. `-v`/`--version` prints only the package version plus a newline, while `-h`/`--help` prints exactly `Usage: js2php [--help] [--version] [file|-]` plus a newline; these flags take effect even if source is piped in.

For a parse or unsupported-syntax failure, the executable must emit no PHP, write exactly one stderr line in the form `<source>:<line>:<column>: <message>`, and exit 1. Use the file path as the source for files and `<stdin>` for either stdin mode, and never expose a stack trace. Invocation failures are distinct: reject unknown options and more than one input operand with exit 2, empty stdout, a concise `js2php:` diagnostic containing `unknown option` or `one input` as applicable, and no stack trace. An unreadable file follows the same exit-2/no-stdout rule and its diagnostic contains `cannot read`.
