I want the original `lark` package's `*Bot` to support heartbeat-based tenant access token renewal for chat bots. For a bot created with `lark.NewChatBot(appID, appSecret)`, calling `bot.StartHeartbeat() error` should synchronously request a tenant access token with the app credentials, store the returned token on the bot so `bot.TenantAccessToken()` and authenticated SDK calls can use it, and then start a background renewal loop. The public stop method should be `bot.StopHeartbeat()`, and calling it should stop that renewal loop so it does not keep fetching new tenant access tokens.

The first `StartHeartbeat` fetch is part of the method's observable behavior: if the Feishu/Lark auth request succeeds, `StartHeartbeat` returns nil and the bot has a non-empty tenant access token; if that initial auth request fails, `StartHeartbeat` returns the error and does not silently continue. `StartHeartbeat` should only be valid for chat bots; calling it on a notification bot created with `lark.NewNotificationBot(...)` should return `lark.ErrBotTypeError` and should not start any background renewal work. After the loop is running, each successful renewal should update the bot's stored tenant access token. The renewal interval should default to 10 seconds, but when the auth response includes an `expire` value greater than 20 seconds, the next renewal should wait `expire - 20` seconds. Later renewal errors should be logged and should not crash the caller's process.
