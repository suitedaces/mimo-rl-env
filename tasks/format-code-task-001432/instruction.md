I want a public `can.Bus(channel=None, interface=None, config_context=None, ignore_config=False, **kwargs)` constructor-style factory for opening a CAN bus from application code. When I call `can.Bus(interface="virtual", channel="test", receive_own_messages=True)`, it should resolve the `virtual` backend and return an initialized bus object created with channel `"test"` plus the remaining keyword options, so the caller can use the normal bus instance API afterward.

If `ignore_config` is false, the factory should merge the explicit arguments and keyword options with the library's normal configuration sources, using `config_context` to select contextual configuration. Explicit `interface` and `channel` arguments should be copied into the configuration before loading, and after the backend is selected the `interface` key should not be passed down to the backend constructor. If `ignore_config=True`, the factory should skip configuration loading and use only the provided arguments and keyword options.

When no channel is resolved, the backend should be constructed without a positional channel so backends with their own default channel can decide what to do. When a channel is resolved, the backend should receive that channel as its first positional argument. Unknown interface names should fail before any backend instance is created, and backend import or class lookup failures should be reported as `CanInterfaceNotImplementedError`. The deprecated keyword aliases `bustype` for `interface` and `context` for `config_context` should continue to work through the existing deprecation warning mechanism.
