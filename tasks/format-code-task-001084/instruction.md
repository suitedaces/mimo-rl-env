The duration registry is used both directly by transpiler clients and indirectly by scheduling passes, but its update path currently assumes a mutable list and lets malformed units reach later stages. Make `InstructionDurations` a dependable public registry for user-supplied duration data. The constructor and `update()` must accept any finite iterable of 3- or 4-item records, including tuples and one-shot generators, without changing the caller's iterable or its records. A 3-item record uses `dt` as its unit; a 4-item record keeps its explicit unit. Supported units are `dt`, `s`, `ms`, `us`, `ns`, and `ps`.

Validate an incoming batch before committing any of it. A malformed record or unsupported unit must raise `TranspilerError`, leave all previously registered durations unchanged, and avoid installing earlier records from the same failed batch. For valid data, preserve the existing lookup contract: an exact instruction-name/qubit tuple is preferred to the name-wide (`qubits=None`) fallback, qubit order remains significant, and a zero-valued duration is still a real match. Queries must work with integer indices as well as `Qubit` objects. Converting between seconds-based units and `dt` must use the registry's sampling period in both directions; when no sampling period is available, a conversion that needs it must retain the established `TranspilerError`. Existing valid list-based callers and wildcard duration behavior must continue to work.
