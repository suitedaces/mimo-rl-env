I want `YOLOWorldDetector` to support prompt caching with `reparameterize(texts: List[List[str]]) -> None` on an already constructed detector instance. Calling `model.reparameterize([['cat'], ['dog'], [' ']])` should encode that prompt list once through the detector's configured text backbone, store the exact prompt list and the returned text feature tensor on that model instance, and return `None`.

After that, `model.predict(batch_inputs, batch_data_samples, rescale=True)` should work even when the provided data samples do not carry a `texts` attribute or `texts` key. In that cached session, prediction should run the image-only backbone path, reuse the stored text feature tensor as the class prompts, pass those cached features to the bbox head, and set the head's class count from the cached prompt feature shape so returned labels index into the cached prompt list. `model._forward(batch_inputs, None)` should also be able to run after `reparameterize()` by using the cached prompts and cached text features instead of requiring data samples with text prompts.

Calling `reparameterize()` again with a different prompt list should replace the cached prompt list and text features for that detector instance. Two separate `YOLOWorldDetector` instances should keep independent cached prompts and should not share prompt state.
