I want Nornir Host objects to manage reusable named connection plugin instances during task execution. A task should be able to call `task.host.open_connection(connection: str, configuration: Config, hostname: Optional[str] = None, username: Optional[str] = None, password: Optional[str] = None, port: Optional[int] = None, platform: Optional[str] = None, extras: Optional[Dict[str, Any]] = None, default_to_host_attributes: bool = True) -> ConnectionPlugin` and have Nornir look up the registered connection plugin by name, instantiate it, call its `open()` method with the resolved connection parameters plus the runtime configuration, cache the plugin object on that host under the connection name, and return the plugin object.

I need `task.host.get_connection(connection: str, configuration: Config) -> Any` to return the already-open plugin's `.connection` object when the named connection is cached, or automatically open it first with inventory-derived parameters when it is not cached. Connection parameter resolution should be available as `task.host.get_connection_parameters(connection: Optional[str] = None) -> ConnectionOptions`: with no connection name, it should return the host's normal inherited hostname, port, username, password, platform, and empty extras; with a connection name, values from that connection's host-specific `connection_options` should win, then inherited group connection options, then defaults connection options, and any missing standard fields should fall back to the host's normal inherited attributes while missing extras become `{}`.

The host should retain state across calls. For example, after `task.host.open_connection("dummy", task.nornir.config)`, `"dummy"` should be present in `task.host.connections`; a later `task.host.get_connection("dummy", task.nornir.config)` should reuse the cached plugin instead of opening a second one; and `task.host.close_connection(connection: str) -> None` should remove the cached plugin and call its `close()` method. Calling `open_connection` for a name that is already open should raise `ConnectionAlreadyOpen`, and calling `close_connection` for a name that is not open should raise `ConnectionNotOpen`.

I also want cleanup helpers for the same lifecycle. `task.host.close_connections() -> None` should close every cached connection on that host, and `Nornir.close_connections(on_good: bool = True, on_failed: bool = False) -> None` should run that cleanup across the selected hosts. When a `Nornir` object is used as a context manager, leaving the `with` block should close connections for both good and failed hosts.
