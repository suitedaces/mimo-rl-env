I want `MolecularHamiltonian.local_energy(ansatz)` to be available on an already constructed `MolecularHamiltonian`. It should return a callable with signature `(rng: Optional[KeyArray], params: Params, phys_conf: PhysicalConfiguration) -> tuple[Energy, Stats]`.

In a session like `local_energy_fn = hamil.local_energy(ansatz.apply); energy, stats = local_energy_fn(rng, params, phys_conf)`, the callable should bind `params` into the ansatz, evaluate the wave function at `phys_conf`, and return the local molecular energy for each electron configuration. The energy should be the sum of the kinetic term from the Hamiltonian's Laplacian factory, nuclear-nuclear energy using the Hamiltonian valence charges, electron-electron Coulomb energy, the configured local potential, and the configured nonlocal potential.

The stats dict should include exactly `hamil/V_el`, `hamil/E_kin`, `hamil/V_loc`, `hamil/V_nl`, `hamil/lap`, and `hamil/quantum_force`, with each value holding the matching component used to form the returned energy, except the Laplacian and quantum-force diagnostics. For a Coulomb Hamiltonian without an ECP, changing `rng` while keeping the same `params` and `phys_conf` should not change the returned energy or stats; for a Hamiltonian with nonlocal ECP terms, the callable should pass `rng` through so quadrature-dependent nonlocal contributions are included. Calling the returned callable repeatedly with the same `rng`, `params`, and `phys_conf` should produce equal JAX pytrees and should not mutate `params` or `phys_conf`.
