I want a stateful `CardinalityRule` rule evaluator for ElastAlert rules, constructed as `CardinalityRule(rules, args=None)` and used by calling `add_data(data)`, `garbage_collect(timestamp)`, and `get_match_str(match)` while reading emitted alert documents from `matches`. The `rules` dictionary must include `timeframe`, `cardinality_field`, and either `max_cardinality` or `min_cardinality`; if neither threshold is present, construction should raise `EAException`.

For a max-cardinality session with `{'max_cardinality': 4, 'timeframe': timedelta(minutes=10), 'cardinality_field': 'user', 'timestamp_field': '@timestamp'}`, calling `add_data` with four events whose `user` values are `bill`, `coach`, `zoey`, and `louis` should leave `matches` empty. Adding another event with duplicate `user == 'coach'` should still leave `matches` empty. Adding a fifth distinct value such as `user == 'francis'` within the same timeframe should append one match containing that triggering event.

For a min-cardinality session with `{'min_cardinality': 4, 'timeframe': timedelta(minutes=10), 'cardinality_field': 'user', 'timestamp_field': '@timestamp'}`, two unique users should not alert before the timeframe has elapsed. After the timeframe has elapsed, `garbage_collect(timestamp)` should evaluate the current window and append a match when the number of unique values is still below the minimum.

The rule should support `query_key` grouping: with `query_key: 'user'`, each user gets an independent cardinality count for `cardinality_field`, and matches for one key should include that key's value in the emitted match. The `cardinality_field` lookup should support dotted paths such as `d.ip`, ignore events where that field is missing, and count duplicate values only once. `garbage_collect(timestamp)` should expire values whose most recent occurrence is older than `timeframe`, and `get_match_str(match)` should return a human-readable message describing whether the max or min unique-value threshold was violated and the time window involved.
