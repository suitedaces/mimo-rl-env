The package advertises Python 3 support, but its public corpus stack still behaves like a Python 2-only implementation: importing `underthesea.corpus` fails on a clean Python 3 runtime, text decoding uses the removed `unicode` name, and corpus files are handled with implicit platform encodings. Bring the public corpus APIs up to a dependable Python 3 behavior without changing the existing Vietnamese data or segmentation results. `from underthesea.corpus import DictionaryLoader, PlainTextCorpus, viet_dict_11K, word_sent` and the nested `underthesea.corpus.word_sent.word_sent` entry point must both be importable and callable. `UnicodeTransformer.transform` must accept either UTF-8 bytes or an existing text string and return equivalent Unicode text. `PlainTextCorpus.load(folder)` must read only regular files directly in the folder, in deterministic lexicographic filename order, decode UTF-8, preserve every line including blank and trailing lines, and replace any documents loaded previously. Each document keeps its filename as `id` and exposes the decoded lines through `sentences`. `PlainTextCorpus.save(folder)` must create the destination directory when absent, write each document as UTF-8 with the same newline-joined sentence content (including a trailing newline represented by a final empty sentence), and leave unrelated existing files untouched. The bundled `viet_dict_11K.words` property must remain lazily usable as an ordered list of 11,373 Unicode strings beginning with `a`. Finally, keep the established model behavior: the two representative Vietnamese inputs `cộng hòa xã hội chủ nghĩa` and `Hồ Chí Minh ?` must continue producing their current underscore-tokenized outputs, including punctuation spacing. Existing callers on the supported Python runtime should not need compatibility shims or path hacks.
