I want a `DistanceJoint` class that I can use with the existing `World` simulation to keep two rigid bodies at a fixed distance between two anchor points. The constructor should be `new DistanceJoint(bodyA: RigidBody, bodyB: RigidBody, anchorA?: Vector2, anchorB?: Vector2, length?: number, frequency?: number, dampingRatio?: number, jointMass?: number)`, where omitted anchors default to the bodies' current positions and an omitted or non-positive `length` uses the initial distance between the two anchors.

After I register both bodies and then register the joint with `world.register(joint)`, each `world.update(delta)` should include the joint in the constraint solve. For example, if two dynamic circles start at `(0, 0)` and `(4, 0)` and I create `new DistanceJoint(a, b, a.position, b.position, 2, 15, 1)`, subsequent updates should apply corrective linear and angular impulses along the line between the anchors so the anchor separation moves toward and remains near `2` rather than freely drifting. If the anchors are offset from the centers of mass, the corrective impulse should also affect each body's angular velocity according to the anchor offset.

The joint should expose `localAnchorA` and `localAnchorB` as body-local anchor coordinates computed from the constructor anchors, so moving or rotating the bodies later still solves against the corresponding attached points. It should expose a mutable `length` property: reading it returns the current target length, setting it changes the target for later solves, and setting it to a negative value clamps the target to `0`. The joint should respect the inherited stiffness controls: positive `frequency`, `dampingRatio`, and `jointMass` create a soft distance constraint using the existing beta/gamma behavior, while a non-positive frequency behaves as a solid distance constraint.

The solver should participate in warm starting when `Settings.warmStarting` is enabled by accumulating the scalar impulse between updates and reapplying it during preparation. It should also respect `Settings.positionCorrection`: when enabled the current distance error contributes bias correction, and when disabled only the velocity error is solved.
