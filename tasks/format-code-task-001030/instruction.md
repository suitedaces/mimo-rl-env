Add per-request GCP Vertex AI safety settings to the existing OpenAI-compatible Gemini chat-completions extension. Callers already use the vendor-specific fields on an OpenAI request for Gemini-only generation options such as thinkingConfig, but there is no way to configure content blocking; the gateway therefore cannot express different moderation policies for different workloads.

Accept a safetySettings array in the same GCP Vertex AI vendor extension, using Vertex's request schema: each entry may carry method, category, and threshold values, and the gateway must preserve the supplied list, its order, and each supplied value when producing the outgoing GenerateContentRequest. Safety settings belong alongside the generated contents and generation_config in the Vertex request, not inside generation_config. The extension must work for both ordinary and stream=true chat completions; streaming changes only the existing endpoint selection/format, and must not discard the settings.

Adding safety settings must not regress standard OpenAI-to-Gemini generation translation or the already-supported vendor thinkingConfig: when those fields are supplied together, temperature, max_tokens, and thinkingConfig remain present with their translated values and the safety list is also forwarded. When no safetySettings are supplied, the outgoing request must omit that field rather than inventing an empty policy. Existing requests without vendor fields and the existing streaming/non-streaming endpoint behavior remain compatible.
