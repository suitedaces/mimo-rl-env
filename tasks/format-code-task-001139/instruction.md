Moto currently exposes EC2 network interfaces through create, modify, attach, and detach calls, but a boto3 client cannot inspect one attribute at a time because `DescribeNetworkInterfaceAttribute` raises `NotImplementedError`. Implement that public operation and make its results agree with the existing network-interface state transitions.

Support the service model attributes `description`, `groupSet`, `sourceDestCheck`, `associatePublicIpAddress`, and `attachment`. Every successful response must identify the requested network interface. `description` must return the value supplied at creation and every subsequent description update, including an explicit empty value used to clear a description. `groupSet` must return the current security groups with their IDs and names after a group update.

The boolean attributes must use the boto3 response shapes: `SourceDestCheck` is a `{ "Value": bool }` structure and `AssociatePublicIpAddress` is a boolean. A newly created standalone ENI starts with source/destination checking enabled and public-IP association disabled. Changes through `ModifyNetworkInterfaceAttribute` must be visible to this API, including changing either setting to `False`; do not conflate an explicit false value with an omitted update.

For `attachment`, an unattached ENI must not expose an `Attachment` result. Once attached, the result must report the attachment ID, device index, instance ID, instance owner ID, and `attached` status. `DeleteOnTermination` defaults to `False` for this attachment and must reflect a later attachment modification. After detaching, the attachment result must disappear rather than returning stale data. A request for an ENI that does not exist must raise the normal EC2 `InvalidNetworkInterfaceID.NotFound` client error with HTTP 400.
