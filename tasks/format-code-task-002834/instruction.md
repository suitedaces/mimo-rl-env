I want the `urlwatch` CLI to support a job-list management command for changing an existing job's location while preserving its cached history: `urlwatch --change-location JOB NEW_LOCATION`. `JOB` should resolve the same way as other job management commands, either by 1-based job index or by the job's current location string, and `NEW_LOCATION` should be required as the second argument.

On a successful run, urlwatch should update the matched job in `urls.yaml` instead of creating a new job: URL jobs change their `url`, Browser jobs change their `navigate`, and Shell jobs change their `command`. It should print `Moving location of <job repr> to "<new location>"`, save the updated job list, and exit with code 0.

The command must guard against overwriting another configured job. If `NEW_LOCATION` already matches any existing job location, it should print `The new location "<new location>" already exists for a job. Delete the existing job or choose a different value.`, skip saving changes, and exit with code 0. If `JOB` cannot be resolved, it should print `Not found: <job>` with the supplied target and skip saving changes.

When the job location changes, urlwatch should move cached snapshots from the old job identity to the new one. If any snapshots are moved, stdout should include `Moved N snapshots of "<old location>" to "<new location>"`; if no snapshots are present, it should not print that line. The `--help` output should list `--change-location JOB NEW_LOCATION` in the job list management options with a short description that it changes the location of an existing job by location or index.
