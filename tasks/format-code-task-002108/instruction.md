I want OneFlow to provide a shell command for enabling and disabling the mock torch import environment without editing my shell variables by hand. I should be able to run either `python -m oneflow.mock_torch` or the installed `oneflow-mock-torch` command, with an optional positional action of `enable` or `disable`; omitting the action should behave like `enable`.

For `enable`, the command should exit 0 and print one shell-evaluable line to stdout: `export ONEFLOW_MOCK_TORCH_LAZY=False; export ONEFLOW_MOCK_TORCH_VERBOSE=False; export PYTHONPATH=<mock_torch_dir>:$PYTHONPATH`, where `<mock_torch_dir>` is the installed directory that contains the OneFlow mock torch shim. Passing `--lazy` should change `ONEFLOW_MOCK_TORCH_LAZY` to `True`, passing `--verbose` should change `ONEFLOW_MOCK_TORCH_VERBOSE` to `True`, and passing both should set both exports to `True`.

For `disable`, the command should exit 0 and print shell commands that remove entries ending in `oneflow/mock_torch` from the current `PYTHONPATH` and unset `ONEFLOW_MOCK_TORCH_LAZY` and `ONEFLOW_MOCK_TORCH_VERBOSE`. If removing those entries leaves no paths, stdout should be exactly `unset PYTHONPATH; unset ONEFLOW_MOCK_TORCH_LAZY; unset ONEFLOW_MOCK_TORCH_VERBOSE`; otherwise it should export the remaining colon-separated `PYTHONPATH` and then unset the two mock torch variables. If `PYTHONPATH` is not set, `disable` should exit 0 without printing anything.

The command should support `--help`, writing argparse-style usage information to stdout with exit code 0 and showing the `enable`/`disable` action plus the `--lazy` and `--verbose` flags. An invalid action such as `oneflow-mock-torch maybe` should fail with argparse's nonzero usage error on stderr.
