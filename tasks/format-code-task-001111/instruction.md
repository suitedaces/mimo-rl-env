Outbound delivery is currently one-shot, so a recoverable receiver failure loses the immediate delivery and repeated submissions are ambiguous to downstream systems. Extend the public outbound configuration accepted by `.send(config, configName, record, recordInfo)` with an optional delivery policy under `destination`.

A `destination.retry` policy has a required positive-integer `max_attempts`, counting the initial request, an optional `status_codes` list of integer HTTP statuses from 400 through 599, and an optional boolean `retry_on_network_error`. Retry only response statuses named in `status_codes`; a status outside the list must reject immediately. Network/transport request failures are retryable by default when a retry policy is present, while an explicit `retry_on_network_error: false` disables that behavior. Stop after `max_attempts` and propagate the delivery failure. When `retry` is absent, retain the existing single-attempt behavior.

Support static `destination.headers` on outbound requests and an optional `destination.idempotency_key_header` naming the header that receives the same canonical SHA-256 payload hash already stored in outbound `completed_tasks`. That key must stay identical across every attempt and for semantically equivalent mapped objects whose keys were inserted in a different order. Merge static headers with existing credential-based header authentication. The fetched Authorization value and generated idempotency value take precedence over caller-supplied collisions, and credentials must be fetched once for a send rather than once per attempt.

Only a successful eventual delivery returns `true` and appends one normal outbound completion. A failed delivery must leave `completed_tasks` unchanged. Validate the retry policy before credential lookup or HTTP delivery: reject an absent, zero, fractional, or non-numeric `max_attempts`, status entries outside 400-599 or not integers, and a non-boolean `retry_on_network_error`.

Preserve the neighboring behavior of the send API. An already-completed identical payload for the same configuration name returns `false` before credentials or delivery and does not alter its completion history. Mapping failures remain reported as mapping errors, are never retried, and do not update completion history.
