I want this JWT library to provide verified parsing as a direct library API. The public API should include `type Keyfunc func(*Token) (interface{}, error)`, `func Parse(tokenString string, keyFunc Keyfunc) (*Token, error)`, `func ParseWithClaims(tokenString string, claims Claims, keyFunc Keyfunc) (*Token, error)`, `func (p *Parser) Parse(tokenString string, keyFunc Keyfunc) (*Token, error)`, and `func (p *Parser) ParseWithClaims(tokenString string, claims Claims, keyFunc Keyfunc) (*Token, error)`.

For a valid compact JWT signed with HS256 using the key `[]byte("AllYourBase")`, calling `Parse` with a key callback that returns that key should return a `*Token` with decoded header and map claims, the third segment copied into `Token.Signature`, `Token.Valid == true`, and a nil error. For a token containing custom claims, calling `ParseWithClaims(tokenString, &MyClaims{}, keyFunc)` should decode the payload into the supplied claims type and return it on `token.Claims` when the signature and registered claims are valid.

Validation failures should return a `*ValidationError` instead of a valid token. A missing key callback should set `ValidationErrorUnverifiable`; a key callback error should be wrapped as unverifiable; an expired or not-yet-valid claim should set the corresponding registered-claim validation bit; and a bad signature should set `ValidationErrorSignatureInvalid`. If `Parser.ValidMethods` is set, parsing should reject tokens whose header `alg` is not in that list with a signature-invalid validation error. If `Parser.SkipClaimsValidation` is true, parsing should still verify the signature but should not fail only because `exp`, `iat`, or `nbf` claims are outside the current time.
