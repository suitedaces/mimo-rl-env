# Preserve RAG provenance through chunking and retrieval

RAG answers can cite a source only if the source survives the entire retrieval path. At the moment a loader can produce a `TextArtifact` with a `Reference` and useful source metadata, but chunking turns it into anonymous artifacts. Equal excerpt text from different sources is then collapsed as one result, so the eventual footnote prompt can silently lose a citation. Rerankers and the `max_chunks` setting make that loss especially hard to diagnose because they operate after the current normalization step.

Make provenance a stable part of the RAG contract. When the shared chunker API receives a `TextArtifact`, every generated chunk must retain that artifact's `reference`, `name`, `encoding`, and `encoding_error_handler`; retain its `meta` values as a deep copy so changing a chunk's nested metadata cannot change the source artifact or a sibling chunk. Chunks must still receive their own normal artifact identities. Plain-string and combined `ListArtifact` inputs have no single source to inherit, so keep their existing plain-chunk behavior without inventing a reference or metadata.

A `TextLoaderRetrievalRagModule` must therefore be able to load a referenced artifact, chunk it, store/query it through a vector store, and return results that still carry the original reference and metadata. Those results must remain usable by `FootnotePromptResponseRagModule`: its generated system prompt needs the retained reference ID and source title.

Normalize retrieval candidates by both excerpt text and source identity, where source identity is `Reference.id` and an absent reference is its own identity. Apply that rule before reranking and again to the reranker output. Text with the same value from different reference IDs must remain as separate chunks; text from the same reference ID, or two unreferenced copies, is one duplicate. Preserve the first occurrence and its complete artifact when collapsing duplicates, and preserve the order supplied by the retrieval or reranking phase. Apply `max_chunks` after the final normalization: a positive value keeps the first N normalized chunks and zero produces no chunks. Reject a negative `max_chunks` with a `ValueError` that identifies `max_chunks`.

Finally, all citation/reference collection paths must use the same identity rule. `RagContext.get_references()` and the footnote prompt must list a shared reference ID once, using the first encountered reference's details and source order, even if a later artifact has a different `Reference` object with that same ID.
