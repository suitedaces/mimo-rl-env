The kubelet resource-metrics endpoint is exposed through the provider API, but clients that speak the upstream kubelet protocol cannot consume the current response. Providers already return Prometheus client-model MetricFamily values, and the same process still serves the legacy JSON stats summary for older metrics-server versions. Make the resource endpoint a compatible, well-documented HTTP surface without regressing that legacy path.

For a successful GET of /metrics/resource (with or without its trailing slash), serialize the returned metric families as Prometheus text exposition (including the standard HELP/TYPE metadata and sample lines), not as a JSON representation of the protobuf structs. Set a Content-Type that identifies the Prometheus text exposition format version 0.0.4. The emitted text must remain parseable by a Prometheus text parser and preserve each family's type, help text, labels, numeric sample value, and timestamp. This applies equally when the endpoint is reached through PodHandler and through the package's AttachPodMetricsRoutes convenience integration.

The two metric routes must be independently reachable when both handlers are configured: /metrics/resource serves the text response, while /stats/summary continues to serve the existing JSON summary contract (including its trailing-slash behavior where already supported). Do not make registration order cause one endpoint to capture the other. A nil metrics provider handler continues to return HTTP 501. If a configured provider returns an error, return HTTP 500 and expose the provider error to the caller using the existing handler error conventions; do not report a successful metrics response.

Update the metrics proposal documentation to state the wire-level Prometheus text exposition contract for /metrics/resource and distinguish it from the backward-compatible JSON /stats/summary endpoint, so provider authors do not infer the format from the Go return type alone.
