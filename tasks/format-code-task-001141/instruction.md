The Python index cataloger currently drops every requirements.txt declaration unless it contains an exact == version. That makes an SBOM hide dependencies that are constrained by ranges or left for the installer to resolve. Extend requirements.txt indexing so dependency presence is preserved without pretending that an unknown version is known.

For a normal requirement line, emit one Python package for the declared project name. Exact == pins keep their parsed version and produce the existing versioned PyPI PURL. A bare project name or a declaration using a supported version operator (>, >=, <, <=, ~=, !=, or a comma-separated combination) must also emit a package, but with an empty Version and the corresponding unversioned PURL (pkg:pypi/<name>). Do not infer a version from a lower/upper bound, exclusion, or compatible-release expression. Preserve the spelling of the declared name, and retain separate package entries when the same name is declared more than once.

Requirements may have an environment marker after a semicolon and trailing comments; those portions must not become part of the package name or version. A backslash-continued declaration is one requirement, and inline --hash=... options (including hashes on continuation lines) are metadata to ignore rather than package text.

Lines that are pip controls or references rather than an indexable project must remain ignored: -r/--requirement includes, --constraint, --index-url and other option lines, editable -e entries, direct URL requirements, blank/comment-only lines, and malformed declarations with no project name. Existing setup.py, lock-file, and installed-package cataloging behavior must remain unchanged.
