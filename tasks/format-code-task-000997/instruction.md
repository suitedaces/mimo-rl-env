Add a first-class way to inspect SQL after templating, without also parsing, linting, or fixing it. This is needed for debugging Jinja and placeholder configurations, including inputs which are intentionally not valid SQL yet.

Expose `render(sql, templater=None, config_path=None) -> str` from both `sqlfluff` and `sqlfluff.api` (including their public export lists). It must run the selected SQLFluff templater and return exactly its rendered text. As in the existing linting pipeline, normalize CRLF and bare-CR input line endings to LF before templating. Do not reject output because it is invalid SQL. The simple API must remain isolated from ambient user and project config: without `config_path` it uses SQLFluff's defaults, while `config_path` explicitly loads that file. A non-`None` `templater` argument has higher precedence than the templater selected by the config file.

Also expose `APITemplatingError` from both public modules. If a templater reports violations, or raises an `SQLTemplaterError` directly, `render()` must raise this aggregate exception instead of returning partial output. Its public `violations` attribute contains the underlying `SQLBaseError` objects. Its text begins `Found <N> issues while templating string.` and includes each violation's text on a following line, matching the existing aggregate parsing-error style.

Add `sqlfluff render PATH` for the same workflow, where PATH is one file or `-` for stdin. Successful output is only the rendered SQL on stdout, byte-for-byte after the documented newline normalization; do not append a newline when the rendered value has none. For a file, discover configuration relative to the target file. `--config` overrides discovered values, and an explicit `--templater` overrides both. Stdin must support `--config` in the same way.

On a CLI templating failure, exit with status 1, emit each templating violation to stderr using SQLFluff's standard location/code/description formatting, and leave stdout completely empty. Never emit a partially rendered SQL string on failure.
