I want `Davis.App` instances to expose a routing lifecycle with `app.start()` and `app.stop()` methods, both taking no arguments. Calling `app.start()` on a stopped app should begin routing exactly once: it should bind the app's link and form listeners, trigger the public `start` event, set `app.running` to `true`, and ignore later `start()` calls while the app is already running.

When `app.start()` runs in a browser where `Davis.supported()` is false, it should trigger the public `unsupported` event and leave the app stopped. Once started, requests delivered through `Davis.location` should run matching before filters first; if every before filter returns either `true` or `undefined`, the app should trigger `lookupRoute`, find the matching route, trigger `runRoute`, run the route, trigger `routeComplete`, and then run matching after filters. If any before filter returns `false`, the route and after filters should not run and the app should trigger `requestHalted` for that request.

If no matching route is found, the app should trigger `routeNotFound`. When `settings.handleRouteNotFound` is false and the unmatched request is not for the initial page load, the app should stop routing and delegate the request back to the server; page-load misses should not be delegated this way. If a route throws, the app should trigger `routeError`; with `settings.throwErrors` true the error should be thrown, and with it false the error should be logged instead.

When `settings.generateRequestOnPageLoad` is true, `app.start()` should immediately dispatch `Davis.Request.forPageLoad()` through the same filter and route pipeline. Calling `app.stop()` should unbind the app's link and form listeners, trigger the public `stop` event, and set `app.running` to `false`.
