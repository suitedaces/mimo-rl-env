## 只想用其中一个子包，却被拉下整个仓库的代码

我在自己的项目里只想用 `go-easy-utils` 里的一个工具，比如：

```go
import "github.com/jefferyjob/go-easy-utils/v2/sliceUtil"
```

但 `go mod tidy` 之后我发现，依赖图里把这个仓库下其它的工具子包（`anyUtil`、`jsonUtil` 等）也都给拉进来了，最终 vendor / 编译进我的二进制的代码，远远超过我实际用到的那一个子包。

翻了一下原因：仓库根目录有一个 `errorcode.go`，里面定义了一组通用的错误变量（`ErrSyntax` / `ErrType` / `ErrValOut` / `ErrUnsignedInt`）。`anyUtil`、`jsonUtil` 这些子包的实现里直接引用了根包的这些变量，导致只要任何一个子包被 import，根包就会被拉进来；而根包又跟整个仓库的模块路径绑在一起，于是连带把其它子包也带进了依赖。

对一个工具库来说我希望的是：**用哪个子包就只拉那个子包**，不要因为内部共享了几个 error 变量就把别的子包代码也带进来。这种全局 error 放在根包的设计也不利于以后单个子包独立扩展自己的错误类型。

希望能调整一下这部分的组织方式，让子包之间在错误定义上不要互相耦合到根包，从而避免引一个子包就拉整个仓库的问题。
