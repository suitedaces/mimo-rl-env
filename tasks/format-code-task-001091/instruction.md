The documentation search page is currently fragile around real URLs and unsafe around the data it renders: whitespace changes the search, malformed escapes can abort initialization, matching snippets are case-sensitive, and query or index text can become HTML. Please make the search page robust while retaining the existing Elasticlunr-backed title/author/content search.

Treat the `query` URL parameter as form-encoded input: decode percent escapes and `+` spaces, trim surrounding whitespace, show that normalized value in the search box, and use the same value for searching and result links. A missing, valueless, or whitespace-only query should leave the result list empty rather than showing a no-results state. Malformed percent escapes must not crash page initialization; they may remain literal.

Index only the search store's own enumerable records. Missing optional `author` or `content` fields count as empty strings. Keep the current relevance priority of title matches over author matches over content matches, and preserve the result order returned by the search engine. A nonblank query with no hits displays `No results found`. Each hit renders exactly one list item, in ranked order, containing its linked title and exactly one `result-text` snippet, even when its content is empty.

A snippet is a context window from the record content containing at most 150 source characters, plus an optional ellipsis. Center useful context around the first literal match when there is one. Within the selected window, wrap every literal occurrence in a `<mark>` element using case-insensitive matching while preserving the source's original casing. Multiple occurrences must not create extra snippets or result items.

Render titles, content, and highlighted query text as literal text, never executable markup. Result links retain the record URL, add one `highlight` parameter containing the encoded normalized query, use `?` or `&` as appropriate, and place the parameter before any fragment. Attribute-special characters must remain data, and executable URL schemes such as `javascript:` must not become clickable links; ordinary relative and HTTP(S) documentation links remain supported.
