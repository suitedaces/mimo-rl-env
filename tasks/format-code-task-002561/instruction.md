I want `sfcc-ci` to support OAuth token renewal for API client authentication from the command line. When I run `sfcc-ci client:auth my_client_id my_client_secret --renew` and Account Manager returns a 200 token response, the command should store the access token, store renewal credentials for that client, persist any returned refresh token, print `Authentication succeeded Auto-renewal enabled.` on stdout, and exit with code 0. When I authenticate with `sfcc-ci client:auth` without `--renew`, any stored renewal credentials and refresh token should be cleared and the success message should be just `Authentication succeeded`.

Browser login should keep renewal state consistent too. When `sfcc-ci auth:login` completes through the implicit browser flow, it should clear any stored renewal credentials and refresh token. If authorization-code browser login is enabled and Account Manager returns a refresh token, that refresh token should be stored; if no refresh token is returned, any stored refresh token should be cleared.

I also need a `sfcc-ci client:auth:renew` command. If renewal credentials are available and a refresh token is stored, it should request `https://account.demandware.com/dwsso/oauth2/access_token` with HTTP basic auth for the stored client credentials and form data `grant_type=refresh_token` plus the stored refresh token. If renewal credentials exist but no refresh token is stored, it should use the same endpoint and basic auth with form data `grant_type=client_credentials` and `response_type=token`. On a 200 response it should replace the stored access token, update the stored refresh token when the response includes one, print `Authentication renewal succeeded` on stdout, and exit with code 0. If no renewal credentials are configured, it should print `Authentication renewal not possible. Ensure initial authentication is done with --renew flag.` on stderr and exit non-zero; if the token request fails, it should print `Authentication renewal failed: <error>` on stderr and exit non-zero.

Commands that use OCAPI requests should use the same renewal state automatically. If a request fails because the response body reports `InvalidAccessTokenException`, or reports `invalid_token` for the currently stored token, and renewal is configured, the CLI should warn `Authorization invalid. Auto-renewal enabled. Running authorization...`, renew the token, then retry the original request with the new token. If renewal is not configured, it should keep the normal invalid-authorization error behavior.

For configuration visibility, `sfcc-ci instance:list -v` should show whether a refresh token is set and whether auto-renew credentials are configured, and `sfcc-ci instance:list -v -j` should include `auth.refresh_token` and `auth.auto_renew_token` in its JSON output.
