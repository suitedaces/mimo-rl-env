I want siuba to provide a pure table verb `rename(__data, **kwargs)` exported from the package so I can rename columns in pandas DataFrames, grouped DataFrames, and SQL lazy tables without changing the row data. Keyword arguments should map each new column name to an existing column named either as a string or as a simple siuba column expression, for example `rename(df, A=_.a)` and `rename(df, A="a")` should both turn a DataFrame with columns `a, b, c` and one row `1, 2, 3` into columns `A, b, c` with the same values. Multiple renames should work in one call, so `rename(df, A=_.a, C=_.c)` and `rename(df, A="a", C="c")` should return columns `A, b, C`. Calling `rename` with the same input should return the same result each time, should not mutate the input DataFrame, and should not perform filesystem, network, or global-state side effects. For grouped DataFrames, renaming a grouping column should update the group key to the new name, so `group_by(df, _.a) >> rename(z=_.a)` should produce columns `z, b, c` and remain grouped by `z`. For SQL lazy tables, `rename(tbl, A=_.a)` should build a lazy query with the selected SQL column labeled as `A`, preserve unrenamed columns, and update lazy grouping keys the same way. If a pandas rename target is not a simple column reference, such as `rename(df, z=_.a + 1)`, it should raise `ValueError`; for the same invalid target on a SQL lazy table it should raise `KeyError`.
