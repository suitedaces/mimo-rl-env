The Trino adapter wraps the driver's DB-API connection in `ConnectionWrapper`, but the wrapper currently behaves like a single mutable cursor and drops prefetched rows after a partial fetch. That makes normal dbt result consumption unreliable, especially when callers mix `fetchone`, `fetchmany`, and `fetchall`, and it prevents connection-level cancellation and cleanup from being reasoned about independently of a cursor. The wrapper also has a legacy escape hatch for deployments that disable prepared statements; that path must remain compatible with the driver's parameterized path while making the resulting SQL and failures deterministic.

Make `ConnectionWrapper` a usable DB-API connection/cursor boundary. Each call to `cursor()` must create an independent cursor backed by its own driver cursor, result buffer, description, and execution state; one cursor's fetches, cancellation, closing, or subsequent execution must not alter another cursor. Cursor `close()` and the connection's `close()` must be idempotent, and closing a cursor must not close the underlying connection. Connection-level `cancel()` must cancel every currently open cursor without creating or canceling unrelated cursors, while closing the connection must close outstanding cursors and the driver handle exactly once.

After `execute(sql, bindings)`, the wrapper must retain the complete result set returned by the driver. `fetchone()` returns the next row or `None` when exhausted; `fetchmany(size)` returns up to `size` unread rows (with size zero returning an empty list without consuming a row); and `fetchall()` returns every unread row. Fetches must preserve order, preserve unread rows across mixed fetch methods, and return empty lists rather than `None` for an executed statement with no rows. A later `execute()` starts a fresh result set and discards any unread rows from the previous execution. The cursor's public `description` must reflect its own driver cursor.

When prepared statements are enabled, pass the original SQL and bindings to the driver without rewriting. When disabled, interpolate bindings using the existing Trino literal rules: quote and escape apostrophes in strings, render `None` as `NULL`, preserve numeric values, render dates as `DATE 'YYYY-MM-DD'`, and truncate timestamp fractions to milliseconds as `TIMESTAMP 'YYYY-MM-DD HH:MM:SS.mmm'`. Unsupported binding values must raise `ValueError` before the driver execute call. The resulting cursor must remain consumable by `TrinoConnectionManager.get_response`, including query id, query text, row count, and the adapter's status string.
