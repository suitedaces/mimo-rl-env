Samsung air conditioners send XML responses whose attribute order, quote style, and spacing can vary by firmware. The binding currently recognizes most responses with literal substring checks, so semantically identical messages can be missed, misleading text can be accepted, and token parsing is fragile. Make the existing public static `ResponseParser` API interpret protocol XML by element and attribute values while retaining the two plain-text protocol greetings.

For every XML predicate, classification is based on the document root and exact, case-sensitive attribute values; attribute order, single versus double quotes, optional whitespace, and XML entity decoding must not change the result. `isResponseWithToken` matches an `Update` with `Type=GetToken`, `Status=Completed`, and a non-empty `Token`; `parseTokenFromResponse` returns that decoded token, or `null` when the input is null, malformed, not that response type, or lacks a non-empty token. Authentication error 301 is recognized only by `isFailedAuthenticationResponse`, while error 103 is recognized only by `isFailedResponse`; both require a `Response` with `Type=Authenticate` and `Status=Fail`. Successful login is `Response` / `AuthToken` / `Okay`, token readiness is `Response` / `GetToken` / `Ready`, and account invalidation is an `Update` with `Type=InvalidateAccount`. Device control is a `Response` with `Type=DeviceControl`, and a status update is an `Update` with `Type=Status`.

A device-state notification is a `Response` with `Type=DeviceState`, `Status=Okay`, and no `CommandID` attribute at all; an empty or non-`cmd` command ID still makes it a command response. `isCorrectCommandResponse` must compare the root `Response` element's complete `CommandID` value to the requested ID, without matching comments, other markup text, or prefixes. Null and malformed XML return `false` from every predicate rather than throwing. `isFirstLine` remains the non-XML exception: after trimming surrounding whitespace it matches exactly `DRC-1.00` or `DPLUG-1.6`, and returns false for null, suffixes, or surrounding noise.

`parseStatusResponse` accepts only successful `Response Type=DeviceState Status=Okay` documents and `Update Type=Status` documents; other well-formed roots return an empty map. Within an accepted document, collect descendant `Attr` elements whose `ID` names a known `CommandEnum`, use the decoded `Value`, ignore unknown or missing IDs, and let the last occurrence of a duplicate known ID win. Malformed status XML must continue to propagate `SAXException`. Reject any status document containing a `DOCTYPE` before entity expansion, so neither internal nor external entity declarations are processed. Preserve support for all canonical double-quoted response forms already handled by the binding and keep the existing public method signatures.
