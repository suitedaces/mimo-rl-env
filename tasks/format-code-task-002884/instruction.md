I want `onlykey-cli` to support wiping an OnlyKey credential slot from both direct command mode and the interactive shell. In direct mode, `onlykey-cli wipeslot <id>` should accept classic slot names `1a` through `6a` and `1b` through `6b`, OnlyKey DUO slot names such as `green1a`, `blue2b`, `yellow3a`, and `purple1b`, and numeric slot ids; it should map those names to the device slot number and send the credential-slot wipe command to the connected OnlyKey. In interactive mode, after starting `onlykey-cli`, entering `wipeslot <id>` should perform the same slot-name mapping and send the same wipe command without exiting the shell.

On a successful wipe, the CLI should read eight text responses from the device and print each response line to stdout in order. The direct command should complete with exit code 0 when the wipe command is sent and the device responses are printed; the interactive command should return to the prompt after printing those responses. For an invalid or missing `<id>`, direct mode should print `wipeslot [id]` followed by `[id] must be a valid slot number` to stdout, produce no stderr output from this validation path, and exit normally without sending a device wipe command. The interactive shell should print the same two validation lines for an invalid or missing `<id>`, produce no stderr output from this validation path, skip sending the device wipe command, and continue accepting commands.
