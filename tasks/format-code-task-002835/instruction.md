I want the standalone `config` helper tool to support encrypted config file workflows from the command line. When I run `config encrypt --in config.json --out config.dat --key secret`, it should read the plaintext JSON input, set the top-level `encryptConfig` value to `1` in the encrypted payload, write an encrypted output file, print `Success! File written to config.dat` on stdout, and exit 0. If I run the same command without `--key`, the tool should prompt for the encryption key with confirmation before writing the encrypted file.

I also want `config decrypt --in config.dat --out config.json --key secret` to read an encrypted config file, decrypt it, set the top-level `encryptConfig` value to `-1`, write plaintext JSON to the output path, print `Success! File written to config.json` on stdout, and exit 0. If the input to `encrypt` is already encrypted, stderr should contain `Error: File is already encrypted` and the process should exit 2; if the input to `decrypt` is not encrypted, stderr should contain `Error: File is already decrypted` and the process should exit 2. The `--key` flag should be accepted by the helper and used for these encrypted operations.

When `config upgrade` or `config downgrade --version N` receives an encrypted config file, it should ask for or use the same key, decrypt the input before applying the version conversion, then write the result back encrypted instead of silently producing plaintext. The help text for the tool should list `encrypt` and `decrypt` as commands alongside `upgrade` and `downgrade`.
