I want `collidertracker` to support a manual SuperCollider mode through a `-s, --skip-sc` CLI flag. When I run `collidertracker --skip-sc` or `collidertracker -s`, command-line parsing should accept the flag and start the tracker UI without running the automatic SuperCollider detection and management path: it should not check whether `sclang` is already running, should not start `sclang`, and should not start a separate SuperCollider instance on a free port.

In this mode, after the tracker model and OSC listener are created, the startup splash should be dismissed immediately instead of waiting for a `/cpuusage` readiness message from SuperCollider. This lets users manually run SuperCollider, evaluate the ColliderTracker support file themselves, and then launch the tracker without the app taking ownership of the SuperCollider process lifecycle.

The flag should be visible in CLI help as `-s, --skip-sc` with the description `Skip SuperCollider detection and management entirely`; `collidertracker --help` should exit 0 and show that option alongside the other persistent flags. The README run instructions and command-line options should also document the manual SuperCollider workflow and the `-s, --skip-sc` flag.
