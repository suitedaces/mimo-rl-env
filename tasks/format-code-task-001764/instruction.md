I want the `signerv2` package to support a Web3 remote transaction signer backend. The public API should include `Web3SignerFn(remoteSignerUrl string) (bind.SignerFn, error)`, plus `NewWeb3SignerClient(url string) Web3SignerClient` where `Web3SignerClient.SignTransaction(from common.Address, tx *types.Transaction) (*types.Transaction, error)` can be called directly.

`Web3SignerFn` should return a `bind.SignerFn` with no setup network call. When that signer is called with a sender address and an Ethereum transaction, it should POST a JSON-RPC 2.0 request to the configured URL using method `eth_signTransaction`, content type `application/json`, and one params object containing `from`, `to`, `gas`, `gasPrice`, `nonce`, and `data` as 0x-prefixed hex strings derived from the transaction. If the remote endpoint returns a JSON object with a `result` string containing an RLP-encoded signed transaction, with or without a `0x` prefix, the signer should hex-decode and RLP-decode it and return the signed `*types.Transaction`. For example, if a test HTTP server returns the RLP for a transaction signed by `0xf39fd6e51aad88f6f4ce6ab8827279cfffb92266` on chain ID 31337, calling the returned signer with that address and matching transaction should return a transaction whose recovered sender is that same address.

The backend should surface remote and decoding failures as errors from the signer call: an unreachable URL returns the HTTP client error, invalid JSON returns an error that indicates response decoding failed, a JSON-RPC `error` member returns an error for the response error, and malformed hex or malformed RLP in `result` returns a non-nil error. `SignerFromConfig(c Config, chainID *big.Int) (SignerFn, common.Address, error)` should also support `Config{Endpoint: ..., Address: ...}`: when both fields are non-empty and no private key or keystore is selected, it should return a signer factory backed by `Web3SignerFn` and return `common.HexToAddress(c.Address)` as the sender address.
