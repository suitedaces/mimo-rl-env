Altair's renderer and data-transformer registries are global, and today switching a plugin is permanent. This makes temporary notebook configuration awkward and makes it easy for one block of code to leak settings into later charts. Extend the public `PluginRegistry` API so plugin activation can carry keyword options and can also be used as a safely nested context manager.

`PluginRegistry.enable(name, **options)` must still activate immediately, so existing calls that ignore its return value continue to work. It must now return a context manager suitable for `with registry.enable(...)`. The registry exposes the active plugin name through `active` (`None` before first activation) and the current option mapping through `options`; callers must receive a copy, so mutating the returned mapping cannot mutate registry state. Each enable call replaces, rather than merges with, the previous options. Passing `name=None` reconfigures the currently active plugin, and must raise `ValueError` if there is no active plugin.

`get()` must return the original registered plugin object when there are no options. When options are configured, the callable returned by `get()` must supply them as keyword defaults when the plugin is invoked; explicit keywords at the invocation site take precedence. This behavior belongs to the generic registry so it works for both renderer and data-transformer registries, including explicitly registered plugins.

A `with` scope must restore the exact plugin name and options that were active before that particular `enable` call. Restoration must work for nested scopes and when the body raises. Attempting to enable an unknown plugin must raise `ValueError` mentioning its requested name without changing the previously active plugin or options.

Make the built-in `default` data transformer configurable through this mechanism with a `max_rows` option whose default remains 5000. A non-negative integer is an inclusive limit: data at the limit is accepted and data above it raises `MaxRowsError`, including the boundary where `max_rows=0`. `max_rows=None` disables the row limit while retaining normal conversion to inline values. These configured transformers must be honored by normal `Chart.to_dict()` serialization, and leaving a temporary transformer scope must restore the former transformer and its options so subsequent charts see the prior behavior.
