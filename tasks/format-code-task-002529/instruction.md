I want the `wstr` package to support pure multi-string UTF-16 block conversion for Win32 APIs that expect several null-terminated strings followed by a final extra null. The public functions should be `EncodeArrToBuf(dest []uint16, strs ...string) int`, `EncodeArrToSlice(strs ...string) []uint16`, `EncodeArrToPtr(strs ...string) *uint16`, and `DecodeArrPtr(p *uint16) []string`.

For encoding, `EncodeArrToSlice("ab", "cd")` should return `[]uint16{'a', 'b', 0, 'c', 'd', 0, 0}`, and `EncodeArrToPtr("ab", "cd")` should point at a heap-backed block with the same words. `EncodeArrToBuf(make([]uint16, 7), "ab", "cd")` should write `[97 98 0 99 100 0 0]` and return `7`. If the destination buffer is too small, `EncodeArrToBuf` should truncate without writing past the buffer and should still write the final double-null terminator when there is room; for example a destination of length `4` with `"ab", "cd"` should become `[97 98 0 0]` and return `4`, while a zero-length destination should return `0`.

For decoding, `DecodeArrPtr` should read a pointer to a double-null-terminated UTF-16 block and return the Go strings before the empty terminator: a block `[]uint16{'a','b',0,'c','d',0,0}` should decode to `[]string{"ab", "cd"}`. Passing `nil` to `DecodeArrPtr` should return an empty `[]string`. These functions should be deterministic for the same inputs, should not use filesystem, network, or global state, and `EncodeArrToBuf` should only mutate the caller-provided destination buffer.
