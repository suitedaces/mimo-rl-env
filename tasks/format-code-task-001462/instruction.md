I want the jmcomic library to provide public option factory helpers so user code can turn configuration into a ready-to-use JmOption in one call. The API should include create_option_by_file(filepath: str) -> JmOption, create_option(filepath: str) -> JmOption as an alias, create_option_by_env(env_name: str = 'JM_OPTION_PATH') -> JmOption, create_option_by_str(text: str, mode=None) -> JmOption, JmOption.from_file(filepath: str) -> JmOption, JmOption.construct(origdic: dict, cover_default: bool = True) -> JmOption, and JmOption.default() -> JmOption.

When I call JmOption.default(), it should return a JmOption built from the module default configuration, with defaults such as the current working directory as the base download directory, the default client implementation, default retry count, image decode enabled, download cache enabled, and plugin validation mode filled in. When I call create_option_by_str('download:\n  image:\n    suffix: .webp\n', mode=None), it should parse the text as YAML by default, deep-merge it with the defaults, and return an option whose image suffix decision uses .webp while unrelated defaults remain populated. When I write the same YAML to a file and call create_option_by_file(path) or create_option(path), it should return the same kind of JmOption and remember the source filepath so option.to_file() can save back to that path.

When I set an environment variable such as MY_JM_OPTION to an option file path, create_option_by_env('MY_JM_OPTION') should load that file. If the requested environment variable is unset or empty, create_option_by_env should raise the library's normal validation exception with a message naming the missing environment variable instead of silently using defaults.

JmOption.construct should support partial dictionaries by deep-merging nested values with defaults without mutating unrelated default branches. It should also honor the top-level log setting by disabling normal logging when log is false and enabling pretty logging when log is 'pretty'. For older option dictionaries, it should migrate download.threading.batch_count into download.threading.image, accept the old top-level plugin key as plugins, and move old zip plugin level settings between after_album and after_photo so album-level zip plugins run after albums and photo-level zip plugins run after photos. If cover_default is false, construct should build directly from the supplied complete dictionary instead of filling defaults.
