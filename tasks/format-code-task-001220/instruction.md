I want the Python scoring API in `navsim.evaluate.pdm_score` to expose `pdm_score(metric_cache: MetricCache, model_trajectory: Trajectory, future_sampling: TrajectorySampling, simulator: PDMSimulator, scorer: PDMScorer) -> PDMResults` and `pdm_score_multi(metric_cache: MetricCache, model_trajectorys: List[Trajectory], future_sampling: TrajectorySampling, simulator: PDMSimulator, scorer: PDMScorer) -> np.ndarray`.

The single-trajectory call should take the metric cache's initial ego state and reference PDM trajectory plus the agent trajectory in ego-relative poses, evaluate both the reference and prediction through the supplied simulator and scorer, and return the prediction row as a `PDMResults` object. For example, if the scorer produces per-proposal scores `[0.75, 0.42]` and its metrics for proposal index 1 are no-at-fault-collisions `1.0`, drivable-area compliance `0.5`, TTC `1.0`, comfort `0.0`, progress `0.8`, and driving-direction compliance `1.0`, then `pdm_score(...)` should return `PDMResults(no_at_fault_collisions=1.0, drivable_area_compliance=0.5, time_to_collision_within_bound=1.0, comfort=0.0, ego_progress=0.8, driving_direction_compliance=1.0, score=0.42)`. If another run produces scores `[0.6, 0.9]` and proposal index 1 metrics all equal `1.0` except progress `0.7`, the returned `PDMResults.score` should be `0.9` and `ego_progress` should be `0.7`.

The multi-trajectory call should evaluate the reference trajectory at proposal index 0 followed by every trajectory in `model_trajectorys` and return only the predicted scores, so if the scorer returns `[0.2, 0.4, 0.8]` for one reference and two predictions, `pdm_score_multi(...)` returns an array equal to `[0.4, 0.8]`. Calling either function twice with the same metric cache, trajectories, sampling, simulator behavior, and scorer behavior should produce the same result values; the functions should not write files, open network connections, or mutate the input `Trajectory.poses`.
