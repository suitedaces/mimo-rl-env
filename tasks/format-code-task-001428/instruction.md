I want HD key objects to support deriving children from BIP32-style path strings instead of forcing callers to split the path and call numeric child derivation one segment at a time. Given an existing `HDPrivateKey`, `key.derivePath(path: string) -> HDPrivateKey` should accept roots `m`, `M`, `m'`, or `M'`, parse slash-separated decimal indexes, treat a trailing `'` as hardened, and return the same child key as applying each parsed segment in sequence. `HDPrivateKey.isValidPath(path: string) -> boolean` should return `true` for valid private derivation paths including hardened segments and `false` for malformed paths.

For example, from the seed `000102030405060708090a0b0c0d0e0f`, `HD.PrivateKey.fromSeed(seed).derivePath("m/0'").toBase58('main')` should be `xprv9uHRZZhk6KAJC1avXpDAp4MDc3sQKNxDiPvvkX8Br5ngLNv1TxvUxt4cV1rGL5hj6KCesnDYUhd7oWgT11eZG7XnxHrnYeSvkzY7d2bhkJ7`, and `derivePath("m/0'/1/2'/2/1000000000").toBase58('main')` should be `xprvA41z7zogVVwxVSgdKUHDy1SKmdb533PjDz7J6N6mV6uS3ze1ai8FHa8kmHScGpWmj4WggLyQjgPie1rFSruoUihUZREPSL39UNdE3BBDu76`.

I also want existing `HDPublicKey` objects to support `pub.derivePath(path: string) -> HDPublicKey` for non-hardened paths only, plus `HDPublicKey.isValidPath(path: string) -> boolean`. From the public master key for the seed `fffcf9f6f3f0edeae7e4e1dedbd8d5d2cfccc9c6c3c0bdbab7b4b1aeaba8a5a29f9c999693908d8a8784817e7b7875726f6c696663605d5a5754514e4b484542`, `toPublic().derivePath('m/0').toBase58('main')` should be `xpub69H7F5d8KSRgmmdJg2KhpAK8SR3DjMwAdkxj3ZuxV27CprR9LgpeyGmXUbC6wb7ERfvrnKZjXoUmmDznezpbZb7ap6r1D3tgFxHmwMkQTPH`. A public-key path containing a hardened segment like `m/0'` should be invalid and `derivePath("m/0'")` should throw an `Error`.

Malformed paths should fail consistently: paths with a bad root, non-numeric segment, segment longer than 10 digits, or an index outside the unsigned 32-bit range should make `isValidPath` return `false` and make `derivePath` throw an `Error`. Calling `derivePath` with the same key state and same path should produce an equal child key each time, and validation should not mutate the key.
