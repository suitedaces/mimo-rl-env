The Travis CI wrapper should prepare repository state reliably before delegating to commitlint. A normal push build needs the base repository available as the `base` remote, while a pull-request build needs both the base repository and the pull-request source repository available under their dedicated remote names. Remote URLs must be derived from the Travis repository-slug variables; when Travis leaves the pull-request slug empty, use the base slug for the source remote. Fetch setup must complete before the commitlint child process is started, and pull-request ranges must still be passed as the two commitlint bounds (with any user CLI arguments preserved after them).

The wrapper temporarily stashes a dirty worktree while it performs setup and linting. That stash must be restored on every exit path, including a failed remote add/fetch and a non-zero commitlint result, while the original failure remains observable through a non-zero process status. Clean worktrees should not be stashed or popped. The existing push-build behavior of linting one commit must remain compatible.
