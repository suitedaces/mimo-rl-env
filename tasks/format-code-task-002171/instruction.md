I want the DSP code to provide a stateful `DelayLine` class for one complex-valued feedback delay element. The public API should be `DelayLine()`, `~DelayLine()`, `void prepare(const int L, const float sampleRate)`, `void setFilterCoefficients(float gDC, float gPI, float fT)`, `std::complex<float> read() const noexcept`, `void write(const std::complex<float> input)`, and `void update()`.

A session should start with `prepare`, which sets the delay length in samples, clears the whole delay buffer to zero, and resets the decay-shaping filter for the supplied sample rate. After `setFilterCoefficients(1.0f, 1.0f, 1000.0f)`, the write path should be transparent: with `prepare(2, 48000.0f)`, the repeated sequence `update(); write(x); read();` for real-valued complex inputs `1, 2, 3, 4` should return `0, 0, 1, 2`. Complex samples should keep both components together; with length 1 and unity gains, writing `(0.5, -0.25)` on one sample should make `(0.5, -0.25)` readable on the next sample.

`setFilterCoefficients` should update the filter used by later `write` calls so feedback can decay differently at DC and Nyquist, using the absolute values of `gDC` and `gPI` and the transition frequency `fT` in Hz. The filter should be a one-pole shelf where each write stores `y[n] = b0*x[n] + b1*x[n-1] - a1*y[n-1]`, and equal DC/Nyquist gains of 1.0 should reduce to `y[n] == x[n]`. Calling `prepare` again should clear both the circular buffer contents and the filter history so a new session starts with zero delayed output.
