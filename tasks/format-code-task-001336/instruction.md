I want `airdialogue prepro` to support an alternate inference input mode for dialogue data. When I run `airdialogue prepro --job_type '0|0|1|0|0' --input_type dialogue --output_dir OUT --output_prefix dev --infer_src_data_file INFER_DATA --infer_kb_file INFER_KB`, it should read JSONL examples from `INFER_DATA` and paired KB JSONL rows from `INFER_KB` instead of requiring the regular `--data_file`/`--kb_file` inputs for that inference job.

It should keep the existing `--keep_incorrect` behavior: by default skip records whose JSON has `correct_sample: false`, and include them when `--keep_incorrect true` is supplied. It should remove non-ASCII characters before JSON parsing and skip very short padding lines in both alternate input files. For every retained example, it should tokenize the intent and dialogue using the normal preprocessing tokenizer, flatten/tokenize the paired KB, and append one line to `<output_dir>/<output_prefix>.infer.src.data` formatted as `<tokenized intent>|<tokenized dialogue>`, with any `<eod> ` marker removed from the dialogue field. It should append the matching flattened KB line to `<output_dir>/<output_prefix>.infer.kb`; this mode should not create `<output_prefix>.infer.tar.data`.

If `--infer_kb_file` points to a missing path, the command should still emit one KB line per retained source example using `no_res` as the KB content. If a retained example has an empty dialogue and `--self_play_start_turn agent` is supplied, its dialogue field should be `<t2>`; with `--self_play_start_turn customer`, it should be `<t1>`. `airdialogue prepro --help` should list `--infer_src_data_file`, `--infer_kb_file`, and `--self_play_start_turn`. A successful run should exit 0 and create `OUT` when needed. If the alternate inference source file cannot be opened or contains malformed JSON, the command should fail with a non-zero exit instead of silently producing successful output.
