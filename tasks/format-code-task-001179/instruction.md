Harden the public `sentry.utils.zip.safe_extract_zip` helper before it is used on uploaded release and debug archives. The current implementation silently skips some unsafe names and can write earlier members before discovering a later dangerous one, which makes archive handling both surprising and vulnerable to path escapes.

A regular archive containing nested files must still extract their bytes beneath the requested destination. Preserve the documented input forms (a filename, a binary file-like object, or an already-open `zipfile.ZipFile`), and do not close an object supplied by the caller.

Treat archive member names as untrusted regardless of the host operating system: reject absolute POSIX names, drive-qualified Windows names, and any `..` path component written with either `/` or `\` separators. Reject symbolic-link members and reject duplicate member names that would address the same output file. Before creating or overwriting any destination file, validate the whole archive and raise `ValueError` for a rejected archive; a rejected archive must leave no newly extracted files behind. Extraction must also refuse to follow a pre-existing symlink anywhere below the destination, so no member can write outside the destination tree. Keep the existing safe regular-file behavior and public function signature intact.
