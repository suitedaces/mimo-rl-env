I want the `openapi-python-client generate` command to accept a `--config <file>` option so I can keep generator settings in a YAML or JSON file instead of passing everything on the command line. For example, `openapi-python-client generate --path openapi.yaml --config client.yml` should read `client.yml` before generation, parse it as YAML, and apply keys such as `package_name_override`, `project_name_override`, `field_prefix`, `class_overrides`, `post_hooks`, and `literal_enums` to the generator configuration. A `.json` config file should be parsed as JSON, while YAML files like `.yml` or `.yaml` should be parsed with safe YAML loading.

On a valid config file, the command should continue with generation and should not print any extra config-specific output; if generation itself succeeds, the process exits with code 0. If the config file cannot be read, is malformed, or contains values that cannot be validated into the generator config, the command should fail before generating files, exit with code 2, and report `Unable to parse config` in the CLI error output.
