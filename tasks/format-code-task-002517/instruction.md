I want the `github.com/reugn/go-streams/aws` module to provide an AWS S3 stream connector that can be used as stateful source and sink objects in a go-streams pipeline.

The source API should expose `type S3SourceConfig struct { Bucket string; Path string; Parallelism int; ChunkSize int }`, `type S3Source`, and `func NewS3Source(ctx context.Context, client *s3.Client, config *S3SourceConfig, logger *slog.Logger) *S3Source`. If `logger` is nil it should use `slog.Default()`, if `Parallelism < 1` it should default to 1 worker, and if `ChunkSize < 1` it should default to 5 MiB. Constructing a source should asynchronously list every object in `config.Bucket` under `config.Path` using paginated S3 `ListObjectsV2` calls, fetch each listed key with `GetObject` using the configured worker parallelism, and emit `*S3Object` values through `Out()`.

The source should also implement `Via(operator streams.Flow) streams.Flow`, which streams the source into the supplied flow and returns that flow, and `Out() <-chan any`, which returns the output channel. Each emitted `S3Object` should contain the S3 key and an `io.Reader` for the object data read with the configured chunk size. When listing finishes, reading finishes, or the context is cancelled, the source should close its output channel after all object reader workers exit; listing, fetch, and read failures should be reported through the configured logger.

The shared object envelope should be `type S3Object struct { Key string; Data io.Reader }`, where `Key` is the full S3 object key and `Data` is the readable payload used by downstream flows and sinks.

The sink API should expose `type S3SinkConfig struct { Bucket string; Parallelism int }`, `type S3Sink`, and `func NewS3Sink(ctx context.Context, client *s3.Client, config *S3SinkConfig, logger *slog.Logger) *S3Sink`. If `logger` is nil it should use `slog.Default()`, and if `Parallelism < 1` it should default to 1 worker. Constructing a sink should start worker goroutines that consume values from `In() chan<- any`; each `S3Object` value or `*S3Object` pointer sent to `In()` should be uploaded with S3 `PutObject` using `config.Bucket`, the object's `Key`, and the object's `Data` as the body.

The sink should log unsupported input types instead of uploading them, log upload errors while continuing to process later inputs, and close its completion signal after the input channel is closed and all upload workers have exited. `AwaitCompletion()` should block until that completion signal is closed so callers can wait for all accepted input objects to be handled.
