Dask graphs are often used to pass structured payloads between tasks, but the low-level graph protocol only traverses lists. A dict or OrderedDict used as a task argument can therefore contain graph keys and nested tasks that are never resolved, while dependency analysis may still see those references. This can leave the synchronous and threaded schedulers with inconsistent state, and it makes graph optimizations unsafe for ordinary mapping-shaped payloads.

Extend the low-level computation protocol so mapping values are first-class computations. Ordinary dict and OrderedDict instances, including mappings nested inside existing list computations, must recursively resolve graph keys and task tuples in their values. Mapping keys are always literal data: a key equal to a graph key must not be looked up or rewritten. Preserve the concrete mapping type and insertion order for dict subclasses that support normal key/value construction, including OrderedDict. Existing non-task tuple values remain literal, and mappings containing no graph references or task tuples remain data rather than becoming scheduled jobs.

The graph inspection helpers must agree with execution: `has_tasks` must detect references and nested tasks inside mapping values, and `get_dependencies` must report those referenced graph keys while ignoring mapping keys. Substitution used by graph optimization must recurse through mapping values, preserve their mapping type, and leave keys unchanged so operations such as `inline` continue to produce executable graphs. `quote` must continue to protect an entire mapping, including task-looking values, from interpretation as a computation.

These semantics must be identical through the synchronous and threaded schedulers. A nested task that raises must propagate its original exception to the caller. Existing list-based computations and literal mappings must continue to work unchanged.
