Silex applications use one shared locale value for routing and translation, but nested requests such as embedded fragments currently overwrite that value. A child request can therefore make the parent controller render in the child language after the child has finished. Worse, if the child throws while it is handled without catching, Application::handle() can leave the public request service pointing at the child request. This makes locale-sensitive rendering and request-aware services depend on earlier nested work.

Make the request lifecycle isolate these scopes through the existing Application, Request, and translator APIs. When a request contains a routed _locale, that locale must be visible through the application locale and the Silex translator while that request is running; both trans() and transChoice() calls that omit an explicit locale must use it. A nested subrequest may temporarily switch the active locale to its own _locale and must expose its own translations while it runs, but once it completes the parent request's locale and translations must be restored. The same restoration is required when the subrequest fails and its exception is allowed to propagate to the caller.

Application::handle() must always restore the public request service to the request that was active before a nested call, including when the nested call throws. After the outer request has completed, accessing the request service outside request scope must retain its existing protected-service failure behavior. Keep existing route matching and normal response/error propagation compatible.
