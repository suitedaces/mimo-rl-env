I want the Go library to expose response validation for a route-matched OpenAPI operation with `ValidateResponse(ctx context.Context, input *ResponseValidationInput) error`. `ResponseValidationInput` should carry the already-built `*RequestValidationInput`, response `Status int`, response `Header http.Header`, response `Body io.ReadCloser`, and optional `*Options`, and `SetBodyBytes(value []byte) *ResponseValidationInput` should replace the response body with a rereadable body containing those bytes.

For a request whose method is `HEAD`, `ValidateResponse` should return nil without validating the response body. For response statuses such as 304, 301, 307, and 308, it should also return nil without further validation. For a normal documented response, such as a 200 response with `Content-Type: application/json`, body `{"id":123}`, and an OpenAPI schema requiring numeric `id`, it should return nil and leave `input.Body` readable again with the same bytes after validation. If the operation defines a default response and the concrete status has no response entry, the default response should be used.

When `Options.IncludeResponseStatus` is false, an undocumented response status with no default response should be accepted; when it is true, the same input should return a `*ResponseError` whose message is `status is not supported`. Required response headers should be decoded according to their OpenAPI serialization style and validated against their schemas; if a required header such as `X-Trace` is missing, return a `*ResponseError` with message `response header "X-Trace" missing`, and if a present header fails its schema, return a `*ResponseError` saying that header does not match the schema. If `Options.ExcludeResponseBody` is true, header and status validation should still run, but body content and schema validation should be skipped.

For body validation, the function should select the response media type from the `Content-Type` header, decode the body using registered body decoders, and validate it as a response schema, including write-only restrictions unless `Options.ExcludeWriteOnlyValidations` is true. A response with `Content-Type: text/plain` when only `application/json` is documented should return a `*ResponseError` whose message is `response header Content-Type has unexpected value: "text/plain"`. A JSON response body that decodes successfully but violates the schema should return a `*ResponseError` whose message starts with `response body doesn't match schema`, and `ResponseError.Unwrap()` should expose the underlying decode, read, or schema error when one exists.
