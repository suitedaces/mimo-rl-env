I want a Go helper `getbpm.GetBPM(name string) (beats float64, bpm float64, err error)` that can infer musical timing from a WAV file path in one call. If the filename includes explicit metadata, it should parse it case-insensitively: `GetBPM("amen_beats8_bpm172.wav")` should return about `beats=8` and `bpm=172`, and `GetBPM("hands_bpm176_beats32.wav")` should return about `beats=32` and `bpm=176`. If the filename only contains a plausible tempo number, it should combine that tempo with the WAV duration to infer beats when the result is usable; for example `GetBPM("Break120.wav")` should return about `beats=16` and `bpm=160` after falling back from the unsuitable parsed timing.

When filename parsing is missing, out of the 100-200 BPM range, or produces a beat count that is not on a 16-beat boundary, the function should fall back to duration-based guessing. That guessing should search tempos from 100 up to but not including 200 BPM and beat counts from 1 through 128, prefer the closest duration match, prefer power-of-two beat counts when matches tie, and use the `MULTIPLE` environment variable as the beat multiplier when it is set to a non-zero number, otherwise `2.0`. For duration-only examples such as `strega.wav`, the function should still return non-zero beats and BPM rather than giving up just because the filename has no tempo marker. If the WAV file cannot be opened or decoded well enough to measure duration, `err` should be non-nil.

When a sampler audio file is selected in the tracker, the same inference should initialize that file's metadata from the chosen audio or its generated waveform WAV: set the metadata BPM from the inferred BPM, set the slice count to twice the rounded inferred beat count, keep the default sliced/even/sync playback flags, preserve the waveform file path, and immediately generate equal slice markers for the inferred slice count.
