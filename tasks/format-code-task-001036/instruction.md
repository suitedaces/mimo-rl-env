Boundary's `Config.Sanitized` method is used to expose effective server settings for diagnostics, but it currently returns only the shared configuration and can mutate a `Config` that did not yet have shared settings. That omits the Boundary-specific settings an operator needs to inspect, while a naive dump would disclose database URLs, KMS material, or generated development keys.

Expand `Config.Sanitized` into a safe, independent diagnostic snapshot. Keep the existing shared settings that are already sanitized, and, when they are configured, add `controller`, `worker`, `plugins`, `events`, and development settings using the following map shape. A `controller` entry must include `name`, `description`, `public_cluster_addr`, `auth_token_time_to_live`, and `auth_token_time_to_stale` using the parsed duration values. Its `database` sub-map includes `max_open_connections`, but must never include `url` or `migration_url`. A `worker` entry must include `name`, `description`, `controllers`, `public_addr`, and the parsed `tags`. A `plugins` entry contains `execution_dir`. Expose `dev_controller` and `dev_ui_passthrough_dir` when set, but never any generated development key.

The `events` entry must expose `audit_enabled`, `observations_enabled`, `sysevents_enabled`, and its configured `sinks` in their configured order. Each sink reports its normal operational fields (`name`, `description`, `event_types`, `event_source_url`, `allow_filters`, `deny_filters`, `format`, and `type`), an empty `stderr` map for a stderr sink, and the file settings `path`, `file_name`, `rotate_bytes`, parsed `rotate_duration`, and `rotate_max_files` for a file sink. Sink and event type values are strings, and collections are represented as slices in the returned `map[string]interface{}` tree.

The returned data is a snapshot: callers may mutate any returned nested maps or slices without changing the `Config`, listener raw configuration, or event configuration. It must contain no parsing-only `*Raw` fields and no sensitive values, including KMS config/key material, controller database URLs, or development keys. A nil `Config` returns nil. Calling `Sanitized` on an otherwise empty `Config` must return a usable shared-settings map without initializing or otherwise mutating that `Config`, and absent optional Boundary sections must be omitted rather than emitted as empty placeholders.
