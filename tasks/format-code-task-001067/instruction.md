The ODD shell relies on a cached release manifest to find Flex system-update artifacts. At the moment a malformed response can be written to the cache and then treated as usable later, while a malformed release entry can flow through lookup far enough to produce an update attempt. Channel selection also treats prerelease names by substring, so versions such as rc, prealpha, or alphabeta can be selected for the wrong channel. Make this update pipeline defensive while keeping the existing public functions and normal successful behavior.

A release manifest is usable only when it is an object with a production object map (an empty map is valid). Every production key must be a valid Semantic Version, and every release entry must contain non-empty string values for fullImage, system, and version. releaseNotes is optional; when present it must also be a non-empty string. Do not discard other manifest or entry fields. getCachedReleaseManifest() and downloadAndCacheReleaseManifest() must expose only manifests satisfying these rules.

Validate a downloaded manifest before writing it to the cache. If the request fails or the downloaded document is invalid, try the existing cache and return it only if it validates; an invalid download must never replace a valid cached file. If neither source is valid, reject instead of returning arbitrary JSON. getReleaseSet(manifest, version) must return the exact valid release entry for that version, or null when the version is absent or its entry is invalid.

When updateLatestVersion() evaluates a manifest, latest means the highest stable SemVer (no prerelease component), beta means the highest version whose prerelease identifier is beta, and alpha means the highest version whose prerelease identifier is alpha. Matching must be by the parsed prerelease identifier, not by a substring search, and unrelated prerelease labels must not qualify. The existing network-failure fallback to a valid cached manifest remains supported.
