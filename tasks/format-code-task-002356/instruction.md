I want `black.format_str(src_contents: str, *, mode: black.Mode, lines=()) -> str` to normalize Python numeric literal spelling as part of formatting ordinary Python source strings. For `black.format_str("x = .1\n", mode=black.Mode())`, it should return `"x = 0.1\n"`, and for `black.format_str("x = 1.\n", mode=black.Mode())`, it should return `"x = 1.0\n"`.

Scientific notation should use a lowercase `e`, remove a redundant plus sign, and keep a minus sign, so `"x = 1E+1\n"` formats to `"x = 1e1\n"` and `"x = 1E-1\n"` formats to `"x = 1e-1\n"`. Complex numeric suffixes should be lowercase while preserving the number spelling rules, so `"x = 123456789J\n"` formats to `"x = 123456789j\n"`. Hexadecimal, binary, and octal prefixes should be lowercase; hexadecimal digits should be uppercase, so `"x = 0XB1acc\n"` formats to `"x = 0xB1ACC\n"`, `"x = 0B1011\n"` formats to `"x = 0b1011\n"`, and `"x = 0O777\n"` formats to `"x = 0o777\n"`.

Calling `black.format_str` repeatedly with the same source string and mode should produce the same result each time. The numeric normalization should only affect the returned formatted source string; it should not mutate caller-owned inputs or perform filesystem, network, or global-state side effects.
