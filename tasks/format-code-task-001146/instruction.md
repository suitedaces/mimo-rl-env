AsyncAPI documents generated for an `AsgiFastStream` currently describe broker channels but omit the HTTP endpoints that are actually mounted on the same application. This makes health, documentation, and custom HTTP routes invisible to consumers of `get_app_schema(app)`. Extend the native ASGI route decorator and schema generation so these routes are discoverable without changing their runtime dispatch behavior.

`get` must accept optional route documentation metadata: `description`, `tags`, and `operation_id`. An explicit description is used for the documented operation; when it is omitted, the wrapped handler's docstring is used when one exists. Tags are an ordered sequence of names and must be emitted as AsyncAPI operation tags. An explicit operation id is emitted unchanged; when absent, use a stable id derived from the wrapped handler's name.

For every mounted `HttpHandler` whose `include_in_schema` is true, add one AsyncAPI channel keyed by its mounted path. Represent the HTTP request as that channel's publish operation and include an HTTP operation binding with method `GET`; include the operation id, description (when available), and tags (when supplied). Routes opted out with `include_in_schema=False` must remain callable at runtime but must not appear in the generated schema. Existing ASGI behavior remains intact: a GET/HEAD route still serves its handler, and other methods receive status 405 with an `Allow: GET, HEAD` header.
