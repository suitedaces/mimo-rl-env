I want a Python library module `module_rag.agent_tools` that lets agent code fetch knowledge-base context as formatted text without managing retrieval details itself.

Expose `search_knowledge_base(query: str, *, source_id: str | None = None, dataset_ids: list[str] | None = None, tenant_id: Any = None, top_k: int = 5, retrieval_type: str = "hybrid", rerank: bool = False) -> str`. It should combine explicit `dataset_ids` with the datasets attached to `source_id`, preserve first-seen order while removing duplicates, and use the current effective tenant when `tenant_id` is omitted. It should call the knowledge retrieval backend with the selected dataset scope, `top_k`, `retrieval_type`, and `rerank` settings.

If no datasets are available after resolving the scope, it should return exactly `未找到可用知识库。`. If retrieval succeeds but returns no records, it should return exactly `知识库中未检索到相关内容。`. When records are returned, it should produce LLM-ready numbered blocks in ranked order, separated by a blank line: a QA record with content `年假为 10 天` should render as `[1] (QA) 年假为 10 天`, and a normal chunk with content `订单表包含金额字段` should render as `[2] (片段) 订单表包含金额字段`. Leading and trailing whitespace in each record's content should be stripped.

Expose `make_kb_tool(source_id: str | None = None, dataset_ids: list[str] | None = None, tenant_id: Any = None, top_k: int = 5)`, returning a callable that accepts only `query: str` and delegates to `search_knowledge_base` with the fixed scope and `top_k`. For example, `tool = make_kb_tool(dataset_ids=["kb1"], tenant_id=7, top_k=3)` should allow `tool("orders 表有哪些字段")` to return the same formatted text as calling `search_knowledge_base("orders 表有哪些字段", dataset_ids=["kb1"], tenant_id=7, top_k=3)`. Passing a `dataset_ids` list must not mutate the caller's list.
