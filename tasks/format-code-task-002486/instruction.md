I want a public `build_install_plan(browser_name: str = "None", browser_package: str = "", include_browser_install: bool = False, preset_key: str = "standard") -> dict` function that builds a fresh Talon install-plan dictionary from the selected preset and optional browser choice.

Calling `build_install_plan()` should return a dict with `version == 1`, `selected_preset_key == "standard"`, `selected_browser_name == "None"`, `selected_browser_package == ""`, and `include_browser_install == false`. Its `items` list should be ordered as `developer-mode`, `remove-edge-permanently`, `uninstall-outlook-onedrive`, `browser-installation`, `debloat-windows-phase-one`, `debloat-windows-phase-two`, `registry-tweaks`, `configure-updates`, and `apply-background`; for the standard preset, all of those are enabled except `developer-mode` and `browser-installation` when no browser install is requested. Each item should include `key`, `text`, `tooltip`, and `enabled`, defaulting missing preset text and tooltip values to empty strings.

Calling `build_install_plan(browser_name="Firefox", browser_package="firefox", include_browser_install=True, preset_key="standard")` should preserve those browser fields and set the `browser-installation` item and top-level `include_browser_install` to true, while keeping the selected preset key as `standard`. Calling it with an unknown preset key should fall back to the standard preset output instead of failing.

The returned plan should also include `winutil_config`, `win11debloat_args`, `registry_changes`, and `applied_background_path` copied from the preset. If a preset stores Win11Debloat arguments as a list, the function should return them as a single whitespace-normalized string; if a preset has `registry_changes` set to null, the function should fill in the default registry-change payload. Repeated calls with the same arguments and preset catalog should return equal dictionaries, and mutating nested values in one returned plan must not affect later calls.
