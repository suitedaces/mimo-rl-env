tox already lets users declare that one environment depends on another, and the scheduler honors those relationships when the named environments are selected. There is no convenient way to ask for an environment together with everything it needs, however: users have to spell out the closure, can accidentally omit a transitive prerequisite, and can run a dependent after a failed prerequisite when using a custom selection. Add an opt-in `--with-deps` flag to the `run` (`r`), `run-parallel` (`p`), and legacy commands.

With the flag, begin with the environments that tox would normally run (the explicit `-e` selection, or the configured default list when `-e` is absent) and add the transitive closure of their `depends` values. Resolve each environment through the normal configuration machinery, including command-line overrides, before reading its dependencies. A dependency shared by multiple roots must run once, and environments outside that closure must not run. The resulting execution must retain tox's stable dependency ordering: every dependency completes before its dependent, while unrelated ready environments may still run independently in parallel.

A dependency that fails or is skipped must prevent every downstream dependent from executing; those blocked environments are reported as skipped and the overall command is unsuccessful, while unrelated branches continue according to the selected scheduler. Detect a cycle in the expanded graph before executing any environment, exit unsuccessfully, and report the participating environment names. Without `--with-deps`, preserve the existing selection and behavior exactly.
