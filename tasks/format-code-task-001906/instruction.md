I want @microlink/mql to expose raw response modes for one-shot calls. `await mql(url: string, opts: object & { stream: string }, gotOpts?: object)` should build the normal Microlink API request, include the requested `stream` option in the query string, fetch the response as an ArrayBuffer, and resolve to `{ url: string, body: ArrayBuffer, headers: Headers, statusCode: number }` instead of parsing JSON.

For example, with the HTTP transport mocked to return status 200, URL `https://api.microlink.io/?url=https%3A%2F%2Fexample.com&stream=screenshot`, an `image/png` header, and bytes `[1, 2, 3]`, `await mql('https://example.com', { screenshot: true, stream: 'screenshot' })` should return those metadata fields and an ArrayBuffer containing `[1, 2, 3]`. I also need `await mql.arrayBuffer(url: string, opts?: object, gotOpts?: object)` to use the same Microlink API request flow and return that same raw envelope with an ArrayBuffer body; `mql.buffer` should be an alias with equivalent behavior. A direct `await mql.stream(url: string, kyOptions?: object)` helper should fetch the provided URL using the package's shared transport defaults and resolve to the readable response body, so a mocked PNG response returns an object whose `getReader` property is a function. These raw helpers should be available as CommonJS properties on the default export and as ESM named exports `arrayBuffer`, `buffer`, and `stream`.
