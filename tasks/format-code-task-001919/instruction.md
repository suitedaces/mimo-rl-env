I want `getValue(fromObject: any, fromKey: string): any` exported by map-factory so my code can read a value from an object using dot/bracket path syntax without mutating the input. Calling `getValue({ foo: { bar: 'baz' } }, 'foo.bar')` should return `'baz'`, and calling `getValue(['foo', 'bar'], '[1]')` should return `'bar'`. It should traverse arrays with `[]` and preserve nested projection shape: `getValue({ foo: [{ baz: [{ fog: { baz: 'bar' } }, { fog: { baz: 'const' } }] }] }, 'foo[].baz[].fog.baz')` should return `[['bar', 'const']]`. It should also support selecting a property array directly, so `getValue({ foo: { baz: ['bar', 'foo'] } }, 'foo.baz[1]')` returns `'foo'` and `getValue({ foo: { baz: [{ fog: 'bar' }] } }, 'foo.baz[].fog')` returns `['bar']`. When a path cannot be resolved, such as `getValue({ foo: {} }, 'fish[0].b')`, it should return `undefined`; if an array projection has no meaningful values, such as all projected values being `undefined` or `null`, it should also return `undefined`. Passing a non-string path should raise a `TypeError`. Repeating the same call with the same inputs should produce the same result, should not write to the filesystem/network/global state, and should not modify `fromObject`. Mapper source paths should use the same extraction behavior when a mapping reads from the source object before writing the destination.
