I want the `pyzotero.Zotero` client to support creating collections from an already constructed client instance. The public methods should be `create_collections(payload: list[dict[str, Any]], last_modified: int | None = None) -> Any` and `create_collection(payload: list[dict[str, Any]], last_modified: int | None = None) -> Any`, with `create_collection` behaving as a singular alias for `create_collections`.

For example, after `zot = Zotero("myuserID", "user", "myuserkey", client=client)`, calling `zot.create_collections([{"name": "foo", "key": "ABC123"}])` should POST that collection list as JSON to `/users/myuserID/collections` on the configured Zotero endpoint and return the decoded response JSON, such as `{"success": {"0": "ABC123"}}`. Each collection dict must include `name`; if any entry does not, the method should raise `pyzotero.ParamNotPassedError` with the message `The dict you pass must include a 'name' key` before making the POST. If a collection omits `parentCollection`, it should be sent with `parentCollection` set to the empty string.

The request should include a `Zotero-Write-Token` header. When `last_modified=5` is passed, it should also include `If-Unmodified-Since-Version: 5`; when `last_modified` is omitted, that concurrency header should not be sent. The method should respect the client's write backoff before sending, store the HTTP response on `zot.request`, and use the package's normal Zotero HTTP error handling for failed responses.
