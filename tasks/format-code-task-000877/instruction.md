I want RapidCheck to provide unique STL container generators through `rc::gen::unique<Container>(Gen<T> gen) -> Gen<Container>`, `rc::gen::unique<Container>(std::size_t count, Gen<T> gen) -> Gen<Container>`, `rc::gen::uniqueBy<Container>(Gen<T> gen, F f) -> Gen<Container>`, and `rc::gen::uniqueBy<Container>(std::size_t count, Gen<T> gen, F f) -> Gen<Container>`. `unique<std::vector<int>>(gen::arbitrary<int>())` should generate vectors where no two elements compare equal, and every shrink of a generated vector should also keep that no-duplicate invariant. `unique<std::list<int>>(3, gen::arbitrary<int>())` should always generate exactly three distinct elements when successful, and its shrinks should preserve both the requested length behavior for fixed-size generation paths and element uniqueness. `uniqueBy<std::vector<std::pair<int, int>>>(gen::arbitrary<std::pair<int, int>>(), [](const auto &p) { return p.first; })` should generate pairs whose first components are all distinct even when the second components repeat. For a concrete fixed-size case, `uniqueBy<std::vector<std::pair<int, int>>>(2, gen::arbitrary<std::pair<int, int>>(), key_fn)` should return a generator whose produced containers have exactly two elements and two distinct projected keys. If the supplied generator cannot produce enough distinct values, such as `unique<std::vector<int>>(2, gen::just(0))`, evaluating the returned generator should fail with `rc::GenerationFailure` instead of returning a container with duplicates. Creating these generators should not mutate the supplied generator object, touch the filesystem or network, or depend on hidden global state beyond the normal randomness and size parameters used when the returned `Gen<Container>` is evaluated.
