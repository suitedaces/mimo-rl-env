Plugin manifests are consumed by the agent bootstrap path, and the plugin configuration is exposed to plugin hooks through environment variables. The current parser is permissive in a few places and the exporter silently drops nested values, which makes a valid manifest lose configuration or fail only after part of it has been applied. Tighten this public behavior while retaining compatibility with existing flat plugin manifests.

`CreatePluginsFromJSON` must accept a complete JSON array only. Array order is significant and must be preserved. Each element is either a location string or an object containing exactly one plugin location key. An object value may be another JSON object or `null`; `null` means an empty configuration. Empty objects, objects with multiple keys, scalar configuration values, non-string/non-object array elements, malformed JSON, and trailing JSON data are errors. A failed parse must return a non-nil error and no partially built plugin slice.

`Plugin.ConfigurationToEnvironment` must recursively expose JSON configuration as an `env.Environment` using the existing `BUILDKITE_PLUGIN_<normalized plugin name>_` prefix. Map keys become normalized uppercase path segments: every run of characters other than ASCII letters or digits becomes one underscore, repeated separators are collapsed, and an empty segment is invalid. Nested map segments and zero-based array indexes are joined with underscores. Strings, booleans, and JSON numbers are leaves; their textual values are preserved, including `false` and `0`. Arrays may contain supported leaves, maps, or arrays. Empty maps and arrays emit no variables. Unsupported leaves, including `null` below the plugin configuration root, and any normalized-name collision must return an error and a nil environment rather than a partial result. The returned environment remains deterministically readable through its existing sorted `ToSlice` API.

Existing flat configurations must continue to produce the same variables: scalar strings, booleans, JSON numbers, and arrays of supported scalar values retain their current names, index convention, and values. Do not change plugin location/version parsing or the public `Environment` API.
