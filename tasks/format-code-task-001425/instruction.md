I want Stripe-backed customer objects to manage subscription lifecycles directly from the customer instance. Given a customer object with a Stripe customer id and live/test mode, it should support `create_subscription(price_or_plan, invoice=True)`, `retrieve_subscription(subscription_id)`, `change_subscription_plan(subscription_id, new_price_or_plan, prorate=True, invoice=True)`, `free_upgrade_or_downgrade(subscription_id, new_price_or_plan)`, and `cancel_subscription(subscription_id)`.

When I call `customer.create_subscription('price_basic')`, it should create a Stripe subscription for `customer.stripe_id` with one item using that price id, return the Stripe subscription object, and immediately create and pay an invoice when `invoice=True`. When I call `customer.create_subscription({'currency': 'usd', 'product': 'prod_123', 'unit_amount': 2500, 'recurring': {'interval': 'month'}}, invoice=False)`, it should send that dictionary as `price_data`, return the Stripe subscription object, and skip immediate invoicing. Passing an unsupported `price_or_plan` type should raise an `Exception` explaining the unsupported type.

When I call `customer.retrieve_subscription('sub_123')`, it should return the Stripe subscription object for that id, while `customer.retrieve_subscription(None)` should return `None`. When I call `customer.change_subscription_plan('sub_123', 'price_pro')`, it should retrieve the subscription, update the first subscription item to the new price, use prorations by default, return the updated Stripe subscription object, and create/pay an invoice when `invoice=True`. With `prorate=False`, it should update with no prorations; with a `dict` plan it should send `price_data`; with an unsupported plan type it should raise `Exception`; and if the subscription cannot be retrieved it should return `None`.

`customer.free_upgrade_or_downgrade('sub_123', 'price_free')` should be a convenience method that changes the subscription with no prorations and no immediate invoice, returning the updated Stripe subscription object. `customer.cancel_subscription('sub_123')` should return `True` if the subscription is already canceled or if Stripe deletion returns a canceled subscription, and `False` when the subscription cannot be found.
