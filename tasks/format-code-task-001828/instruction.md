I want the Go package to expose a stateful coordinate transformation handle for converting coordinates between two `SpatialReference` values. The public API should be `func CreateCoordinateTransform(source SpatialReference, dest SpatialReference) CoordinateTransform`, with methods `Transform(numPoints int, xPoints []float64, yPoints []float64, zPoints []float64) bool`, `TransformPoint(x float64, y float64) (float64, float64, float64)`, `Destroy()`, `IsNull() bool`, `Err() error`, and `Warn() error`.

A typical session should let me create WGS84 and Web Mercator spatial references, set traditional GIS axis order on both, create a transform, verify `ct.IsNull() == false`, and call `ct.TransformPoint(0, 0)` to get coordinates very close to `(0, 0, 0)`. With the same transform, `ct.Transform(2, []float64{0, 10}, []float64{0, 20}, []float64{0, 5})` should return `true` and mutate the three slices in place: the first point remains near `(0, 0, 0)`, and the second point is near Web Mercator `(1113194.9079, 2273030.9270, 5)`.

If the underlying coordinate conversion fails, `Transform` should return `false`, and `TransformPoint` should return `(0, 0, 0)`. If GDAL cannot construct a transform from the supplied source and destination spatial references, the returned handle should be detectable with `IsNull()`, and callers should be able to inspect CPL failure or warning state through `Err()` and `Warn()` just like the other GDAL handle types in this package. Calling `Destroy()` should release the transform handle without affecting the source or destination spatial references.

I also need geometry objects to accept these transform handles through `func (geom Geometry) Transform(ct CoordinateTransform) error`. Applying a WGS84-to-Web-Mercator transform to a point geometry should update the geometry coordinates in place to the same values produced by the coordinate-array transform, and the method should return the GDAL error as a Go `error` when the geometry transformation fails.
