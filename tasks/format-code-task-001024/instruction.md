Event listener pools currently have two operational failure modes that are hard to tune: a full buffer always throws away the oldest queued event, and a listener that repeatedly rejects one event can replay it forever ahead of useful work. Add explicit delivery controls to `[eventlistener:x]` sections while preserving today's behavior for existing configurations.

Add `buffer_overflow` with the values `discard_oldest` and `discard_newest`. Values are case-insensitive and the parsed configuration should expose the normalized lowercase value. When omitted, it defaults to `discard_oldest`. If a newly published event arrives at a full buffer, `discard_oldest` removes the event at the head and appends the new event, while `discard_newest` drops the arriving event and leaves the already queued FIFO sequence unchanged.

Rejected in-flight events still have priority over untouched queued work when they are eligible for redelivery. They are reinserted at the head. If that reinsertion occurs while the buffer is full, apply the configured policy to the combined ordering: `discard_oldest` removes the previous head before putting the rejected event at the head (the existing behavior), whereas `discard_newest` removes the tail and puts the rejected event at the head. Every overflow discard must continue to produce an ERROR-level log record identifying the pool and the serial of the event that was actually discarded.

Add `event_retries` to bound rejection loops. It is an integer with default `-1`; `-1` means unlimited redeliveries for compatibility, `0` means discard on the first rejection, and a positive value is the maximum number of redeliveries after the initial delivery. Once that allowance is exhausted, discard the rejected event, leave later queued events available for delivery, and emit an ERROR-level record that identifies the pool and event serial and makes clear that the retry/redelivery limit was reached. Retry accounting must be independent for each event listener pool, even when the same event object is delivered to multiple pools. A transient `EPIPE` before an event is successfully handed to a listener must rebuffer the event as today and must not consume this rejection allowance.

Reject unknown `buffer_overflow` values, non-integer `event_retries`, and retry values below `-1`; the configuration error must identify the `[eventlistener:x]` section, option, and bad value. Finally, include both settings in event-listener pool configuration comparison so changing either option is detected by reread/reload.
