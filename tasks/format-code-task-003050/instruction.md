I want the Go parser API to support Kubernetes `apiVersion: v1`, `kind: List` manifests when I call `(*Parser).ParseFiles(files []domain.NamedReader) (domain.AllTypes, error)`. If a named reader contains a List with a Service item named `list-service-test` and an `apps/v1` Deployment item named `list-deployment-test`, `ParseFiles` should return successfully with one entry from `Services()` for the Service and one entry from `Deployments()` for the Deployment, just as if those two objects had been supplied as separate YAML documents.

An empty valid `v1/List` should parse successfully and produce no objects. If any item inside the List is malformed for its Kubernetes kind, `ParseFiles` should return a non-nil error instead of silently dropping the item, and valid items should not make the bad List look successful. List support should also work when the List appears alongside other YAML documents in the same input stream.
