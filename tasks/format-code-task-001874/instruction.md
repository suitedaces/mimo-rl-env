The config generator currently accepts one dotenv or YAML file, but real projects maintain shared defaults and small environment-specific overlays. Extend the public `rnuc` CLI and its normal `load_env` path so YAML configurations can inherit other config files through a reserved top-level `extends` entry. A single string names one parent; an array names multiple parents in the listed order. Parent paths are resolved relative to the file that declares them, and each parent may itself inherit recursively. YAML and dotenv parents may be mixed, using the repository's existing extension-based parsing rules.

Resolve the full inheritance graph before rendering any output. Merge mappings so earlier parents provide defaults, later parents override those values, and the child overrides every parent. Preserve keys that exist in only one layer, including explicit false, zero, empty strings, and null values. When a value changes between a scalar and a platform mapping, the more-specific layer replaces the whole value; when both layers provide platform mappings, retain the per-platform values from the more-specific mapping and inherit missing platforms from the less-specific mapping. The resolved mapping, with the reserved `extends` metadata removed, must feed all existing generated artifacts (JavaScript typings, Objective-C constants, Android YAML, and iOS xcconfig) exactly as a normal non-inherited configuration would.

Inheritance must be safe to use in automation. Detect cycles, including cycles reached through different relative paths, and fail with a non-zero CLI status and an actionable message naming the involved config files. Reject an `extends` value that is neither a string nor an array of strings, and report the source file. A referenced parent that does not exist and a parent that is not valid YAML must likewise fail with a non-zero status and identify the relevant path. Do not silently treat these cases as an empty configuration. Resolve and validate the complete graph before writing anything: if loading or merging fails, pre-existing generated files must remain byte-for-byte unchanged, and no partial output may be created. Existing configs without `extends` and the existing CLI options and dotenv behavior must remain compatible.
