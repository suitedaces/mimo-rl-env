I need the `access.Access` type to expose `Can(requester upspin.UserName, right access.Right, pathName upspin.PathName, load func(upspin.PathName) ([]byte, error)) (bool, error)` so directory code can ask whether a parsed Access policy grants one right on one namespace path. A typical session is: parse an Access file with `access.Parse`, then call `a.Can` repeatedly for different requesters and rights; when a referenced Group file is first encountered, `Can` should call `load` with that Group path, parse and cache the group, and later calls can reuse the loaded group membership.

For an Access file at `me@here.com/Access` containing `r: reader@foo.bar, *@nsa.gov` and `w: writer@foo.bar`, `a.Can("reader@foo.bar", access.Read, "me@here.com/foo/bar", load)` should return `(true, nil)`, `a.Can("writer@foo.bar", access.Read, "me@here.com/foo/bar", load)` should return `(false, nil)`, and `a.Can("writer@foo.bar", access.Write, "me@here.com/foo/bar", load)` should return `(true, nil)`. The owner has implicit read, list, and any-right access, so `a.Can("me@here.com", access.Read, "me@here.com/foo/bar", load)` and `a.Can("me@here.com", access.List, "me@here.com/foo/bar", load)` should return true even if those rights are not listed, while create/delete on ordinary files still require an explicit policy grant. Wildcard users should match by domain, so `*@nsa.gov` grants read to `joe@nsa.gov` but not to the literal requester name `*@nasa.gov`.

Groups must be expanded during `Can`: if the Access text says `r: family` and `load("me@here.com/Group/family")` returns `sister@me.com, brother@me.com`, then `a.Can("sister@me.com", access.Read, "me@here.com/foo/bar", load)` should return true and `a.Can("aunt@me.com", access.Read, "me@here.com/foo/bar", load)` should return false. Nested groups should be followed, group owners should count as members of their own group, and the special `all` user parsed from an Access file should grant the requested right to any authenticated requester. If the requester string is not a valid Upspin user name, `Can` should return `(false, err)`; if the right is not one of the recognized rights or `AnyRight`, it should return `(false, err)`. For Access and Group files themselves, only the owner may create, write, or delete them, regardless of grants to other users, while other rights are still evaluated by the policy.
