The Data Controller module is meant to prevent publisher first-party identifiers (EIDs) and seller-defined audience data (SDA) from being sent together, but its current request transformation is brittle. EID sources can be missed when a bidder has more than one ad-unit request, malformed or absent ORTB fragments can abort an auction, and changing or removing the configuration can leave filtering enabled with stale state.

Make the behavior deterministic through the existing data-controller configuration and auction request hook. For `filterEIDwhenSDA`, build SDA keys from both global `ortb2Fragments.global.user.data` and each bidder's `user.data`. A key is `name:segtax:segment.id` with omitted leading components when they are absent. A configured key matches only that bidder (global SDA applies to every bidder); matching bids must have `userIdAsEids` and `userId` cleared, and the corresponding bidder/global ORTB `user.ext.eids` arrays must be cleared. Non-matching bidders and their EIDs must remain unchanged. The wildcard `*` matches every bidder, including a request with no ORTB fragments.

For `filterSDAwhenEID`, collect the union of EID `source` values across every bid and ad unit for each bidder. A configured source (or `*`) removes that bidder's `user.data`; because global SDA is shared by all bidders, clear global `user.data` whenever at least one bidder is filtered. Other bidders' SDA remains intact.

Missing fragment maps and malformed SDA records (including records without a segment array) are treated as empty input and must never throw; valid neighboring records still participate in matching. Removing the data-controller configuration makes the hook a safe no-op and must not mutate later requests.
