`ios_l2_interfaces` currently treats every entry supplied with `state: deleted` as a request to wipe all L2 settings from that interface. That makes the structured `config` shape misleading and prevents playbooks from removing one setting without disrupting unrelated access, voice, or trunk configuration. Make `config` act as a selective deletion filter while retaining the existing broad-delete forms.

For an interface entry containing fields beyond `name`, only explicitly supplied fields are candidates for deletion; omitted fields must remain untouched. A supplied scalar (`mode`, `access.vlan`, `voice.vlan`, `trunk.encapsulation`, or `trunk.native_vlan`) selects the setting only when its value equals the currently gathered value. A different value is a no-op. An explicitly empty `access`, `voice`, or `trunk` mapping selects every currently configured setting in that subgroup, but nothing outside that subgroup. A non-empty subgroup selects only its supplied children.

Treat `trunk.allowed_vlans` and `trunk.pruning_vlans` as numeric VLAN sets. Each list element may be a decimal VLAN or an inclusive `start-end` range. Delete only the intersection between the requested set and the currently configured set. Emit one `switchport trunk allowed vlan remove <vlans>` or `switchport trunk pruning vlan remove <vlans>` command per non-empty intersection; do not reset the entire list. Format `<vlans>` in ascending order, coalescing consecutive VLANs into `start-end` and separating segments with commas. For example, deleting `15-25,40,99` from current `10-20,40` must render `15-20,40`. A requested list with no overlap is a no-op.

Keep command output deterministic and safe for IOS parent context. Process interface entries in the order provided, emit `interface <name>` only when that entry has at least one effective child command, and keep child commands in the collection's established order: mode, access VLAN, voice VLAN, trunk encapsulation, trunk native VLAN, allowed VLANs, then pruning VLANs. Matching scalar deletions use the existing `no switchport ...` forms; list intersections use the `... vlan remove ...` forms above. If no selector matches anything, return `changed: false` with an empty `commands` list. Unknown interfaces must likewise produce no command.

Preserve both legacy scopes: a name-only entry still removes every gathered L2 setting from that named interface, and an omitted or empty `config` still removes all gathered L2 settings from all interfaces. Existing behavior for merged, replaced, overridden, rendered, parsed, and gathered states must remain unchanged.
