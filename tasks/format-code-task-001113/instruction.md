Complete the missing view-catalog lifecycle for the embedded SQLite SQL dialect. A view is a logical StackQL definition stored in the existing __iql__.views catalog and must remain lazy: registering it must not create a backend/physical SQLite view. SQLDialect.CreateView receives a logical view name, the raw StackQL SELECT definition, and the translated SQL definition. Reject a name or either definition that is empty after trimming, and report a view-related error without changing the catalog. For valid inputs, preserve both definition strings exactly (including whitespace and a trailing semicolon), make the entry discoverable through GetViewByName, and leave deleted_dttm NULL. Names may contain SQL punctuation and must be handled as data rather than interpolated SQL. Calling CreateView again for an existing name must atomically supersede the active definition: the previous active row becomes historical with deleted_dttm set, exactly one replacement remains active, and GetViewByName returns only that replacement. If a replacement is invalid, the prior active definition and catalog state must remain unchanged. Keep the existing seeded catalog entries.
