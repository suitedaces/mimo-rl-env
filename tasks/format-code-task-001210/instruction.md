I want an AngularJS service named `boards` that keeps the application's FPGA board catalog and selected board state. The service is injectable as `boards` and exposes `getUserBoardsDir()`, `loadBoards(projectDir)`, `selectBoard(name)`, and `boardLabel(name)`.

`getUserBoardsDir()` should return the profile `externalBoards` path when it is set, otherwise it should return `common.DEFAULT_EXTERNAL_BOARDS_DIR`. `loadBoards()` should populate `common.boards` from `resources/boards/menu.json`, reading each listed board folder only when it has `info.json`, `pinout.json`, and `rules.json`; each board record should include `name`, `info`, `pinout`, `rules`, `type`, `mode`, `apioBoard`, `origin`, `path`, and `readOnly`. Distribution boards should have `origin === 'distribution'`, `readOnly === true`, their `type` from the menu family, `mode === 'apio'` by default, legacy `mode: 'integrated'` normalized to `custom`, legacy `mode: 'project'` normalized to `apio`, and `apioBoard` from `info.apio.board` or the board name when absent.

`loadBoards()` should also scan user boards from `getUserBoardsDir()` without requiring a menu file, treating every child directory with the three required JSON files as a board, using `info.group`, then `info.type`, then `USER` as its family type. `loadBoards(projectDir)` should additionally scan project boards from `<projectDir>/boards` the same way, using `PROJECT` as the fallback family type. Missing user or project board directories should simply contribute no boards. If the same board name appears in more than one source, the later source should replace the earlier record with precedence `distribution < user < project` while preserving the first-seen ordering in `common.boards`.

After `loadBoards()` has run, `selectBoard('icezum')` should set `common.selectedBoard` to the matching board object and return that same object. Calling `selectBoard('missing-board')` or `selectBoard('')` should fall back to the default `alhambra-ii` board. Selection should also regenerate `common.pinoutInputHTML` and `common.pinoutOutputHTML` as `<option>` lists starting with an empty option; input options include pins whose type is `input` or `inout`, and output options include pins whose type is `output` or `inout`. `boardLabel(name)` should return the matched board's `info.label`, and should return the original `name` when no board matches.
