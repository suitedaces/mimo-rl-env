GeoJSONImageDataset currently assumes a one-to-one relationship between GeoJSON features and media. Real exports often contain one feature per geometry, so repeated features for the same image are silently overwritten, null geometries crash during import, and set-based bookkeeping makes sample order unstable. Make the public GeoJSON image importer/exporter support these files losslessly while preserving the existing default export format.

On import, resolve a feature's media identity as follows: `filename` is relative to `<dataset_dir>/data`; an absolute `filepath` remains absolute; and a relative `filepath` is relative to `dataset_dir`. Group features by this resolved absolute media path without changing the first-seen order. With `multi_location=True`, emit one sample per path and combine every non-null geometry in the group into its `GeoLocations` value, preserving geometry order. Merge non-media properties when values agree or occur on only one feature; if two features provide different values for the same property, raise `ValueError` and identify that property. With `multi_location=False`, more than one non-null feature for a path is ambiguous and must raise `ValueError` with a message containing `multiple features`.

A feature whose `geometry` is JSON null is valid and imports with `location=None`; media found only in `data/` is likewise unlabeled. `skip_unlabeled=True` must exclude both of those cases, while a grouped path with at least one real geometry is retained. When unlabeled media are included, yield unique paths from the GeoJSON in document order, followed by media-only files in sorted absolute-path order. Apply a supplied `property_parsers` function only to keys present in that mapping; preserve all other property values unchanged.

Add an opt-in `flatten_locations=False` argument to `GeoJSONImageDatasetExporter`. The default remains one feature per sample, including the current GeometryCollection representation for multi-location labels and a null geometry for missing labels. When enabled, emit one feature for each individual populated geometry, in points-then-lines-then-polygons order and original order within each kind, using primitive `Point`, `LineString`, and `Polygon` geometries. A sample with no populated geometry still emits one null-geometry feature. Repeat its generated properties on each feature, but copy/reference the media only once and reuse the same `filename` or `filepath` on every feature for that sample. Preserve existing `property_makers`, `omit_none_fields`, `copy_media=True`, and `copy_media=False` behavior. A flattened export must therefore round-trip through the importer with `multi_location=True` without losing locations, properties, or unlabeled-state semantics.
