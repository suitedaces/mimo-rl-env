The build-time version helper in `tools/version_utils.py` must be reliable when invoked from packaging jobs, temporary checkouts, and source distributions. `git_version(cwd)` should inspect the repository rooted at the supplied `cwd`, returning the seven-character `HEAD` revision and the number of commits reachable from `HEAD` but not from the previous branch-point tag (`v<MAJOR>.<MINOR-2>.0`), using the existing `0` fallback when that count is unavailable. It must not silently inspect the caller's current checkout; when `cwd` is not a Git repository, return `("Unknown", "Unknown")`.

`get_version_info(source_root)` should use that Git information when `.git` exists beneath `source_root`. Otherwise it must load `scipy/version.py` beneath the supplied root (not relative to the process working directory) and return its `full_version`, `git_revision`, and `commit_count`; if neither source is available, retain the existing unknown metadata behavior. The generated module must continue to expose the established `short_version`, `version`, `full_version`, `git_revision`, `commit_count`, and `release` values, with unreleased builds using `full_version` as `version`.

`write_version_py(source_root, filename)` must create missing parent directories for `filename` and write valid, importable Python metadata. The command-line entry point must accept both `--source-root` and an optional `--filename` so packaging can place the generated module outside the checkout's default path. Existing callers that omit `--filename` must keep the current default destination and version semantics.
