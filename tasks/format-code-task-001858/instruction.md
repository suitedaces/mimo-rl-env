I want gpu-curtains to provide a stateful `Plane` class exported from the main package, usable as `new Plane(renderer, element, parameters?)`, where `renderer` is a `GPUCurtains` or `GPUCurtainsRenderer`, `element` is an `HTMLElement` or selector string, and `parameters` accepts normal DOM mesh/material options plus optional `widthSegments`, `heightSegments`, `instancesCount`, `vertexBuffers`, and `geometry`.

Constructing a `Plane` should create a DOM-synchronized WebGPU quad: the instance should behave like a DOM-backed mesh, have `type === 'Plane'`, bind to the supplied DOM element, and pass through DOM mesh options such as source autoloading, scroll watching, DOM textures, render/material settings, and lifecycle callbacks. With no explicit geometry, `new Plane(gpuCurtains, '#card')` should use a `PlaneGeometry` with `widthSegments = 1`, `heightSegments = 1`, `instancesCount = 1`, no extra vertex buffers, and a default label of `Plane` unless the user provides one.

If `parameters.geometry` is already a `PlaneGeometry`, the `Plane` should use it directly. If no valid plane geometry is supplied, the class should derive a plane geometry from `widthSegments` and `heightSegments`, default missing segment values to `1`, reuse a cached matching plane geometry when there are no custom vertex buffers, and create/cache a new `PlaneGeometry` when no cached one exists. When a cached geometry is reused, the requested `instancesCount` should still be applied to that geometry before the DOM mesh is initialized.

I also want `gpuCurtains.planes` to return all created `Plane` instances from its curtains renderers, filtered out of the broader DOM mesh collection, so code can inspect or manage only DOM-backed planes separately from other DOM meshes.
