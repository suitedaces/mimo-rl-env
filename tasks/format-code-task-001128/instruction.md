The push-list pipeline receives file paths from pull requests, merges them with hand-maintained server files, and then serializes the resulting queue. At present, adding an item rewrites the caller's PushItem, hierarchy handling depends on insertion details, and a URL containing a fragment can make server-file parsing fail. These are particularly painful for callers that retain the original PR records or process URLs from APIs.

Make the public PushItems and PushItem behavior consistent and composable. `PushItems.add(item)` must normalize family files (TTF, OTF, HTML, PB, TXT, YAML, and PNG beneath an ofl/ufl/apache/designers family) to the family directory, transform internal lang and axisregistry textproto paths to their server representation, ignore unsupported lang/axisregistry files and top-level repository roots, and leave the supplied PushItem unchanged. Queue entries should represent paths canonically. When adding entries, an exact duplicate path is replaced by the newest item's metadata; a directory entry supersedes entries below that directory, while entries in different directory trees remain independent, regardless of which one was added first.

`PushItems.from_server_file` must continue to recognize category headers and path-only lines, and when a line has a URL it must split only at the path/URL separator so URL contents, including additional `#` fragments, are preserved verbatim. The resulting item carries the selected status and push-list arguments. The `+` and `-` operators must produce independent queues: combining or subtracting queues may normalize copied entries and apply path-based duplicate/subtraction rules, but neither operand (nor its PushItems) may be mutated. Existing valid server-file output and equality-by-path behavior must remain compatible.
