I want the Python SDK clients to let an existing agent session poll for unread user replies. On a synchronous `OmnaraClient`, I should be able to call `get_pending_messages(agent_instance_id: str | uuid.UUID, last_read_message_id: str | None = None) -> PendingMessagesResponse`; on an `AsyncOmnaraClient`, I should be able to `await get_pending_messages(...)` with the same arguments and response shape.

The method should accept either a UUID object or a valid UUID string for `agent_instance_id`, and invalid IDs should raise `ValueError` before making an API request. It should call the agent API's pending-message endpoint with `agent_instance_id` as a query parameter, and include `last_read_message_id` only when the caller provides one.

For a response like `{"agent_instance_id":"11111111-1111-1111-1111-111111111111","status":"ok","messages":[{"id":"m1","content":"ship it","sender_type":"user","created_at":"2026-01-02T03:04:05Z","requires_user_input":false}]}`, the SDK should return a `PendingMessagesResponse` whose `agent_instance_id` is that UUID string, `status == "ok"`, and `messages[0]` is a `Message` object with the same id, content, sender type, timestamp, and `requires_user_input` value. If the API returns `status == "stale"` with an empty message list, the SDK should preserve that status and return an empty `messages` list rather than treating it as an exception.
