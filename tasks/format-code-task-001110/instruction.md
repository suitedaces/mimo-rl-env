The release tooling is used by all three projects in this repository, but its small text helpers currently make release automation fragile: parser whitespace is inconsistent, assignment rewrites can damage line endings, and malformed versions can reach the bump logic. Harden the public helpers in `hypothesistooling.releasemanagement` while keeping their existing callers compatible.

`parse_release_file_contents()` must accept a release directive as the first logical line even when the file begins with a UTF-8 BOM or surrounding horizontal whitespace, and it must accept normal LF or CRLF input. The directive must contain exactly `RELEASE_TYPE:` followed by one of `major`, `minor`, or `patch`; trailing words, comments, or tabs on that directive are invalid. Return the selected type and a body with surrounding blank whitespace removed, while preserving indentation and tabs belonging to non-blank body lines. Empty files, missing directives, and unknown types must raise `ValueError`.

`extract_assignment_from_string()` and `replace_assignment_in_string()` must match a complete assignment name rather than a substring. Extraction and replacement must reject both a missing target and more than one target with `ValueError`; one target may use arbitrary indentation and spacing around `=`. Replacement must change only the value and preserve the input newline convention, including CRLF and whether the input had a terminal newline.

`parse_version()` must accept exactly three dot-separated, non-negative decimal components with no surrounding whitespace or leading zeroes (apart from the single component `0`), returning an integer tuple. `bump_version_info()` must accept exactly three non-negative integer components and a valid release type, increment the selected component, and reset all less-significant components to zero; malformed shapes, negative or non-integer components, and unknown release types must raise `ValueError`.

`update_markdown_changelog()` must prepend a heading containing the supplied name, version, and one stable UTC date, then the stripped new entry and a blank separator, while retaining the previous changelog byte-for-byte after that separator.
