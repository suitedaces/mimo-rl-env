I want the `Curtains` controller to manage page scroll state as part of its instance lifecycle. The constructor should accept `watchScroll?: boolean` alongside the existing rendering options; when it is omitted or `true`, the instance should listen to the browser `scroll` event, and when it is `false`, it should not install that native listener but should still allow manual scroll updates.

A session should work like `const curtains = new Curtains({ container, watchScroll: true }); curtains.onScroll(cb); curtains.updateScrollValues(x, y); curtains.getScrollValues(); curtains.getScrollDeltas(); curtains.dispose();`. `getScrollValues()` should return the current tracked offsets as `{ x, y }`, initialized from `window.pageXOffset` and `window.pageYOffset` and updated after resize sizing as well as after scroll changes. `updateScrollValues(x, y)` should set the tracked offsets, compute deltas as the previous offset minus the new offset, and make `getScrollDeltas()` return `{ x: previousX - x, y: previousY - y }`; for example, starting from `{x: 10, y: 20}`, calling `updateScrollValues(15, 5)` should make `getScrollValues()` return `{x: 15, y: 5}` and `getScrollDeltas()` return `{x: -5, y: 15}`.

Whenever the tracked scroll changes, the controller should update every plane in `curtains.planes` that has `watchScroll` enabled by passing the latest deltas to the plane's scroll-position update path, force at least one render even if drawing is disabled, and then call the callback registered with `onScroll(cb)`. `onScroll(cb)` should store the callback and return the same `Curtains` instance so it can be chained with other lifecycle callbacks. When `watchScroll` is true, native browser scroll events should use `window.pageXOffset` and `window.pageYOffset` to drive the same update behavior. When `dispose()` is called, any native scroll listener installed by this feature should be removed so later page scrolls no longer invoke the instance callback.
