Make Alexa proactive state reporting send meaningful deltas and tolerate transiently invalid temperature readings. At present, any Home Assistant state event for an endpoint with a proactive capability posts the endpoint's full property set as changed, even when only an unrelated attribute moved. Temperature states such as `unknown` can also raise during serialization and abort the event task.

For updates that have both an old and a new state, send a `ChangeReport` only when at least one currently serializable property belonging to an interface whose discovery metadata declares `proactivelyReported` has changed value or has newly appeared. Put all and only those current changed proactive properties in `event.payload.change.properties`. Put the current value of every other serializable, retrievable endpoint property in `context.properties`; property ordering is not part of the contract. Do not make an HTTP request for an update that changes no Alexa property, or one that changes only a retrievable interface which is not proactive. A single update may change properties from multiple interfaces, and every such delta must be included.

Connectivity is a proactive property: Alexa discovery must advertise `Alexa.EndpointHealth` as proactively reported. A transition to Home Assistant's `unavailable` state must therefore emit an `UNREACHABLE` connectivity delta. Preserve the existing health distinction: `unavailable` is unreachable, while `unknown`, missing or malformed measurements, and non-finite measurements do not by themselves make a reachable endpoint unhealthy.

Temperature serialization must be safe for both temperature sensor states and a climate entity's `current_temperature`. Omit the `Alexa.TemperatureSensor` property when the reading is absent, `unknown`, `unavailable`, not numeric, NaN, or positive/negative infinity. Such a reading must not abort a `ReportState`, a proactive state event, or serialization of the endpoint's other valid properties. If it is the only would-be delta and connectivity remains unchanged, produce no empty `ChangeReport` and no error-level background-task log. If an omitted reading later becomes a finite number, treat the temperature property as newly changed. Numeric strings remain supported, including `"0"`, which must serialize as the numeric value `0.0` with the existing Alexa temperature scale. Existing discovery and state-report behavior for ordinary valid temperatures and healthy/unhealthy endpoints must continue to work.
