I want a stateful session store API exposed as `simples.store(options?) -> Store`. Calling `const store = simples.store()` should create an independent in-memory store with async methods `store.set(id: string, session: any, timeout: number): Promise<void>`, `store.get(id: string): Promise<any>`, `store.update(id: string, timeout: number): Promise<void>`, and `store.remove(id: string): Promise<void>`.

With the default store, `await store.set('sid', {user: 'ada'}, 1000)` followed by `await store.get('sid')` should resolve to the same stored session value. If I then call `await store.update('sid', -1)`, the next `await store.get('sid')` should resolve to `null` because the entry is expired and removed. If I call `await store.set('sid', 'value', 1000)`, then `await store.remove('sid')`, then `await store.update('sid', 1000)`, `await store.get('sid')` should still resolve to `null`.

Two stores created with `simples.store()` must not share entries: setting `sid` in one store should not make it visible from another store. I also need `simples.store(options)` to accept custom async implementations for `get`, `set`, `remove`, and `update`, forwarding each public method call to the matching custom function with the same arguments. If a custom function throws, the store method should reject with that error; if a configured function returns a non-Promise value, the store method should reject with an `Error`. A store created with `null` or `{}` should still construct, but calling an unimplemented method such as `set` or `get` should reject with an `Error`.
