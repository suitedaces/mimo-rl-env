Make Rancher's Helm post-delete cleanup hook aggregate failures instead of aborting midway or inferring success from command output. The hook is the chart job's operational cleanup boundary, so one bad release or pod must not prevent the remaining namespaces and final cleanup from being attempted. Keep the existing chart-facing environment variable names and the existing Helm/kubectl integration.

Validate the complete invocation before calling either tool. `NAMESPACES`, `RANCHER_NAMESPACE`, `TIMEOUT`, and `IGNORETIMEOUTERROR` are required; `NAMESPACES` must contain at least one non-whitespace token, `TIMEOUT` must be a base-10 non-negative integer, and `IGNORETIMEOUTERROR` must be exactly `true` or `false`. Invalid input must produce a useful diagnostic and a nonzero status without invoking Helm or kubectl. Treat `NAMESPACES` as a whitespace-separated list and process a repeated namespace only once.

For each namespace, list its Helm releases. A list failure is a hard failure for that namespace, but processing continues with later namespaces. Continue skipping release names ending in `.crd`. For every other release, determine `helm uninstall` success solely from its exit status: a silent success is still success and output from a failed command is not success. Do not poll pods after a failed uninstall; record the namespace/release and continue with later releases. After a successful uninstall, observe pods selected by `app=<release>` until none remain or `TIMEOUT` seconds are exhausted. `TIMEOUT=0` still performs one immediate observation and never sleeps. A pod-inspection command error is a hard failure, distinct from a timeout, and must not stop later work.

After release processing in each namespace, discover pods whose returned names begin with `pod/helm-operation-` and attempt to delete them. Both discovery and deletion errors are hard failures but must not stop other cleanup. After every namespace has been attempted, always attempt deletion of `bootstrap-secret` from `RANCHER_NAMESPACE`; an error from that deletion is also hard.

`IGNORETIMEOUTERROR=true` suppresses only timeout failures. It must not hide Helm list/uninstall errors, pod-inspection errors, operation-pod errors, or bootstrap-secret errors. Finish with a human-readable summary: successful completion must be clear, while each non-ignored problem must identify the affected namespace and, where applicable, release or pod plus the failed stage. Exit 0 only when no non-ignored problem remains; otherwise finish all possible work and exit 2.
