The public character-mapping APIs need one consistent contract for fonts created in memory and fonts loaded from disk. A glyph's `unicode` is its primary code point, while the optional `unicodes` list contains every code point that should select that glyph; callers must be able to supply aliases without them being silently discarded. This matters for generated fonts, where the cmap is built from the glyph metadata, and for clients that use supplementary-plane characters.

Make `Font.hasChar` report true only when the requested code point is actually mapped to a real glyph, and false for an unmapped code point (including a missing supplementary-plane character). `Font.charToGlyphIndex` should return the mapped glyph index for primary values and aliases, and `null` for an unmapped value. `Font.charToGlyph` and `Font.stringToGlyphs` must continue to return the `.notdef` glyph for missing characters rather than throwing or producing an invalid glyph, including when glyphs are loaded lazily in low-memory mode.

The same results must hold for both TrueType and CFF fonts. When a programmatically constructed font is serialized with `toArrayBuffer()` and parsed again, its primary mappings and every supplied alias must remain usable, while unknown characters still follow the missing-character contract. Preserve existing mapped-character behavior and do not require callers to know which outline format or memory mode is in use.
