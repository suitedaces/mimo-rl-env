SassDoc's parsed output needs reliable cross-reference metadata for libraries that publish compatibility names and depend on helpers. Today @alias only works accidentally for one shape, reverse links are duplicated when a dependency is listed more than once, and running the resolver again can change the graph. Extend the public parse/getData behavior as follows.

An @alias declaration identifies the documented item as an alias of another documented item. It may be written as a bare name (which uses the declaring item's context type) or as {type} name (which selects the explicit Sass context type); surrounding whitespace is insignificant. After the complete source set is parsed, each resolved target exposes an aliased array containing the declaring items' context.name values in first-seen order, with no duplicate entry even when the declaration is repeated. A missing target must not throw, must leave the source alias value intact, and must not add an aliased entry anywhere.

A local @requires reference resolves by its declared type and name. Its parsed requirement retains its metadata and gains an item reference to the documented target; that target exposes usedBy entries for the requiring documented item. Repeating the same requirement from one requester must not duplicate the reverse usedBy edge, while each original requirement entry remains present. Namespace-qualified requirements (for example vendor::utility) remain external metadata, including an optional URL, and are never linked. A non-external requirement whose target is absent likewise remains in the requires array without an item reference or fabricated reverse link.

Resolution must be safe to invoke repeatedly on the same parsed result: a second post-processing pass preserves the same alias and dependency arrays rather than appending duplicates. Each original requirement entry remains present in its declared order.
