I want a PyTorch `LightFC` module exported from `lib.models` so callers can use `from lib.models import LightFC` and construct it as `LightFC(cfg, env_num=0, training=False)`. The constructor should read `cfg.MODEL.BACKBONE.TYPE`: `MobileNetV2` creates a MobileNetV2 backbone, and `tiny_vit_5m_224` creates a TinyViT-5M backbone. Each instance should own its own `backbone`, `fusion`, and `head` submodules; the fusion block should be configured from `cfg.MODEL.FUSION.PARAMS.num_kernel` and `cfg.MODEL.FUSION.PARAMS.adj_channel`, and the head should be configured from `cfg.MODEL.HEAD.PARAMS.inplanes`, `channel`, `feat_sz`, `stride`, and `freeze_bn`.

For training use, `net.forward(z, x)` with `training=True` should extract features for both the template tensor `z` and search tensor `x`, fuse those features, and return the configured head output without wrapping or renaming it. For online tracking, `net.forward_backbone(z)` should return the cached template feature from the backbone, and `net.forward_tracking(z_feat, x)` should run the search tensor through the backbone, fuse it with the supplied cached template feature, and return the configured head output. When constructed with `training=False`, calling `net.forward(z_feat, x)` should follow the same tracking path as `net.forward_tracking(z_feat, x)`, so a tracker can cache the template once and reuse it across later frames.
