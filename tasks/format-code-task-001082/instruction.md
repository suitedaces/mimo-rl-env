The mock currently treats every registration as either one-shot or globally reusable. That is awkward for clients whose behavior is deliberately bounded: a retry policy may allow exactly three attempts, a paginated operation may be expected a known number of times, and a callback or injected exception should participate in the same accounting as a static response. Add a per-registration `times` option to `HTTPXMock.add_response`, `add_callback`, and `add_exception`.

When `times` is supplied it must be a positive integer (booleans are not integers for this purpose); reject zero, negatives, floats, strings, and other invalid values immediately at registration with a clear `ValueError` or `TypeError` that names `times`. The quota counts only requests that actually match that registration. A registration with `times=N` is eligible for its first N matching requests, in normal registration order, and is unavailable after its Nth delivery; a later matching registration can then handle the request, while an exhausted registration must not be revived by the fixture-wide `can_send_already_matched_responses` setting. The same rules apply whether the registration returns a response, invokes a synchronous callback, invokes an asynchronous callback, or raises an exception (request errors must still carry the received request).

Quota accounting must integrate with the existing teardown assertion: a required registration is considered satisfied only after its full quota has been delivered, while `assert_requested=False` explicitly permits a quota to be used partially or not at all. Existing registrations that omit `times` retain their current one-shot/global-reuse behavior, and explicit `can_send_already_matched=False` remains compatible with a bounded registration; combining a finite quota with `can_send_already_matched=True` must be rejected rather than creating ambiguous semantics. `times` is a registration option, not a request filter, so `get_request` and `get_requests` must continue to reject it as an unknown retrieval argument.
