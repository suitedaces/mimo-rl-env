I want `stolon-sentinel` to support an `--initial-cluster-spec <path>` flag for bootstrapping a brand-new cluster from a JSON cluster specification file. When I run `stolon-sentinel --initial-cluster-spec spec.json` with the normal store configuration flags and the store has no cluster data yet, the sentinel should read `spec.json`, parse it as a cluster specification, validate it with the same rules used for cluster specs, create the initial cluster data document from that spec, and atomically write it to the configured store. After that write, the cluster data should have the current cluster data format version, a generated cluster UID, initial generation, initializing phase, an empty keeper/DB/proxy layout, and the provided spec as the cluster spec.

If the store already has cluster data, the flag should not replace or mutate that existing cluster data; the sentinel should continue with normal reconciliation. If the file cannot be read, the command should fail during startup with a non-zero exit and an error message containing `cannot read provided initial cluster config file`. If the file is not valid JSON for a cluster spec, startup should fail non-zero with `cannot parse provided initial cluster config`. If the parsed spec is invalid, startup should fail non-zero with `invalid initial cluster`. `stolon-sentinel --help` should list `--initial-cluster-spec string` and describe that it provides the initial cluster specification used only when the cluster is not already initialized.
