The file reader currently forwards every keyword to Fiona, so callers cannot ask GeoPandas for a small, filtered view of a layer without post-processing it themselves. Extend the public `geopandas.read_file` API with explicit `columns` and `where` parameters while preserving the existing file, URL, and file-like reading behavior. The public callable should expose `filename`, `bbox`, `mask`, `rows`, `columns`, and `where` before its existing variadic Fiona options.

`columns` is an optional sequence of non-geometry attribute names. Validate that it is a sequence (a bare string is invalid), that names exist and are unique, and that the geometry column is not requested explicitly. Return attributes in exactly the requested order, followed by the active geometry column. An empty sequence therefore returns only geometry. With `ignore_geometry=True`, apply the same projection but return an ordinary pandas DataFrame containing only the requested attributes; an empty projection has zero columns and the source row count/index.

`where` is an optional string containing an OGR/Fiona attribute-filter expression. Only features satisfying it are returned, in source order; a non-string value is rejected. The expression may reference source attributes that are not in `columns`, and filtering must happen before `rows` slicing, so slices select positions within the filtered sequence. `where` is conjunctive with an existing `bbox` or `mask` spatial filter. These options must work for filesystem paths and file-like inputs.

When `columns` is omitted, retain the existing Fiona `include_fields` and `ignore_fields` options and their projection behavior. Supplying either legacy field option together with `columns` is ambiguous and must be rejected. Calls that omit the new options keep their existing CRS, geometry, ordering, row-selection, spatial-filter, `ignore_geometry`, and legacy field-selection behavior.
