I want a public `maestro.loader.load(filename, filters=None, functions=None)` function that reads a Maestro environment description, renders it as a Jinja template, parses the rendered YAML, and returns the resulting Python configuration object.

When `filename` is a file path, the function should resolve templates relative to that file's directory. For example, if `/tmp/envs/demo.yaml` contains `name: demo\nfoo: {{ env.BAR }}\n` and `BAR=bar` is present in the process environment, `load('/tmp/envs/demo.yaml')` should return a mapping where `name == 'demo'`, `foo == 'bar'`, and `__maestro['base_dir'] == '/tmp/envs'`. If the parsed YAML does not define `__maestro`, the function should add it before returning; if it already exists, the function should preserve its other keys and set `__maestro['base_dir']`.

When `filename == '-'`, `load` should read the template text from standard input and set `__maestro['base_dir']` to the current working directory. The Jinja context should expose process environment variables as `env`, and callers should be able to pass custom Jinja filters through `filters` and callable globals through `functions` so templates can use them during rendering.

YAML mappings with duplicate keys should be rejected by raising `yaml.constructor.ConstructorError`; for example, a document containing two top-level `name` keys should not silently keep one value. If a named template file cannot be found, `load` should raise `maestro.exceptions.MaestroException` with a message indicating that the environment description file was not found. If opening or loading the template fails for another reason, it should raise `MaestroException` describing the read error instead of leaking a raw Jinja template-loading exception.
