I want github.com/go-sql-driver/mysql to support filesystem-backed LOAD DATA LOCAL INFILE sources. In my program I should be able to call mysql.RegisterLocalFile(filePath string) before running db.Exec("LOAD DATA LOCAL INFILE '<same path>' INTO TABLE t"), and the driver should treat that registered path as an allowed local infile source when the MySQL server asks for it. An empty registered file should complete successfully and load zero rows, while a registered file containing tab-separated rows should be opened and used as the data source for the statement.

I also need mysql.DeregisterLocalFile(filePath string) to remove a path from the allowlist so later LOAD DATA LOCAL INFILE requests for that path are rejected unless another policy permits them. If the server requests an ordinary filesystem path that has not been registered, Exec should fail with an error like local file '<path>' is not registered.

The connection configuration should expose Config.AllowAllFiles bool and the DSN parameter allowAllFiles=true/false. ParseDSN should accept normal boolean spellings such as true, TRUE, True, and 1 for allowAllFiles, reject invalid boolean values, and set Config.AllowAllFiles. FormatDSN should include allowAllFiles=true when Config.AllowAllFiles is true. When AllowAllFiles is true, LOAD DATA LOCAL INFILE should be allowed to open the requested filesystem path without an explicit RegisterLocalFile call, while file open or stat failures should still surface as Exec errors.
