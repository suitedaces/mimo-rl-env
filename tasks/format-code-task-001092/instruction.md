Capacity configuration now contains increasingly long histories, but the public lookup helpers still compare serialized timestamps as strings and callers have no way to obtain a complete change series for an interval. Harden capacity resolution so snapshots and interval output share one predictable temporal contract.

Keep the existing get_capacity_data(capacity_config, dt) and get_capacity_data_with_source(capacity_config, dt) APIs, and add get_capacity_data_series(capacity_config, start, end). A mode may still be configured as a numeric scalar, None, a legacy single record mapping, or a list of dated records. Scalars are constant; a single record mapping remains effective at every query time for backward compatibility. An empty list means the mode is unavailable. Preserve zero and None values rather than treating either as absent. The plain snapshot API returns raw values, while the source-aware API returns CapacityData(value, source) and uses None when a source is omitted. Neither lookup may mutate the supplied configuration.

For a non-empty dated list, parse each record's ISO 8601 datetime and select the chronologically latest record at or before the query. An exact timestamp is inclusive, list order is irrelevant, and a query before the first record continues to use the earliest record. Offset-aware timestamps and queries must be compared as absolute instants, not by their text. A timeline and its query must either all be offset-aware or all be naive; reject mixed awareness with ValueError. Reject a timeline with ValueError when a record lacks datetime or value, its datetime is not valid ISO 8601, its value is neither numeric nor None, or two records denote the same instant (including equivalent offsets). Both snapshot APIs must apply the same validation.

get_capacity_data_series returns a list of (datetime, snapshot) tuples, with each snapshot containing CapacityData for every configured mode. It must emit the full state at start, followed in chronological order by one full state at each distinct record time after start and through end where the resolved state changes. Coalesce simultaneous mode changes into one tuple, do not emit records after end, and do not add entries for scalar or single-record modes. The interval is inclusive, so start == end returns exactly the initial snapshot. Reject start > end and reject ranges whose endpoints differ in timezone awareness with ValueError; the range and its timelines follow the same awareness rule as snapshot lookup.
