I need a Python API for routing outgoing Iris messages through configured vendor backends. The public class should be `IrisVendorManager(vendors: list[dict], application_vendors: list[str])`, with `send_message(message: dict)` and `cleanup()` methods, plus an `IrisVendorException` for exhausted delivery attempts.

When I construct `IrisVendorManager([{"type": "iris_dummy"}], ["dummy_app"])`, calling `send_message({"mode": "call"})` should use the default dummy vendor and return `1`. With the same manager instance, calling `send_message({"application": "dummy app", "mode": "call"})` should use the application-specific wrapper and return `2`.

The manager should build vendor instances once during construction from each vendor config's `type`, register each vendor for every supported mode, and keep those instances alive across sends so repeated `send_message()` calls use the manager's current vendor rotation state. If an application-specific wrapper exists for `message["application"]` and supports `message["mode"]`, that wrapper should be preferred; otherwise the manager should fall back to the default vendor rotation for that mode. If a selected vendor raises during send, `send_message()` should try the next vendor for that mode, stop after the manager's per-message retry limit, and then raise `IrisVendorException` indicating that all vendors for the requested mode failed. Calling `cleanup()` should call `cleanup()` on every constructed vendor instance that provides it and should ignore vendors that do not expose a cleanup method.
